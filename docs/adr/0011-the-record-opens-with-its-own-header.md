# 0011 —— 记录的第一行是文件自己的：格式版本与会话身份

- **日期**：2026-09-26
- **状态**：**已采纳**
- **记录格式升到 2**（`harness.edge.http/record-format`）——同一次提交引入第一行，因为一个必须遇见新首行的
  读者必须能说出自己在读什么。**文本快照（ADR 0010）没有让版本动**：那是一族新的 CUSTOM 名字，没听过它的
  读者用 `kind`/`fact-frame?` 的既有词汇就会忽略它，轮不到版本。
- **参照**：`.scratch/event-persistence/spec.md` 票 06（主人蓝图里的「文件头」，2026-09-25 拍定值得补）。

## 背景

一份记录今天靠**文件名**与 `provider/init` 行承载「这是谁」：文件名会被 `move-log!` 改写、被 carry-back
拼接、被人手动挪动；`provider/init` 是一次运行的事实，且一场没有 run 的会话可以根本没有它。崩掉一半的
文件、被工具截断的文件、两个工作区里同名的一对文件——今天都要靠读内容来分辨。**头行把这件事变成第一个
字节就说明。**

## 决策

1. **第一行是 `CUSTOM record/header`**（`{:format .. :thread .. :created ..}`），走 `harness.edge.http`
   既有的 `row-of` 信封（`ts`/`runId` 在外、payload 在内）——**不造第三种行**。`jsonl-two-kinds` 的两种行
   一个字不动。
2. **它不是线上的一帧，是 harness 说自己的话**：故意**不**加进 `harness.edge.replay/wire-custom-names`，
   于是折叠把它读成一条具名事实——每一个从没听过它的读者都会像忽略 `model/start` 那样忽略它。**读侧不改**
   是这一条能用的一半理由：老记录（没有头）读出来和以前一模一样。
3. **一行一字**，标记在**文件路径**上而不是线程上（`record/headers-written`）：一次 `swap-vals!` 同时检查
   与标记，两个线程（同一会话的 run 与 hook）不会写两份；对话**搬走**（`move-log!` 造出新文件）后新文件
   得到自己的头。
4. **谁写：写手知道「何时」，边（edge）知道「说什么」。** `record/set-header!` 是这个家族一贯的缝
   （`prepare-with!`/`set-sink!`/`set-forcer!`），由装配处（`http/start!`）装进去——行形的词汇是
   `row-of` 的，会话的身份是 home 的。写发生在 `log!` 解析文件的同一把锁里（「哪个文件」与「这个文件有
   头了吗」是一件事），而**追加本身在锁外**（ADR 0007 的分法）。
5. **写头不抛异常**：最坏情况是回到没有头的世界（读者把第一行当对话自己的第一行，与今天一样），而不是
   一个写不下去的 run。
6. **读侧两个新谓词**：`replay/header?` / `replay/header-of`。想要的人问第一个行；不要的人永远不会遇到它。

## 代价

- **行号全体移一位**：每份新记录从第二行开始才是对话。这正是记录格式升到 2 的原因——任何数行数、按行号
  索引的旧工具读新文件都要知道为什么。`entries` 的 `:seq` 是「这一行在文件里的位置」，头行占第 0 行，
  所以它不破坏语义，只是起点变了。
- **多一行**（约 90 字节）与会话数成正比。

## 边界（不做的事）

- **不在每行加 `seq`**（ADR 0003 决策 9），**不造第三种行**，**不改读侧的折叠**。
- 头**不进** `wire-custom-names`——它不是会话的一部分，折叠不能看见它。
