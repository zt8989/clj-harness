# 0017 —— 轮也写进记录：`turn/start` / `turn/end` 两处都在

- **日期**：2026-10-02
- **状态**：**已采纳**
- **取代** `docs/adr/0006-turn-and-model-call-are-the-two-levels.md` 的**决策 3**（「`turn/*` 走会话级下行，
  不进记录」），以及 `docs/adr/0011-a-step-is-a-request-plus-its-tools.md`「边界（不做的事）」第一条
  （「不改轮：`turn/*` 仍不进记录」）。0006 / 0011 的其余部分——轮与步与一次模型调用是三个层级、
  `model/*` 两处都在、`seq` 是记录行号、发送点只有一个、不背历史——**一个字不改**，两份正文也一个字不改
  （本仓的规矩是加注）。
- **参照**：`.scratch/turn-rows/spec.md`。

## 背景

**ADR 0006 决策 3 的纪律是「算得出来的不写」**：轮的开合由记录算得出来（一条没见过的
`:source "client"` 的 user 行），再写一行就是同一件事的第二份。ADR 0011 为「步」走了反方向，
理由是一步的开合**算不出来**（一次请求要哪些工具、它们什么时候都答完，只有内核那次迭代知道），
所以 `step/*` 各写一行。

**今天轮的问题不是算不出来，是算的人太多，而且算的结果没有落下来**：

- `harness.edge.stats/user-ids`：数「没见过的 client user 行」；
- `harness.edge.trajectory` 的 `fresh`：同一套判据的第二遍写法；
- 客户端 `ui/src/lib/turns.ts` 的 `turnBounds`：按**相邻 assistant 消息**分组，与上面两者的
  判据在「一轮里有几次请求」这一点上不是同一件事，只是多数时候碰巧一致。

三份实现就是三次各说各的机会，而同一份记录因此可以被读出两种轮。轮又是本仓的**调度单位**
（`harness.edge.turn`、折叠那一行、轨迹的每一格都按它组织），读它的人最多。

## 决策

1. **`turn/*` 两处都在**：记录里各写一行（`turn/start` / `turn/end`），会话那条下行照旧发。
   与 `model/*`（0006 决策 4）、`step/*`（0011 决策 2）同形。
2. **`:seq` 是它自己那一行**，不再是借开轮那条 user 行的号。于是推来的那一半与窗口那一半按行号
   对齐的规矩（0006 决策 5）对三族一视同仁。
3. **`turn/start` 先落盘，再写开轮那条 user 行**：边界行在它界定的东西之前。
   `turn/end` 写在返回尾巴落地之后（与今天发 fact 的同一处、同一颗钟）。
4. **轮的名字仍然是 derive 不是 mint**（0006 决策 3 的原话）：`turnId = <threadId>-t<turn/start 的行号>`。
   行里不写它——写那一行的时候还不知道自己的行号。
5. **轮的开合语义一个字不动**：一条人说的话开一轮（悬置恢复不带新消息，不开新轮），
   run 的**终局**（`:run/end` / `:run/error` / `:run/stopped`）收一轮，`:run/interrupt` 不是终局。
6. **读侧只认行**。`stats` 数 `turn/start` 行；轨迹的一轮由一行开；客户端不再自己分组、自己数，
   服务端把每轮的账随窗口送下来。
7. **不背历史照旧**（0006 决策 7）：不为旧会话补发 fact。
8. **老记录不补**：读侧只认行，今天之前的记录读出来**没有轮**。这不是缺陷，是这一决定的边界——
   真要读它，是一个单独的数据迁移决定，不在本 ADR 里。

## 代价

- **记录每轮多两行**，一次最少两行的请求（`turn/start` + `turn/end` + `message`）涨到四行上下。
  事实族那个内存环（`harness.edge.mux`）因此也涨：一轮至少两帧。`fact-buffer-size` 复核过一次
  （见 0011 的代价一节），本轮不再动它，但**断线补齐**那一格要重新量。
- **三份推导要一起删干净**：删掉一处而留着另一处，比三处都在更糟——两份读数并存正是 0006 想避免的。
- **老记录读出来没有轮**（决策 8）：历史会话的折叠行与轨迹分组会缺一块。主人拍过，认。
- **`harness.edge.turn` 的角色变了**：它那份内存折从「读侧的答案」变成「写侧为本轮攒
  `turn/end` 的载荷」。`records->turn`（离线 twin）因此删掉。
- **客户端多一份窗口载荷**：`turns` 随 `window` / `append` 帧走，与 `entries` 同一条路。

## 边界（不做的事）

- **不改 `step/*` / `model/*`**，不动 AG-UI 的帧词汇，不开第三条 socket。
- **不做历史回放**：fact 照旧只是那个有界内存环，窗口那一半才是历史。
- **不迁移老记录**（决策 8）。
