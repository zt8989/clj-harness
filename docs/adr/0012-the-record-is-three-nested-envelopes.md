# 0012 —— 记录是三层信封：轮包住一轮，步包住一次请求与它的工具，模型调用包住请求、工具调用包住结果

- **日期**：2026-09-27
- **状态**：**已采纳**
- **参照**：主人 2026-09-27 拍定的四句——Turn 的生命周期要包裹这一轮的全部；Model 的生命周期要包裹请求；
  Tool 的生命周期要包括工具结果；`step` 那一族也要进来（一步 = 一次模型请求 + 它调的那些工具）。
  后一句把 `.scratch/step-events/`（`step-events` 分支上的 spec 与六张票，没有代码）并进来。
- **取代** `0006`（轮与模型调用是两级）的**决策 2**（不吃 DSH 的 `step`）与**决策 3**（`turn/*` 不进记录）。
  0006 的其余决策原样保留——尤其**决策 4**（`model/*` 两处都在）、**决策 5**（`seq` 是记录行号）、
  **决策 6**（事实不从落盘门铃发）与**决策 7**（不背历史）。
- **不再推翻** 0002 / 0003 的 `seq` 代数 / 0004 / 0005 / 0007（同步写：调用者线程、当场拿行号、不 fsync）/

## 背景

**同一件事在记录里有两份，时机不同。** 当场写的是帧与审计行（`TOOL_CALL_*`、`TEXT_MESSAGE_*`、
`model/*`、`tools/*`）；而**所有 `message` 行**是押后写的——内核把「这一轮加了哪条消息」攒在 `:added` 里，
只在 `:run/done` 交给边，边一次写完。一份真实记录（2026-09-27 的走查，一次 `bash sleep 25`）量出了这件事：
`tools/pre-execute` 到 `RUN_FINISHED` 之间那 26 秒里，盘上关于这次调用只有审计行，助手与工具的 `message`
行都在终帧**之后**的同一批里。

**三层边界在记录里都没包住该包住的东西**：工具的结果在 `tools/post-execute` 之后；请求在 `model/start`
之前、回答在终帧之后；**步与轮的边界根本不在记录里**。

0006 当年不收步与轮，理由是同一条：「边界算得出来，再写一行就是同一件事的第二份」。那条纪律的另一半
是它自己写的：**算得出来的不写，算不出来的写**。今天两处都算不出来——

- **步的边界**至少有两份现推：`ui/src/lib/turns.ts` 与 `harness.edge.turn`，谁也说不准一步在哪行结束；
- **轮的边界**同样两份：`harness.edge.stats/user-ids` 与客户端那套邻接判据。

**症状**：一轮正在跑的时候，轨迹（以及任何记录读者）只看得见提问与注入，看不见它在做的工具调用。

## 决策

1. **记录长成三层信封，一行的位置由「发射它的那一层的边界」决定。**
   `turn/*` 包住这一轮的全部；`step/*` 包住一次请求与它调的那些工具；`model/*` 包住这次请求写下的行
   与它产生的回答；`tools/*` 包住它的结果。**这意味着 0006 决策 2 与决策 3 都被推翻**（见上）。

2. **内核逐条报「加了哪条消息」**，边收到就在调用者线程上同步写（0007 不变）。**发射点决定信封**。

3. **`:run/done` 的 `:added` 变成对账表**：它仍是这一轮自己加了什么的账（重放时「回答放到它回答的那次
   调用后面」这种位置只有它知道），但边**不再照它写行**——逐条报过的就不写，没报过的从账里补写并点名。
   **同一条消息绝不许落两行。**

4. **Model 信封包住请求。** 这一轮为这次调用写下的行（prompt、提问、派生的注入、请求将发出时的压力读数）
   落在 `[model/start, model/end]` 里：边照旧先拼好，**攒着不写**，等这次调用的 `:model/start` 到达时
   一次写下去。**代价**：请求不再「发出前就在盘上」（差几毫秒）。第二次起的调用没有这一段。

5. **Tool 信封包住结果。** 结果帧与工具的 `message` 行搬进缝，落在 `tools/execute` 与
   `tools/post-execute` 之间；**spill 一起搬进缝**（否则「先落盘、再被替换」是同一件事两个真相）。

6. **`step/*` 是第三级，两端进记录。** 一步 = 内核 loop 的一次迭代：一次模型请求 + 它调的那些工具。
   `step/start` 发在一次调用的外面；`step/end` 发在**这一步最后一个工具的结局之后**（没调工具的步紧跟
   `model/end`），载荷 `{:tools [{:id … :name … :outcome …}]}`（没调是空向量，不是缺键）。
   **重试算同一步**；**被停的步要收口**；**`run/interrupt` 不是一步的终局**（回来收的是同一步）。
   身份由记录行号说，**不发明第三个 id**。

7. **Turn 信封进记录。** `turn/start` 写在边判定这一轮开了的那一刻（一条没见过的、`source` 是 client 的
   user 消息——**不是**由 run 触发：悬置恢复是同一轮的续），**它的行号就是这一轮的名字**；
   `turn/end` 写在返回侧全部落地之后、**就是这一轮的最后一行**，带
   `{turnId, steps, messages, reasoning, seqFrom, seqTo}`。`:run/interrupt` 不是终局。

8. **收了它们，读侧的现推就必须删——一份事实一个主人。** 服务端那条轮判据（`stats/user-ids`）、那份步
   判据（`harness.edge.turn`）、轨迹算轮、客户端 `turns.ts` 的邻接判据与 `turnCounts`，都改成读
   `turn/*` / `step/*`。0006 决策 3 当初警告的是「同一件事的第二份」；留两份才是漂。

9. **段机的判据改成按 `step/start` / `model/start` 认。** 轨迹今天靠「run 的第一条 `message` 行」开段、
   靠「第一条 `event` 之前 / 之后」切提交侧与返回侧；请求侧的行落进 `model/start` 之后，这两条都失效。
   新判据：**一次调用的请求侧 = 从它自己的 `model/start` 到它产生的第一条帧 / 消息之间的那些 `message` 行**。

10. **`seq` 一个字不改**（0003 决策 1/9）：仍是那一行自己的行号。**三族在同一轮里的相对偏序是判据**：
    `turn/start` 在任何 `step/start` 之前；同一步的 `model/*` 与 `tools/*` 在它两端之内；`turn/end` 最后。

11. **事实族的类型表只有一处拼写。** 那六个名字今天至少四处各写了一遍；三族之后漏改一处的后果是
    **这一轮被打死**（事实落进 run 那一支会被 `@ag-ui/client` 的 schema 校验拦下）。加族之前先收敛。

12. **旧记录是一等公民**：没有 `turn/*` / `step/*`、请求在信封外、返回侧押后的历史，读侧两种形状都认。
    **新写的记录不许再产生旧形状。**

## 代价

- **写侧三处、读侧一片。** 读侧是 `stats` / `turn` / `trajectory` / `context` / `pressure` / `replay`
  与客户端那两处判据——每一处都要「两种形状都认」，这是这版最容易漏的一格。
- **请求不再「发出前就在盘上」**（决策 4）：几毫秒，换记录自描述。
- **一族两个名字变成三族六个名字**：事实环（`harness.edge.mux` 的有界环）的容量要按新的帧数复核——
  断线补的是短缺口，这个数要量出来落进 `evidence/`，不许拍脑袋。
- **收口那一行带摘要**（`turn/end` 的 `steps`/`messages`、`step/end` 的 `tools`）是同一件事在盘上的第二份，
  所以每一处都要有一条用例断言**它与区间里的行一致**，否则它就是一条会漂的缓存。
- **`turn/end` 的时机仍然是个陷阱**（0006 的代价一节已点名）：发早了条数是错的。

## 边界（不做的事）

- **不动 AG-UI 的帧词汇**：三族事实都不是 AG-UI 帧。
- **不改行的两种类型与 `:source` 那套**；**不改同步语义**（0007）。
- **不从落盘门铃发事实**（0006 决策 6）；**不开第三条 socket**；**不做历史回放**（0006 决策 7）。
- **不给旧记录补行**：历史是历史。
