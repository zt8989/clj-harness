# 0010 —— 跑着的答案写快照，不写逐字：记录里的文本按 50–100ms 整句落一行

- **日期**：2026-09-26
- **状态**：**已采纳**
- **修正** `docs/adr/0009-the-record-holds-a-thought-once.md` 代价一节里「文本 delta（2%）不在此列，它照旧
  逐条写」这句，以及 `.scratch/jsonl-two-kinds` 的「记录就是线上那些帧」在**文本**这一族上的读法：
  **线上仍逐帧相同，记录不再逐字**。0009 的其余部分（推理族不进记录、从 run 自己的行折回）一个字不动。
- **参照**：`.scratch/event-persistence/spec.md` 票 03 的剩余半（主人 2026-09-25 拍的「流式 delta 合并成
  快照，50–100ms 一次，保住无洞的有序前缀」）。

## 背景

推理族那半已经落了（ADR 0009，一份日志 82% 的字节）。**剩下这一族小得多，口径却不同**：文本 delta 只占
2%，而它逐条写的**理由是硬的**——一条没跑到 `:run/done` 的 run，推理有模型自己的行兜着（模型行没有，那份
推理就当没发生，009 把这写成知道的代价），**文本没有别人兜**：记录是它唯一的去处，被掐断时留下的那半句
答案，正是靠它逐条写才留下来的。所以这一族不能像推理那样「不进记录」，只能**换个写法**。

**这一笔省下来的不是文本，是壳。** 一帧一个 JSON 信封（`ts` / `runId` / `type` / `payload` 的骨架），一个
两百来个 token 的答案就是两百来个信封——文本本身只占 2%。合并成整句一行，省的是那 98%。

## 决策

1. **记录里的文本是「到此刻为止的全文」，每 `text-snapshot-ms`（默认 75，落在票面要的 50–100 中间）落
   一行**，线的形状是 `CUSTOM text/snapshot`（`{:messageId :content}`）。
   **不是**把整句塞进 `TEXT_MESSAGE_CONTENT` 的 `:delta`：`row-of` 的规矩是 payload **逐字节是厂商给的**
   （`.scratch/jsonl-two-kinds`），而今天每一个读者都会把 `:delta` **追加**到自己手里那份上。
2. **一条消息的第一句立即落**，之后才按周期。只按周期的话，一条**在第一个 tick 之内就被掐断**的 run，
   记录里一个字都没有——而那正是这一族唯一不肯换掉的性质（`http_test` 的
   `a-run-that-stops-mid-thought-keeps-its-words-and-not-its-thinking` 量到过这一点：整句在一个 tick 内
   到达、又没有终点帧）。
3. **消息的 END 与 run 的终点都**先补一次**，在关掉它们的那一帧之前落行**：记录必须按线上发生过的顺序读。
   与上一笔内容相同的快照不再写——一样的东西不是新事实。
4. **折叠按「替换」读**：`harness.kernel.frames/apply-frames` 见到快照就**换掉**手里的那份内容；没有这条
   消息时**凭它建一条**。于是「只有一行」的读者（窗口开在句子中间、日志头被截掉）手里也是整句——这正是
   快照胜过「攒几个 delta 一起写」的地方：攒出来的每一行都是零件，缺一行就是残句。
5. **线上一个字节没动。** `runner` 与子 agent 路线照旧广播每一帧、照旧收进 `settle!`，客户端照旧一个 token
   一帧，`mux` 的补发环与 `frame-bus` 也不知有这回事。改的是**哪些行存在**，不是哪些帧存在。
6. **它是一族「会话的帧」，不是「harness 说自己的话」。** `harness.edge.replay/wire-custom-names` 里加了
   `text/snapshot`：那个集合的注释本来就写着「新族必须在同一个提交里加进来——否则一条事实和一条帧会被读成
   同一种东西」。不加上去，折叠会把它当成关于自己的事实，**静静地把答案的正文丢掉**（写这版时实测过：
   正文折出来是空字符串）。
7. **两条路共用同一处判据**（`harness.edge.http/text-lines`），与 `reasoning-frame?` 同形：第二次拼写就是
   第二条规则。子 agent 的快照带上它所代表的那一帧的 `:seq`——记录与总线那道边界靠它比对。

## 代价

- **被掐断的 run 丢最后一个周期（≤75ms）里到达的字。** 这是换「整句一行」付的钱，也正是周期不能再长的
  理由；「第一句立即落」把它兜住——记录里一定有东西，只是可能不是最后那半句。
- **记录不再是线上一帧一行。** `http_test` 那条契约用例（「记录 == 线上去掉推理族」）改成「……再去掉逐字的
  文本，加上它变成的快照」，并且逐字证明**折出来的对话与线上一样**——契约从「逐帧相同」变成「折出来相同」。
- **行号会变。** 同一场对话按快照写要少很多行，而 `entries` 的 `:seq` 是**这一行**在文件里的位置
  （ADR 0003 决策 9），所以两种写法的行号本来就不同：**比对话，不比行号**。
- **一个答案的字节数不再与它逐字的总和相等**：整句的前缀会重复出现。换来的是封套的大量消失，而净额是省。

## 边界（不做的事）

- **不改厂商的 payload**，不给 `TEXT_MESSAGE_CONTENT` 加第二个意思。
- **不丢尾巴**：合并**不是**「丢掉还没写出的部分」——最后一份快照永远是**整句**（到那一刻为止）。
- **不在每行存 `seq`**（ADR 0003 决策 9），**不动记录的行种类**（仍是 `message` / `event`）。
- **不改工具调用、状态、消息的落法**：关键事件照旧逐条。
