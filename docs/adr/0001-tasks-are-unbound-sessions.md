# 0001 —— 侧边栏分两块：任务（未绑定的会话）与项目

- **日期**：2026-09-20
- **状态**：已采纳
- **推翻**：`.scratch/project-sidebar/spec.md` 决策 1 里「项目是一等实体，**界面不再产生未绑定会话**」
  那一条（以及它派生的「新建任务必须先有项目」）。

## 背景

`project-sidebar` 立这条决策时，未绑定是一个**服务端的容忍**：AG-UI 那条边接受任何客户端铸的
thread id，库里没有它就照跑，日志落 `projects/.unbound/`。界面那一侧则被收紧成「每条会话都属于一个
项目」——新建任务落在选中的项目里，一个项目都没有时给一句「先添加一个项目」。

两件事随后让这条路显出它的代价：

1. **库里合法的状态，界面上一个都看不见。** 未绑定是 `sessions` 表里正正经经的一个状态
   （schema 的 `CHECK` 保着两列一起为 NULL），而 `GET /api/projects` 按 `project_id` 分组，
   把 NULL 那一组丢掉。于是「一段不属于任何目录的对话」在一台真机器上存在，却在界面上不存在。
2. **页面自己开的那一场是唯一列不出来的一场。** 页面挂载时铸一枚 id（它从来是客户端铸 id 的），
   一条消息发出去，记录就落在 `projects/.unbound/<id>.jsonl`——有日志、有对话、侧边栏看不见。
   这不是边角：它是「页面被加载了然后有人打了字」这条最普通的路。

## 决策

**侧边栏分成两块。上面一块是「任务」——未绑定的会话，平铺、不分组；下面一块是「项目」，
按目录分组（原样）。归档是一块，两种都装。**

具体地：

1. **谁是任务**：库里 `project_id IS NULL` **且** `last_project_path IS NULL` 的会话。
   移除项目放走的会话**不是**任务——它记得那个目录，加回来就回家（那条行为与文案一字不动）。
2. **任务由界面产生**：「新建任务」铸 id、`POST /api/sessions` 登记、切过去，不需要先有项目，
   也不落在任何项目里。落在项目里的路只剩项目行自己那颗「新建会话」。
3. **一条会话什么时候“存在”**：点「新建任务」当场登记，或者第一次**跑起来**的那一刻登记
   （AG-UI 那条边收到一个库里没有的 thread id 时）。挂载时铸的那枚 id 不登记——一行登记配一段真的
   对话，否则每刷新一次多一条空任务。
4. **任务的磁盘事实按 stem 问整棵树**（与点开它时 `rebuild` 问的是同一个问题）：一个任务的日志
   不一定在 `.unbound/` 里（显式解绑放走的会话留着旧 workspace 的那份文件）。
5. **归档是一块**：项目底部那个折叠组收掉，整个列表最下面一块默认折叠的「已归档」，装任务也装
   项目会话；项目会话那一行写出它原来属于哪个项目。
6. **本特征不给任务加「归到项目」的入口**。（既有的 composer 目录选择器本来就是「这个会话的目录」，
   对任务照旧有效——那是另一条路，不是本特征加的。）

## 代价

- **界面重新产生没有围栏的会话。** 未绑定 = 恒等：相对路径以进程工作目录为根、围栏关着、
  不读项目的 `harness.edn`。这是 `harness.cap.project` 的核心回归语义，本决策让它重新从界面可达——
  决策 1 当年正是为不走到这里才立的。**要收紧的话，动手的地方是「任务里跑什么」，不是这块列表。**
- **一块「已归档」让项目的归档分组消失了**，与之相关的既有验收（分组、折叠、行落点）都跟着改。
- **`GET /api/projects` 的形状从数组变成对象**（`{projects, tasks}`）：这是本仓管理边第一处
  「同一个端点答两半」的形状，客户端与断言都跟着改了一次。

## 边界（不做的事）

- 不做「把任务绑进项目」的界面入口、不做项目之间搬会话。
- 不改 schema：未绑定这个状态早就有，不加表、不加列（`db_test` 的元断言原样绿）。
- 不移除项目放走的会话（照旧不列，等目录回来）。
- 不做任务的重命名 / 标题 / 搜索。
