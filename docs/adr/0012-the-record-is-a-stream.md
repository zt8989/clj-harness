# 0012 —— 记录是一条流：一个写队列、两个生产者、两种读法

- **日期**：2026-09-28
- **状态**：**已采纳**（票 01/02/03 已落地；票 04 落了一半，05/06 未完——见文末「落地状态」）
- **主人拍的方向**（原话）：

  > kernel 应该需要提供写队列，由 infra 来保证写入成功，kernel 的事件和消息，内核 push，
  > edge 的事件和消息依赖 kernel 来 push 队列。读的机制分两种：一种是拉流，挂消费者；
  > 还有一种是推流，挂监听器，新增就推送。

- **参照**：`.scratch/record-stream/spec.md` 与同目录六张票；与 ADR 0007（同步写）是**收编**关系，
  不是取代——它立的两条（**同步答号**、**不许留洞**）一个字不改。

## 背景

记录今天有**两个生产者**（内核发事件、边写行）、**一条隐式通道**（`run-chan`，无缓冲 core.async），
却**没有一条有名字的队列**：写成功的承诺——重试、fsync、失败时按序攒住——一直是 `harness.edge.record`
在扛，名字却挂在**边**下；而**读**的两种形态（推：`events.mux` 的订阅与 `sessions/watch!` 的门铃；
拉：`replay` 折文件、轨迹、窗口）各有一套游标与语义，**行本身还不说它是谁写的**，于是轨迹只能按
「run 的第一个 `event` 前后」这种**位置**去猜哪一侧——一遇到「先答后提交」的 resume 就猜错
（`.scratch/record-envelopes` 的尾巴，两处红）。

## 决策

1. **一条队列，主人在 `harness.infra.stream`。** 「字节在盘上，或者这一行被攒住、在它落地之前不再写
   任何东西」是关于 IO 的承诺，本来就该是 infra 的名字。搬过去时**行为一字不改**：文件句柄、fsync
   策略、按线程攒住与 `retry!`、`prepare-with!` 的 re-base、`set-sink!`、metrics 全部照旧，入口改名
   `push!`，**当场答出这一行的偏移**（ADR 0007 决策 1 原样保留）。
2. **两个生产者，一条队列，一个号源。** 内核 push **它自己的消息**（它先有），边 push**它自己那批**
   （请求批、线上帧、事实）。号由队列答，不设第二个号源。
3. **每一行都说它从哪来。** 行的信封多一个 `:producer`：`record`（记录自己的家具：head 行、carry-back
   审计行）／`kernel-event`（由内核事件派生的审计行）／`kernel-message`（内核产出的消息）／
   `request`（这一轮为某次调用写下的请求批）／`frame`（线上帧）／`fact`（以 CUSTOM 帧形态落行的事实）。
   默认值一处决定，写批次的两个人自己说。**读者从此不必猜哪一侧。**
4. **内核自己写它那批，顺序靠栅栏。** 内核写完自己的一条之前，先问消费者「前面发的都排空了吗」
   ——新事件 `:drained`（带一个 promise），消费者**在自己的排空循环里**兑现它。**问的是 run 自己的
   通道，不是某次调用自己那道闸**：那道闸在 attempt 结束后会丢帧（那是对的），控制事件走那里会被丢掉，
   内核就会白等到死线。**代价**是每条消息一次往返 + 一个死线（消费者始终不答时照写不误：一次 run 卡在
   记录上，比一行落在错位置更坏）。**消费者因此多了一项义务：答 `:drained`。**
5. **两种读法上台面，挂在同一条流上。** **推流**：`listen!`——新增就推给挂上的监听器（锁外调用，
   所以监听器不许阻塞）。**拉流**：`consume!` / `after`——挂一个消费者，从游标补齐再继续听；
   游标是**行号**（`:seq`），所以断线补齐不漏不重。**每一件 item 同时带着行的两种形状**
   （`:line` 是落进文件的字节，`:row` 是它来自的 map）与 `:producer`。**`after` 是短环**（有界），
   **长缺口读文件**——这正是文件存在的理由，不是妥协。
6. **写入者不再认识任何读者。** 写路径今天还直接叫着 `sessions/row-written!` 与 `record-grew!`；
   目标是改成会话上线时挂一个 `listen!`。**动手前的一条纪律**：直接调没有竞态，挂监听器有一条窗口
   ——**挂上之前写下的行，监听器永远收不到**——所以挂的点必须**不晚于第一条写**。

## 与旧决定的关系

- **ADR 0007**：两条核心（同步答号、不许留洞）**原样保留**，只是主人从边换成 infra；
- **ADR 0002 决策 3**：那条被 0007 推翻的异步队列**没有被复活**——现在的队列是**同步写**的队列，
  异步只发生在读者那一侧；
- **ADR 0004 一族**：记录由边写 → 记录由 **infra 写**，边降为**它的一个生产者**。
