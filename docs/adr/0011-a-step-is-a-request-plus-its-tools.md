# 0011 —— 步是第三级：一次请求加它调的工具，两端进记录也上线

- **日期**：2026-09-27
- **状态**：**已采纳**
- **取代** `docs/adr/0006-turn-and-model-call-are-the-two-levels.md` 的**决策 2** 与它「边界（不做的事）」
  第一条（「不做 DSH 的 `step/*`」）。0006 的其余部分——轮与一次模型调用是两个层级、`turn/*` 不进记录、
  `model/*` 两处都在、`seq` 是记录行号、发送点只有一个、不背历史——**一个字不改**。
- **本决定的「不改轮」那一条被 0017 取代**（2026-10-02）：`docs/adr/0017-the-turn-is-written-down.md` ——
  `turn/start` / `turn/end` 现在**也进记录**（`harness.edge.turns` 折它、`stats` 数它、`trajectory` 按它
  分段、客户端读它）。本决定的其余部分（第三级是步、`step/end` 只带 `{:tools …}`、`seq` 是记录行号、
  一步的四条收口、不背历史）一个字不动。
- **参照**：`.scratch/step-events/spec.md` 与它的六张票；DSH 的 "Turn flow"
  （<https://deepseek-harness.github.io/deepseek-harness/en/reference/>）：*A step is one model request
  plus the tools it calls. A turn is zero or more steps.*

## 背景

**0006 拒 `step/*` 的三条理由里，有两条今天仍然成立**——工具那一圈确有自己的族说全了，本仓确不需要
第三种「请求 + 工具」之外的调度单位。翻案的是第三条的**前提**：0006 说「我们要的三个数没有一个需要那个区间」，
于是把它判成同一个事实的第二个名字。**但记录里根本没有那个区间可读**：一步今天只能由读者拿 `model/start`
与随后属于它的 `tools/*` 行**现推**，而推法至少两份（`ui/src/lib/turns.ts` 与服务端 `harness.edge.turn`），
谁也说不准一步的边界落在哪一行。

0006 自己对轮立的纪律是**「算得出来的不写，算不出来的写」**：轮的开合由记录算得出来（没见过的 user 消息），
所以不写行。一步的开合**算不出来**——一次请求要哪些工具、它们什么时候都答完，只有内核那次迭代知道。
同一个纪律，反的方向。

## 决策

1. **三个层级：轮 ⊃ 步 ⊃ 一次模型调用。** 一步 = 一次模型请求 **+ 它调的那些工具** = `harness.kernel.loop`
   里的一次迭代。DSH 的定义照旧（turn = zero or more steps）。
2. **两端进记录**：`step/start` / `step/end` 各一行，与 `model/*` 一样**两处都在**（记录 + 会话下行），
   `:seq` 是**它自己那一行**的行号（ADR 0003 决策 1/9、0006 决策 5）。这是它与 `turn/*` 的区别：
   轮的行号是借来的，步的不是。
3. **发在哪**：`step/start` 在这一步的请求之前发，**在停止检查之后**——一个被人按停的 run 不该开一步它
   收不了的步；`step/end` 在这一步那些调用**都有了结局之后**。一次工具也没调的步，它就紧跟在 `model/end`
   之后（最窄的一刀）。
4. **收口有四种，都收**：工具都答了 / **停止**（被切掉的调用先拿到 cut-off 答案，再收）/ **悬置** /
   **失败**（内核那个 `catch` 里收，与 `model-call!` 在自己的 catch 里收一次调用同形）。
   **悬置关的是同一步**：一步就是一次请求，回答一个人问题的那次请求是**下一步**——这是步与轮分野的地方，
   轮跨 run，步不跨。
5. **`step/end` 的载荷只有 `{:tools [{:id :name} …]}`。** 每个调用后来怎么了（跑过、被拒、悬置、被切掉）
   在它自己的 `tools/*` 行上，**同一批 id**——不在这里说第二遍。
6. **它不是 AG-UI 帧**：不进 `apply-frames`、不落 `data` part、不被回发。`harness.edge.ag-ui/step` 对这两个
   类型是**空操作**，而且必须显式写出来：那个 `case` 没有 default，漏一个分支第一个走到的 run 就会抛。
7. **与轮一样不背历史**：新事件不进「打开会话」的载荷，不为旧会话补发；打开一场旧会话仍走读侧
   （0006 决策 7）。
8. **折叠那一行改按步计。** `harness.edge.turn` 数 `step/start` 行，`turn/end` 带 `{steps, messages}`；
   客户端对**落定的轮**仍从会话视图读（一次请求 = 一条助手消息）。**工具调用数从这一行与这份载荷里去掉了**：
   它不再被任何地方画，而一个没人读的数就是第一个走形的。

## 代价

- **记录每步多两行。** 一次没有工具的请求 = `step/start` + `model/start` + `model/end` + `step/end` 四行。
  内存里那圈事实因此也涨：一步四帧起（工具调用不算在内，它们不是事实），`fact-buffer-size` 仍够
  （见 `.scratch/step-events/spec.md` 票 04 一节）。
- **「步」这个词第一次进 `CONTEXT.md` 词表**——今天那一栏写着「别叫成 step」，改成说清它是什么。
- **重试是客户端的步数与服务端分家的唯一地方**：vendor 因长度拒绝、这一层重发，记录里是**一步**
  （`loop_test` 有一条钉住它），而客户端看见**两条消息**。落定的轮以读侧为准这条规矩照旧，这一格记在这里
  当已知分歧；`turn/end` 带 `steps` 正是为了让有事件在手的那一方可以不信客户端的读法。
- **多数轮里「步数」与「助手消息数」相等**（一次请求一条消息），折叠那一行才敢只说步数、不说消息数：
  一行里把同一个数说两遍是对读者的噪音。

## 边界（不做的事）

- **不改轮**：`turn/*` 仍不进记录，语义一个字不动。
- **不改 `model/*`**：两处都在照旧（0006 决策 4）。
- **不做 `step` 的历史回放**，不按步拆 socket、不开第三条。
- **不给工具调用的结局起第二个名字**（决策 5）。
- **不动 AG-UI 的帧词汇**。
