# spec: 侧边栏可折叠（收起后左上角一颗浮标；窄窗就是手机那副样子）

2026-09-20 立。**要的是：侧边栏能折起来，折起来之后左上角有一颗浮动图标，点它把侧边栏打开——
像那份桌面 harness 的手机模式。** 这一条没有进 tracker，是为了这次改动补上的记录：原话是

> 给这个项目加一个侧边栏折叠功能就像你这个 Deepseek Harness的手机模式一样，在左上角有个浮动的图标，
> 点击打开侧边栏。改完后记得只跑前端的单元测试，不需要全量跑单元测试，然后提交并复试。

## 定下来的五件事

**一、折叠是一个 bit，归页面。** `app.tsx` 的 `folded`。侧边栏自己画不了「展开」那颗按钮——
折起来的它是一棵 `hidden` 子树，隐藏的子树画不出一颗要被看见的控件——所以状态在页面、浮标也归页面画。
**不落盘**：跟 `view` 同一个理由，这是「这会儿怎么看」。参考实现把它叫 transient layout preferences。

**二、一对控件，一个契约。** `components/sidebar-toggle.tsx` 里两颗：收起那颗在侧边栏头部图标行的末位
（面板的出口就该在那儿），展开那颗是左上角浮标。两端 `aria-controls` 指向同一个 `SIDEBAR_ID`
（= `aside` 上那个 `id`），`aria-expanded` 各报**被指那块的状态**（折着 = `false`、开着 = `true`）。
模块里那份注释把这条与「为什么是一对、为什么拆成模块」一起说了。

**三、折 = `hidden`，不是卸载。** 这条是复试收回来的（见下），也是这次唯一一处正确性级别的改动：
`sidebar.tsx` 是 `GET /api/projects` **唯一**的读者，而挂载恢复（`app.tsx` 的 `onListed`）正是从
那一次读取里知道「记住的那一场还在不在」。手机宽的窗口一开就是折着的——卸载它，这些窗口就恢复不了
任何东西，记住的 id 一直陈旧到有人展开列表；列表自己那份状态（滚到哪儿、哪个项目是展开的）也会
每折一下丢一次。

**四、窄窗（< `lg` = `64rem`）是断点，不是第二份状态。** 那以下侧边栏 `absolute` 浮在对话上、
盖一层背板（点背板收起），那以上才是并排的一列。所以「多宽算窄」只有 `lg` 一个出处，JS 侧只有一处
`matchMedia`（`isWideWindow`），且三处都是**当场读**：初值（手机上开在对话上，列表一按就有）、
选中会话要不要把抽屉收走、Esc 要不要收。没有 resize 监听。

**五、抽屉的两条礼貌。** **选中会话就收**：否则刚选的那一场还盖在面板底下，点了像没反应。
**跳过的两条路**：挂载恢复（页面落到自己记住的那一场，没有谁需要让路）与 Esc **当 Radix 浮层
已经吃掉了这个键时**（它先 `preventDefault`，所以关掉对话框不会顺带把抽屉折了）。

## 走查（`node scripts/dev.mjs --scripted`，临时家、OS 分配端口）

1280×800：

- 点头部那颗收起 → `[data-slot="sidebar"]` **还在 DOM 里**、`display: none`、`id="app-sidebar"`；
  浮标出现在 (8,8)、32×32、`aria-controls="app-sidebar"`；`view-switch` 的 `padding-left` 是 44px、
  首个页签落在 x=44（浮标占 8..40，压不到）；对话里的内容一个字没动。
- 点浮标 → 侧边栏回到并排的一列（`display: flex`，x=0）。
- 点另一条会话行 → **侧边栏不收**（宽窗不是抽屉），对话从日志重建回来（脚本厂商那句回答在屏幕上）。

390×844：

- 抽屉开着时 `position: absolute`、背板 `display: block`。
- 点一条会话行 → 抽屉收起（`display: none`）、背板消失、浮标回来。
- **重载**（复试指出的那条坏路径）→ 页面开在折起来的样子，**并且把记住的那一场恢复回来**：
  自己发的那句与脚本厂商那句都在屏幕上、「今天我能帮你做什么？」这个空态不在、记住的 id 没变。
  修复前这一格是坏的：侧边栏没挂载 ⇒ 没有人去读 `/api/projects` ⇒ 恢复不发生。
- 点浮标 → 抽屉开；按 Esc → 收起。
- 开着「设置」对话框时按 Esc → 对话框关、**抽屉留着**（Radix 的 `preventDefault` 交接）。
- 抽屉里点「新建任务」→ 抽屉收起、新会话在眼前。

控制台只有 favicon 404 与「还没跑过的会话」那条 `/api/threads/<id>/stats` 404（后者本来就这么答）。

## 套件钉住了什么、钉不住什么

`ui/test/suites/sidebar.tsx` 加了两例（`EXPECTED_CASES` 50 → 52）：两颗控件两语的词，与
`aria-controls` / `aria-expanded` 那两条读得出来的事实。**钉不住的**：整块 `Sidebar` 在这一跑里
渲染不了（它经 `settings-panel.tsx` 走到 `lib/i18n.ts`，那份模块在加载时就碰 `document`），所以
`aside` 上的 `id` 按源码文本读——否则那两处可以指着一块不存在的东西而全绿。布局与交互
（浮标压不压页签、抽屉收不收）是浏览器的答案，也就是上面那节走查。
