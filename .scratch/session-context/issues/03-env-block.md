# 03 — 新增 `<env>` 行

**What to build:** 内核的行里多一条 `<env>`：**这台机器长什么样**。平台、`bash` 工具与 hook 命令
**实际会被交给哪个 shell**（以及它是什么）、以及一份声明名单里**这个 shell 看得见哪些命令行增强工具**。
它顶掉的是刚砍掉那两行的位置——三条变两条，两条里有一条是新的。

**Blocked by:** 01（行集合先减完，再加）、02（shell 的身份由那条链回答）

**Status:** ready-for-agent

## 为什么这条必须说，而 `<tools>` 不必

`<tools>` 的名册在 wire 上（`:tools` 数组），**这台机器不在**。模型写的每一条 shell 命令都建立在一串
它无从知道的假设上：是 Windows 还是 POSIX、有没有 `rg`、有没有 `fd`。今天它只能靠试。
「写一条 `rg` 而机器上没有 rg」——这正是这块唯一要防的错，所以**「有」要说，「没有」也要说**。

## 形状

```
<env>
platform: macos (Darwin 24.6.0, aarch64)
shell: bash (at /bin/bash); commands run through `bash -lc`
available: rg, fd, jq, git
not found: (nothing from the list)
</env>
```

标点与措辞由实现定，**这四件事必须在**：平台、解析到的 shell（连它的 kind 与路径）、
走的是哪种起法、名单里哪些**有**哪些**没有**。一条都测不出来的事实不许写成句子。

- **平台**：windows / macos / linux（附 OS 版本与架构，一行）。
- **shell**：`harness.infra.shell` 的解析结果——`kind` + 真会 spawn 的命令 + `argv-prefix`。
  **读它，不要在这里重新判定**：那是唯一定夺这件事的地方。
- **增强工具**：一份**声明名单**（初版 `rg` / `fd` / `jq` / `git`，加一个名字 = 加一行），
  分成「有」与「没有」两半。`rg` 值得特别一提：`anchor_grep` 与 `glob` 本来就依赖它
  （`harness.infra.rg`），而这块管的是**模型自己写的命令**能不能用它。

## 两条纪律

1. **机器事实每进程算一次，块每 run 现算。** 平台、shell、增强工具都是**机器的属性**，
   与今天 `infra/shell.clj/binary` 那个 `defonce` 同一个位置、同一个理由；块仍然每 run 现算——
   那条纪律管的是会话事实。**两条合起来给出一条可断言的性质**：同一台机器上连跑两次，
   这段文本**逐字节相同**（provider 的前缀缓存因此照旧命中）。
2. **探测走同一个 shell。** 一次 `bash -lc`（或链上那一级自己的形态）跑一个「逐个 `command -v`」的小循环，
   输出就是「有」的名字。**不许用 `System.getenv("PATH")`**：登录 shell 会重新 source profile，
   它的 PATH 与 JVM 的可以不同，而模型真去跑时用的是前者——用 JVM 的 PATH 答出来的是一句
   到执行时才不成立的话。探测失败（shell 起不来、超时）**如实说**：这一半报「不知道」，
   不让整块消失，也不假装没有。

## 验收

- [ ] `<env>` 出现在组装文本里，位于 `<project>` 之后、任何声明块之前（内建档位的顺序）
- [ ] 四种「有没有」的形态都可断言，且**不靠改真实机器的 PATH**：探测有一个测试可替换的缝
      （链的答案与探测结果各有一个可注入的读法），且缓存有显式的重置
- [ ] `available` / `not found` 两半都真的出现过：一个「名单里全都有」的用例与一个「有名字缺席」的用例
- [ ] shell 那行**读的是 `harness.infra.shell` 的解析结果**：拿它 stub 成 `:pwsh`，
      这块报的就是 pwsh 与 `-NoProfile -Command`（不在这里重新判定）
- [ ] 探测**经 shell 起**（一个用例断言它走的是一条真命令，而不是读 JVM 的环境变量）
- [ ] 同一台机器上两次组装**逐字节相同**（前缀缓存那条性质）
- [ ] 探测失败时这块**仍在**、且说清「问不出来」，不抛、不让整次组装失败
- [ ] 它是一条**普通的行**：`effective-hooks` 里看得见、`session-disable!` 关得掉、关掉后组装文本里没有它、
      再打开又回来（换个样本，性质与既有那条一样）
- [ ] 组装文本里**搜不到 api-key**（与 01 搬过来的那条同一条断言，now 覆盖新块）
- [ ] 离线全量 `harness.test-runner` 全绿

## 不做

- 不在块里枚举**每个**工具的可用性，也不列版本号：名单是「写命令时会不会用到的东西」，
  不是一份环境清单。
- 不做 UI、不加端点、不加 jsonl 行种类（块的可见性仍止于服务端与 `message` 行）。
