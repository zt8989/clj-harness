# 01 — 手机端的点按尺寸低于触屏建议

**Status:** needs-triage
**Blocked by:** None

**症状（2026-09-30 实测，390×844）**：「会话」页的筛选按钮 **24 px 高**、三个动词 **28 px 高**，
低于 iOS / Android 建议的 **44 px**。同一个数量级在设置导航项、侧栏行上也一样——**这是全 app 的
既有密度**，不是某一次改动引入的。

**已经修掉的那一半**（不要再来一遍）：手机端"横向溢出"和"上下被切"两处硬伤已经落地
（`.scratch/record-window/spec.md` 邻近的那两笔：`grid-cols-[minmax(0,1fr)]` 与
`h-[min(40rem,calc(100dvh - 9rem))]`，各自有 390×844 / 844×390 / 1400×732 的实测）。

**要定的（所以是 needs-triage）**：这是一条**全局密度**的决定，不是某个面板的样式修补：

- **接受**：这个产品主要在桌面用，手机上能用即可（这一次已经把"溢出/不可达"那类硬伤修掉）；
- **定一套触屏尺寸**：比如 `sm` 以下把控制项的最小高度提到 44 px，并在**所有**行/按钮上落地——
  那是一次跨面板的改动，要带自己的浏览器走查与 `ui` 用例。

**验收**：按选定那条给出机器可查的判据——要么一份"接受"的裁定写进文档，要么一条在 390 宽度下
断言关键控制项高度 ≥ 44 px 的用例。
