# 06 — 被挂住的调用由人来答（子agent 的 park 冒泡）

**What to build:** 子agent 里一个被**围栏**或**审批**挂住的调用，不再在子agent 内部变成一句"办不到"，
而是以它所属**主会话**的一条 interrupt 交到真人手上：人看到那张卡，批准或否决，子agent 接着把这一轮
跑完，委派的结论仍然回到主对话。

这是本组最重的一张，因为它要跨过一条本来就窄的缝：park 是按 `(thread-id, tool-call-id)` 记的，
而这次挂住的是**子会话**的调用，等人的却是**主会话**的界面。要解决的是"这两者之间那条对应关系住在哪、
谁在什么时候把它写成一条 interrupt"，而不是给子agent 新开一套审批。

**可以不做。** 砍掉它，02 里那句"这次调用需要人批准，子agent 不能等人"就是终态——行为是诚实的、
不静默的，只是子agent 遇到要人批的调用会绕道走。要不要付这个代价，由排期决定。

**Blocked by:** 02

**Status:** ready-for-agent

## 验收

- [ ] 委派一个会挂住的调用（越界的读，或本会话里被审批策略声明要批的写），人在**主会话**里
      看到那条审批卡，卡里能看出它来自哪个子agent 的哪次调用。
- [ ] 批准：子agent 拿到批准、把那一轮跑完，结论回到主对话；记录里那条子会话的 jsonl 能看到
      这次决定（既有 `approval/decided` 那种行，形状不变）。
- [ ] 否决：子agent 收到的是否决本身，不是失败也不是静默跳过；它自己决定下一步，委派仍然有结论。
- [ ] 拼不上的人和机器各有一种明确答复：一个**进程重启后**再也答不上的挂起（park 只在造它的进程里活着），
      和**父会话已经结束**时的挂起——两种都按名说清，不做猜测性的批准。
- [ ] 主会话在等人期间的状态与既有 park 一致（`:run/interrupt`，不是 `:run/error`；客户端拿到的是
      一张能决定的卡）。
- [ ] 同一轮里两个委派各自挂起：两条 interrupt 各归各的调用，答复不会串。
- [ ] `node scripts/test.mjs` 全绿（本票不动 `ui/`；若审批卡需要多显示一行来源，
      那部分落在客户端并配走查）。
