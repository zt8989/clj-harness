# 03 — 子会话进店：归属与读回

**What to build:** 一次委派在 store 里**有身份**：这条子会话属于哪条会话（父）、它是哪个子agent、
绑在哪个项目。今天 02 已经让它落了自己的 jsonl，但那还是"树里一个文件"；这一票把它变成
`projects/<workspace>` 下**挂得住的**一条会话。

同时守住两条既有语义：

- **它不是一条普通的会话。** 父会话所在项目的普通会话列表里不该冒出这一行——一条子会话出现在
  列表里，读起来就是"我也能给它发消息"，而它不能。
- **按 id 读得回。** 直接拿子会话的 id 去 rebuild 能拿回它自己的消息，读轨迹能拿到它自己的轨迹
  （既有那两条读法不改形状，只是对一个 id 也能用）。

**"跑完没有"由记录回答，不进库。** store 只装"属于谁、叫什么"这两件事；状态是进程内的一张表
（正在跑的），跑完与否看那条 jsonl 的末帧——这是本仓「库装状态、文件装记录」那条线，
也是 `harness.infra.db-test` 的元断言在守的东西。

**Blocked by:** 02

**Status:** ready-for-agent

## 验收

- [ ] 跑一次委派后，store 里那行子会话带父会话 id 与子agent 名，且绑在父会话的项目上。
- [ ] 该项目的普通会话列表（侧边栏读的那一份）里**没有**这条子会话；父会话仍在原来的位置。
- [ ] 按子会话 id 调 rebuild：拿回的是**它自己**的消息（它的 system 消息、它的工具调用与结果），
      不是父会话的。
- [ ] 按子会话 id 读轨迹：段落划分与它自己的记录一致。
- [ ] 删掉父项目 / 归档父会话这些既有动作，对子会话不产生半截状态（要么一起被释放，要么都还在，
      哪一种由实现定，但用例要把选的那一种钉住）。
- [ ] store 的表结构变更按既有迁移规矩走（新的一步，不是改老的一步），且新列在
      「库装状态、文件装记录」这条线上有明确归属。
- [ ] `node scripts/test.mjs --backend` 全绿，其中 `harness.infra.db-test` 的元断言仍然通过。
