# 01 — 两处面板不再轮询：接上推送那一半

Status: ready-for-agent
Blocked by: None (can start immediately)

## 做什么

`docs/rules/panel-data.md` 那条原则（**先拉一次存量，之后由推送走**）今天有两处没照做，这一票把它们转掉：

1. **右侧任务视图**：`ui/src/hooks/use-task-pane.ts` 是 `setInterval(read, 1000)`
   （`TASK_PANE_POLL_MS`），子代理与作业两段搭在同一个 timer 上。
   代码里写下的理由是「作业的结局没有推到客户端的通道——那条通知搭的是**下一次模型调用**，不是帧」
   （`.scratch/right-pane-tasks` 决策 7）。
2. **左侧清单**：会话/项目那一栏靠挂载与重拉事件（`ui/src/lib/sidebar-refetch.ts`），**没有订阅**——
   别处新建的会话，只有这一页自己动手才出现。

**做的是补那条通道，不是调短那个间隔。**

- **先回答「写点在哪」。** 现在的推送家族（`ui/src/lib/mux.ts`：window / run / fact）**都按 `threadId` 路由**，
  而这两处要推的是**进程级的事实**：一条作业的结局（写在它自己那份记录的末行）、一次委派的开始与结束
  （写在会话记录里）、一条会话被新建（写在库里）。第四、第五个家族长什么样由这些写点决定——
  **`harness.edge.mux` 那一侧与 `lib/mux.ts` 这一侧的名字是一份契约**，两边一起改，别只改一边。
- **ADR 0004（一条 socket、按 `threadId` 路由）是这条路的前置。** 如果这一票决定要按别的键路由，
  那是改 ADR，先写 ADR 再动手；不改就先照 `threadId` 那一套。
- **存量那一半照旧。** `use-task-pane` 已经有的形状留着：挂载时一次读、同一栏的两段共用**一个**中止、
  迟到的答案不许盖到新会话上。换掉的只是 `setInterval`——它连 `start` / `stop` 那套可见性判断一起换成订阅的
  挂上 / 摘下。
- **重连补一次存量。** socket 重开时按 `declaredSet` 重新声明并带游标；游标之外的重拉一次。
  这条**必须有**，否则就是把轮询换成了丢帧（`docs/rules/panel-data.md`「断了怎么办」那一段）。
- **唯一留下的滴答是那个数字。** 「这条作业跑了多久」是服务端给不出的「此刻」，
  画它的那一格自己滴答、**不发起任何请求**——这是那条规矩里唯一一种例外。

## 验收

- [ ] 任务视图开着：挂载时各发**一次** `GET /api/threads/<stem>/jobs` 与 `GET /api/subagents`；
      之后一条作业结束、一次委派开始，**不需要第二问**就在屏幕上变。
- [ ] 网络面板里对这两条路由**没有定时器**：一次 run 期间的请求数不随秒数增长。
- [ ] 左栏同理：一次存量读之后，别处新建的会话自己出现（不靠这一页动手）。
- [ ] socket 断掉再重连：两处都补上断线期间变过的行，**不丢**、也**不重画成空**。
- [ ] 「跑了多久」那一列**仍在每秒动**（本文件的唯一例外），并且拨一下网络面板确认它**不发请求**。
- [ ] 两处都不再有 `setInterval`；`ui/test/suites/right-pane.tsx` 那一套改成**推帧驱动**的断言
      （喂一帧 ⇒ 屏幕上变了），并补一条「断线重连后补存量」的用例。
- [ ] `cd ui && npm test`、`npm run typecheck`、`npm run build` 全绿；
      `clojure -M:test -m harness.test-runner` 全绿。
- [ ] 真机走一遍：开右栏、起一条后台作业、让它结束 ⇒ 屏幕自己变；断网再通 ⇒ 不缺行。
      （`node scripts/dev.mjs --scripted` 那套起服务，自己开浏览器走——AGENTS.md 的规矩。）
