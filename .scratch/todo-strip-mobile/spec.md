# 任务横条上那两只手的手机形状

**状态**：已实现。

## 要解决什么

横条第二行那两只手（`提醒一下` / `自动提醒 · 开|关`）在窄屏上太宽——两个带字的按钮把横条挤到了
两行。人报的是「手机端要精简文字，不然会变成两行」。

## 量到的事实（2026-10-03，dev.mjs --scripted + 浏览器）

- **两个按钮各自不会换行**：按钮基类带 `shrink-0` 与 `whitespace-nowrap`，320px 下它们是同行
  （91px + 114px = 209px，行宽 259px）。
- **会折行的是上面那行摘要**（`composer-todos-summary`，`white-space: normal`）：把根字号放大到
  20px（手机上「大字体」档）它自己折成两行（40px 高）。
- 所以「两行」的可见来源有两个可能，人选的是**按钮这一半**。

## 决定：手机上只留图标（人选）

词包进 `<span class="sr-only sm:not-sr-only" data-slot="composer-todos-{remind,auto}-word">`：

- **`< sm`（640px）**：词不占可见宽度，按钮只剩图标（320px 下实测 36×28）。
- **`≥ sm`**：`not-sr-only` 把词放回来，与桌面完全一致（700px 下实测 91×28 / 114×28）。
- **词没有丢**：`sr-only` 保留它在**无障碍树**里的位置，所以按钮的名字还是「提醒一下」/「自动提醒 · 关」；
  开关的状态另有 `aria-pressed`、`data-on` 与 `title`——手机上靠图标本身的差异（铃 / 划掉的铃）读。
- 两个词 span 各带 `data-slot`，套件 pin 住 `sr-only` 与 `sm:not-sr-only` 两半（只有一半就是两个 bug：
  词在桌面上消失、或者在手机上又占宽度）。

## 不做的事

- **不去动摘要那一行**：人能选 D 却没选；要动它就该单独一笔（`whitespace-nowrap` + `truncate` 会把
  `1 已完成 · 1 进行中 · 1 待处理` 截掉，换行反而读得全）。
- **不放宽 `sm` 这个断点**：`sm` 是仓库既有的窄/宽分界（`picker.tsx`、`settings-panel.tsx` 都在这条线上）。

## 代价

- 手机上那两个按钮是 **36×28**，比触屏推荐的 44px 高要矮——这是 `size="sm"` 这个既有尺寸的代价，
  桌面上也一样，本票没有改它（改了会同桌面一起动）。
- 手机上看不出「开/关」两个字，只看得出一颗铃和一颗划掉的铃。要更醒目就得再加样式（比如开时染色），
  本票没做。
