# 09 — 会话级 hook 的增删改与启停（eval 的新面）

**What to build:** 一个会话能在运行期给自己的 hook 表长出条目、改写条目、把条目**关掉/打开**，只影响本
thread，进程重启即失。两条正交轴，与工具表同一套词汇与语义：

- **presence**：register 新增一条本会话的声明（同名则覆盖，基座配置不动）；unregister 只撤本会话新增的，
  对基座里的条目是 no-op（要停它用 disable）。
- **availability**：disable 把一条声明关掉——**它仍在本会话的 hook 表里，只是永不触发**（既不 spawn、
  也不落审计行）；enable 立刻恢复。关闭不是隐藏：agent 能读到自己的表，看到被关的条目并自己打开。

这一票是 eval 收敛之后真正的新能力面（见 13 号票的定位与文档收口）。它不改任何真相源：
本会话的 overlay 与基座装配合成"当前生效的表"，进程重启即失。

**Blocked by:** 08

**Status:** ready-for-agent

- [ ] 四个入口（增 / 撤 / 关 / 开）只作用本 thread；另一个会话读到的表不受影响
- [ ] register 覆盖本会话的同名声明（基座配置一字不动）；unregister 撤本会话新增的，对基座条目是 no-op
- [ ] 被关的 hook 仍出现在本会话的 hook 表里，但**永不触发**：不 spawn、不落审计行；打开后立刻恢复
- [ ] 撤回一条新增时连带清掉它的关闭标记：同名重新加进来是**打开**的（不继承僵尸关闭态）
- [ ] 关闭/打开幂等；对表里没有的名字不发明条目（关闭从不"造出"一条 hook）
- [ ] 有一个读取入口能拿到本会话生效的 hook 表（基座装配 + 本会话 overlay）——eval 靠它自省
- [ ] 端到端：一个会话经真实 eval tool-call 加一条 hook、关掉它（不再触发）、再打开（恢复），
      另一个会话全程不受影响
- [ ] 全绿，新增断言
