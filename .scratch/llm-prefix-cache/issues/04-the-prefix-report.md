# 04 — 前缀报告：一条命令回答「这次为什么没命中」

**What to build:** `scripts/llm-prefix-report.mjs`——一个**只读**的 node 脚本（零依赖），
吃一份 `llm-debug.jsonl`（默认 `~/.clj-harness/logs/llm-debug.jsonl`）与一个会话记录目录，
打出三件事：逐次调用的 `prompt/cached/rate`；与上一次的**共享字节前缀长度**与**第一处分歧的
偏移 + 上下文**；跨会话的**工具表哈希**与**第一个不同的工具/字段**。

**Blocked by:** 01、02（先让表稳定，报告才有东西可测——但它对**改动前**的记录同样要能读）

**Status:** ready-for-agent

## 要落地的判断

1. **它比的是原始字节，不是再序列化一遍的 JSON。** 这是 `harness.infra.llm-debug` 的 namespace
   docstring 立下的理由（`infra/llm_debug.clj:15-20`）：请求以**字符串**落地，比的是**发出去的
   字节**。所以脚本**只做** `JSON.parse(line)['body']`，然后对**那个串**取前缀、算 sha。
   **不许**把它 `JSON.parse` 成对象再 `JSON.stringify` 回来比——键序、空 `reasoning_content`
   补位、工具表顺序都会在那一趟里被换成第二种拼法，「前缀相同」就不再是关于线上的一句话。
   脚本里要有一段注释说这件事，并**指回**那个 docstring。
2. **共享前缀要精确到字节，分歧要报出上下文。** 对第 N 次与第 N−1 次的 `body`，报：
   共享前缀字节数、占上一次的比例、第一处分歧的**字节偏移**，以及 `±120` 字符的上下文。
   这一条正是本次定位里手搓的那段脚本——它花掉的时间就是这张票存在的理由。
   与厂商的数字并排打：`cached/prev_prompt` 才是「厂商把上次那份认回了多少」，
   `cached/prompt` 是会话级那个会被冷启动拖下来的数——**两个都要打，别只打一个**。
3. **跨会话那一节读记录，不读日志。** 工具表在会话记录里（`projects/<project>/<thread>.jsonl`
   的 `kind == "model/start"` 的 `payload.tools`）。对每个会话取**首次**与**末次**的表：
   - 首次 ≠ 末次 ⇒ 打印 `DRIFT` 与**会话中途换过表**这件事（本次证据里 35 个有表的会话里 6 个这样）；
   - 跨会话两两不同 ⇒ 打印哈希差与**第一个不同的工具名 + 字段名**（本次证据里 11 种不同的表）。
   记录里的 `kind` 在 JSON 里是 `model\/start`（斜杠被转义）——**按 `JSON.parse` 后的
   `kind` 字段判**，别按字符串搜索 `"model/start"`，那会一个都搜不到（本次踩过）。
4. **只读，而且读得安全。** 不 `require` 任何 harness 命名空间、不开 `harness.db`、
   **绝不写 `~/.clj-harness`**（仓库铁律）。默认参数指向真家是**读**，允许；但脚本里
   **一处 `write` 都不许有**。参数：`--log <path>`、`--records <dir>`、`--project <path>`
   （用来解析出记录目录）。
5. **它要能复现本次的结论。** 对着现有的那份 `llm-debug.jsonl` 跑出来必须是：
   第 1 次 `3072/22049 = 13.9%`、后面四次 `22016/22049`、`26880/26957`、`27648/28052`、
   `28672/28936`（≥98.6%）、会话合计 `108288/137384 = 78.8%`，并且**五次请求的 `body` 两两
   构成字面前缀延长**（共享前缀长度 = 上一次的 `body` 长度减掉结尾那个 `]`）。
   这是这张票的**验收基线**：跑不出来就是脚本错了，不是记录错了。
6. **放 `scripts/`，跟 `dev.mjs` 做邻居。** 那里已经放着开发期脚本（`dev.mjs`、`proc.mjs`），
   而这是开发期读证据的东西，不是产品的一部分。命令行写进它的文件头注释里，**不写进 README**
   （README 只有四节）。
7. **票 03 指过来的那件事在这里落地。** 跨进程相等的**证据**就是第 3 条那一节：
   两个不同进程写下的工具表哈希相同 ⇒ 表是进程无关的。脚本要有一个 `--assert-stable` 开关：
   发现两个会话的表哈希不同就**退出 1**，这样它可以被接进任何机器门。

## 验收

- [x] 默认参数跑一次，打出第 1 次 13.9%、续轮 ≥98.6%、会话 78.8%（与 `spec.md` 的数字逐位相同：
      `13.9 / 81.7 / 95.8 / 95.5 / 91.3`，`cached/prevPrompt` 另列 `- / 99.9 / 99.7 / 98.6 / 99.1`，
      会话 `108288/137384 = 78.8%`）
- [x] 打出五次请求两两「逐字节前缀延长」这句话，并给出每次的共享前缀字节数
      （`18883/18883`、`41530/41530`、`48428/48428`、`53771/53771`，零处分歧）
- [x] `--records` 指向真家那个项目目录时，报出 **11** 种工具表哈希与 **8** 个漂移会话
      （票面写 6，那是脚本的 bug，见下）
- [x] 任意一对不同的表，打印出**第一个不同的工具名与字段名**（`job_output.description` /
      `bash.description` / `order: read is #87 … #88`）
- [x] `--assert-stable` 语义拆成两个，见下（票面合成一个，在任何有 MCP 差异的机器上会恒红）
- [x] 脚本里没有一处写文件（`grep -n "writeFile\|appendFile\|createWriteStream\|mkdir"` 为空）
- [x] 脚本头部注释里写着「比的是原始字节」以及指回 `infra/llm_debug.clj` docstring 的那句
- [x] 额外加了「原始文本 vs 折叠结果」的对照行：响应侧落地了原始 SSE（见下面第 3 条）之后，
      脚本重新解析原始 `usage` 与折叠出来的 `telemetry` 比一次，不一致就点名。历史行没有
      `:body`，它就**沉默**（`null`），不编结论。

## 落地记录：三处与票面不一致

**1. `--assert-stable` 拆成两个开关，因为票面那一个是恒红的。** 票面要求「两个会话的表哈希不同
就退出 1」。可事实上不同会话本来就会有不同的表：编辑模式不同、MCP 名单不同、描述改过一次——
在这样一台机器上它会**永远**失败，于是没人会把它接进机器门。拆成：

- `--assert-stable`（默认该用的那个）：**会话内**漂移就退出 1。那是永远算 bug 的那一种，同一场
  对话里表变了，代价是整段前缀加整场对话。
- `--require-identical`（严格版，显式要才用）：有多于一张表就退出 1。只在「所有会话共享一套配置」
  时才有意义。

**2. 我自己的 `toolFingerprint` 写错过，而它把 11 张表说成了 6 张。** 第一版是
`JSON.stringify(tools, Object.keys(tools).sort())`——**replacer 数组会在遍历的每一层生效**，
于是每个工具对象都被过滤成 `{}`，指纹退化成「数组长度的哈希」。表数因此按长度塌缩：41 个工具
的表不管内容全归一类。改成 `canonical()`：数组 `map`、对象按排好的键重建，**逐层**。
改完就是 11 张表 / 8 个漂移会话，与我手工用 Python（`json.dumps(sort_keys=True)`）算的一致。
**教训值得留着**：这个脚本里每一处「我们的哈希」都必须能说清它报的是不是线上事实——
指纹只用来**分组**（把说同一件事的两张表算成一张），而所有关于字节的断言一律走原始字符串。

**3. 「11 张表」是修的产物，不是记录的性质**——所以那个数字要跟着脚本一起被质疑。

## 在野读出来的三条根因（这张票的价值就在这里：它把三类漂移分开了）

| 会话 | 第一处分歧 | 归类 |
|---|---|---|
| `02ba8830` `4aec5144` `7d65cd27` | `job_output.description` | 票 01 的身份哈希 |
| `b553ed1d` `d230946c` `f7085705` `d3dfb66c` | `bash.description` 文本 | 我们自己改过描述——必然代价，不是 bug |
| `d62a2cd9` | `order: read is #87 → #88` | 票 02：多一个 MCP 工具把**内建**挤位 |

分开这三类正是「不能只看一个命中率数字」的理由：前两类都不该再出现（一类已修，一类是编辑成本），
第三类在票 02 之后应当变成「分歧落在 MCP 边界」，报告点得出来。
