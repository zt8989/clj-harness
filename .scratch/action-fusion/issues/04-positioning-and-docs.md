# 04 — 定位与文档收口

**What to build:** 把「本地序列住在 eval 里」这件事写进模型读得到的地方，并把 `docs/architecture/`
那几个页面改成今天的样子。这一票不改行为，但它是**让机制真的被用起来**的那一票：能力今天就在，
模型不知道才是那个缺口。

**Blocked by:** 02, 03 — 先让形状定死再写，否则写的是中间态

**Status:** ready-for-agent

## `prompt.md`

`eval` 今天被写成 hook 的入口（「Self-extension … A hook is a shell command …」），
一句都没提它可以直接调工具。补的是**本地序列**那一段：

- 一个 eval 里可以调用工具表里的任何工具、按返回值决定下一步、循环做批量操作——**中间不回到模型**，
  这就是省下来的那些往返；
- 所以「改完就跑测试」是一次调用，不是两次；
- 两条做不到的事要点名：需要人点头的调用、以及 `skill` 的加载，都必须**作为顶层调用**发出；
- hook 那一段**保留**：eval 仍能给本会话长行为，两件事不冲突，说清它们各自是什么。

改 `prompt.md` 要记得那条冻结纪律：测试同进程里要 `llm/reset-prompt!` 才读得到新文本。

**与 `system-prompt-blocks` 的次序**（同日在办，5 张票）：那套票把 `prompt.md` 改成「固定开头 + 块」。
这一段属于**固定开头**——讲的是能力，不是本会话的事实，与 hook 自助那段同类。它先落地就写进 `prompt.md`；
那个特征先落地就写进新的固定开头，**别塞进块**（块按会话现算，放进去它就会为一个与会话无关的理由而变）。

## `docs/architecture/`

| 页 | 该说什么 |
|---|---|
| `kernel`（工具表 / 执行缝那一节） | 内层调用：`call!` 入口、走完整缝（关闭/缺参数/审批/门禁一条不少，**这是刻意的**：只看顶层的规则用 eval 包一层就绕过去了）、两类被拒的事 |
| `edge`（审计行那一节） | 内层调用的三行与它们的 id 形状；「审计三行不带 args」继续成立 |
| `hooks`（payload 那一节） | 门禁看得见内层调用——与上面同一条理由 |
| `architecture.md` 索引 | 模块地图里 `tools` 那一行若因此变了就改；**「在办」段**里 Action Fusion 这一条落地后要拿掉 |

## 验收
