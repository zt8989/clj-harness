# 17 — 条件决定装不装：`:inject` / `:optional` / `:when`

**What to build:** 「一个插件什么时候该活着」今天只有一根轴（`:inject` 里的依赖）。这一票把它写全成**三条互不
混淆的轴**，每条有自己的语义与代价：

- **`:inject`（必需依赖）**：值变 truthy 之前 `apply` 不跑；值一变就**回滚**（不是停用），仍 truthy 则回滚完
  再**重新加载**。票 03 / 05 立的是这条的两半（等 / 撤），这里把它与另外两条的界线写清。
- **`:optional`（可选依赖）**：可以在 `apply` 里直接用，但**不参与生命周期**——不等它、不因为它变化回滚。
  判据是「这件事不在，也不影响这个插件活不活」。
- **`:when`（按 ctx 事实的条件启用）**：**本仓自己加的一轴**。Cordis 核心的条件只认「服务的值」；平台这类
  条件在 dsh 那边靠配置行、`disabled` 与 patch 层，而我们上一轮明确**不要 patch 层**（spec 决定 4），
  所以这处空白只能由运行时补。谓词读的是 ctx 的**事实**（平台、这台机器有哪只壳、配置里的开关），
  不成立时与「依赖未齐」**同态**：`apply` 一行没跑、状态是 PENDING、注册表里说得清它在等什么条件；
  条件翻转即装即撤——与票 05 是同一条规则的两个方向。

**为什么不许在 `apply` 里自己写 `if`**：Cordis 的官方文档（[服务与依赖](https://cordis.moe/zh-CN/guide/essential/service.html)）
把它点名为**标准错误答案**——服务/事实要等启动完才可用；写在 `if` 里的副作用在热重载与条件翻转时没处撤，
条件重新成立时那段代码也不会重跑。本仓的 `infra.env`（平台、选壳解析结果）与配置开关同样会在进程里被
重新探测 / 重读，理由一模一样。

**Blocked by:** 03 — fiber 与 `:inject` 就绪门（外加 05 的级联规则）

**Status:** ready-for-agent

## 形状

```clojure
{:id   :shell/pwsh
 :when (fn [facts] (= :windows (:platform facts)))   ; 读那份事实，不是自己去问 OS
 :apply (fn [ctx] …)}
```

## 验收

- [ ] 三条轴各有断言：必需依赖（等 + 值变即回滚重装）、`:optional`（不等、不因它变化回滚）、
      `:when`（不成立与「依赖未齐」同态）
- [ ] **`:when` 不成立不算失败**：状态不是 FAILED、不报错，注册表里写得出它等的是哪一个条件
- [ ] **条件翻转两个方向各一条断言**：事实假→真 ⇒ 自动装上；真→假 ⇒ 自动卸干净
- [ ] **可测**：谓词收的是**事实 map**（喂进去就能翻转），不是自己 `System/getenv` 或读文件——
      有一条反证：拿两份不同的事实 map 驱动同一个插件集合，得到两种装配
- [ ] `:when` 与 `:inject` 同时不成立时，两条理由都说得出来（不互相盖掉）
- [ ] 拿 `pwsh` 当端到端用例：只有 Windows 上挂的那个壳后端（`plugin-tree` 票 14 用它当判据），
      在别的平台**不进表、不占坑、不报错**
- [ ] 官方那条反例写进 docstring：为什么不能在 `apply` 里自己 `if`
