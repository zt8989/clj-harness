# 05 — 依赖消失即撤销（级联卸载）

**What to build:** 一条服务的消失会**带着**所有依赖它的插件一起走：先撤依赖者、再撤提供者，与装载顺序相反。
这条让「热插拔」成立——撤掉 `:config`，靠它活着的插件不会留在一个已经没有配置的世界里。

「依赖就绪即启动」与「依赖消失即撤销」是**同一条规则的两半**，一张票只能算它的一半。

**Blocked by:** 04 — 拓扑排序与 `mount-all!`

**Status:** ready-for-agent

## 验收

- [ ] P 提供 `:x`，Q `:inject [:x]`，R `:inject [:q-svc]`：撤掉 P ⇒ Q 与 R 都卸载，
      撤销顺序是 **R 先于 Q**（依赖者先走），顺序可断言
- [ ] 无关的插件 S 仍在，状态照旧 ACTIVE，且一次 `apply` 都没再跑
- [ ] 把 `:x` 重新注册 ⇒ Q、R **自动回来**（顺序 Q 先于 R）
- [ ] 自己依赖自己提供的服务、或两个插件互指成环时，撤销**有界**且报得清（不是栈溢出，也不是转不完）
- [ ] 级联卸载里某个 disposer 抛异常：剩下的照撤完，异常看得见（一个坏 disposer 不等于其余效果留着）
