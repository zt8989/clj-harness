# 16 — WebSocket：一条双向实时通道

**What to build:** 一个插件把「一条长活的、双向的、服务端能主动推的通道」暴露成服务，别的插件 inject 它；
撤销时活着的连接被关掉、端口交回。它与票 11 的区别是：票 11 那条路径一问一答就完，这条路径**活着**，
所以在它上面「撤销」与「端口交回」这两件事第一次真的难。

**Blocked by:** 11 — `:http/server` 插件

**Status:** ready-for-agent

## 验收

- [ ] 端到端走真 socket：客户端连上后服务端**主动推**一条、客户端收到；客户端发一条、服务端收到
      （两个方向各一条断言）
- [ ] 通道随宿主插件的撤销而关闭：撤销后那条连接**被关掉**（不是悬着让客户端等），端口立刻可再绑
- [ ] 连接与断开都进得了日志（谁连、谁断）；握手失败/中途断说得清原因
- [ ] 一条连接上的消息不被静默丢掉：推的时候对端已经走了，这件事要看得见
- [ ] 库选型由实现者按仓库纪律定：本仓已经在用 http-kit，它自带 WebSocket 服务端——
      **引不引新库见 spec 的「依赖」那一节，净新增依赖必须当场论证**
- [ ] 测试不写死端口（与票 11 同一条规矩）
