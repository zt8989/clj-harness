# 18 — 子插件：只有一部分功能依赖某个东西

**What to build:** Cordis 对「**一部分**功能依赖某个服务」给的是**子插件**（`ctx.inject(['console'], ctx => …)`,
等价于一个 `:inject` 了它的插件），而不是把整块功能塞进父插件再自己判空。这一票把这条立起来：
子插件有**自己的 fiber**——自己的依赖、自己的 disposer 栈——随父插件卸载而撤，父子各自的回滚互不牵连。

本仓今天最像它的东西是「动态来源」：`cap.mcp` 的工具经 `install!` 进来、工具表按会话收窄。
子插件把这类事从「往缝里塞函数」变成「挂一根有依赖的 fiber」，于是「谁在等什么」在注册表里看得见。

**Blocked by:** 17 — 条件决定装不装

**Status:** ready-for-agent

## 验收

- [ ] 子插件是**独立 fiber**：它自己的依赖没齐时它不动，而父插件照旧是 ACTIVE（一条断言）
- [ ] 父插件卸载 ⇒ 子插件跟着撤干净（与票 05 同一条路）；子插件卸载**不带走**父插件的注册
- [ ] 子插件的 effect **不漏进**父的 disposer 栈：两边的撤销顺序各断言一次
- [ ] 同一个父插件挂两个子插件，一个的依赖没齐不影响另一个
- [ ] 说得出它买到了什么：**「`:config` 齐了才出现的那条工具 / 那条路由」**不需要在父 `apply` 里写判空
- [ ] 父子关系在注册表里看得见——自省那一票（`plugin-tree` 23）要打得出这棵树
