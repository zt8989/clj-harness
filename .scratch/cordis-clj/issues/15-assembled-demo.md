# 15 — 装配示例：最小应用与一次热插拔

**What to build:** 把 08–14 拼成方案末尾那段 `mount-all!`：config + router + server + 一页 + 一条查询，
跑成一个人打开浏览器就看得见的东西；然后**在它跑着的时候**换掉一条 route 的定义，**同一个端口**答新路由
——服务器不重启。这是这批票里唯一一张「演示」票：它的价值是把前面那些机制摆在一起，看它们是不是真的成立
（分开测全绿、合起来发现装不上，是这种系统最常见的失败）。

**Blocked by:** 11 — `:http/server` 插件；12 — `:http/middleware` 插件；13 — `:render/html` 插件；
14 — `:db/sql` 插件

**Status:** ready-for-agent

## 验收

- [ ] 一条命令（或一段写下来的 REPL 序列）起得来，并报出实际端口
- [ ] 打开它三样都看得见：配置里的值、渲染出来的那一页、从库里查出来的一行
- [ ] 热插拔：改一条 route 的定义后 `reload-plugin!` 生效——**端口没变**，那条 route 答的是新的，
      其余 route 照旧，活着的连接没被打断
- [ ] 撤掉 `:config` 时，靠它活着的那几个插件一起有序退场（票 05 那条规则在真装配里成立）
- [ ] 收摊干净：停一次就停完，端口立刻可再绑，不留背景线程
- [ ] 这段示例的依赖面与 08–14 完全一致（**不因为拼起来而多一个库**）
