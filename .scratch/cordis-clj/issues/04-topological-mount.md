# 04 — 拓扑排序与 `mount-all!`

**What to build:** 一次给一批插件，它们按依赖序装上——被依赖的先装。顺序是**算出来的**，不是调用者排的，
也不是碰巧的加载顺序。这一票把「一个一个装」变成「一次装一批」，并且让顺序本身成为可以被断言的东西。

**Blocked by:** 03 — fiber 与 `:inject` 就绪门

**Status:** ready-for-agent

## 验收

- [ ] A ← B ← C（B inject 依赖 A 提供的服务、C inject B 的）一次 `mount-all!` ⇒ 启动顺序 A、B、C 可断言
- [ ] 批内依赖成环 ⇒ **不静默**：点名环上的那些 id；环外的插件照装（或整批不装——由实现定，
      但必须报出来，并且测试钉住这一条）
- [ ] 依赖在**本批之外**且当下不存在 ⇒ 保持 PENDING（与票 03 同一条规则），**不是**报错
- [ ] 同一批装两次：第二次不重复启动（幂等），注册表里同一个 id 不出现两条
- [ ] 排序是纯函数那一半可以单独测：构造插件 map 的向量，断言它给出的顺序——不启任何东西
