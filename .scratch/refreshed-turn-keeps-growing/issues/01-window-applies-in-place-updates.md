# 01 — 窗口把同 id 的新版本当更新，刷新回来的那一轮接着长

**做什么**

一场还在被服务端回答的会话，浏览器整页刷新回来之后，**屏幕上那一轮回答要接着长**——像没刷新过
一样：服务端每写出一段，页面上就多一段，直到这一轮真的结束。

今天不是这样：刷新落回这一场，尾页把那一轮画到「刷新那一刻」为止，之后再收到多少帧，那一段回答
都停在原地不再变。窗口自己知道服务端还在跑（composer 的提示、侧栏那一行都对），只有**内容**冻住
了——所以「提示在跑」和「内容不动」自相矛盾。

根子在：服务端在 run 进行中通过**记录**给出这条半写好的回答，而且随着更多内容落盘，**同一个消息
id** 会被反复给出、每次内容更长（项目自己的用例 `a-log-that-stops-mid-run-numbers-its-partial-answer-last`
钉的就是这件事）。客户端把「同一个 id 又来了」一律当作**重复**丢掉——那条规则是为「行还没落盘、
下一帧原样再来一遍」写的，可这里的重复是**同一个消息的新版本**，不是副本。于是副本留下、新版被扔。

要做的是把这条去重升级成**原地更新**：同一个 id 再次到达时，把它在窗口里的位置上的那一份**换成新
版本**，位置不变、不新增一份；只有内容真的没变时，窗口才原样返回（不重渲染）。同一条缝也覆盖
「从侧栏点开一场正在跑的会话」（同一扇 `running` 落下走窗口的门）与连接断掉后的尾页对齐。

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

- [ ] 整页刷新回到一场服务端仍在回答的会话：那一轮回答在刷新后继续增长（文字与工具行都算），
      不再停在刷新那一刻。
- [ ] 从侧栏点开一场服务端仍在回答的会话，得到同样的效果。
- [ ] 同一个 id、内容**一模一样**的重复仍然不算第二条目；一帧什么都没改变时窗口按**原身份**返回
      （不产生多余的导入与重渲染）。
- [ ] run 结束后，这一轮的**最终版本**落在原位置，那一轮不再被画成「还在写」。
- [ ] 客户端用例：新增一条钉住「同 id、内容变长 ⇒ 原地更新，既不去重也不重复」；既有的
      「重复不是第二条目」用例保持绿。
- [ ] 真浏览器走查：run 跑到一半整页刷新，断言刷新之后屏幕上的回答文本**确实在变长**（`ALL GREEN`）。
