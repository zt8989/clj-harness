# 03 — `job_output`：读作业说了什么，可以等到它结束

**What to build:** 后台多一个**读**动词。今天读了记录那份文件就够了（`.scratch/job-output` 立的），
缺的是**「等」**：模型的循环是同步的，下一步的输入就是这一步的结果，而它手里唯一会阻塞的工具是
`bash` —— 于是真会话里它拿 `sleep 290` 当 `join` 用。这一票之后：

```
job        {command: "node scripts/test.mjs --backend"}   → j1 + 记录的路径
job_output {job: "j1", wait: true, timeout: 300000}       → 头一行 [exit 0] + 它打出来的那些行
```

答案 = **一行状态** + 命令自己的行（在那个区间里的）。读的位置**由调用者给**（`offset` / `limit`，
与 `read` 同一套规矩，答案点名「接着从哪读」）—— **不立服务端游标**：那要回答「读到哪个字节、半行
算不算、新的一行从哪算起」，是本仓自己发明、自己维护、自己出错的一类问题（`.scratch/job-output`
问题 5 就是它出错的样子），而「我读到哪了」在模型这边是它已经会的动作。

**Blocked by:** 02（正文的字节预算与溢出形状是那一票定的）

**Status:** ready-for-agent

## 要落地的判断

1. **状态就是记录的末行**：`[exit N]` / `[stopped]`，**没有那一行就是还在跑**。不引入
   `running|stopping|completed|killed|failed` 这套本仓没有的枚举 —— 它想说的两件事记录已经答了。
   答案的头一行说的就是这件事，正文是命令自己的行（那条末行不重复进正文）。
2. **条目要活过终点。** 今天 `stop!` 把作业移出注册表、进程结束也一样，于是「它怎么结束的」只存在于
   文件里。这一票让条目在终态之后**仍答得出**（记录在哪、末行是什么）——这是 `job_output` 的前提
   （`job_kill` 幂等是 04 的前提）。注册表仍然是会话内、进程内、随进程消失；条目比作业活得久一点，
   但**不长过这个进程**。
3. **`wait` 挂到的是终态**（记录末行写完的那一刻），不是「进程刚死」：今天 `[exit N]` 由排空线程在
   `settle!` 之后写，所以「等到末行出现」与「等到真的结束」是同一件事。**超时返回 `status: running`，
   不是错误**（参考规格的判据）；有位置可读时**立即返回**，不为了等而等。
4. **`timeout` 是「我这次等多久」，不是作业的时限**（作业照旧没有时限）。默认值与描述插值一处决定。
5. **被停掉的作业照样读得到**（记录不删，`.scratch/job-output` 决策 5）。
6. **不认识 id 与「没有新东西」是两件事**：前者指名拒绝（列出本会话的作业，与今天 `job_kill` 的
   拒绝同一形状），后者是一句「没有新的」+ 状态。**没有新东西不等于它结束了**。
7. **工具面跟着这一票改**：工具数 17 → 18、三处硬编码清单、`CONTEXT.md` 的闭清单；两个描述串里的轴
   写成 **「接下来只会等它 → `bash`（把 `timeout` 开大）；接下来要干别的 → `job` 起，回头用
   `job_output` 等它」**（`bash` 那句「for something that has to outlive the call」与 `job` 那句
   「a slow test or build」都在这一票里改对；「慢」不是判据）。
8. **描述里必须写明「要读就用这个动词」**，并说清 `wait` 的语义（超时回 `running`）—— 它是**唯一**
   会阻塞的后台动作，与「作业没有时限」是两件事。
9. **薄的工具面**：读记录、算状态在 `harness.cap.jobs`，`cap.tools` 只留一张脸（`tool-parity` 的规矩）。
   不给 `reason` 之类的参数（没人读的参数是没兑现的承诺）。

## 验收

- [ ] `job {command: "echo one; sleep 1; echo two"}` → id；`job_output {job, wait: true, timeout: 10000}`
      在**一秒多**回来：头一行 `[exit 0]`，正文是 `one` / `two`；紧接着再 `job_output {job}` → 没有新东西，
      状态仍是终态
- [ ] `job_output {job, wait: true, timeout: 300}` 对一条长命作业 → `status: running`（**不是错误**），
      而且是**按时**返回的（墙钟可测）
- [ ] `job_output {job, offset: N}` 从第 N 行读，答案点名**接着从哪读**；`grep` 那个记录文件拿到的
      行号与 `offset` 说的是同一件事
- [ ] 一条被 `job_kill` 停掉的作业，`job_output` 仍读得到它的记录与终态
- [ ] 不认识的 id → 指名拒绝，列出本会话的作业；**「没有新东西」与「它不在了」是两句不同的话**
- [ ] 工具面：两处清单用例 + `CONTEXT.md` 闭清单是 18，`job_output` 在表里
- [ ] 两个描述串里那句轴在（用例断言文本）；`bash` / `job` 描述里对彼此的指名仍是对的
- [ ] `node scripts/test.mjs --backend` 全绿（失败用例名与基线一致）
- [ ] `.scratch/bash-lifetime/spec.md` 决策 10 那两行**划删除线 + 一行日期注**（旧话不逐字改；本票落地当天做，`.scratch/bash-record` 决策 4 已在立票当天划掉）
