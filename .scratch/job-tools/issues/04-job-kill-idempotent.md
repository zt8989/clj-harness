# 04 — `job_kill` 幂等且不阻塞

**What to build:** 停一条后台作业这件事，两个性质今天都不对：**不幂等**（第二次问同一个 id 拿到的是
指名拒绝，因为 `stop!` 把条目移出了注册表），**要等**（`stop!` → 收整棵树的路上有一句等壳死的
`waitFor 2s`，对 `trap '' TERM` 那种命令真的会等满）。这一票之后：

- 已经在**终态**的作业：`job_kill` **答它的终态**（末行是什么就说什么），不报错；
- 在跑的作业：认领 `[stopped]`、**请求**把整棵树收掉、**立即返回**，进程真的死透由收尾那边收敛；
- **不存在的 id** 仍然指名拒绝（列出本会话的作业）—— 这与「已经结束」是两句不同的话，不许并成一句。

**Blocked by:** 03（要幂等答出的那个终态，是 03 让条目活过终点的）

**Status:** ready-for-agent

## 要落地的判断

1. **幂等是「再问一次得到同一个答案」，不是「再杀一次」**：已经在终态时一个字不写、一个进程不碰，
   把记录在哪 + 怎么结束的答出来。**重复请求没有任何副作用**。
2. **不阻塞**：`job_kill` 的返回**不等进程死透**。整棵树照旧要收（先收子孙再杀壳，父进程一死子孙就被
   重新领养，那棵树再也走不到），但那件事发生在调用之外；`kill-tree!` 那 2 秒的温柔期不许吃在调用上。
   `bash`（前台）到点收树那条路**一个字不改** —— 那里等到死透正是对的。
3. **状态最终收敛，不卡在中间**：一次请求之后，作业在**有限时间**内真的不在（进程没了）、记录末行
   就是 `[stopped]`（它先认领、后杀，所以排空线程醒过来也补不上一个 `[exit 137]`）。
   收敛由收尾那一侧完成（销毁、子孙、条目的终态），**有名字**，不是「过一会儿大概就好了」。
4. **记录照旧不删**（答案是叫模型去读它的；被杀之后正是最想读的一刻）。
5. **不做 `reason` 参数**：它的值不出现在任何答案里（参考规格里它也只是个可选字段）。
6. **点名拒绝的形状不变**：一个不认识的 id 仍然列出本会话的作业（今天 `job_kill` 就是这么拒的）。

## 验收

- [ ] 一条在跑的 `sleep 300`：`job_kill` **很快**返回（墙钟远小于那 2 秒的温柔期，用例断言），
      记录末行 `[stopped]`、文件还在、`job_output` 还能读到它
- [ ] 那条命令起的**子孙**在有限时间内真的没了（用例轮询，不许只断言「我们发过信号」）
- [ ] **再 `job_kill` 同一个 id** → 答终态（末行 + 记录的路径），**不是**拒绝；
      `bash` 前台到点收树那条路的用例一条不改
- [ ] 一个自己跑完的作业，`job_kill` 报它怎么结束的（今天已有的一半行为，扩成幂等的那一半）
- [ ] 一个不存在的 id → 指名拒绝，列出本会话的作业（与「已经结束」是两句不同的话）
- [ ] `node scripts/test.mjs --backend` 全绿（失败用例名与基线一致）
