# 05 — 收口：词、文档、报数

**What to build:** 前四张票落地之后，把**需要新写一段话**的地方写完，把数报出来，并给这个特征自己
留一份落地记录。**一票落地那天就会撒谎的东西不留给这一票**：工具数、三处硬编码清单、`CONTEXT.md`
的闭清单、两个描述串，全在 03 里改了。

**Blocked by:** 04（收口要前四张的成品一致：同几处文档、同一批词）

**Status:** ready-for-agent

## 要落地的判断

1. **`CONTEXT.md`**：立词（读法 / 一次调用的答案上界 / `workdir` 与 `stdin` 属于谁），核对闭清单；
   凡是被这一族改过的旧说法（「作业没有时限、也（因为没人通知而）没有等」）当场改掉。
2. **`docs/architecture.md`** 的模块地图：`cap.jobs` 一行现在装着三件事（注册表、记录的写法、
   读动词的状态自答），`cap.tools` 一行点明读动词在哪儿；`infra.shell` 一行补上「前台也记一份」
   与 `run` 一直收着的 `:stdin` / `:dir`。
3. **`docs/architecture/kernel.md`**：「不做超时」那句的范围（它讲的是审批）—— 后台照样没有时限，
   而 `job_output` 的 `timeout` 是「这一次我等你多久」。
4. **`docs/architecture/overview.md`** 的状态表：作业那一行跟着说清「记录住哪、活多久、谁能读」。
5. **`README.md`** 那一节（介绍这一族的四只手的表 + 段落）：四只手的轴、答案的上界、怎么等一条作业；
   报数用**实测**（写清分支与切出提交）。
6. **`docs/architecture/client.md`**：核一遍「新增一个工具不动那两张表也能用」是否仍成立
   （本特征一个字节不改 `ui/`，若成立就一个字不动，并把这一句核过记在落地记录里）。
7. **两套全量**：后端（`node scripts/test.mjs --backend`）+ 前端；`ui/` 没改，所以
   `node scripts/dev.mjs --scripted` 走查**不是**本特征的判据，但 AI 那一侧跑一次也无妨（记在落地记录里）。
8. **落地记录**写进本特征的 `spec.md`（票面按仓库约定删除）。
