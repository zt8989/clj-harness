# spec: 命令进得去、出得来 —— `bash` 的 `stdin` / `workdir` 与答案上界，`job_output`，幂等的 `job_kill`

**一句话**：作业这一族今天只有「起」与「停」两个动词（`bash` / `job` / `job_kill`，见
`.scratch/bash-lifetime` 与 `.scratch/job-output`），三处缺口都在模型那一侧：前台 `bash` **喂不进
stdin、换不了工作目录**，它的答案**没有上界**（`(str out err)` 原样进上下文、也原样进 jsonl），
而后台作业**没法读、更没法等** —— 于是真会话里那条 `job {… > /tmp/x} + bash {sleep 290; grep …}`
是模型用 `sleep` 拼出来的 `join`（`.scratch/bash-record/spec.md` 问题 2 记着现场）。本特征把这一族
对齐到参考规格（会话里那份《工具行为规格：bash / bash(后台) / job_output / job_kill》）：`bash` 收
`stdin` 与 `workdir`；一次调用的答案**按字节封顶、留尾部、带省略量与溢出路径**；后台多了读动词
**`job_output`**（位置由调用者给，`wait` 可以挂到终态）；`job_kill` **幂等且不阻塞**。工具数 17 → 18。

2026-09-18 立。**词照着本仓来**（这是「复用当前工具的参数」那一条的落地）：后台**不**引入
`run_in_background`（本仓后台已经是一个独立动词），`timeout_ms` 是 `timeout`（毫秒），`job_id` 是
`job`；五个状态收成记录的末行那一种自答。

## 问题

1. **前台 `bash` 的进路是断的，而底下那台机器是通的。** `infra.shell/run` 收 `:stdin`、收 `:dir`；
   `t-bash` 只把 `:command` / `:dir`（本会话的项目绑定）/ `:timeout-ms` 接了进去。于是「喂一段文本给
   一个命令」只能靠 `echo … | …` 写进命令串（引号、换行、大小上限全是模型自己要处理的事），而
   「换个目录跑」只能 `cd` 一个前缀 —— 与 `job` 那条路（cwd 与 `bash` 同一处解析）也对不齐。

2. **前台 `bash` 的答案没有上界，落点还不止上下文。** `t-bash` 返回 `(str out err)`，一个字不裁：
   一条跑几分钟的测试打几万行，**原样进上下文，也原样进 jsonl**。同一个文件里躺着 `clip`（8000 字符
   就砍，唯一调用点是 `t-eval`）—— 「要不要给答案上界」本仓回答过一次，只是没轮到 `bash`。
   参考规格在这一处说得比本仓细：**按字节、不按行**（一行 100KB 的 JSON 撑爆按行方案）、
   **截断必带省略量与溢出路径**、**stdout 与 stderr 各自计数**。

3. **作业没有读动词，也没有「等」。** 读的是记录那份**文件**（`bash tail` / `read` / `grep`，
   `.scratch/job-output` 决策 2 立的），这对「整份、可搜」已经够用 —— 但模型的循环是同步的，
   下一步的输入就是这一步的结果，而它手里**唯一会阻塞的工具是 `bash`**，于是它拿 `sleep` 当 `join`
   使（`timeout: 330000` 只是把时限抬到 `sleep` 之上）。一条作业跑完了，**没有任何东西会告诉它**，
   它也没有一个动词可以「等到它结束」。参考规格给的就是这个动词：读增量 + 挂到终态。

4. **`job_kill` 不幂等，而且走的时候要等。** 第二次 `job_kill` 同一个 id 拿到的是**指名拒绝**
   （`stop!` 把条目移出注册表）；而 `stop!` → `close!` → `kill-tree!` 里有一句等壳死的
   `waitFor 2s`（对 `trap '' TERM` 那种命令真的会等满），于是「请求终止」这个动作被做成了「等它死透」。

5. **这件事哪儿都没记着。** `README.md`、`CONTEXT.md`、`docs/architecture*.md` 写的是「十八个工具 /
   作业的记录是一份文件 / 作业没有时限、也（因为没人通知而）没有等」——本特征让其中几处成为必须跟着改
   的话，并立一个新词（作业的读法）。

## 决策

1. **`bash` 多两个参数：`stdin` 与 `workdir`，后台**不**多一个 `run_in_background`。**
   `stdin` 写进去随即**关掉**（`run` 已经这么干：一个读 stdin 的命令看到的是 EOF，不是
   「等一个不会打字的父进程」）。`workdir` 是本会话项目绑定之下的一个目录，**解析与本仓其它路径同一处**
   （相对路径就是相对项目目录），不是目录就**指名拒绝**（说出它是文件 / 不在）。后台**不**引
   `run_in_background`：本仓的后台是一个**独立动词**（`job`，名字不带 `bash_` 是 `omp-parity` 那次复议
   的规矩），而 `.scratch/bash-record` 的轴（接下来会不会等）已经写在两条描述里。

2. **一次调用的答案有上界：按字节、留尾部、带省略量与溢出路径。** 一个 `def` 决定预算（描述里
   插值 —— `bash-default-timeout-ms` 的先例：写第二个 `120000` 就是留一次「改了默认值、描述没跟上」），
   **stdout 与 stderr 各自独立计数**（大 stdout 不许把一行 stderr 挤掉）。超预算时：整份写进配置家里
   一份记录（**一个写入者、一行不丢**），答案是**尾部 + `[truncated: 省略 N 字节]` + 那个路径**，
   模型接着用 `bash` / `read` / `grep` 读完。**留尾部而不是头部**：测试的头部全是 `Testing …`，
   要读的在尾巴（`bash-record` 决策 7 的判据，这里只是把它用在溢出的那一半）。

3. **`clip` 不动。** 它是 `eval` 的（字符数、留头部）；前台 `bash` 要的是另一种裁法，不去改它。

4. **`job_output`：位置由调用者给，不立服务端游标。** 参数 `job` / `offset`（1-based，缺省从头）/
   `wait` / `timeout`，**复用 `read` 已经教过模型的规矩**：答案点名「接着从哪读」。
   理由：服务端游标要回答「读到哪个字节、半行算不算、新的一行从哪算起」——那是本仓自己发明、自己维护、
   自己出错的一类问题（`.scratch/job-output` 问题 5 就是它出错的样子），而「我读到哪了」在模型这边
   是一个它已经会的动作（`read` 的 `offset`、`grep` 的行号）。**2026-09-18 复议（牛总）：复用。**

5. **`job_output` 可以等：`wait` 挂到终态，超时不是错误。** `wait: true` 时：有未读内容立即返回；
   作业还在跑就等到**终态**（记录末行写完的那一刻，不是「进程刚死」）/ 超时；超时返回
   `status: running`。**这是本特征唯一反着旧话走的一条**：`.scratch/bash-lifetime` 决策 10 与
   `.scratch/bash-record` 决策 4 都写过「不做半阻塞读、不给 `job` 加 `wait`」，理由当时是「没有读动词
   就不该有第二种等待语义」——现在读动词有了（决策 4），那个理由不成立。`.scratch/bash-lifetime` 决策 10
   那两行**划删除线 + 日期注**（落地那天做，票 03；旧话不逐字改），`.scratch/bash-record` 决策 4 的同一
   句已在立票当天随那张 spec 一并划掉。

6. **状态就是记录的末行，不新立五种状态。** 记录的最后一行只有两种写法（`[exit N]` / `[stopped]`，
   缺席即**还在跑**，`.scratch/job-output` 决策 6），`job_output` 的答案头一行说的就是这件事，
   正文是命令自己的行。**不引入 `running|stopping|completed|killed|failed` 这套枚举**：它是本仓没有的
   词汇，而它想说的两件事（进程走了没有、是我们停的吗）记录已经答了。`[stopped]` 在**请求终止的那一刻**
   认领（先写后杀，所以醒过来的排空线程不可能在它后面补一个 `[exit 137]`）—— 于是「已请求停止」与
   「记录的末行」是同一个事实，不需要一个 `stopping` 挡在中间。

7. **`job_kill` 幂等，而且不等进程。** 已经在终态的作业：**答它的终态**（末行是什么就说什么），
   不报错；**不存在的 id** 仍**指名拒绝**（列出本会话活着的作业）——这是两条不同的问法，不能并成一条。
   在跑的作业：认领 `[stopped]`、**请求**把整棵树收掉、立即返回；进程真的死透由收尾那边收敛
   （`kill-tree!` 那 2 秒不吃在调用上）。记录**照旧不删**（答案是叫模型去读它的）。

8. **`reason` 不做。** 参考规格里它是一个可选参数，但它的值**不出现在任何答案里** —— 一个没人读的
   参数是一次没兑现的承诺。要留痕的话，会话历史里已经有那次调用。

9. **记录的规矩一条没动。** 记录仍住配置家（围栏自由，所以 `read` / `grep` / `bash` 都够得着）、
   仍是这个进程的寿命（退出钩子收）、`job_kill` 仍不删、仍不进 jsonl / sqlite / AG-UI / 轨迹。
   本特征只**多一个读者**（`job_output`），不多一份记录。

10. **工具面：17 → 18，跟着 03 那一票改。** 三处硬编码清单（`harness.kernel.tools-test`、
    `harness.cap.editing-mode-tools-test`）与 `CONTEXT.md` 的闭清单、两页文档的数目，**不留给收口**。
    两条描述（`bash` 与 `job`）里的轴跟着 03 写一遍：**接下来只会等它 → `bash`（把 `timeout` 开大）；
    接下来要干别的 → `job` 起，回头用 `job_output` 等它**。

## 非目标

- **不给作业喂 `stdin`**（参考规格也把 `stdin` 只给了前台；`shell/start` 的 `:write-line!` 在那儿，
  需要时再挂）、**不做推送通知**（要等就 `job_output {wait}`，没有「跑完叫我」）。
- **不改 `job` 的既有性质**：没有时限、不随 run 死、不挂审批、不进任何持久层。
- **不复用 `.scratch/bash-record` 的设计**（按**行**阈值、答案「头一行 + 尾巴 + 行数」、`jobs/` →
  `records/` 改名）：它整张被丢弃（见文末「状态」），本特征按**字节**封顶、留**尾部**。
- **不改 `infra.shell/run` 的时限语义**（毫秒、默认 120000、不封顶）与 `start` 的两种 argv 形状。
- **不给 `bash` 加过滤参数**（`grep` / `tail` 挂在命令后面就够了）。
- **不改 `read` / `grep` / `clip` / `anchor_grep`**，不做作业面板与列表端点、不做日志轮转、
  **不跨重启**（作业仍是进程内、按会话分家）。
- **不动 `ui/`**：新动词是工具卡表的兜底（`TOOL_ICONS` 没有它就退到扳手），`docs/architecture/client.md`
  的「新增一个工具不动这两张表也能用」照旧成立。

## 验收主线

一条真会话（或直调），八件事看得见：

1. `bash {command: "sort", stdin: "b\na\n"}` → `a` / `b`；`bash {command: "pwd", workdir: "src"}` →
   解析后的绝对路径；`workdir` 指向一个文件 → 指名拒绝。
2. `bash {command: "seq 1 200000"}` → 答案是**尾部** + 一行省略 N 字节 + 一个路径；
   `bash {command: "wc -l < <path>"}` 答 200000；`read` / `grep` 读那个路径**不挂审批**。
3. `bash {command: "echo hi"}` → 与今天**逐字相同**（`hi`），没有路径、没有省略量、**没有落盘**。
4. `bash {command: "seq 1 5000; sleep 300", timeout: 1000}` → 记录里是到点前打出来的那些行，
   末行是既有的那条「到点被停掉」的话；那条 `sleep` 的进程不在。
5. `job {command: "echo one; sleep 1; echo two"}` → id；`job_output {job, wait: true, timeout: 10000}`
   在**一秒多**回来，头一行说 `[exit 0]`，正文是那两行；紧接着 `job_output {job}` 说没有新东西、
   状态仍是终态。
6. `job_output {job, wait: true, timeout: 300}` 对一条长命作业 → `status: running`（**不是错误**）；
   带 `offset` 的调用拿得到「接着从哪读」。
7. `job_kill {job}` 对一条在跑的作业 → 立刻返回（不等到进程死透），记录末行 `[stopped]`、
   文件还在、`job_output` 还能读到它；**再 `job_kill` 同一个 id** → 答终态，不报错；
   一个不存在的 id → 指名拒绝。
8. 工具面：`job_output` 在、总数 18（两处清单用例是证据）；`bash` 与 `job` 的描述里那句轴在。

### 01 — `bash` 的进路：`stdin` 与 `workdir`

- `cap.tools` 多一个 `work-dir`：不给 `workdir` 就是本会话的项目绑定（与从前逐字相同，未绑定时子进程
  继承本进程的 cwd），给了就按 `cap.project/resolve-path` 解析——**与 `read` 同一处**。判据只有一条：
  它得是个目录；两种不是的方式分开说（是文件 / 那里什么都没有）。
- `t-bash` 只多传一个 `:stdin`（`infra.shell/run` 一直收着它，写完即关）。
- **不挂围栏**：`bash` 本来就能 `cd` 到任何地方，给 `workdir` 挂 park 是拿装样子换一次审批。
- 描述里两个新参数各自的默认值都在描述串里，`workdir` 与项目目录的关系照 `read` 的说法写。

### 02 — 答案有上界：按字节、留尾部、带省略量与溢出路径

- `cap.jobs` 多一节「the answer」：`answer-budget-bytes`（8000，**一个 `def`**）、`tail-within-budget`
  （按字节从尾部切，切点落在行首；UTF-8 的多字节字符**要么整个在、要么整个不在**）、
  `truncation-line`（`[truncated: omitted N bytes of stdout; the whole output is <path>]`）、
  `spill!`（前台的一次性记录）。
- **前台记录是 `cN`，作业是 `jN`**：两个计数器，两种东西（一个是文件，一个是能被问、被停、被等的命令）。
  目录仍是 `<配置家>/jobs/<会话>/`，`shutdown!` 一并收掉（`spilled` 那张表就是为此存在的）。
- `t-bash`：stdout / stderr **各自**切（一行 stderr 不会被大 stdout 挤掉），**不超预算时逐字不变、
  一个字节都不落盘**；超了才写记录，答案 = 尾部 + 每条被切流的省略行 + 结束行。
- **结束行在溢出时一定出现**（`[exit 0]` 也写）：记录末行与答案末行是同一句话，两者不可能对不上。
  不溢出时保持老样子（`[exit N]` 只在非零时出现）——**这就是「下面那条纪律的例外只发生在溢出这一侧」**。
- `clip` 一个字没动（它仍是 `eval` 的：字符数、留头部）。

### 03 — `job_output`：读作业说了什么，可以等到它结束

- `cap.jobs/output`：状态 = 记录的末行（`terminal?` 问的是 writer 有没有被认领——它与「末行写完了」
  是同一件事，因为 `write-last-line!` 两件事一起做），窗口 = 尾部（无 `offset`）/ 从 `offset` 往前
  （有），都受 `answer-budget-bytes` 约束；`:from` / `:to` / `:total` 是**记录自己的行号**，`grep -n` 数
  的是同一批。
- **`wait` 挂的是 `:ended` 这个 promise**（`write-last-line!` 里 `deliver`），不轮询文件：末行写完、
  `wait` 醒、`terminal?` 为真是同一刻。超时（默认 `job-output-default-timeout-ms` = 120000）到点答
  `[running]`。
- **条目活过终点**：`stop!` 不再把作业移出注册表。这是 `job_output` 能回答一条已经结束的作业、以及
  04 的幂等能成立的前提。排空线程的循环因此加了一条「writer 还被认领吗」——不然它会对着一条
  已经被 `close!` 掉、永不再出行的队列每秒轮询一次。
- 工具面 17 → 18：三处硬编码清单、`CONTEXT.md` 的闭清单、`bash` / `job` 两个描述串里的轴
  （「接下来只会等它 → `bash`（`timeout` 开大）；要干别的 → `job` 起，回头 `job_output` 等它」）。
  两个答案串（`job` 与 `job_kill`）也都改成指 `job_output`。
- `.scratch/bash-lifetime/spec.md` 决策 10 划删除线 + 日期注（「不做半阻塞」那一半被翻，
  「没有人通知」那一半不动）。

### 04 — `job_kill` 幂等且不阻塞

- `stop!` 答 `{:id :path :stopped? :ending}`：`ending` 是记录末行，工具面据此说「stopped」或
  「was already over ([stopped])」——**第二次问同一个 id 是回答，不是拒绝**；只有本会话没发过的 id 才拒。
- 收整棵树移到**另一个线程**（`future`）：调用立刻返回，`destroy` / 有界等待 / `destroyForcibly`
  仍照旧走完。`bash` 前台到点收树那条路一个字不改（那里等到死透正是对的）。
- 不变的是：`[stopped]` 仍**先认领再杀**（排空线程不可能在它后面补一个 `[exit 137]`），记录仍不删。
