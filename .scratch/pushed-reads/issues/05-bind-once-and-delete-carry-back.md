# 05 — 绑定只发生一次：把不变量立起来，然后删掉 carry-back

**What to build:** 一场会话的**项目绑定**是一次性的事实：它发生在**会话开口之前**，此后**不可变**。
把这条从「界面上的习惯」变成**服务端的不变量**，然后删掉那条为「绑定会搬家」而写的补路。

界面今天已经是这样了：选目录那颗控件是 `{!started && …}`，会话一有消息就不画（它自己的注释：
no messages, show; any messages, hide）。**服务端不是**：

- `cap.project/bind!` 的注释原话：「rebinding to another directory is just binding again —— the last bind
  wins」，而 `(bind! id nil)` 被写成「释放这个会话，**通常因为它马上要绑到别处**」。
- 绑定路由自己算 `before` / `from-dir`，目录一变就 `record/flush!` + `move-log!`，注释里还写着
  「一次排队的行落到旧路径 ⇒ **一场对话两个文件** ⇒ **下一次绑定**再按名字拒绝」。
- `edge.http/carry-back!`（配 `ts-range`）就是修那条路的：目标文件已在项目 workspace、而保留区里
  还留着一截时，按时间戳范围判断顺序、把它追加回去并改名留证。

**做法：先立不变量，再删。**

1. **第二次绑到别的目录被拒**（绑到同一个目录仍是幂等的 no-op 成功）。这一条与界面已经一致，只是把它
   挪到服务端——脚本、测试、以后的界面也换不了。
2. **会话开口之后不许换**，所以「无家 → 项目」这次搬家只可能发生在**还没有任何一行**的时候：
   `move-log!` 与 `(not= from-dir to-dir)` 那一段随之退场（**没有东西可搬**）。
   说清楚代价：一场**已经说过话的任务**绑不进项目了——今天界面上已经如此，这一票让服务端也这么说。
3. **删掉补路**：`carry-back!`、`ts-range`、`carry-back-checked`、记录写者消费者里那次 per-line 调用，
   以及 `log/carried-back` / `log/carry-refused` 两条审计 kind。**2026-09-25 那次扫描里「碰记录的两处」
   就此归零。**
4. **`edge.replay/locate` 那条「同一个 stem 两个 workspace 的日志」的拒绝留着**：它是**读侧**的防御
   （一次目录扫，不读文件内容），手工往目录里放第二个文件仍然该被指名拒绝。只改它注释里
   「一次绑定没搬成是寻常原因」那半句——不变量立起来之后，它不再寻常。

**Blocked by:** 无 — 可以立刻开始。

**Status:** ready-for-agent

- [ ] 第二次绑到**别的**目录被拒，句子说清「绑定在会话开口之前定下，之后不可变」；绑到**同一个**目录
      仍是 no-op 成功。
- [ ] `move-log!` 退场（或只剩一个「没有行可搬」的形状）：绑定不再在 workspace 之间搬日志。
- [ ] `carry-back!` / `ts-range` / `carry-back-checked` 与消费者里那次 per-line 调用**删干净**；
      两条审计 kind 不再出现；`grep` 里再也搜不到它们。
- [ ] `locate` 的「两个日志」拒绝仍在（手工放进去的第二个文件照样被指名拒绝），注释里「寻常原因」
      那半句改掉。
- [ ] 一场**已经有行**的会话（说过话的任务）绑到项目被**拒绝**，句子照实说「它已经有内容了，绑定只在开口之前
      定下」；还没有行的会话照旧绑得上。
- [ ] **不变的那部分**：无家会话绑到一个项目、项目会话在建号时绑定、绑到同一个目录幂等——行为照旧；
      既有用例全绿（除了「换目录会被搬」那几条，它们按新规矩改成「被拒」）。
- [ ] 后端 `clojure -M:test -m harness.test-runner` 全绿。

**落地时要记下来的**：这一票翻掉了 `cap.project/bind!` 里「rebinding is just binding again」那一句
（以及 `(bind! id nil)` 那段「通常因为它马上要绑到别处」的措辞）——是**决策层的翻转**，
收口时要在原地留日期注，别让注释和代码各说各的。
