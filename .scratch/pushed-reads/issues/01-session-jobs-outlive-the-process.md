# 01 — 作业的身份与状态进库：作业记录一个整份读都不许

**What to build:** 一条后台作业的**身份**（`j1` 是谁、跑的是哪条命令、什么时候起的、记录在哪个文件）与
**状态**（还在跑 / `[exit N]` / `[stopped]` / `[exit ?]`）都是**库里的事**：那一栏、`job_output`、
`job_list`、`job_kill` 读的都是库。换一个进程（重启 harness）、刷新页面之后，那场会话的作业**还在**，
`j1` 仍然是**同一条命令**，起点不变，「跑了多久」是真的。

**顺带清掉这条规矩的最后一个例外：作业记录不许整份读。** 今天 `cap.jobs` 的 `record-lines` 是 `slurp`，
它有三个调用点，都在**读路径**上：

- **那一栏**（`listing` → `status-of`，**每行一次**）：那一栏开着时每秒列一次 ⇒ 每秒把每条作业记录的整份
  读进内存，只为读它最后一行。
- **模型的 `job_list`**（`records-for` → `ending-of`）：把这个会话**产生过的每一条**作业记录各整份读一遍。
- **模型的 `job_output`**（`output` → `record-lines`）：它最后**只发一个窗口**（`tail-window`），却为这个窗口
  把整份读进内存。

三件事一起改：

- **身份与状态落库**：id / 命令 / 起点 / 记录路径 / 状态一行一个作业。编号从库接着数，所以同一场会话里
  **不再有两代 `j1`**（今天 id 是进程内计数器；命令与起点只活在内存登记表里，进程一走就没了）。
- **读的一律读库**：`listing`、`job_output` 的状态、`job_list` 对**本家起过的作业**，都不碰记录文件。
  `job_output` 要发的那个**窗口**从记录的**尾部流式**取（`io/reader` + 从末尾往回读，或逐个窗口流式扫描，
  不必整份进内存）；`job_list` 对盘上**别家/更早**的旧文件也改为流式读。
- **记录的末行照旧写**：`[exit N]` / `[stopped]` 一个字不改地留在那份记录末尾——它是给「用 `read` / `bash`
  直接翻这份文件」的人看的。但它**不再是读的权威**：权威是库。

**异常退出之后的补档，是唯一读作业记录的地方**（正常结束，包括干净关进程，都在写结局的那一句落库了）。
进程被杀、崩溃、断电之后，库里还写着「在跑」而没有进程在跑它：**启动时做一次**，对每一行还写着「在跑」的
作业——**只读它那份记录的末行**（尾部读，不是 `slurp`）——有结局就照抄进库，没有就记成
「那次跑的东西没了，没留下末行」（今天 `[exit ?]` 那个词）。补完，库里不再有「在跑」的孤儿。

**代价要正面接受：结局写两处**（记录末行 + 库），不一致时以**库**为准。记录仍会降级（那套既有的话照旧说），
而库写失败是本地库的失败，不是这一票新造的。

**Blocked by:** 无 — 可以立刻开始。

**Status:** ready-for-agent

- [ ] **一个记录文件都不整份读**：那一栏列一次、`job_list` 列一次、`job_output` 读一次，都不读整份记录
      （拿得住的话，钉一条「读路径不调用 `slurp`」或「读的字节数与记录大小无关」的测试）。
- [ ] `job_output` 的窗口仍与今天**逐字节相同**（`:lines` / `:from` / `:to` / `:total` 与 `grep -n` 对得上），
      而它是从尾部**流式**取出来的。
- [ ] 那一栏、`job_output`、`job_list` 的状态**都来自库**，与记录末行**逐字相同**
      （四种词：`[running]` / `[exit N]` / `[stopped]` / `[exit ?]`）。
- [ ] **干净关进程**（`shutdown!`）把每条在跑的作业落成它自己的结局，于是补档只处理**异常**那一种。
- [ ] **补档**：杀掉 harness 进程再起来，库里还写着「在跑」的那一行，若它的记录有末行就照抄进库、没有就记成
      `[exit ?]`；补完库里没有「在跑」的孤儿。补档**只在启动时跑一次**，而且**只读末行**。
- [ ] 记录文件里那一行**字面不变**：用 `read` / `bash` 直接翻它的人看到的东西与今天一样。
- [ ] 重启之后那一栏**还是那两条**：`j1` / `j2` 是同两条命令，起点与「跑了多久」逐字段一致。
- [ ] 重启之后新起的一条**不会**又叫 `j1`。
- [ ] 重启之后**能读不能停**：进程不在了就没有可停的东西（那种行不画 ■）；`job_output` 照旧读得出来
      （今天它答 `unknown job`——那句要消失）。
- [ ] 记录被回收（或被人删掉）的那条作业**不画在那一栏**——一个指向不存在记录的 id 是骗人的。
- [ ] `job_list` 里那句 `(no command kept -- a record holds what it said)` 对本家起过的作业**不再出现**；
      对**别家/更早**的旧文件仍然成立（那是另一回事，见非目标）。
- [ ] `job_output` / `job_kill` / `job_list` 对本进程持有的作业的其他行为一个字不改（既有用例全绿，除了
      「状态从哪儿读」这一处）。
- [ ] 后端 `clojure -M:test -m harness.test-runner` 全绿；`cd ui && npm test`、`cd ui && npm run build` 全绿。

**落地时要记下来的**：库里那张表属于**哪一层**要写进它的建表注释——它与 `sessions` / `session_claims`
是同一层（会被改写、会被清掉的事实），而作业的记录文件仍是 append-only 的那一份。两边的关系一句话：
**库答「这是哪条作业、它怎么了」；记录答「它说过什么」。**
