# 01: 判定与信号——`normalized?` 与它上不上下行的字段

**What to build:** 一个判定（记录是否已重整化，按 spec 的三条）与它的**信号**：读侧（`sofar`/`stats`/`page`
等既有答案）带上这个字段，前端与客户端据此决定能不能继续。判定必须是**读一条记录就能答**的，
不许要求把整份记录折进内存。

**Blocked by:** 无（可以立刻开始）

**Status:** ready-for-agent

- [ ] 三条判据各有真记录上的判例（旧格式、裸露消息、缺消息行各一条）
- [ ] 既有读侧答案带 `normalized`（缺省视为什么，要写明；老客户端不受影响）
- [ ] 判定是流式的（一遍扫过，不建整份向量）
- [ ] 判据与 `harness.edge.replay` 的读侧边界一致（它认的两形状不许被判成不可读）
