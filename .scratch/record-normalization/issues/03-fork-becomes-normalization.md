# 03: fork 变成重整化

**What to build:** `POST /api/threads/<stem>/fork` 今天「逐字复制截点之前的行、给被截断的 run 补终局」。
把它升级成**重整化**：同一趟里补齐信封（新格式）与**缺失的消息行**（例：被 resume 重放的工具答复，
今天只有帧没有行），使得产物按 spec 的三条判据成立。原来的语义一个字不改：
新 thread-id、新文件、原会话**一个字节不动**、截断点照旧。

**Blocked by:** 01（「补什么」取决于缺失行的那条写手已经修好——见 `.scratch/record-stream` 票 05 的第 1 步）

**Status:** ready-for-agent

- [ ] fork 出来的记录按 01 的判据**已重整化**（对旧格式、裸露消息、缺消息行各有一条用例）
- [ ] 原会话字节不变（既有用例仍绿）
- [ ] 重整化本身是**可重放**的：对一份已重整化的记录再 fork 一次，产物与它逐字相同（幂等）
- [ ] 缺的那一行与 `.scratch/record-stream` 票 05 的修法**共用同一处写手逻辑**，不许两套
