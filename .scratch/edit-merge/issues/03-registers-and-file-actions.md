# 03 — 寄存器与文件级动作：`CUT` / paste / `REM` / `MV`

**What to build:** 载荷里多出「搬」这件事。一段代码可以从一个文件剪下、贴到另一个文件：

```text
[src/harness/cap/hashline/old.clj]
CUT a3f9..b1c2 @fn

[src/harness/cap/hashline/new.clj]
PUT <k7m2 @fn
```

外加两个文件级动作：`REM`（删掉本段的文件）与 `MV DEST`（本段编辑完之后改名/移动）。

**Blocked by:** 02（多段：一次调用改多个文件，围栏看得见段头）

**Status:** ready-for-agent

## 为什么需要寄存器

没有它 `CUT` 就没有去处，「把一个函数挪到另一个文件」在今天只能是**读出来 → 写过去 → 删原地**：
三次调用、三段上下文，而中间那一次还有可能写歪。omp 的答案是有**寄存器**：
`CUT a..b @name` 剪下并记名，`PUT <a @name` 在别处贴上去；换成 `MV` 则是整个文件搬家。

**寄存器是本特征唯一新增的会话状态**，所以它的归属要按 `.scratch/immutable-data/` 那节纪律写清楚：
**按会话分家、进程内存、读写都在同一个 `swap!` 里**（与 `kernel.tools` 的 overlay 同一立场）。

## 要做的事

- **动词照 omp 拼**（地址换成锚点）：
  - `CUT a3f9..b1c2` / `CUT a3f9`：删除并捕获（区间或单行），可带 `@name`
  - `PUT <a3f9` / `PUT >a3f9` / `PUT >$`（**没有冒号**）：把寄存器贴进一个缝
  - `PUT <a3f9 @name` / `PUT >a3f9 @name` / `PUT >$ @name`：贴一个具名寄存器
  - `PUT a3f9..b1c2 @name`：用寄存器**替换**一个区间（span/block 的 paste **必须**具名）
  - `REM`：删掉本段的文件
  - `MV DEST`：本段的编辑落盘之后改名/移动（含空格的路径要能被引号包住）
- **两条寄存器规矩照抄**：**匿名**寄存器是**批内**的（每次调用开始是空的）；
  **具名**寄存器**活在会话里**，而且**只在它的写成功之后才发布**——一次失败的载荷不许留下
  半个搬运（这条与票 02 的 fail-fast 是同一条纪律的两面）。**重复 paste 不消耗**寄存器。
- **名字字符集**：ASCII 字母、数字、`_`、`-`；不在这张表里的名字**指名拒绝**。
- **`REM` / `MV` 过围栏**：它们的路径来自段头，票 02 的 derivation 已经覆盖；本票要断言
  **它们真的被判**（一条越界的 `REM` 必须 park，不是删了再说）。
- **冲突与目的地校验**：`MV` 的目的地非法/已存在/是本段的父目录 → 指名拒绝；
  `REM` 与同段其它动作冲突（删了又改）→ 指名拒绝。
- **`undo_last_replace` 的边界**（本票只需确认，不改）：`REM` / `MV` **不进**撤销记录——
  撤销的单位是「一次 `replace` / `insert` 的文本」，删文件与改名不在其中；这条写成用例钉住，
  免得日后被顺手扩进去。

**跟着改的**：`edit` 的描述（动作表补全 + 一个跨文件搬的例子）、`CONTEXT.md` 立「寄存器」这个词、
`kernel.md` 的编辑那节。

## 不要做的事

- 不做 `N*` 的块形态（spec 决策 3），不做 `ast-edit` 那套 staged 审批流。
- 不给 `REM` / `MV` 加新的审批类型（spec 非目标）：它们与 `write` 同类，围栏照旧。
- 不许具名寄存器跨会话可见（按 `thread-id` 分家），不许它跨重启存活（进程内存，与 parked 记录同命）。

## 验收

- [ ] **跨文件搬**：`CUT a..b @fn` 在一个文件、`PUT <a9 @fn` 在另一个文件 → 两个文件都对，
      且剪下的那段内容**逐字节**出现在目的地
- [ ] **具名寄存器活在会话里**：同一次搬运之后的**第二次** `edit` 调用仍能 paste 同一个寄存器
      （它没被消耗）
- [ ] **匿名寄存器只活在批内**：一次调用里 `CUT` 然后 `PUT` 缝上成功；**下一次**调用里无名 paste
      得到指名拒绝（说清「一次调用开始它是空的」）
- [ ] **写成功才发布**：一次载荷里前一段 `CUT @fn`、后一段畸形 → 全都不落盘，且**寄存器里没有
      `fn`**（再 paste 得到未知寄存器）
- [ ] `REM`：文件真的没了；**越界的 `REM` park**（用例断言 `parked-for-call` 有记录，文件还在）
- [ ] `MV`：改名/移动真的发生（含带空格的路径）；目的地已存在 / 非法 → 指名拒绝且**原文件没动**
- [ ] 未知寄存器名、名字里有非法字符 → 各一条指名话术
- [ ] 撤销的边界被钉住：`REM` / `MV` 之后 `undo_last_replace` 的行为有用例说明它不覆盖这两个动作
- [ ] `timeout 900 clojure -M:test -m harness.test-runner` 通过，失败**用例名**与基线一致
