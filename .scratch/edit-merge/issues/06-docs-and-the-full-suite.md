# 06 — 收口：词、文档与全量验证

**What to build:** 「编辑只剩一个名字、它的载荷是一门语言、两个模式共用它」这件事在**现状文档**里
说得清，且全仓没有旧名字的残渣。

**Blocked by:** 05（守卫与拒绝词汇）——五张票落完才有一份完整的现状可以描述。

**Status:** ready-for-agent

## 要动的四处，和各自为什么

### `CONTEXT.md`（词）

- **立「补丁 / 载荷」**：一次 `edit` 的那段文本，以及它由**段**与**动作**组成。
  要写清它不是 diff（`+` 行是**最终内容**，不是 before/after）。
- **立「段」**：`[path]` 那一行所辖的范围——**一个段一个文件**，一次调用可以有几个段。
- **立「寄存器」**：`CUT` 的产物与 paste 的来源；**匿名**是批内、**具名**活在会话里、
  写成功才发布。*别叫成* 剪贴板 / clipboard（英文里可以，中文一律写寄存器，不然会与系统的
  剪贴板混起来）、buffer。
- **改「锚点」与「已展示行」两条**：它们今天说的是「`read` / `anchor_grep` 印出来的行算已展示」——
  入口名字没变，但要补一句**编辑入口是 `edit`**，以及「一行不动它的锚点一直是它」在载荷里同样成立。
- **改「工具名的写法」那张闭清单**：`replace` / `insert` 出、`undo_last_edit` 入。
- **改「编辑模式」那条**：它今天说的是「两种模式服务哪张表」——现在两个模式都服务 `edit`，
  差的是 `edit` 的**脸**；把这条的措辞改对。

### `docs/architecture/kernel.md`（模式表与编辑那节）

- 模式表：`edit` 进「两种模式都服务」那一列（它不再只属于 str-replace），
  两个模式各自还服务哪些名字（`anchor_grep` / `undo_last_edit`）说清。
- 「编辑」那一节要能回答：**一个名字、两副脸、一段语言**，以及「所有段先解析再落盘」的语义。
- 围栏那节补一句：载荷里的路径同样被判，**任一段越界 park 整条调用**（park 的粒度是调用）。

### `docs/architecture/` 的两页与模块地图

- `hashline` 那一页（讲锚点实现的那页）里，凡是把工具名当锚点的地方都要改成新入口。
- `client.md` 的两张表（`TOOL_ICONS` / `subjectOf`）写的是**当前认识哪些名字**——跟着改，
  并写清 `edit` 的两种脸各显示什么（锚点脸显示第一个段头）。
- `architecture.md` 的模块地图：`cap.tools` 那行的工具数与名字清单（**18 → 16**：`replace` / `insert` 两个名字退休，`undo_last_replace` 是改名不计数）。

### `README.md`

- 「文件编辑的两种实现」那一节：改成「一个 `edit`、两种脸」，并把补丁语言讲一遍
  （一段例子足够），以及 `CUT` / paste 能跨文件搬代码这件事。
- 验证那节的报数换成实测（带分支与提交）。

## 不要做的事

- 不回头改 `.scratch/` 里任何旧文件（那是历史）：`hashline-edit` 的票面与 spec 尤其不动——
  **复议以加注的形式记在本特征自己的 spec 落地记录里**（spec 的「跨特征对照」已经写了怎么写）。
- 不改 `prompt.md`：它今天一个工具名都不提（锚点语法归工具描述讲），本特征维持这条分工。
- 不写新功能；本票只改文档 + 报数 + 收尾证据。
