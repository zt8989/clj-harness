# 02 — 多段：一次调用改多个文件，围栏看得见段头

**What to build:** 一个载荷可以含**多个 `[path]` 段**，一次 `edit` 调用因此能改几个文件：

```text
[src/harness/cap/tools.clj]
PUT a3f9..b1c2:
+(defn t-bash [])

[src/harness/cap/jobs.clj]
PUT >$:
+(defn reset! [])
```

**所有段先解析校验、再按序落盘**：任何一段有语法 / 锚点 / 空改动问题，**一个文件都不改**。
答案**按段**给：每段一个结果（新的锚点行、警告、以及后面的 `MV` 会说的事）。围栏（park）
看得见每一段的路径。

**Blocked by:** 01（载荷与 `PUT` 四形：锚点模式的编辑只剩一个名字）

**Status:** ready-for-agent

## 为什么

1. **「同时改两个文件」今天要靠两条消息里的两个调用。** omp 的载荷天生多段。合并之后，
   一个调用一次改多处，模型的轮次少一半。
2. **fail-fast 是照抄的语义**（omp 明说：每一段先解析、先准备，任何语法/锚点/空改动问题都
   早失败；文件随后按序写）。本仓今天没有这个概念——一次调用只碰一个文件，所以「全有或全无」
   是白送的。
3. **围栏必须跟着走。** 今天 `replace` / `insert` 的 `:park-reason` 靠一条 derivation 从**锚点**
   反推文件（`fenced-path`）；载荷进来之后文件由**段头**给出，所以 derivation 要多一条
   「从段头取路径」。这条不做，`edit` 就成了绕过围栏的一条缝——**这是本特征最容易出漏洞的地方**。

## 要做的事

- **段头**：`[path]`，一行一段，路径可以是相对（按会话的项目目录重根，与文件工具一致）；
  同一段落里重复的段头**合并**（omp 就这么做：同一文件的段合起来，原始锚点一起适用），
  合并的顺序与冲突规则要写清。
- **fail-fast**：全部段解析 + 全部锚点校验都在**任何写之前**完成；通过之后按段序落盘；
  OS 写失败**可能**留下已落盘的前缀——这条**明说**在描述与文档里，不假装原子。
- **答案按段**：每段一节，含新锚点行（供下一次编辑直接用）；一段失败时，答案是**所有段**的
  诊断，且一个字节都没落盘。
- **围栏的 derivation 从段头取路径**：纯函数、畸形答 nil（与今天 `fenced-path` 逐字同一立场）。
  **本仓 park 的粒度是调用**：一个载荷里**任一段**越界就 park **整条调用**——不是只拒那一段。
  理由：park 是把决定交给人的一次中断，半条执行的载荷没法向人解释「哪一半没跑」；这条要写进
  spec 的落地记录与文档。
- **UI 不用再改**（票 01 已经让 `subjectOf` 读第一个段头）。

**跟着改的**：`cap.tools` 里 `edit` 的描述（多段与 fail-fast 的语义、给一个两段的例子）、
`docs/architecture` 里讲围栏的那一节（park 的粒度与载荷路径）、`CONTEXT.md` 的围栏词条。

## 不要做的事

- 不做寄存器 / `REM` / `MV`（票 03）。**但段头解析要为 `REM` 与 `MV` 留好位置**：它们同样
  在段里，围栏的判据同样来自段头——票 03 只是把动词接上。
- 不做到「跨文件搬代码」那种需要寄存器的事。
- 不改批计划器的语义（票 01 已把它改认 `edit`）；本票只是让一条调用能装下多文件。

## 验收

- [ ] 一次调用改**两个文件**：载荷三段、两个 `[path]`，两个文件的内容都对了，答案是**分段**的
      （每段带自己的新锚点行）
- [ ] **fail fast**：三段里第二段的锚点未知（或 body 空、或区间逆序）→ 三个文件**一个都没改**
      （逐字节比对调用前后的文件），答案指名说第二段错在哪
- [ ] 同一文件的两个段被合并、锚点一起适用（顺序与合并规则有用例）
- [ ] **围栏**：任一文件的路径解析到项目目录与配置家之外 → 这条调用 **park**（用
      `tools/run!` + `parked-for-call` 断言之，与该能力的现有围栏用例同一套手法）；
      未绑定项目的会话**照旧放行**（回归保证）
- [ ] 相对路径按会话项目目录重根（与该会话里 `read` 的解析结果一致）
- [ ] 载荷畸形（段头缺 `]`、路径为空）时**围栏不炸**：derivation 答 nil，参数检查那一行给出
      **有用的话术**（这条直接照着 `fenced-path` 的现有用例写）
- [ ] `timeout 900 clojure -M:test -m harness.test-runner` 通过，失败**用例名**与基线一致
