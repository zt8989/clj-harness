# 02 — 夹具建一次、拷多次（40 → 8 个进程）

**What to build:** `scratch-repo` 一次起 **8 个** git 进程（`init` + 3 条 `config` + `add` +
`commit` + `branch -m main` + `branch side`），而 5 个用例各建一个新仓库 = **40 次**。改成
`use-fixtures :once` 建**一个**模板仓库，每个用例 `cp -r` 一份：纯文件操作、**0 spawn**，而拷过去
的仍然是一个真仓库。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

## 要落地的判断

1. **模板由真 git 建。** 不是把一份预制的 `.git` 塞进目录 —— 那会把「这些断言是在一个**真 git 建的**
   仓库上读回来的」这个前提换掉，而那是整个测试文件的立场（它自己的 docstring：一个 stubbed git
   只能测出 stub）。省的是**次数**，不是**真实性**。
2. **拷贝是最强的隔离形式，所以要维持它。** 每个用例必须拿到一个干净、独立的仓库：一个用例写的
   文件不能出现在下一个用例的目录里。`cp -r` 比 `git clean -fdx` 可靠 —— 后者要信任 git 的状态，
   而这里有三个用例是**故意把仓库弄脏**的（一条未跟踪文件、一条已改未提交、还有一条为了让分支
   真的分开而多提交一次）。**不许**改成「一个共享仓库、用例之间互相清理」。
3. **落在本仓的临时目录纪律里**：模板放在 `support/temp-dir` 给出的那个**每进程唯一**的根下面，
   跟今天 `dir` 的用法一样，别自己拼 `java.io.tmpdir`（`docs/rules/testing.md`）。
4. **拷贝过来的仓库里不要假设绝对路径。** 今天 fixture 设的三条 config 都是仓库级的
   （`user.email` / `user.name` / `commit.gpgsign`），拷过去仍然对；`.git` 内部没有写死的工作树路径。
   别引入 `core.worktree` 之类会把绝对路径写进去的东西。
5. **那 5 次 `scratch-repo` 的调用点不搬家**：用例仍然要（在概念上）拿到「一个新仓库」，只是这次
   它是拷来的。用例的正文与断言**一条不改**。
6. **模板仓库随临时根一起删掉**，不用另写清理。

## 验收

- [ ] **进程数**：夹具相关的 spawn 从 **40 → 8**（临时给 `shell/run` 装计数器，跑完还原）
- [ ] `git-test` 既有 7 个用例**一条不改**、全绿
- [ ] **用例之间不串**：专门加一条断言/用例 —— 在前一个用例的仓库里写的那个文件，在后一个用例的
      仓库目录里**不存在**（今天靠各自新建保证，改拷贝之后这条要显式钉住）
- [ ] 那条「未提交改动不冲突就不挡切换」的用例仍然真的看到**只有它自己动过的**仓库（它是这一票
      最容易被打穿的一格：共享仓库会让它悄悄变绿）
- [ ] 模板仓库跑完随临时根消失，不在 `java.io.tmpdir` 里过夜
- [ ] `git status` 在拷来的仓库里答的是拷过来的那份状态（既有那几条从仓库读回来的断言就是判据）
