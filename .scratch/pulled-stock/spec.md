# spec: 存量一律拉（而且是两次），增量仍旧推；推送缓存就是投影

**主人（2026-09-26）当场定的口径**：

> 未来我计划**所有的存量都通过拉的形式，而且是二次拉**。除了旧的折叠的形式，还有那个**新的存量**
> 也只拉折叠前的那一条；**工具还有描述**存量的点开再进行**二次拉**。**新增的话还是推送**。然后这个
> 推送缓存的话，**保留投影**——最好就是投影有的——**直接把内存里的那个增量推清理掉**。

## 背景：今天「存量」与「增量」各自的来路

ADR 0003 立的是：**存量是尾页，增量是推送，更早的历史是拉**。落地到今天，这条边界只走了一半：

| 要看的东西 | 今天怎么来 | 出处 |
|---|---|---|
| 侧栏点开一场会话 | **拉**，但拉的是**整份** AG-UI 消息表（推理、工具调用都在） | `http.clj/rebuild-post` |
| 刷新回来 | **拉**（`sofar` + 尾页 `page`） | `http.clj/sofar-get`、`page-get` |
| 往前翻 | **拉**（按 `beforeSeq` 补页） | `http.clj/page-get` |
| 一场 run 的 AG-UI 帧 | **推**；断线的缺口由 `mux/runs`（4096 条）重放 | `mux.clj/record-run!`、`http.clj/mux-broadcast!` |
| turn/model 事实 | **推**；缺口由 `mux/facts`（1024 条）重放 | `mux.clj/record-fact!`、`http.clj/family-send!` |
| 窗口增量 | **推**（`window` / `append` 帧） | `http.clj/mux-watch!` |
| 轨迹 | **拉一次**（NDJSON），持有时之后**推** | `http.clj/trajectory-get`、`.scratch/session-as-kernel` 票 13 |
| 一轮的折叠 | **客户端渲染层**——数据全在手里，只是不画 | `ui/src/lib/turns.ts`、`components/turn-steps.tsx` |

`.scratch/cheap-session-load/spec.md` 已经立过「折叠从渲染层挪到读层」这一案（票 01–05 **全部还没落地**，
五张票都是 `ready-for-agent`）。本特征**不推翻它**，而是把它的道理扩成一条通则：折的不该只有「打开会话」
那一处——**一切存量都折、都两次拉**。

## 决策

1. **存量 = 拉，而且分两次。** 第一次拉答**投影的形状**（折好的那一层：一轮一条 / 一个工具一条）；
   点开某一处，才**第二次拉**它下面那一层的原始 entries。寻址用那一处自己的 `seq` 区间。
   ADR 0003 决策 4 的原话是「更早的历史是拉，不是推」——本特征把「更早」换成**一切存量**。
2. **旧的折叠形式保留，而且从渲染层落到读层。** 会话的一轮今天由 `ui/src/lib/turns.ts` 在客户端折
   （`thread.aui.tsx` 只是不画步骤）。改成服务端投影折：第一次拉只给**折好的轮 + 最后一轮原样**，
   步骤根本不进载荷，点开才拉回来。这一条与 `.scratch/cheap-session-load` 的票 01 / 03 / 04 是
   **同一件 work**，不另立第二套规则。
3. **新的存量（轨迹）也只拉「折叠后的那一条」。** `.scratch/session-as-kernel` 票 13 让轨迹成为会话的
   一个视图：一次读之后由写流**增量推**。改为：轨迹第一次拉**每轮只答折叠后的那一条**（不带它下面的
   步骤），点开某一轮再第二次拉那一轮的原始 entries；`GET …/trajectory` 不再是一条长连接。
   **（待主人确认：这里的「新的存量」指的就是轨迹那一处。）**
4. **工具与它的描述是同一件事。** 一步工具行的文字是 `名字 · 摘要`（`.scratch/flat-step-rows` 的摘要
   投影表，闭表）。第一次拉只给这一行（名字 + 描述那一行字）；点开工具卡再第二次拉它的参数与结果。
5. **增量仍旧推。** 正在发生的事（run 帧、turn/model 事实、窗口 append）照旧走 `events.mux`
   （ADR 0004）。拉管**存量**，推管**增量**——这条边界一个字不动。
6. **推送缓存就是投影，不再攒原始增量。** `harness.edge.mux` 今天为每场会话在内存里留两份**原始增量**
   ——`runs`（4096 条 run 帧）与 `facts`（1024 条事实）——专供断线的人「把缺的那一截要回去」。既然存量
   是拉的，断档重连就不该重放增量，而应**拉一次投影**（第一次拉）对齐；这两个缓冲随之退场，客户端也不再
   声明 `runSince` / `factSince`。**（待主人确认：「推送缓存」指的就是这两个缓冲。）**

## 待主人拍的

- **决策 3 的「新的存量」= 轨迹？** 还是另指一处（`sofar` 的内存分支 / compaction 摘要 / 别的）。
- **决策 6 的「推送缓存」= `harness.edge.mux` 的 `runs` / `facts` 两个内存 atom？** 还是客户端的窗口
  副本（`app.tsx/useWindowFeed` 的 `held`）？
- **`.scratch/cheap-session-load` 的 01–05 是前置（照旧留在那份目录）还是并进本特征重切？**

## 非目标

- **不改记录格式、不动写侧。** 65 MB 还在盘上，本特征只保证它不再被整份传输、整份解析。
- **不改 ADR 0004 的下行载体**：仍是 `events.mux` / `events.host` 两条 socket，只是不再替**存量**兜底。
- **不改窗口 / 游标代数**（ADR 0003 决策 1–9），除非某一条被这里点名取代（决策 6 动的是 `mux` 的
  内存缓冲，不是窗口代数）。
- **不给「第一次拉」加缓存层。** 投影是纯的、现算的；加一层缓存就是又一份会比记录旧的东西。

## 验收主线

1. 侧栏点开一场 65 MB 会话：载荷 ≈ **每轮一张卡 + 最后一轮原样**，没有一步推理、一次工具调用。
2. 点开某一轮：**多一次请求**取回它的原始 entries，与直读整份得到的那一轮**逐字节一致**。
3. 点开某个工具卡：**多一次请求**取回它的参数与结果。
4. 轨迹栏：切过去**第一次拉**只有每轮一行；点开某轮拉它的原始；切走之后**没有长连接**。
5. 断线重连在一场 run 中途：**没有**增量重放，客户端拉一次投影 / 尾页对齐。
6. `harness.edge.mux` 里不再有 `runs` / `facts` 两个 atom（`rg` 得到零），客户端不再发 `runSince` /
   `factSince`。
7. 后端全量 + `cd ui && npm test` / `typecheck` / `build` + 一次真浏览器走查。
