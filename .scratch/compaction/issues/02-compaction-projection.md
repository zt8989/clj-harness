# 02 — 压缩投影：模型读摘要，人读原文

**What to build:** 记录里记下一次压缩之后，**只有模型视图**被改变。被遮蔽的那些消息从模型视图里去
掉，一条摘要消息顶在它们**原来的位置上**（遮蔽段的最前面，旧内容在前、保留的尾部在后）；**会话投影
与轨迹一个字不动**——人翻得到全部原文，遥测还算得出原始用量；记录**一行不删**。这是第 6 章那句
「一份日志，多个读法」的兑现，也是这一章「记录继续变长、投影变短」两个相反方向的落点。

遮蔽的**权威清单**是逐条列出的那批（按位置顺序），不是两个端点：第二次压缩时端点会翻转（摘要节点的
持久 seq 很大，却坐在很前面的位置），拿两个数去做大小比较必错。记账形状（示意，实现随本仓既有事实
行的写法）：

```clojure
{:kind "compaction/summary"
 :shadowed   [2 3 4]        ; 权威：逐条、按位置顺序
 :range      {:start 2 :end 4} ; 只是两个端点的名字，不是数值区间
 :tokens     12345
 :summary    "…"}
```

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

- [ ] 给一份带压缩记账的记录：模型视图 = 摘要消息 + 未被遮蔽的消息；被遮蔽的原消息**不出现**在模型视图里
- [ ] 摘要消息落在被遮蔽段的**最前面**（旧内容在前，逐字保留的尾部在后）
- [ ] **会话投影与轨迹**对同一条记录**不含**摘要、仍含全部原消息——只有模型可见的那一份变短
- [ ] 记录文件**一个字没改**（对同一场会话压缩前后逐字符比对）
- [ ] 只遮蔽一个节点时同样正确（此时端点比较与位置比较恰好还能对上，测试要说出这一点）
- [ ] 连续两次压缩：第二次的遮蔽段包含第一次写下的摘要节点（位置在前、seq 更大）；遍历与比较一律按
      **位置**，有测试专门覆盖端点翻转（第二次 `start > end`）
- [ ] 遮蔽清单为空的压缩记录不改变模型视图
- [ ] 一条记录里多次压缩可叠加：模型视图最终只留最后一次摘要 + 各次保留的尾部，且顺序与位置一致
- [ ] 离线全量 `harness.test-runner` 全绿
