# 02 — Models 页只列有密钥的厂商

**What to build:** 设置 → Models 列出的，是**这个家有一把钥匙指向**的厂商。没有密钥的厂商默认不
出现——一家必然 401 的厂商摆在清单上，就是把人往一次注定失败的 run 上领。它们没有消失：
一句可展开的话交代「还有 N 家没有密钥」，点开仍是今天那行、能进去补一行 key。

「有密钥」用服务端已经随目录一起回来的那个事实（`present?`），**不分来源**：`.env` 里那行算，
真实环境变量也算（顺序仍是 `.env` 优先，这件事已经有唯一的答案，这里不另立一套）。
那个事实**不带值**，页面上也不出现任何密钥值。

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

- [ ] 有密钥的厂商默认列出，顺序与今天一致（按 id 排）。
- [ ] 没有密钥的厂商默认不在那一段里；有一句话说明它们为什么不在（有几家）、以及怎么让它们出现。
- [ ] 那句话可以展开：展开后仍是今天那行——点得进去、能补 key、能保存。
- [ ] 补上 key 保存后，这家厂商回到默认那一段（写后重读那条既有刷新就够，不新增第二套刷新）。
- [ ] 一个家一家密钥都没有时，页面不是空白：那句话本身就是内容，「添加提供方」仍然在、仍然点得动。
- [ ] 展开/收起是**版面**行为，不是取数行为：切来切去不发新请求、不丢已经在编的那份草稿。
- [ ] 新句子进 settings 目录，两种语言都有；`cd ui && npm run typecheck` 0 error、`npm test` 套件数不变。
- [ ] 真机走查一张截图：默认态（只有有密钥的那几家）与展开态（没有密钥的那几家也在、点得进去）。
