# 03 — 模型选择器只上有密钥的厂商的模型

**What to build:** composer 的模型选择器只列出**有密钥**的厂商的模型；分组标题仍然是厂商。
本会话此刻正被服务的模型/厂商即便没有密钥也照旧画得出来（沿用「不在模型目录里」那种画法）——
把正在用的东西从菜单里抹掉，是比多列一家更大的谎。

这条规则与 02 是同一条，落在另一个面：厂商被展示 ⟺ 这个家有一把钥匙指向它。
选择器今天读的是另一个端点，所以那个事实要先随它一起回来。**只带事实，不带值**：
回答里任何深度都不出现密钥值，既有断言照旧。

**Blocked by:** None — can start immediately.（与 02 共用一条规则，但没有代码依赖。）

**Status:** ready-for-agent

- [ ] 选择器读的那个端点，每个厂商带上「有没有密钥」这一件事；应答里任何深度都没有密钥值
      （既有那几条断言逐条不变）。
- [ ] 选择器里只出现有密钥的厂商的模型；分组标题仍是厂商（有显示名就显示名，否则 id）。
- [ ] 本会话此刻的模型/厂商即便没有密钥也画得出来，并且**看得出来**它为什么不合群
      （沿用既有那句「不在模型目录里」的表达，不新增第二种画法）。
- [ ] 一家有密钥的都没有时，选择器不是空的：当前那一条仍在，仍然选得中/显示得对。
- [ ] 搜索仍然同时匹配厂商标题与模型 id（既有行为不变）。
- [ ] 新句子进 composer 目录，两种语言都有；`cd ui && npm run typecheck` 0 error、`npm test` 套件数不变。
- [ ] 真机走查一张截图：菜单里只有有密钥那家的模型；当前无密钥那条在列表顶上标着。
