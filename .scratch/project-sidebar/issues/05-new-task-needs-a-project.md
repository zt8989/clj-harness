# 05 — 新建任务必须先有项目（含「添加项目」）

**What to build:** 点「新建任务」时，界面**不问废话也不假装能开**：已经选中某个项目就直接在该项目下开一个
新会话并切过去；一个项目都没有时说的是"先添加一个项目"并当场给出添加入口。

添加项目有两条填法：服务端的**原生目录对话框**（复用 `POST /api/project/pick`，选中的路径只填进输入框，
仍需显式提交才建项目）与**手输绝对路径**。assistant-ui 07 的行为契约搬到本票，那条票已置 `wontfix`。

**Blocked by:** 04

**Status:** ready-for-agent

- [ ] 有项目时：新建任务直接落在当前项目下，新会话出现在该项目下并成为当前会话
- [ ] 没有项目时：按钮不进入"能开"的假状态，说的是"先添加一个项目"+ 添加入口就地在旁边
- [ ] 添加项目：手输绝对路径能建；服务端返回的绝对路径回填显示，成功与失败都就地给反馈
- [ ] 添加项目：「选择文件夹…」走服务端的原生目录对话框；选中路径只填字段，**人来显式提交才建项目**
      （选文件夹不是一步到位的绑定，这条与 assistant-ui 07 的判断一致）
- [ ] 用户取消选择 → 说的是"已取消选择"，不是错误
- [ ] 校验失败（目录不存在 / 不是目录）→ 把服务端的原因显示出来，不假装成功
- [ ] 添加一个**已经在列表里的**目录 → 归并到已有项目并切到它，不产生第二行（与 02 的 find-or-create 一致）
- [ ] 请求进行中，两种填法的提交按钮都禁用，避免连点造成两次写入
- [ ] 新建会话在**没有任何一轮 run** 之前也是可见的（它已经在库里），但它的日志文件此时还不存在——
      列表要能显示这种"还没有日志的会话"，不报错、不显示成 0 字节的假文件
- [ ] 真 Chromium：两条填法各一次 + 取消一次 + 无项目时的空态一次，截图留档
