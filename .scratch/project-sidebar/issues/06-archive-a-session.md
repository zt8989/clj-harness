# 06 — 会话的归档与取消归档

**What to build:** 每个会话行有一个「归档」动作。归档的会话从项目下移出，落进该项目底部默认折叠的
「已归档」分组；展开后能取消归档，把它放回项目下。**jsonl 一个字节不动**——归档是库里那一行的状态，
不是删除。进程重启后归档状态还在，因为它在库里。

**Blocked by:** 04

**Status:** ready-for-agent

- [ ] 归档：行从项目下移出，出现在该项目的「已归档」分组里
- [ ] 「已归档」默认折叠；展开后每一行能取消归档，取消后回到项目下的正常列表
- [ ] 归档**不碰文件**：归档前后 jsonl 的字节数与 mtime 逐字相等（用例直接断言这两个数）
- [ ] 重启进程后归档状态仍在（内存清掉、只留磁盘）
- [ ] 归档**当前会话**：允许，并自动切到该项目下最近活动的未归档会话；该项目下没有别的会话时落到
      "新建任务"的空态。**不允许留下一个指着已归档会话的当前态**——那是界面上最容易被忽略的一类错状态
- [ ] 一个项目的归档分组为空时不出现（不是显示一个空的"已归档"标题）
- [ ] 取消归档一个**别的项目**下的会话不会串项目（用例两条：A 项目归档、B 项目取消）
- [ ] 归档动作在请求进行中禁用，失败时把服务端的原因显示在那一行
- [ ] 真 Chromium：归档 → 折叠组出现 → 展开 → 取消归档 → 行回来，截图留档
