# 02 — 项目与会话成为持久的一等行

**What to build:** 在动界面之前，先让"项目"这个词在服务端有实体：**一个项目 = 一个绝对目录**；
**一个会话 = 一个 thread id，属于恰好一个项目（或不属于任何项目）**。今天那个 thread-id → 目录的内存
atom 换成库里的行，`harness.project` 的对外契约一个字不变——未绑定仍然是 `nil`、仍然不是错误、工具侧
「未绑定 = 恒等」的回归保证原样成立——差别只在下一次进程启动之后，绑定还在。

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] `projects` 表：id、绝对路径（唯一）、创建时间；`sessions` 表：thread id（主键）、项目 id（可空）、
      归档标记、创建时间
- [ ] **`sessions` 表里没有任何消息内容**：它记的是"哪个会话、属于谁、归档没有"，不是会话说了什么。
      一条元断言钉住列清单——消息属于那个 jsonl 文件，把它镜像进库就等于在库里造一份会腐烂的第二真相
- [ ] 同一个目录被绑定两次 → 拿到**同一个**项目 id，库里不产生第二行
- [ ] 路径的记账用**解析后的真实路径**：同一目录经不同写法（相对路径、带 `..`、符号链接）访问时归到
      同一个项目，不出现"同一个目录两个项目"
- [ ] `bind!` 的三种结果与今天逐字一致：成功返回绝对路径、`dir` 为 nil 时解绑、目录不存在或不是目录
      各自是原来那句点名错误
- [ ] 解绑一个会话只清它的项目归属，**不动项目行**（项目还在，只是下面没有它会话）
- [ ] **重启仍可答**：清掉内存、只留磁盘，重启进程后绑定的目录还答得出来——这是本票存在的理由，要有
      端到端用例（不是单元测试里换个 atom 的那种）
- [ ] 同一目录下的两个会话互不干扰：归档一个不影响另一个，解绑一个不影响另一个
- [ ] 并发：两个线程同时把不同会话绑到不同目录，两笔都在，不互相丢写
- [ ] 既有的 project / approval / tools 断言全绿，**一条不改**——这是本票的回归保证，改了就是契约变了
- [ ] `clojure -M:test` 全绿

**给 03 的地基：** 会话的项目归属现在问得出来，日志的落点因此可以按它算。
