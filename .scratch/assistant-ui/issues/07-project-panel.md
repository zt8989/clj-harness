# 07 — 项目目录面板：这个会话被绑在哪

**What to build:** 聊天上方的那一行回到位：当前会话绑定的项目目录是什么，以及绑定它的两种办法——手输
绝对路径、或让**服务端那台机器**弹出原生目录对话框选一个。没绑定与会话还没开始是两句不同的话，不能
混成一句「未绑定」。

绑定的路由只有一条（一个写操作），两种填法都只是「把路径填进那个框再提交」，所以「选文件夹…」不会
直接改绑定——它只负责填字段，人来确认。

**Blocked by:** 03

**Status:** ready-for-agent

- [ ] 显示当前会话绑定的项目目录绝对路径；会话还没开始（没有 threadId）时说的是「会话开始后可绑定」，
      不是「未绑定」
- [ ] 已开始但没绑定，说的是「未绑定」并说明相对路径按进程工作目录解析
- [ ] 手输绝对路径能绑定；服务端返回的绝对路径回填显示，成功与失败都就地给反馈
- [ ] 「选择文件夹…」走服务端的原生目录对话框，选中的路径只填进输入框；人选完仍需显式提交才改绑定
- [ ] 用户取消选择时说的是「已取消选择」，不是错误
- [ ] 校验失败（目录不存在等）把服务端的原因显示出来，不假装成功
- [ ] 会话换成另一个 threadId（新建会话、或恢复一个旧会话）时重新读取该会话的绑定，不沿用上一个
- [ ] 面板的两种按钮在请求进行中禁用，避免连点造成两次写入
- [ ] 用 Tailwind 写，与抄来的组件同一套类名习惯；不引第二套样式体系，也不为了对齐而改上游组件
- [ ] 位置与视觉与今天对位。官方 `Thread` 自带全高布局（根节点就是 `h-full`），面板要放在它上方而不被它
      抢走高度——这是本票唯一需要当心的布局问题，验收时窗口拉高拉矮各看一次
- [ ] 真 Chromium 验收：绑定 / 读回绑定 / 选文件夹（含取消）三条路各一次，截图留档
