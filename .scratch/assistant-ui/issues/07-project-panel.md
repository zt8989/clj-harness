# 07 — 项目目录面板：这个会话被绑在哪

**Status: wontfix（2026-09-15）** — 被 `.scratch/project-sidebar` 取代，见那份 spec 的决策 7。

**为什么不是「延后」而是「作废」。** 本票要的是「聊天**上方**一条项目目录面板，会话跑起来之后可绑定」；
`project-sidebar` 把项目搬进**侧边栏**，把绑定挪到**建会话时**（新建任务必须先有项目）。两条形状不相容，
照本票做完会立刻被拆掉。

**票面里对的东西已经搬走了，不是丢了：**

- 三种填法（手输绝对路径、原生目录对话框、取消不是错误）与「请求进行中禁用」→ `project-sidebar` 05；
- 「会话换成另一个 threadId 时重新读取绑定」这条前提本身消失了：一个会话的项目在建它的时候就定了，
  不再是"跑起来之后才绑"的独立状态；
- 「官方 `Thread` 根是 `h-full`，面板别抢它的高度」这条布局接点 → 继续有效，落在 `project-sidebar` 04。

**底层没白做。** 本票要用的三条路由（`GET/POST /api/project`、`POST /api/project/pick`）**已经在
`harness.http` 里实现并通过验收**，`project-sidebar` 05 直接复用，不改一条。

## （原票面，留作记录）

**What to build:** 聊天上方的那一行回到位：当前会话绑定的项目目录是什么，以及绑定它的两种办法——手输
绝对路径、或让**服务端那台机器**弹出原生目录对话框选一个。没绑定与会话还没开始是两句不同的话，不能
混成一句「未绑定」。

绑定的路由只有一条（一个写操作），两种填法都只是「把路径填进那个框再提交」，所以「选文件夹…」不会
直接改绑定——它只负责填字段，人来确认。

**Blocked by:** 03

**Status:** wontfix
