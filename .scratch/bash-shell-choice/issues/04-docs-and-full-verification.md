## 要落地的判断

1. **`CONTEXT.md` 只加该加的那一句。** 运行时状态那一带今天写着「作业 = 进程内存，命令的记录 =
   文件」；本特征要说的是「一次调用跑在哪只壳里由调用指名，默认是本机解析出来的那只」——
   **一句**。词条不长篇解释参数。
2. **`docs/architecture/kernel.md` 的 shell 那一节要提到这张表**（`how-to-start` 的 kind → argv），
   以及在它上面多了一层「按 kind 解析」。理由与位置都写在 `shell.clj` 自己的 docstring 里，
   文档这一层只指路，不抄第二份。
3. **工具描述的最终一遍**：票 02 写的那段，与 `stdin` / `workdir` / `timeout` / `run_in_background`
   四段放在一起读一遍，确认「哪句讲哪种壳」不会互相打架（尤其后台那段：`timeout` 不适用、
   `stdin` 被拒，与壳无关）。
4. **两套全量报数是判据，不是装饰**：改前（`main` @ 立票时的那个提交）与改后各一次，**比失败名单**，
   不只比绿不绿 —— 本仓的纪律就是「比失败名单，不只比绿不绿」（`.scratch/tool-parity/spec.md`
   记过这条的来历）。测试数与断言数的变化要能逐条解释（本特征新增的用例）。
5. **`-lc` 一个字不动**（6652097），这一票也不许顺手改。文档里若要提启动成本，只说结论、不重开
   那个实验。
6. **落地记录写进 `spec.md` 的「状态」一节**，按本仓约定：票面本身在交付后**删除**，记录只活在
   `git log` 与 spec 里。
7. **WSL 那一段不许被顺手删掉**：spec 的「非目标」里记着 `wsl-launcher?` docstring 那条理由已经
   不成立的实测（exit=0、输出正确、冷启动 ~14s）。本期不做，但那个发现要留着，别让它随着文件整理
   一起消失。
