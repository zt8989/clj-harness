# 01 — 比较的缝与那份记忆

**What to build:** 进程里按 thread 记一份**上一轮送出时的指令签名与那份 system 文本**。签名**不是组装后的
文本**，而是两个廉价的 name hash：

- **hooks 的名字集合**：SystemPrompt 点上参与组装的 hook 身份（名字 + 来源 + 顺序）；
- **tools 的名字集合**：该 thread 有效工具表的**工具名**集合（`<tools>` 块只报集合、不复制描述，
  见 `.scratch/system-prompt-blocks` 决策 6）。

每次 run **先算这两个 hash 比一次**：一样 ⇒ 复用上一轮那份 system 文本，**hooks 一个都不跑**；不一样 ⇒
报「变了」、重建 system prompt（跑 hooks、拼文本），怎么送是 02/03 的事。

**为什么不是文本**：比文本要求每轮把 hooks 跑一遍、把 system 消息拼出来再 diff——正是「每 run 现算」那笔
开销，而 hooks 可以是 shell 命令。name hash 不用跑任何 hook，从注册表与工具表直接算。

**不算的**：工具**描述**改了不管；hook 输出里与名字无关的差别不管；`prompt.md` 不参与（进程内冻结，
`reset-prompt!` 要显式作废）；project 绑定**不许动态变**（今天也不支持），所以 `<project>` 的变化不在本票里。

从用户视角：今天两个特征之间没有任何东西能说出「这次 run 的指令和上一轮不一样」这句话，这一票把它变成
一句可以问出口的话。

**Blocked by:** `.scratch/system-prompt-blocks` 票 03（跨特征：`<tools>` 块落地之后，「工具名字集合变了」
才有地方被说出来）

**Status:** ready-for-agent

## 要落地的判断

1. **家**：进程内存，按 thread-id 分家，与 `edge/http.clj:469` 的 `session-started`、`:498` 的
   `live-runs` 同一条纪律——`defonce` 一个 `atom`，一个 atom 一个事实，名字就说它装的是什么。
   **不进库、不落盘、不进进程日志**：它记的是「我刚说过什么」，不是一条事实；重启即失是特性。
2. **比较在组装之前**：先算签名；没变就**跳过** `assemble`（复用记忆里那份文本），变了才组装。
   组装的**唯一**调用处仍是 `edge/http.clj:841` 那一段——跳过与组装两种结果都从那里出去，比较跟着它，
   否则会与「实际送出去的到底是哪一份」漂开。它必须仍在 hook sink 的绑定之内（`assemble` 靠那个绑定才
   触发 `SystemPrompt` 点）。
3. **比的是两份 name hash**：hooks 的名字集合 + tools 的名字集合。不落在组装后的文本上，不算内容。
   谁的内容变了、哪一块变了，**不问**。
4. **「第一次」不是变化**：没有记忆（新 thread、重启后）⇒ 必须组装（没有可复用的文本），但**不算作一次
   「变化」**——今天的 `:replace` 行为就是第一轮的正确答案；把它报成一次变化，会在每条新会话上送一条
   毫无意义的 developer 消息。
5. **组装失败那次不留痕迹**：`assemble` 在 hook 拒绝时抛异常（run 不开始），记忆只在组装**成功之后**
   更新；抛出的那次 run **不更新记忆**——没送出去的东西不是「上一轮说过的话」。
6. **签名不含 provider / binding 档**（本项目今天也不允许中途换它们）。这条是个**要写下来的边界**：
   若哪天允许，签名要跟着加一格；现在不许有第二个主人。
7. **一个 thread 一次 run**：`live-runs` 的存在说明同一 thread 的 run 是串行的。后到的以先到的为基准，
   **不加锁**——加锁是给一个不存在的并发写答案。

## 验收

- [ ] 连着两轮什么都没改 → 签名相同、读到「没有变化」、**hooks 没有被重跑**（用例断言 hook 的副作用只发
      生一次）
- [ ] 加一个工具 / 删一个工具 → tools name hash 变 → 读到「变了」，且重建了一次
- [ ] 加一条 hook / 关掉一条 hook → hooks name hash 变 → 读到「变了」，且重建了一次
- [ ] **只改一个工具的描述** → 两份 hash 都不变 → 「没有变化」，hooks 没重跑
- [ ] 重启（或换一个 thread）后的第一轮 = 组装一次、但报「没有变化」（有用例）
- [ ] `prompt.md` 改了（`reset-prompt!`）→ 签名不变，所以要有**显式作废**的路径（本票决定并落地，
      不能让它悄悄用旧的）
- [ ] hook 在 `SystemPrompt` 点拒绝、run 没开始 → 记忆**不更新**（有用例）
- [ ] 两个 thread 互不影响（有用例）
- [ ] 记忆里没有任何东西写进 sqlite / jsonl / 进程日志（按名字检查，与既有的隔离检查同一套口吻）
