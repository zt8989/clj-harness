# 01 — 比较的缝与那份记忆

**What to build:** 进程里按 thread 记一份**当前生效的指令文本**——就是上一次送出去的
`harness.cap.system-prompt/assemble` 的输出。每次 run 组装完 system 消息之后比一次：一样就什么都不说；
不一样就报出「变了」与那份**新的全文**。这一票只回答「变了没有」，怎么送是 02 与 03 的事。

从用户视角：今天两个特征之间没有任何东西能说出「这次 run 的指令和上一轮不一样」这句话，这一票把它
变成一句可以问出口的话。

**Blocked by:** `.scratch/system-prompt-blocks` 票 03（跨特征：`<tools>` 块落地之后，「工具变了」
才有地方被说出来）

**Status:** ready-for-agent

## 要落地的判断

1. **家**：进程内存，按 thread-id 分家，与 `edge/http.clj:469` 的 `session-started`、`:498` 的
   `live-runs` 同一条纪律——`defonce` 一个 `atom`，一个 atom 一个事实，名字就说它装的是什么。
   **不进库、不落盘、不进进程日志**：它记的是「我刚说过什么」，不是一条事实；重启即失是特性。
2. **比较在哪一步**：`edge/http.clj:841` 那一次 `assemble` 的输出旁边——组装的**唯一**调用处就在
   那儿，比较必须跟着它，否则会与「实际送出去的到底是哪一份」漂开。它必须仍在 hook sink 的绑定
   之内（`assemble` 靠那个绑定才触发 `SystemPrompt` 点，`cap/system_prompt.clj:82` 的 docstring）。
3. **比的是字节，不是来源**：判断落在**组装后的文本**上，不落在各块身上。谁变了、哪一块变了，
   **不问**——问一遍就是给「谁变了」造第二个主人。
4. **「第一次」不是变化**：没有记忆（新 thread、重启后）⇒ 结果是「没有变化」，不是「全变了」。
   今天的 `:replace` 行为就是第一轮的正确答案；把它报成一次变化，会在每条新会话上送一条毫无意义
   的 developer 消息。
5. **组装失败那次不留痕迹**：`assemble` 在 hook 拒绝时抛异常（run 不开始），比较只在组装**成功**之后
   发生；抛出的那次 run **不更新记忆**——没送出去的东西不是「上一轮说过的话」。
6. **一个 thread 一次 run**：`live-runs` 的存在说明同一 thread 的 run 是串行的。后到的以先到的为
   基准，**不加锁**——加锁是给一个不存在的并发写答案。

## 验收

- [ ] 连着两轮什么都没改 → 第二轮读到「没有变化」（有用例；02 落地后体现为请求体逐字节相同）
- [ ] 一轮里 `project/bind!` 到别处 → 下一次组装读到「变了」+ 新的**全文**（用例断言全文，不是断言
      一个布尔）
- [ ] 重启（或换一个 thread）后的第一轮 = 没有变化（有用例）
- [ ] hook 在 `SystemPrompt` 点拒绝、run 没开始 → 记忆**不更新**（有用例）
- [ ] 两个 thread 互不影响（有用例）
- [ ] 记忆里没有任何东西写进 sqlite / jsonl / 进程日志（按名字检查，与既有的隔离检查同一套口吻）
