# 02 — 锚点本身：算法、归属、以及能跨重启活下来的存储

**What to build:** 一行的锚点与它内容的校验和。给定文件内容，算出每一行的锚点；给定一行的当前内容，
算出它的校验和；给定一次「删掉这几行、插入那几行」，算出哪些锚点**位置未动而保留**、哪些**释放**、
哪些**新分配**。这些答案在两台机器、两个进程上必须一致——因为它们要落盘。

**与内容无关的分配。** 锚点从一张随仓携带的表里按步长取（两位一段、4 字符、按 tokenizer 实测筛过），
不是从内容推导出来的。步长与表长互质，因此相邻行拿到的锚点落在表上毫不相干的区域；会话的起始探针由
`thread-id` 折叠而来，所以两个会话给同一个文件发的锚点是两套，互不撞车。**独占**：一个锚点属于某文件
的某一行，直到该行被改动、文件被写、或会话被清空为止。**两行内容相同也绝不共用一个锚点**——这正是
锚点方案相对 `old_string` 的核心收益。

**校验和与规范化。** 校验和算在**规范化之后**的行上：去掉所有 `\r`、去掉行尾空白（行首空白保留）、
超过 500 字节的先截断（不切开码点）。摘要取 SHA-256 前 16 个十六进制字符。这套规范化的意义在于：
编辑器存一次盘、CRLF 与 LF 互换、行尾多两个空格，都不该让模型手里的锚点失效。

**跨重启（2026-09-15 改写：从 EDN sidecar 改为共用的 sqlite）。** 落盘在 **`~/.clj-harness/harness.db`**
——home 的元数据库，由 `project-sidebar` 01 建起来并拥有迁移链；本票往那条链上加一级，占三张表：

| 表 | 内容 |
| --- | --- |
| `hashline_snapshots` | 该路径上次被服务时的整文件校验和、行数、逐行锚点、逐行校验和（主键：文件绝对路径的 sha256） |
| `hashline_undo` | 该文件最近一次 replace/insert 之前的正文、BOM、行尾、锚点、改后正文（留到 07/08 用；本票只把表建出来） |
| `hashline_sessions` | 本会话归属的事件折叠（`session` / `allocate` / `free` / `minted` / `clear`），按 thread-id 的 sha256 索引 |

**写入都在一个事务里**：推进归属与落撤销是同一件事的两半，要么都成要么都不成（07/08/09 的验收靠这条）。
"临时文件 + rename + 每份带 `:version`"那套自制设施不再需要——版本在 `user_version` 上，原子性由事务给。

损坏的处置归 `project-sidebar` 01 的库级隔离重建；本票只保证自己那三张表在重建后是空的，且**不谎报成
「锚点不存在」**：说话的是「锚点表是空的」。

- [ ] `MIT` 署名写进仓内 `NOTICE`（原项目 RimuruW / Yugimob，附来源 URL 与版本）
- [ ] 4 字符锚点的**字符类**：表里出现的都是字母；解析侧接受字母与数字（模型可能手抖写数字），
      两者都要有用例
- [ ] 内容校验和：`\r` 全去、行尾空白全去、行首空白保留、超 500 字节按 UTF-8 字节截断不切码点。
      四条规则各有用例（含一个 500 字节边界上的多字节字符）
- [ ] 归属对齐：一次编辑后，位置未动的行**锚点不变**且校验和不变；改过的行换新锚点；删掉的行锚点
      释放并可被后用；插入的行拿到新锚点。分别有用例
- [ ] 全会话内的独占性：同一锚点绝不会同时属于两行；两行内容字节相同也拿两个锚点
- [ ] 交叉会话：两个 thread-id 对同一个文件拿到**不同**的锚点集合，且 A 会话的锚点不会被 B 会话误用
- [ ] 迁移链：本票的三张表通过 `project-sidebar` 01 的迁移建成，`user_version` 只往上走一级；

      断言项目行还在）
- [ ] 快照落盘与读回：存一次、清掉内存、重新加载后逐行锚点与校验和**逐一相等**
- [ ] 重启后仍可编辑：进程重启（清内存、只读库）后，用重启前 read 得到的锚点仍能定位——这是本票
      存在的理由，要有端到端用例
- [ ] 归属与撤销在**一个事务**里推进：中途抛异常时，库里的锚点归属与撤销记录都与调用前逐行相等
- [ ] 快照按**路径**存、归属按 **thread-id** 存：两个会话读同一文件互不覆盖
- [ ] 提供一个**按路径互斥**的原语（一笔编辑的临界区要整段持有它：读 → 校验 → 写盘 → 推进归属 →
      落撤销）。本仓同一回合的多个工具调用是并发跑的（`harness.loop/drive!`），没有这把锁，
      09 的批处理断言测不出真问题——两个线程会在读到同一个基态后互相覆盖。库的隔离级别**不代替**它：
      sqlite 保证的是不写坏，不是"两笔编辑合并"
