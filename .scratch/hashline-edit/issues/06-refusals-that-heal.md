# 06 — 编辑被拒时，把「重试所需的一切」一起交回去

**What to build:** 锚点方案只有在**拒绝得有用**时才比 `old_string` 好。这一票专做被拒的那些路：
每一种拒绝都要说清「哪一行对不上」「现在是什么」以及「下一步怎么做」，而且**不需要模型再 read 一次**。

**四种拒绝，各自的下一步。**

- **锚点不属于本会话**（文件没 read 过、或 read 之后被写/被撤销清空了归属）：指名拒绝，说清这个文件
  需要先 read。文件从没被模型看过就当锚点可用，是把「猜」放进了一个号称不猜的机制里。
- **文件在 read 之后漂移了**（区间里某几行的内容校验和对不上）：拒绝，并**当场把当前区间的行连同新
  锚点回给模型**。这些新锚点同时被登记为「已展示」，所以模型拿着它们直接重试即可，**不必先 read**。
  区间很长时只回前若干行并给出继续看的 `offset`，但**重试所需的那几行一定在里面**。
- **替换内容与当前完全一致**：不写盘、保留撤销历史、说明「没有变化」——静默成功会让模型以为改成了。
- **整个文件会被清空**：拒绝并指向 `write`（与 05 同一条规则，在 05 已实现时会自然重合；本票补充
  它在**多个调用/批量**语境下的表现）。

**没有 `path` 时的兜底。** 只用锚点就够定位（锚点独占本会话的一个文件），所以 `path` 默认不必填。
但要处理「锚点确实该死」的情形：锚点在任何文件里都找不到归属时，若调用里带了 `path`，就用**改动区间
的当前文本**去那个文件里定位一次；命中唯一就照常执行并**说明是兜底命中的**，不唯一或找不到才报
「先 read」。这条兜底是给「锚点表被清空但模型手里还有一份过期锚点」准备的，不是常规路径。

**锚点必须来自「已展示」的行。** 一个锚点即使被分配给某行，只要那一行**从没出现在任何工具结果里**
（比如 read 被截断掉的部分），也不许被编辑——否则模型是在改它没看见的东西。

**Blocked by:** 05

**Status:** ready-for-agent

- [ ] 未 read 过的文件上编辑 → 指名拒绝，信息含文件路径与「先 read 该文件」
- [ ] 文件漂移 → 拒绝 + **当前区间的行带新锚点**；新锚点可用；**同一回合内直接重试成功**（端到端用例）
- [ ] 漂移区间超长时只回前 N 行 + 继续看的 `offset`，且**重试所需的那几行必然在回来的内容里**
- [ ] 漂移拒绝的信息里区分「一行对不上」与「多行对不上」，并说得出是文件的第几行到第几行
- [ ] 漂移拒绝回来的行被登记为「已展示」（与 04/05 同一套登记），因此可以直接编辑
- [ ] 内容无变化的编辑：不写盘、撤销历史保留、信息说明无变化
