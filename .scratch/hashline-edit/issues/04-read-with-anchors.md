# 04 — `read` 带锚点出行：看得见、可翻页、非文本点名拒绝

**What to build:** hashline 模式下读一个文件，回来的每一行长这样：

```
Hasu│第一行
AAAB│第二行
```

`│` 左边是 4 字符锚点，右边是本行内容。锚点就是下一票 `replace` 的定位方式——模型从此**按锚点编辑，
不按内容、也不按行号**。相对路径仍然按会话绑定重根，越界的路径仍然照旧 park 等审批（`read` 上的
`:fence-paths` 标记与 `:mode` 无关，继续生效）。

**这是覆盖，不是并存。** `read` 是同一个工具名：str-replace 模式下它今天怎么写还怎么写（模式感知归
01，本票对齐），hashline 模式下就是上面的带锚点行。用户请求的原话是「覆盖内置 read」。

**翻页与体积。** `offset`（1 起）/ `limit` 两个可选参数；超出行数或字节预算时在末尾附一行提示，直接
给出下一段的 `offset`，模型照抄即可继续。单行本身超预算时，**锚点照出**、内容换成一句提示——那一行
仍然是可编辑的，只是不能靠 read 看全。

**非文本一律点名拒绝。** 二进制、图片、UTF-16/UTF-32（有 BOM 的）、目录、超 100MB 的文件，各给一句
说得出**为什么**和**换什么办法**的信息。参考实现把图片转交给 pi 的宿主内置 read 去视觉附挂；本仓没有
那个宿主能力，所以这里是拒绝，而不是假装支持。

**Blocked by:** 02, 03

**Status:** ready-for-agent

- [ ] `path` 必填；`offset` / `limit` 可选、必须是正整数，`0`、负数、非整数各给一条指名错误
- [ ] 输出形状：一行 `锚点│内容`，无表头、无行号、无尾部空行。空文件给出一个**内容为空的锚点行**
      （那一行是可以被 `replace` 填的），再加一句提示
- [ ] `offset` 超出文件末尾时的信息说得出文件共有几行、该用哪个 `offset` 重来
- [ ] 按字节预算截断时，末尾提示含**下一段的 offset** 与截断原因（行数上限 / 字节上限）
- [ ] 单行超预算：锚点保留、内容换成提示，且**用那个锚点仍能替换整行**（本票只保证锚点可解析，
      替换行为由 05 保证——两票的用例衔接上）
- [ ] 每一行的锚点在本会话内与那个文件的归属表一致（与 02 的分配结果同源，不另算一套）
- [ ] 同一次 read 的锚点可**重复使用**：读两次同一文件（内容未变）拿到的锚点相同
- [ ] 非文本/不可读各有一条点名信息：目录、二进制、图片、UTF-16 BOM、超过 100MB 的文件
- [ ] 文件在 read 之后被外部改动时，read 重新服务并给出与新内容一致的锚点（内容变了的行换锚点）
- [ ] 相对路径按会话绑定重根；绑定会话读越界路径仍然 park 等审批——**两条都与模式无关，都要有用例**
- [ ] 工具描述（模型看的那段）说清：锚点从哪来、编辑按锚点、哪几个参数可翻页、什么时候要重读
- [ ] 离线全量 `harness.test-runner` 全绿
