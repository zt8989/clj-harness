# 05 — `replace`：按锚点改一段，改完就把下一笔要用的锚点交回手里

**What to build:** `replace` 是本特性的正身。给两个锚点（区间的首行与末行，同一行就填同一个）和一串
**新行**，这段区间就被换掉：

```
remove_from:      "AAAB"
remove_to:        "AAAE"
replacement_lines: ["新的一行", "另一行"]
```

`replacement_lines` 每元素一行，**不带 `│`、不带换行**；`[]` 是删除，`[""]` 是一行空行。真值表要写死：
`[]` 删掉区间；`["a"]` 区间换成一行 `a`；单行区间把那一行换掉；相邻插入是「区间为空 + 有内容」的写法
（锚点取同一行的首尾）。

**改完之后回给模型的东西，才是这一票的重点。** 不是一句 "edited"，是**改动区间的当前状态**——上下文
行 + 改动行，每行带当前锚点，改动行带 `+`，删掉的行带 `-`（前缀位留空以免模型把一个已经失效的锚点
当活的用），边界去重剥掉的行标 `dedup` 且**不可当锚点**。模型照着 `+` 行与空格行的锚点就能直接下下一笔
编辑，**不必重读整个文件**——这是锚点方案相对 `old_string` 最直接的收益，也是「一次编辑一次重读」这个
成本陷阱的出口。

**边界去重。** 模型很自然会写「删掉这行、再写一遍这行、后面跟新的」——那个被写回来的边界行是重复的。
`:boundary-dedup` 三态：`:on` 剥掉并提示、`:strict` 直接拒绝并说清该去掉哪几行、`:off` 照字面执行。

**警告与严格模式。** 模型手抖的几种形态是**可自动修正**的，修完告诉它修了什么：把整份 JSON 数组塞进
一个元素里、元素里嵌了 `\n`、行首抄了 `锚点│`、抄了 diff 预览的 `+`/`-` 标记、首尾锚点写反了。
`:strict-input true` 时这些一律**拒绝而不是修**——用于「宁可让它重写一遍，也不要我替它猜」。

**撤销记录在这一票里就写好。** 写盘**之前**先记录改前正文、BOM、行尾、锚点与改后正文；写入抛异常时
把记录一起退回。`write` 成功会清掉它（04 的 write 边界）。读回与撤销的行为归 07，本票只保证记录被
正确地写下与退回。
