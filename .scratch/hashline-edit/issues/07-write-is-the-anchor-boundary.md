# 07 — `write` 是锚点的边界：释放、清撤销、拒绝回显、以及改完随手能接着改

**What to build:** 一次 `write` 之后，那个文件与模型手里的锚点**没有关系了**——内容已经不是模型看过的
那一份。所以 `write` 成功时：该文件在本会话的锚点归属全部释放，撤销记录清空，`replace` / `insert`
下次必须说「先 read」。

**拒绝回显锚点的写入。** 模型从 read 输出里复制内容时，把 `锚点│` 前缀一起抄进去是**很自然**的动作。
真写进去，文件就被污染了，而且之后每一次 read 都会把 `Hasu│` 当成正文再发一遍锚点——错误会自我繁殖。
所以带锚点前缀的 content 被**拒绝**并说清是第几行的哪个锚点。这条守卫长在 `write` 的工具体里；将来
hook-engine 的 PreToolUse 落地后，它是一步机械搬迁，现在不为它预留接口。

**`auto-read`：改完随手能接着改。** `:auto-read true`（默认）时，一次成功的 `write` 之后附一段该文件
开头的带锚点读，模型因此不必为了改自己刚写下的东西再 read 一次。`:auto-read false` 时只回一句
「已写入，用 read 取锚点」。自动读失败（比如写的是非文本）不能把 write 变成失败：写成功了就是成功了，
附注说明读不回来即可。

**Blocked by:** 02, 03（`read` 的锚点渲染来自 04，因此实际落地时 04 应在先；本票的断言以
锚点归属被释放、撤销被清空、回显被拒为主）

**Status:** ready-for-agent

- [ ] 一次成功 write 后：该路径的锚点归属全部释放，之前 read 得到的锚点**全部失效**，用它们编辑得到
      的是「先 read」那条拒绝（与 06 同一条信息）
- [ ] 一次成功 write 后：该文件的撤销记录被清空
- [ ] content 的某一行以**该文件已服务的具体锚点**加 `│` 开头时，write 被拒绝，信息含行号与那个锚点。
      只以 `│` 开头、或用了别的文件的锚点，不拒（那是正文，不是回显）
- [ ] `:auto-read true`：write 的返回里含该文件开头的带锚点行，且这些锚点**立即可用于编辑**（端到端：
      write → 直接用返回里的锚点 replace，不 read）
- [ ] `:auto-read false`：返回里没有带锚点行，但明确说了用 read 取锚点
- [ ] 自动读失败时 write 仍然报告成功，另附一句说明读了什么、为什么没读到
- [ ] 被拒绝的 write **什么都没改**：文件内容、锚点归属、撤销记录三者都与调用前一致
- [ ] write 到**新文件**（之前不存在的路径）：不报错，锚点归属自然为空，其后 read 正常发锚点
- [ ] write 仍然照旧 park 越界审批、照旧按会话绑定重根（`:fence-paths` 与模式无关）
- [ ] 相对路径与文件名里含 `..`、符号链接等情形下，锚点归属按**解析后的真实路径**记账——同一文件
      经两条路径访问时共享一份归属（否则会出现「改了但锚点失效」的假象）
- [ ] 离线全量 `harness.test-runner` 全绿
