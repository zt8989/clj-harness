# 11 — `anchor_grep`：搜出来的命中行可以直接改

**What to build:** 模型搜一个模式时，最想做的下一件事就是改命中处。今天这中间隔着一整次 read：
grep 给的是路径与行号，行号不能用来编辑。`anchor_grep` 把两者接起来——每一行命中**带锚点出行**，
于是搜完直接改。

```
=== src/harness/tools.clj ===
  42 │ Hasu│(defn- t-edit [{:keys [path old_string new_string]}]
```

行号本身仍然给（人看着方便），也仍然是**给模型看的参考**；模型动手时用的是 `│` 右边的锚点。

**`:anchor-grep true`（默认）时它是 `grep` 的**替代**，不是并存。** 两套搜索结果同时在场的代价是
模型把行号当锚点用。`:anchor-grep false` 时回到内置 `grep`（本仓没有内置 grep 工具，那就什么都不
注册——不假装有一个）。模式与工具表的对应关系归 03，本票负责它自身。

**实现走 `ripgrep`。** flags 沿用参考实现那一套（`--json --line-number --color=never --hidden
--glob !.git --max-count=<limit+1>`），10 秒超时。`rg` 不在 PATH 上是**点名失败**并说清装什么，不是
静默降级成爬目录——一个偷偷变慢十倍的搜索工具比一个明确的错误更难查。正则要挡指数级回溯（反向引用、
嵌套量词、量词化的选择分支、多个可变量词、`{n}` 里 n 过大），拒绝时说可以用 `literal`。

**Blocked by:** 04（锚点渲染与「已展示」登记），05 的拒绝路径不涉及

**Status:** ready-for-agent

- [ ] 参数：`pattern` 必填；`path` / `glob` / `ignore-case` / `literal` / `context` / `limit` 可选，
      非法取值指名报错（`context` 非负、`limit` 正整数）
- [ ] 输出：每命中一行 `行号 │ 锚点│内容`，按文件分组并带文件头；**锚点是当前有效且已登记为「已展示」**
- [ ] 命中行**立即可编辑**（端到端：grep → 用输出里的锚点 replace，不 read）
- [ ] 上下文行（`context > 0`）同样带锚点且可编辑
- [ ] 搜索范围尊重 `.gitignore`，跳过二进制/图片/超大文件且不报错（静默跳过的是**不可读**，不是**出错**）
- [ ] 超长行进 `read` 同款处理：锚点照出、内容给一带 `...` 的片段，用那个锚点仍能替换整行
- [ ] 命中数超 `limit`、行数或字节超预算时的截断提示说清「还有更多」以及怎么收窄
- [ ] 指数级正则被拒绝并给出「用 `literal: true` 或简化表达式」的出路
- [ ] `rg` 不在 PATH 上 → 点名失败，信息含要安装的可执行名
- [ ] `:anchor-grep false` 时本工具不在工具表里（模式与工具表的对应由 03 的机制承担）
- [ ] 上下文/结果里出现的锚点要**跳过**「已展示」登记之外的来源：只有真的出现在输出里的行才登记
      （锚点被发出去才算展示，这一条与 04/05/06 是同一套规则）
- [ ] 工具描述说清：行号是给人看的、编辑用锚点、`literal` 是正则太复杂时的出路
- [ ] 离线全量 `harness.test-runner` 全绿
