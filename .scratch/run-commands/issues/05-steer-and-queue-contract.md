# 05 — `/steer` 与 `/queue`：先把契约钉死（**这一轮不做**）

**What to build:** 两条命令的**形状**，写下来，免得日后各造一套。实现**不在这套里**。

**`steer`** —— 「对正在进行的那一步说一句」。

- `{:type "steer", :text "…"}`：一条**消息**（spec 决定 7），在**下一个模型调用前**变成一条 user 消息
  进对话、进记录；模型因此在本轮就改主意，而不是等这一轮结束。
- **要求有 run**：没有 run 就拒（`no-run :refuse`）——「正在进行的那一步」不存在时它什么都不是。
- 它**不打断**正在跑的调用的：`interrupt` 才停，`steer` 只是把话塞到下一个边界。这一条是它与 `interrupt` 的分界。

**`queue`** —— 「这句话下一轮再说」。

- `{:type "queue", :text "…"}`：一条**消息**，但 **`no-run :wait`**——**不起 run**，留在队列里等下一个 run。
- 这正是「没 run 在跑就留队列等下一个 run」那条的落点；`compact`/`goal` 与它的区别就在这一格。
- **跨重启由客户端负责**：队列在进程内存里，重启即失；一条排队的话是**客户端**手里的，
  下一次请求再带一遍（与 `append` 按 id 去重同一套）。这条写进实现里，不靠记性。
