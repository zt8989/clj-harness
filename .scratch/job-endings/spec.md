# spec: 作业结束了就说一声 —— 终态通过上下文注入走到模型面前，并在轨迹里看得见

**一句话**：后台那一族只有三个动词（`job` 起、`job_output` 问、`job_kill` 停），而**没人等它**恰恰
是它存在的理由——于是「我不等了，去干别的」之后，那条命令的结局**没有任何通道回来**：`job_output {wait}`
是**停下等**，模型的循环是同步的，它不会想起来再问。本特征给结局一条通道：**会话的前置步骤**
（`before-llm`，每次模型调用前施加、幂等、已经承载技能正文）把「已结束且还没告知」的作业取出来，
作为一条 `<job-ended id="…" path="…">` 的尾随 user 消息注入 —— 模型**下一次开口**就看得见；
而这一条注入物**自己会进记录**，所以轨迹那一栏（会话界面的「轨迹」页）**一个字都不用改**就画得出它。

2026-09-20 立。**这不是推送**：没有任何东西会唤醒模型、不会为它新起一个 run，它只是**下一次开口时**
摆在面前（`.scratch/bash-lifetime` 决策 10「没有人通知你」于是要改成「你下一次开口时就知道」，
而不是删掉）。

## 问题

1. **作业从不说话。** 起它、问它、停它，三个动词都是**模型主动**的。它提前完成（「提前」= 在模型
   去干别的之后、在它想起来问之前）时，那个结局只躺在配置家那份文件里，谁也看不见。
2. **「等」只解决了一半。** `job_output {wait: true}` 覆盖的是「我就在这儿等它」；而后台的全部意义
   是**不等**（起个 dev server、跑一套慢测试、干别的）。模型没有「轮询」这个习惯，也不该有——那是
   把同步循环硬塞进一个异步世界。
3. **缝已经在了，只是没人用它。** `harness.kernel.loop` 每次模型调用前施加 `:before-llm`（技能正文
   就走它，「下一句就看得见」是它写下来的承诺）；`edge/http.clj` 有两处组装点：记提交侧之前一次、
   交给内核一次。记录读侧也已经把「`returned` 尾巴里的 user 消息」画成注入物
   （`harness.edge.trajectory/returned-items` 的 docstring 就是为技能正文写的）。
4. **这句话现在写在工具描述里，是半句谎。** `job` / `job_output` 的描述写着「没有人通知你，得自己来问」
   ——本特征之后前半句仍真（没有推送），后半句要改：**你下一次开口时就知道**。

## 决策

1. **通知是会话级前置步骤的一部分，不是推送。** 它发生在 `:before-llm` 里（内核每次模型调用前施加），
   所以「什么时候送到」有一个确切答案：**本轮的这一次模型调用**（如果作业是在本轮中途结束的），
   或者**下一次开口的第一次调用**（如果本轮已经结束了）。不唤醒、不新起 run、不加 AG-UI 帧。
2. **形状：尾随 user 消息，块名就是框。** `<job-ended id="j1" path="…/j1.log">` … `</job-ended>`，
   先例是 `<skill name="…">` / `<instructions path="…">`：块名是模型读的框，也是读侧认它的锚。
   正文是**记录的尾部**——末端就是那条结论行（`[exit N]` / `[stopped]`），因为记录本来就这么结束。
~~3. **有界，而且是按字节的有界。** 一个 `def`（`notice-budget-bytes`，比一次答案的预算小：通知是提醒，
   不是回答）。超了就写成尾部，并在前面补一行**同一处**的截断话术
   （`truncation-line`，答案里那句就是它）。路径就在标签上，`job_output` 读得到全部。~~
   **2026-09-20（同日更晚）**：`.scratch/bash-background/spec.md` 把它收成**三样事实**
   （`<job-ended id="…" path="…">[exit N]</job-ended>`）——通知是事实，不是答案：没有尾部、
   没有截断话术、也不提怎么读。`notice-budget-bytes` 退场。
4. **一次，永远一次。** 注册表给每个作业记一个**已告知**（`:told?`）。三条路都算告知：
   `job_output` 把终态交回给模型、`job_kill` 把结局交回给模型、通知本身。标记与读在**同一次 `swap!`**
   里完成（`.scratch/immutable-data` 的纪律：读写都在同一个 `swap!` 里）。
5. **幂等不靠历史，靠注册表。** 技能正文的做法是「把它自己折进历史里、再施加一次不变」——因为
   `<skill>` 那条触发消息**一直在客户端的历史里**。通知没有这个锚：客户端从不持有它，所以
   「说过了」只能记在**注册表**（进程内、按会话、与作业同寿命）。代价写在非目标里。
6. **一处组装。** 两半装进**同一个**函数里（`cap.project/before-llm`），所有调用者——两条 run 路径
   （记提交侧之前的那一次、交给内核的那一次）与作者侧的 `edge/replay.clj`——因此自动都拿到，谁也不必
   知道另一半的存在。
   **2026-09-20 落地那天改的**：原计划装在 `edge/http.clj`（组装根），落地时改在这里，理由是
   `cap.project/before-llm` **本来就**是「会话历史被装饰」的唯一一处（技能正文那半当年就是为这个
   放在这里的），而 `edge/replay.clj` 那条路确实会跑真模型调用——不告诉它反而是不一致。
   代价写在这儿：`before-llm` 从「纯派生」变成「带一次标记」的步骤，docstring 里写明了。
7. **界面：一个字都不用改。** 轨迹那一栏已经画注入物（`context` 项 + `injected: opening / during run`），
   而且它的规矩是「同一段字节整场只画一次」（`.scratch/trajectory-injection-once`）——本特征给的是
   **证据**（读侧用例 + 一次真会话走查），不做「会话」栏的卡片（那要一条新协议帧，是另一件事）。
8. **模型自己读文件不算告知。** 它 `bash tail` 那份记录我们看不见，于是会多收到一次通知。接受：
   通知小、只有一次、而且「多知道一次」比「漏一次」便宜。

## 非目标

- **不推送、不唤醒**：不为一条作业新起一个 run、不做通知徽标、不做桌面/浏览器通知。
- **不做作业面板与作业列表端点**（`.scratch/job-output` 的既有非目标，不动）。
- **不加 AG-UI 帧、不动客户端状态、不动 `ui/src`**：注入物是服务端**每次调用现算**的，客户端从来
  不持有它（与技能正文同一条纪律）。
- **不跨进程**：进程一死，还没说出口的结局就没了——记录还在，`job_output` 还能问（这是
  `.scratch/job-output` 决策 5 已经认下的代价）。
- **不给作业加时限**、不做「等 N 毫秒看有没有新输出」的半阻塞、不做轮询。
- **不改 `job_output` 的 `wait` 语义**：它是「我就在这儿等」，与本特征的「你回头会看到」是两件事，
  描述里要把这层区分说清。

## 验收主线

1. **一轮里**：模型起一条作业、去干别的、作业在这期间结束 → **下一次模型调用**收到的历史里就有那个块
   （`harness.kernel.loop-test`：同一个 run 里两次调用，第二次的历史里 `<job-ended`）。
2. **真会话（HTTP）**：跑一轮，记录里那条 user 消息就在 `returned` 尾巴里；把同一份记录交给轨迹读侧，
   它以 `context` / `source: "run"` 出现，并且**两次不同的作业是两格**、同一格重复出现只画一次。
3. **一次**：`take-notices!` 第二次是空的；`job_output` 看过终态之后不再通知；`job_kill` 同理。
4. **还在跑的作业没有可说的**；一条 5000 行的记录，通知是**尾部 + 一行省略话术 + 标签上的路径**。
5. **界面走查**：`node scripts/dev.mjs --scripted <脚本>` 起真后端 + 真前端，用真浏览器看「轨迹」那一栏，
   那一格在位（证据记进落地记录）。
