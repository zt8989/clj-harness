# 03: 记录流的短环只留解析后的 row

**What to build:** 记录流的那个有界短环（`after` 背后的 kept）今天每条 item 同时存**两种形态**：
`:line`（写进文件的原始字节）与 `:row`（解析后的 map）。`:line` 在生产代码里**没有消费者**——实测：
拉流那对入口（`consume!` / `after`）**只被测试调用**，推流的 `listen!`（按会话）**一个调用点都没有**，
唯一的 production 消费者是内核的进程级监听（`listen-every!`），它 `(fn [{:keys [thread-id row]}] (when row …))`
——只要 `:row`，而且明确把「没有 row 的行」判为不属于自己。所以短环只留 `:row`（连同 `:seq` / `:producer`）。

**同时把这张 ring 的键也收紧**：会话没了，它的那条队列要跟着走（今天的键永不删除，会话被放掉之后
行还留着——这与 02 修的是同一个病根的另一半）。

**一条必须写下来的约束**：`row` 重新序列化**不等于**那一行字节（键序、空白都不同），所以
**「要原始字节」的正确来源是文件**（那正是记录读侧那份读者在做的），不是内存里的环。这句话要写进
`after` 的说明里，免得将来有人再往环里塞一份字节。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] item 不再携带 `:line`；`after` / `consume!` 的公开形状与说明一致地说「只有 row」
- [ ] 同一批 item 的字符数约为原来的一半（今天「两种形态都存」那条注释面前后对照一次）
- [ ] 要原始字节的读者只有文件一条路：全仓没有生产代码从环里取字节
- [ ] 一个会话的队列在它被放掉之后不再留在环里（键随会话走）
- [ ] 记录流的用例全绿，且没有一条测试再依赖 `:line`
