# 04: 让内容投影值得开回来——一轮只碰有变化的会话，一轮只开一条连接

**What to build:** 把**已经暂停**的那一层改成一件事能开回来的东西（暂停本身已经落地：`edge.http/start!`
里那次 `projection/start!` 摘掉了，原地留着一句指回本目录的注释）。ADR 0008 决策 4 当年就把这一条
点名留下：「这一条与 `harness.infra.db` 今天的连接纪律要合起来看（它是 per-call 打开、不缓存句柄的
——投影消费者要是长期持有的第二个连接，得单独说清）」——**那句话到今天还没被说清**，而它正是那一层
被停掉的直接原因：一轮 pass 遍历 store 里每一个会话，每个会话都要查一次进度，而每一次查询都是
**一条新连接（带一遍迁移）**。

两件事：

1. **一轮只碰有变化的会话**：文件长度没变的会话不该产生一次查询，更不该产生一条连接。
2. **一轮一条连接**：投影自己的连接纪律说清楚，与 ADR 0008 决策 4 对齐（它要的不是「不缓存句柄」，
   是「把这一层的纪律单独说清并按它做」）。

验收是「一轮的成本远低于调度间隔，**并且落后仍然是一个说得出来的数**」（决策 5：文件字节数 −
已投影的 offset）——省事不许省成沉默。

**Blocked by:** None (can start immediately)。放回来那一步，就是把 `edge.http/start!` 里那次摘除
撤销回去（连同它的 `:require`）。

**Status:** ready-for-agent

- [ ] 文件长度没变的会话不产生任何写入、也不产生一次建连接：一轮的耗时与连接次数对会话数不再线性
- [ ] 在一个「什么都没变」的 home 上，一轮远低于调度间隔——判据是一个**量出来的数字**，不是「感觉快了」（今天的读数是 3,914 ms vs 2,000 ms）
- [ ] 投影延迟仍是读得出来的一个数（记录字节数 − offset），不因为省事而变成沉默
- [ ] 把那次摘除撤销回去之后，服务起来时 CPU 底噪回到个位数百分比；离线用例仍然直接驱动一轮 pass（没有一条用例依赖后台时钟才绿）
- [ ] 有一条用例把「两轮之间没有新字节 ⇒ 零次建连接」写下来
