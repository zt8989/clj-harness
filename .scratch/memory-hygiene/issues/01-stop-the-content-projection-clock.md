# 01: 停掉内容投影的时钟，并把「为什么停」记进现状

**What to build:** 服务起来时**不再启动内容投影的后台时钟**——组合根里那次启动摘掉，原地留一句注释
指向本票与 04，说清它为什么停、什么条件下放回来。同时把这条**已落地行为的变化**写进现状文档与
ADR 0008：

- 现状文档（`docs/architecture.md`）里如实描述：内容投影这一层**今天暂停**，因此 `messages` /
  `tool_calls` 两张表**停止增长**（旧行留着），`projection/lag` 这个数**没有使用者**。
- ADR 0008 上一条现状注记：哪一半仍然成立（**JSONL 仍是唯一真相**、投影只读、`rebuild!` 仍能整份
  重算——决策 1 / 2 / 6 一个字不改），哪一半暂停（那一层消费者），以及它当年留下的那句
  「连接纪律得单独说清」（决策 4）**还没有被说清**——指向票 04。

**为什么停**（实测，见本特征的 spec）：这一层每一轮遍历 store 里的每一个会话、每一轮里的每一次
查询都**重开一条 sqlite 连接（带一遍迁移）**；间隔 2000 ms、单轮实测 3,914 ms，固定速率下永远
追不平，进程 CPU 有 46%（累计 9,914 秒）花在它上面，而它每轮只换来 8 行 / 6 KB。与此同时**全仓
没有任何一条 `SELECT ... FROM messages|tool_calls`**——没有读方。所以停掉它今天不损失任何现有读法。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 进程起来后不再有投影的后台线程，也不再有周期性的 store 全量扫描（线程名单里没有它；进程闲下来时 CPU 不再有约 46% 的底噪）
- [ ] 现状文档如实写出「投影暂停 + 原因 + 放回来的条件」，且它被当作**现状**描述，不是未落地的计划
- [ ] ADR 0008 上有一条现状注记，点名决策 4 那句「得单独说清」至今未说清，并指向 04
- [ ] 摘掉的那一处留着注释指向 01 / 04，且**没有留下半开的开关**（不留一个配了没人读的配置项）
- [ ] 后端全量离线 suite 绿（`clojure -M:test -m harness.test-runner`）；投影自己的那些用例照旧直接驱动一轮 pass（它们本来就不依赖后台时钟），schema 那几条断言（表还在、投影可重算是它的护栏）一条不改
