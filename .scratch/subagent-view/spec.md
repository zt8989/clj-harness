# spec: subagent-view（子agent 的实时视图）

主 agent 委派出去之后，**那次工具调用本身是一个可以点开的门**：点一下，右侧展开一个面板，
里面就是这个子agent 自己的对话——和主对话同一个形状（消息、思考、工具卡），**边跑边长**，
只是没有输入框。它是一面镜子，不是第二个会话。

这一版**替掉** `.scratch/subagents` 里的 04：那一版把「有哪些子agent、跑过什么」做成了左侧导航栏
里的一个块，点运行记录会**把主栏显示的会话换掉**。牛总 2026-09-19 指出这是两回事——要的是
**右侧并排**、**看它干活的过程**、**入口在主对话里那次调用上**。

## 决策

- **真流式（牛总裁定）。** 子agent 干活的过程要**当场**看得见，不是点开读一次快照。
- **入口是主对话里那次 `agent` 工具调用本身（牛总裁定）。** 不是侧边栏的一张清单。
  **2026-09-24**：同一面镜子多了**第二条入口**——右栏「任务视图」里子代理那一行（`.scratch/right-pane-tasks`
  票 03：点的是那一行自己的 `threadId`）。那张卡那条路一个字没改；「不是侧边栏的一张清单」照旧成立
  （新的这一条在右栏，不是左栏）。
- **左侧栏那一块拆掉（牛总裁定）。** 名册退回去由设置页回答（05 那一版已经能编辑），运行记录不再
  有左侧栏的门。
- **并排，一次一个（牛总裁定）。** 主对话变窄，右栏固定宽度；再点另一个子agent 就换掉面板里那一个。
- **帧走进程内的**帧总线**，不走「tail 日志」。** `http.clj` 的头注释写死了这条：
  *All of it is a RECORD, never a source of truth —— 服务器从不读回文件*。让服务端一边写一边把
  自己的文件读出来发给第二个客户端，就是把记录变成分发通道。总线与既有的 `subagents/live`、
  parked 表是同一条规矩：**进程内、随进程退出消失**。没有订阅者时 publish 是零成本。
  （连上时**补发**一次历史是另一件事，走的是 `rebuild` 同一条读法，见 02。）
- **配对靠父会话记录里的一行，键是 `toolCallId`。** `kernel.tools/*tool-call-id*`
  （`kernel/tools.clj:345`）在工具体里是可见的，所以「这次调用开的是哪个会话」是一个**事实**，
  不用靠「同一父会话里第 N 次委派」去猜——两个委派并发时猜法就会错。
- **面板是一面镜子。** 里面不接受输入、不显示 composer 的禁用态、没有「发消息」的按钮。
  它的作用域里没有「说话」这件事。

## 非目标

- 不做「在面板里给子agent 追加输入」——子agent 不接受中途插话，这一版不新开这种形状。
- 不做多开（同时铺开两个子agent）。一次一个，换就是换。
- 不给子agent 自己的预算 / 时限 / 模型旋钮。
- 不改 AG-UI 协议，也不动 `POST /api/agent` 的语义：那条流仍然只属于它自己那一次 run。跟随通道是
  另一条**只读**的流，父子不同路。
- 不做「跑到一半重连不丢帧」的强保证：跟随通道连上时补发已有的帧、之后跟着总线走；断了再连就是
  一次新的补发。日志本身仍是完整的（`run-subagent!` 一直在写），所以事后 `rebuild` 照旧。

## 验收主线

离线 `node scripts/test.mjs` 的失败名单与基线一致（这台 Windows 上后端本来就有一批预存失败，按
名字比对，见 `.scratch/subagents/evidence/regression-analysis.md` 的方法）；**动过 `ui/src/`
就必须走一次真浏览器** `node scripts/dev.mjs --scripted`：

- 主对话里那次 `agent` 调用**是**可点的，且标明是哪个子agent；
- 点开右栏，主对话**还在**（并排），右栏**没有**输入框；
- 子agent 干活时右栏**边跑边长**（这是本特性唯一无法用离线套件证明的一条，只有真浏览器说得清）；
- 再点另一个子agent，右栏换人；关掉右栏，主对话复原；
- 跑完之后右栏仍然读得到（跟随通道关了，`rebuild` 那条路还在）。

端到端那一票在 **02**：一个会话委派一次，右栏在子agent 还没跑完时就已经看到了它的一部分。
