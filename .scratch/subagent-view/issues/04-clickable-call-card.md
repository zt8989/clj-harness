# 04 — `agent` 那张工具卡可点

**What to build:** 主对话里那次 `agent` 工具调用**自己**是一扇门：它标明是**哪个**子agent 在跑、
跑的是什么，并且**可点**；点一下开右侧面板（05）。

要点：

- **先说清它是什么。** `message-parts.tsx` 的 `subjectOf` 是一张**闭合的投影表**，一行一个工具，
  把参数投成一句人能读的话（而不是截断的 JSON）。给 `agent` 加一行：读出来应该是
  `agent · explore · 找出 deps.edn 用到的所有命名空间` 这样的句子——名字在前，任务一句话在后。
  没有这一行的话它现在会落到「第一个字符串参数」，那会显示成任务原文、看不出是哪个子agent。
- **可点的条件是「这个家知道它开的是谁」**——即 03 那行 `delegation` 读得回来。
  注意两件由此推出的事：
  - **还在跑的时候最该能点**（那时工具结果还没有，卡片正是「进行中」的样子），所以可点性**不**依赖
    工具结果，只依赖 03 那一行。
  - **老记录里没有那一行**，于是那些卡片不可点。这是诚实降级，不是 bug；但**不许**让卡片看上去
    可点却点不动——不可点就不给可点的样子（悬停、指针、下划线都要一致）。
- **`toolCallId` 从工具 part 上取**，父会话的 id 从 `ThreadIdContext` 取（`components/composer-chrome.tsx`
  已经提供，composer 的 chrome 就是靠它知道自己在配置哪个会话）。这两个是配对的钥匙，别用位置或
  顺序代替。
- **一次解析，能缓存。** 同一个父会话的 `delegations` 读一次就够；点开时不重复请求。卡片很多时
  不许每张各发一个请求。
- **有一处形状要现场决定，并写清理由。** 本仓刻意只注册了 `ToolFallback` 一个渲染器，好处写在
  `message-parts.tsx` 的头注释里：**新工具零前端改动就能在对话里出现**。让 `agent` 可点有两条路——
  给它注册一个具名渲染器（放弃上面那条 property），或者在 fallback 里开一个受控的例外。**选哪条都
  行，但要在注释里说明为什么**，因为这是一个会被人重新讨论的决定。
- 中英两套文案都要在（`locales/{en,zh}/shell.json`）。
- **不是导航。** 点它不换主栏显示的会话（那正是这一版要拆掉的行为），它开的是右侧那块。
