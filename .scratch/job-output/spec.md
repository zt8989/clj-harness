# spec: 作业的记录是一份文件 —— 读它的是模型自己的 `bash`

**一句话**：后台作业今天把输出收在**内存里的一圈尾巴**（最近 500 行，丢掉的算成一句「丢了 N 行」），
再由一个专门的读动词（`bash_output`）带游标交给模型；于是模型把命令的输出重定向到自己挑的文件
（`… > /tmp/clj-api.txt 2>&1`）时，那个读动词答 `(no new output)` —— **而那条命令明明打了两行**。
本特征让作业的输出落成**一份文件**（在配置家里，一份作业一份），**读它的是模型已经有的那几个工具**：
`bash`（`tail` / `grep` / `cat`）、`read`、`grep`。读的动词退场，起的动词改名：`bash_background` → `job`、
`bash_kill` → `job_kill`，**工具数 18 → 17**。

2026-09-17 立。**2026-09-18 复议（牛总）**：不给「读一份正在长的文件」单开一个工具。作业的记录与
一份文件没有区别，而那个专门的读动词的每一种边界（游标读到哪、半行算不算、丢了 N 行怎么报）都是
本仓自己发明、自己维护、自己出错的地方 —— 它们回答的是**本仓造出来的**问题，不是模型的问题。
读法就交给模型手里的文件工具。三张票重排，见文末「交付顺序」。

## 问题

1. **模型的习惯不是无理的，它是对「输出会丢」的正解。** 真实会话里那句话是：

   ```
   cd <worktree> && timeout 1200 clojure -M:test -m harness.test-runner > /tmp/clj-api.txt 2>&1; echo "EXIT=$?" >> /tmp/clj-api.txt
   ```

   四个动作里三个是模型在**重实现本仓已经有的东西**：`cd`（作业的 cwd 就是会话的项目目录，
   `cap.tools/t-bash-background` 走 `project/binding-for`）、`timeout`（作业按设计没有时限）、
   `EXIT=$?`（答案的状态行已经给退出码）。**第四个是偷**：命令的 stdout 全去了
   `/tmp/clj-api.txt`，`shell/start` 的管道一行都收不到。

2. **那时 `bash_output` 的答案是错的，不是「不够好」。** 同一条命令不重定向就是两行；
   重定向之后得到 `(no new output)` + `[exit 0]`（立票当天实测过）。而作业模块自己的规矩是
   **缺口必须看得见**（`cap.jobs` 的 ns docstring：*"Lines that scrolled off before the session read
   them are COUNTED rather than hidden …"*，`jobs.clj:16-21`）。这里是**全部**丢失，且一个字不说 ——
   那句话在内存尾巴上成立，在「输出从未到过这里」时失效。

3. **模型为什么挑这个形状：它要的是「整份、可搜」——而且 README 就是这么教它的。**
   `README.md:308-310` 一个字节不差地写着：

   > 输出只留最近 500 行（丢了会报数），因为这是给模型读的尾巴，不是一份日志（**要日志就让命令自己
   > 重定向到文件，再用 `read` 去看**）。

   所以这不是先验，是**本仓写下来的路**：尾巴不是日志，要日志就自己重定向。而尾巴确实更差 ——
   500 行、在内存里、不能搜；文件是全部、可 `grep`（本仓的 `grep` 给行号）、可 `read`、还能喂给别的
   命令。长测试跑几千行，只在结束时读一次尾巴就只剩 500 行加一句「丢了 N 行」。
   **要模型不选那条路，只能把那条路修好。**

4. **这件事哪儿都没记着。** `README.md:308-310`、`CONTEXT.md:117-118`、`docs/architecture.md:68`
   与 `tools.clj:735-743` 四处都把「有界尾巴（最近 500 行 + 丢了多少行）」当现状写着，
   其中两处还写着**「不落盘」**（`CONTEXT.md:118`、`architecture.md:68`）——
   本特征让这四处成为必须跟着改的谎话，而 README 那个括号是本特征要**反过来**的一句。

5. **（复议新增）读的动词是本仓第五处自己养着的复杂度。** 上一版打算保留 `bash_output`，让它改读文件：
   于是要继续维护**游标**（读到哪个字节）、**半行**（没换行的尾巴不许交回）、**`(no new output)`**
   （新语义：不再等于「它结束了」）、以及**「同一份记录两个读者」**那条纪律。
   这四样没有一个来自模型的需求，全部来自「本仓要替模型读一份正在变长的文件」这个决定。
   模型要的只是：**命令说了什么、说完了没有**。一份文件加一个末行就答得完。

## 决策

1. **作业的输出落成一份文件，那份文件就是记录。** 内存尾巴、丢行计数（`[N earlier lines were dropped]`）
   与「最近 500 行」这个概念一并退场：**文件里什么都不丢**，于是没有缺口需要报，
   也不需要为了让读者看得见缺口而解释「尾巴有界」。

2. **读它的工具是模型已经有的那几个：`bash`（`tail` / `grep` / `cat`）、`read`、`grep`。
   于是 `bash_output` 退场** —— 连同它的游标、`(no new output)`、「上次读之后的新行」一起。
   理由：读一份文件不需要本仓再造一个读动词，而每个读动词都要有一套自己的边界语义，那套语义由本仓
   发明、由本仓出错（问题 2 就是它出错的样子）。**状态也由记录自答**：记录写完时末行是 `[exit N]`，
   没有那一行就是还在跑。这正是文件相对内存尾巴的根本好处 —— **同一份记录，一个写入者，读者是模型
   自己的工具**：写入者只管把行按顺序写下去，读的人怎么读、读多少、要不要搜，都是 `tail` / `grep` /
   `read` 已经回答过的问题（`cap.project/fence` 把**配置家**列为自由路径，`bash` 自己也没有围栏，
   这一条是本特征成立的前提，票 01 有用例钉它）。

3. **名字收成两个：`job` 起，`job_kill` 停。** `bash_background` → `job`（`bash_` 是这一族里多余的字，
   先例是 `omp-parity` 那次复议：`anchor_grep` → `grep`，「名字不要带一个说了等于没说的词」），
   `bash_kill` → `job_kill`。仍然**一个动词一个名字**（不是 `job {action}` 一张表，理由见
   `tools.clj:713-720` 的那段注释：schema 各自只带自己的参数，缺参数的拒绝落在动词上）。
   **工具数 18 → 17**：三处硬编码清单、`CONTEXT.md` 的闭清单、`docs/architecture.md` 的「十八个」
   跟着改。

4. ~~**两个答案都说出记录在哪。** `job` 的答案是一句话带路径；`job_kill` 的答案也一样（它停的或发现
   已经结束的那条作业，记录在哪）。路径**只在一处拼**（`cap.jobs` 的 `start!` 答出 `:id` 与 `:path`），
   工具面**不许**重算一遍 —— 两处拼路径就是留一次「改了一处、另一处没跟上」，
   先例是 `bash-default-timeout-ms` 在描述里插值。~~
   **2026-09-23 复议（`.scratch/job-receipt-no-path/`）：两个答案都不再说路径。** 说的是**读法**——
   ``read it with `job_output {"job": "j1"}`.``，与通知那第三行同形：`job_output` 与 `job_kill` 都按
   id 说话，路径是本仓在自己配置家里的形状，模型拿它做不了任何事。记录仍是一份文件、仍活过写它的
   进程，退场的是「按答案里那条路径去读」这条路。**路径只在一处拼**那条规矩不变（`cap.jobs` 的
   `:path` 仍是 `output` 读记录时的把手）。
   **同日再复议（主人第二轮）**：不报路径的是**回执**；**读的那个动词报**——`job_output` 的答案在「窗口不是
   整份记录」时带上记录的路径（`cap.jobs/output` 的 `:path`），`bash` 溢出那条路径照旧。

5. ~~**记录能读多久 = 这个进程活多久，只有一条规矩。** 收尾钩子（`shutdown!`，进程退出那一刻）
   把本进程所有作业的记录删掉；**`job_kill` 不删**。理由：答案里那个路径是叫模型去读的，
   删掉它等于答案给一个死链；而「停掉之后还想看它最后说了什么」正是最想要读它的一刻。
   被硬杀的进程留下的文件也一样 —— 那正是你最想读的一刻，而它在配置家里，
   不在别人的仓库里，这个代价可以接受。**这反转了本特征上一版的决策 3 的一半**（那一版把「删」
   挂在 `bash_kill` 上，出自 `bash-lifetime` 的「停掉并忘掉」）：现在读的是模型，
   它读之前不会有人替它把文件收走。~~
   **2026-09-20**：`.scratch/bash-record-persistence/spec.md` 翻掉这半条——`shutdown!` **不再删任何
   记录**（只停进程、放开文件），文件留在配置家；「`job_kill` 不删」那条一字不动，而它当年给的理由
   （路径是给模型读的，删掉就是死链）现在成了整条寿命规矩的理由：**没有谁比读它的人更有资格收走它**。

6. **记录 = 命令打出来的那些行 + 本仓补的最后一行。** 最后一行只有两种写法：`[exit N]`
   （进程走了、输出也排空了）与 `[stopped]`（本仓停的）。**没有别的**：不加命令、cwd、起始时间的
   表头 —— 那是会话历史的题目；记录答的是「这条命令说了什么、说完了没有」。
   而且 `[exit N]` **只在排空之后进程确实不在了**才写：`exec 1>&-` 那种「流停了、进程还在」
   （现有用例 `a-command-that-let-go-of-its-stdout-is-still-running`）的记录里**没有**这一行，
   而这一行的缺席本身就是答案（还在跑）。上一版把这一行写在「看见 eof」那一刻，会在那种命令上
   写出一个编出来的退出码。

7. **重定向只报告，不拒绝。** 判据保守：命令串里出现把 stdout/stderr **指向文件**的 token
   （`>`、`>>`、`2>`、`&>`），`job` 的答案里就加一行指名说「这条作业的记录会是空的，因为命令把输出
   送去了 `/tmp/x` —— 读那个文件，或者去掉重定向、让本仓替你留着」。**`| tee FILE` 不算**：tee 把输出
   复制一份，stdout 仍然流回本仓。不拒绝的理由：判定是**尽力而为**的（引号、变量、`$(mktemp)` 都可能漏），
   而拿一个尽力而为的判定去**拦下**一条可能正当的命令（`> report.csv` 是真正的活）是拿真事换姿态。
   复议之后这一句比上一版更重要：**读文件的是模型，一条空的记录没有地方解释自己为什么空。**

8. **作业的输出仍然不是会话历史。** 不进 jsonl、不进 sqlite、不加审计行、不动 AG-UI 与轨迹、不跨重启
   （一个作业的存活仍然等于这个进程的存活），也没有作业列表端点与作业面板。

9. **写入者只有一个，每行 flush。** 记录只有一个作者：那条每作业的排空线程（`pumping!`）。每写一行
   flush 一次，所以模型在任何一刻 `tail` 都能看见已经打出来的行。命令自己 `printf` 一半（没有换行）
   就停住时，文件里就是半行 —— 谁读谁看见什么，**本仓不再为此发明拼接逻辑**（上一版为了不许把半行
   交回而记字节数，那是给「读的人」写的规矩，现在读的人不是本仓）。

## 非目标

- **不拦、也不改模型的 `timeout` 与 `cd`**：它们不是偷输出，是重实现（描述里已经写着作业没有时限、
  cwd 与 `bash` 同一处解析）。答案是哪个 cwd、要不要报一句，本特征不做决定 —— 那是另一件小事。
- **不给后台作业喂 stdin**、**不做半阻塞读**、**不做「跑完了通知我」**（`bash-lifetime` 的立场不动）。
- **不改 `bash`（前台）的任何行为**，不改 `timeout` 的语义（毫秒、默认 120000、不封顶）。
- **不动 `cap.mcp` 与 hook 引擎**：它们各自有超时，作业的记录只服务作业。
- **不碰 `.scratch/immutable-data/spec.md`**（它此刻正被另一个会话修改）：注册表「进程级容器按键分家、
  读写都在同一个 `swap!` 里」的纪律本特征不动，只是容器里的东西换一样。
- **不做日志轮转**：一份作业一份文件、随进程一起消失，不引入第二种清理策略。
- **不给记录写元数据**（命令、cwd、起始时间、pid）：记录是那条命令打出来的行加一行结束行，
  别的都在答案里或会话历史里（决策 6）。
- **不改 `bash` / `read` / `grep` 这三个读法里的任何一个**：本特征的立场就是它们已经够用。

## 验收主线

一条真会话（或直调两个工具），六件事看得见：

1. `job {command: "echo one; echo two; echo three; sleep 60"}` → 答案里**指名**这份记录在哪；
   **同一份文件**用 `bash {command: "cat <path>"}` 看得到那三行，`bash {command: "grep two <path>"}`
   找得到它（`read` / `grep` 工具读同一个路径同样成立，且**不挂审批**）。
2. 命令结束后，记录的**末行**是 `[exit 0]`，`bash {command: "tail -1 <path>"}` 拿到的就是它。
3. 起一条**重定向到自己文件**的命令（就是模型那句的形状）：`job` 的答案指名说出 `/tmp/…` 这个目标；
   记录**真的是空的**（0 字节），而答案里已经说了为什么。
4. 一条打印 600 行的命令：记录里**600 行一字不少**，也没有「earlier lines were dropped」这种句子。
5. `job_kill` 之后：**文件还在**、末行是 `[stopped]`，作业从注册表消失（再 `job_kill` 指名拒绝）；
   `shutdown!` 之后本会话的记录目录不在。
6. 工具面：`job` 与 `job_kill` 在、`bash_output` 不在、总数 17（`harness.kernel.tools-test`
   与 `harness.cap.editing-mode-tools-test` 的清单用例是证据）。

## 落地记录

### 01 — 记录是一份文件，读它的是 `bash`；工具面收成 `job` / `job_kill`

- `cap.jobs`：作业一开就建 `<root>/jobs/<home/sanitize thread-id>/<job-id>.log`（`io/make-parents` 建目录，
  `io/writer … :encoding "UTF-8"` 开文件）。注册表条目瘦成 `{:id :handle :path :writer}`，`:writer` 是
  `AtomicReference<Writer>`——既是「记录还开着吗」的答案，也是每次 append 拿的那把锁。
- 写入：`append-line!` 每行 flush，writer 一旦被认领（结束行写完）就不再写——pump 晚了半拍的行不会落到
  `[exit N]` / `[stopped]` 后面。`write-last-line!` 用一次 `getAndSet` **认领**结束行，写一次。
- 结束行：pump 看见 eof 之后 `settle!`（`.waitFor` `exit-grace-ms` = 2000ms）等进程真的没了，再写
  `[exit N]`；`exec 1>&-` 那种命令等不到，就**不写**——那一行缺席本身就是「还在跑」。`stop!` **先认领
  `[stopped]` 再杀进程**，所以醒过来的 pump 不可能在它后面补一个 `[exit 137]`；对**已经结束**的作业，
  `stop!` 一个字不写，退出码由 pump 写（它手里还有没排空的尾巴）。
- 退场：`tail-lines`、`add-line!` 的丢最旧分支、`mark-ended!`、`status-line`、`unread`、`answer`、
  `read-output`、`update-job!`，以及工具面的 `bash_output` 与它的描述。工具数 18 → 17。
- 寿命：`shutdown!` 先 `reset!` 注册表、再关进程、再放掉 writer、**最后**删文件（Windows 删不掉还开着
  的文件，顺序就是这么来的）；删不掉只 `log/warn!` 一行，不抛。`job_kill` **不删**（~~答案里的路径是叫
  模型去读的~~ **2026-09-23 补（`.scratch/job-receipt-no-path/`）：现在是叫模型去用 `job_output` 读**）。
  `start!` 起不来时不留文件——文件是在 spawn 成功之后才建的。
- 跟着改的谎话：`tools.clj` 里 `job` / `job_kill` 两个描述与 `bash` 那句指路、`README.md`、`CONTEXT.md`、
  `docs/architecture.md`、`docs/architecture/kernel.md`、`docs/architecture/projects.md`、三处硬编码清单；
  `.scratch/bash-lifetime/spec.md` 的决策 6 与 9 划掉并各加一行日期注。
- **撞上的坑**：`(.waitFor p ms)` 是**一参**方法（两参要 `TimeUnit`），反射失败被 pump 的 `catch` 吞掉，
  于是普通命令的记录里没有 `[exit N]`——定向跑抓到的唯一一个真 bug。修法是 `settle!` 里显式
  `(.waitFor p (long exit-grace-ms) TimeUnit/MILLISECONDS)`。

### 02 — `job` 的答案：命令自己把输出送走时指名说一声

- `cap.jobs/output-redirect`：字符级扫描（认引号与反斜杠），见到 `>` / `>>` / `&>` 就把下一个**词**当目标；
  `>&`（`2>&1`）与 `&-` 不算、`| tee` 不算、只答第一个目标。**尽力而为**写在 docstring 里。
- `cap.tools/redirect-note`：命中时在**同一个答案**里加一句「记录会是空的，输出在 <路径>」；不命中不加。
  **不拦**：命令照起，用例断言重定向真的发生了（那个文件里确实有输出）。
- **票面有一处自相矛盾**：表里 `sh -c 'x > /tmp/x'` → `/tmp/x`，与同一条规矩「引号里的 `>` 不算」冲突。
  按**规矩**落地（引号里的 `>` 是词），用例那一行写成 `x > /tmp/x`，并在注释里写明嵌套 shell 是这条判据
  **允许漏掉**的形状——漏了只少一句提醒，误报却会把模型指向一份其实有内容的记录。
