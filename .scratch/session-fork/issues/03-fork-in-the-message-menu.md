# 03: 消息动作里的 Fork

**What to build:** 被 fork 的那场会话的对话里，消息动作条（复制 / 刷新 / 更多）的「更多」下拉多一项
**Fork**；点它，服务端 fork 出一场新会话，侧边栏（Project 栏）立刻新增一行，标题与原来的一致、
前面是 `[fork]`。

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] 「更多」下拉加一项 Fork（中英文案各一份，与现有 `message.*` 文案同住）。
- [ ] **一轮结束之后才点得动**：run 在跑时（工具调用中途）不给 fork——那时既没有干净的截点，
      也没法把一个人为选择的中间态讲清楚。按现有的 running 判定禁用/提示即可。
- [ ] 点 Fork 调服务端 fork 路由（默认从最近一次压缩前）；成功后靠 host 推送让侧边栏出现新行，
      **不额外轮询**。
- [ ] 新行标题 = `[fork] ` + 原标题（前缀是服务端写下的，UI 不自己拼）；原会话那一行不动，
      也不切走当前视图。
- [ ] fork 失败（该会话没有压缩点 / 记录被 02 判为不可用）时给出可读的拒绝，不静默、不留转圈。
- [ ] `cd ui && npm test`、`npm run typecheck`、`npm run build` 全绿；真浏览器走一遍
      （`node scripts/dev.mjs --scripted`），确认新行真的出现、标题对。
