# 04 — 迁移：并进新段，老文件改名 `.bak`

**What to build:** 开机时（与 `ensure-config!` / `migrate-config!` 同一处，由组合根调用）
把老文件搬进新段：`harness.edn` → `:session`、`mcp.edn` → `:mcp`、`.harness/harness.edn` /
`.harness/mcp.edn` 两份项目级**不搬内容**（读侧已经不认），也要改名走。

**Blocked by:** 02, 03

**Status:** ready-for-agent

## 规则（照 spec 的三条）

- **逐键并入，config.edn 已有的键赢**：老文件的键一个个看，新段已有同名键时**不覆盖**，
  并在那一行里点名说「这些键没搬，因为 config.edn 已经有了」。
- **原文件改名**成 `<原名>.bak`（`move`，不是复制）：那个名字从此不存在。**已有同名 `.bak` 时不覆盖**，
  退成 `<原名>.bak.1`、`.bak.2`……（`.bak` 里可能是一个人唯一的旧配置，第二次迁移不许吃掉它）。
- **读不动就一个字节都不动**：不是 EDN、不是 map、顶层不是 map —— 原文件留在原地，
  只把读取器那句按名字的失败打出来（迁移不能让人写的文件消失在自己的解析错误里）。

## 验收

- [ ] 一个老的家（`harness.edn` 七个键 + `mcp.edn` 的 `:servers`，且与 config.edn 有**重叠键**）开机后：
      新段里有内容、重叠的键是 config.edn 那份、两份老文件变成 `.bak`、日志**一行**说清搬了什么/没搬什么
- [ ] **幂等**：第二次开机什么都不做、不打印、不动任何文件
- [ ] 一份**坏的** `harness.edn`（不是 EDN）：文件原地不动，日志打读取器那句话，**开机照常成功**
- [ ] `.harness/harness.edn` / `.harness/mcp.edn`：改名走；`.harness/` 目录本身与里面的
      `hooks.edn` / `subagents/` / `skills/` **一个都不碰**
- [ ] 迁移**失败不影响开机**：任何一步抛了，捕获、打印、接着起（今天的 `migrate-config!` 就是这个脾气）
- [ ] 一个「读到老名字」的场景：老文件还在（迁移没跑过）时，读侧**不用它配置**，日志警告一行，
      **不失败**（离线工具、只读调用者不该因为一份历史文件跑不起来）

## 不做

- 不搬 `hooks.edn`（它是留下的那一份）。
- 不做「新旧并存」的兼容读——迁移不是兼容层，是搬运。
