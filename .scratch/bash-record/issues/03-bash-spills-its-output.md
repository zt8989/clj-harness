# 03 — `bash` 落记录：超阈值就写下来，答行数与路径

**What to build:** 一条命令的输出不再按大小倒进上下文。超过阈值（行数或字节数，各一个 `def`）就**整份
落成一份记录**，答案是：

```
<spill 行：多少行（与多少字节）、记录在哪>
<尾巴：最后 K 行>
<既有的结束行：[exit N] / [timed out after Nms …]>
```

没超过阈值时**逐字与今天相同**——一个字节不多、不少，`(no output)` 那条照旧。读完这条记录的是模型
**已经有的**工具：`bash`（`tail` / `grep` / `cat`）、`read`、`grep`，而且不挂审批（记录住在配置家、
围栏已自由，票 02 把路径收到了一处）。

**Blocked by:** 01 and 02 —— 01 因为它与 03 动**同一个 `bash` 描述串**（本仓工作树是几个会话共用的，
两张票同时改一处只会换来一次合并冲突，理由同 `bash-lifetime` 的「02 挡在 01 后面」）；02 因为要指名
的那条路径得先是一处拼、一条寿命。

**Status:** ready-for-agent

## 现场

`t-bash`（`cap/tools.clj:189-219`）今天的样子：`shell/run` 拿回 `{:exit :out :err :timeout}`，拼成
`body (str out err)`（`:209`），末尾按情况补一行结束行（`:210-219`），整串返回。**没有上界**：
一条跑几分钟的测试套件几万行，原样进上下文、也原样进 jsonl。

而同一个文件里已经有一处「答案给上界」的先例：`clip`（`:66-67`，8000 字符就砍），唯一的调用点是
`t-eval`（`:222`）。**它不能直接拿来给 `bash` 用**：`clip` 留的是**头部**（`subs 0 8000`），而一条日志
的头部恰好是最没用的那段（测试跑的头部全是 `Testing …`），要读的在尾巴——这也是为什么这一票是
**落盘 + 尾巴**而不是裁剪。

模型今天自己动手做的那件事（`… > /tmp/backend-probe.txt 2>&1`，再用 `grep` 反复查），本票把它
**变成 harness 自己做的事**：路径由答案给，名字不用模型起，围栏不用模型操心。

## 要改成什么

1. **两个 `def`**：`bash-spill-lines`（超过多少行就落盘）与 `bash-spill-bytes`（超过多少字节就落盘，
   管住「一行 5MB」这种形状），以及 `bash-tail-lines`（落盘时答案里留多少行尾巴）。
   **都是唯一一处字面量，描述串里插值**——理由与 `bash-default-timeout-ms` 同一句：描述里手写第二个
   数，就是留一次「改了默认值、描述没跟上」。
2. **超阈值时**：把**整份** `body` 写进一份记录（走票 02 那个门，路径由 `record-path` 拼），
   再写结束行（**末行自答**，与作业记录同一条纪律），答案是 spill 行 + 尾巴 + 结束行。
   spill 行要说清三件事：**多少行**、**多少字节**、**记录在哪**（绝对路径），并且**是第一行**
   （尾巴再长也淹不掉它）。结束行照旧在最后一行。
3. **落盘是搬家，不是过滤**：记录里的字节 = 今天 `body` 会带的那些字节，顺序一样、一行不少
   （`(str out err)`——`infra.shell` 已经把 stdout/stderr 的先后丢了，本票**不**试图比它更懂）。
   结束行是**唯一**新增的一行，而它今天就在答案里。
4. **不超阈值时**：今天那条路一个字不改（包括空输出时的 `(no output)`），**不写文件、不提路径**。
5. **`bash` 的描述**（`:692-700`）加一句：输出超过「多少行 / 多少字节」时，整份会落成一份记录，
   答案是行数、路径与尾巴，读它用 `read` / `grep` / `bash`（插值上面那两个数）。
6. **`job` 一个字不改**：它是另一档（没人等它），记录的形状一样，但它的末行由 pump 认领、由
   `stop!` 或进程结束收尾。两档在 ns docstring 里说清（票 02 已把那一段扩过）。

## 验收

- [ ] `bash {command: "seq 1 5000"}` → 答案第一行里有 **5000 行**与一个**绝对路径**；路径指向的文件里
      `wc -l` 是 **5001**（5000 行输出 + 末行 `[exit 0]`）；答案里的尾巴是最后 K 行
- [ ] 同一份记录用三种读法都读得到，且**都不挂审批**：`bash {command: "grep -c '^4999$' <p>"}` 答 `1`；
      `read <p>`（带 `offset`）；`grep` 工具对同一路径
- [ ] `bash {command: "echo hi"}` → 答案**逐字**是 `hi`（今天的样子），**没有** spill 行、没有路径，
      并且配置家里**没有**为它多出一份记录
- [ ] 空输出：`bash {command: "true"}` → `(no output)`，与今天一致
- [ ] 到点那条：`bash {command: "seq 1 5000; sleep 300", timeout: 1000}` → 记录里有到点前打出来的行，
      **末行**是 `[timed out after 1000ms …]`；那条 `sleep` 的进程不在（`kill -0` 说不）
- [ ] 单行巨物：一条打出一行超长文本的命令也落盘（`bash-spill-bytes` 在管），答案里仍然是行数 + 路径 + 尾巴
- [ ] 路径只由 `record-path` 拼：`grep -n "io/file" src/harness/cap/jobs.clj src/harness/cap/tools.clj`
      里拼这份路径的只有那一处
- [ ] 记录的寿命：进程退出（`shutdown!`）之后那份记录不在了——与作业记录同一条规矩，有用例
- [ ] 阈值与尾巴的两个数**在描述里插值**：`grep -n "bash-spill-lines\|bash-tail-lines" src/harness/cap/tools.clj`
      一处 `def`、描述里引用它（用例断言描述里那两个数就是 `def` 的值，照 `bash` 默认超时那条既有用例写）
- [ ] `node scripts/test.mjs --backend` 与基线一致；`node scripts/test.mjs --ui` 条数与基线一致
      （本票不碰 `ui/`：工具卡读的是参数，答案变长变短不影响 `subjectOf`）
