# spec: 前台也有一份记录 —— `bash` 的输出落成文件，`job` 只管「没人等它」

**一句话**：`bash` 今天把命令打出来的**全部**塞回上下文（`t-bash` 就是 `body (str out err)`，一个字不裁，
而 `clip` 就在同一个文件里、只给 `eval` 用）；于是模型自己动手把输出送去 `/tmp`，再用
`job + sleep + grep` 拼出它真正要的那个交集：**等到结束、又不堵上下文、还能对同一份东西反复搜**。
本特征让**前台的 `bash` 也落一份记录**——超过阈值就整份写下来，答案是「多少行 + 路径 + 尾巴」，
读它的还是 `bash` / `read` / `grep`；并把两个工具的分工从「慢就用 `job`」改回真正的轴：
**你接下来只会等它，还是要去干别的。**

2026-09-18 立。三张票 + 一张收口，见文末「交付顺序」。

## 问题

1. **`bash` 的答案没有上界。** `t-bash`（`cap/tools.clj:189-219`）返回 `(str out err)`，一条跑几分钟的
   测试套件能打几万行：原样进上下文，**也原样进 jsonl**。而同一个文件 46 行上面躺着 `clip`
   （`:66-67`，8000 字符就砍），唯一的调用点是 `t-eval`——**要不要给答案上界这件事，本仓已经回答过
   一次，只是没轮到 `bash`**。

2. **模型自己动手那条路，方向是对的。** 实测的那对调用是：

   ```
   job  {command: "cd <项目> && node scripts/test.mjs --backend > /tmp/backend-probe.txt 2>&1; echo \"EXIT $?\""}
   bash {command: "sleep 290; grep -c … /tmp/backend-probe.txt; …", timeout: 330000}
   ```

   它要的东西一样不缺：**整份**（不是尾巴）、**可 grep**（本仓的 `grep` 给行号）、**不堵上下文**、
   路径由自己掌握。这不是模型笨，是它准确——它手里的两个工具恰好互补：**会等的那个会把整份倒回来，
   不倒回来的那个不会等**。它要的是交集，交集没有，于是它拼了一个。

3. **那两个动作各自都能对上一条本仓的话。** `job` 是**照描述做**的：`bash` 的描述写着
   「for something that has to outlive the call, use `job` instead」（`cap/tools.clj:699`），
   `job` 的描述写着「a dev server, a watcher, a slow test or build」（`:720`）。**慢就是规则**——可真正的
   轴不是快慢，是「你接下来要去干别的吗」。`sleep 290` 则是补那个不存在的动词：`job` 没有「等」，
   而模型的循环是同步的（下一步的输入就是这一步的结果），`bash` 是唯一会阻塞的工具，于是
   `sleep` 被当成 `join` 用，`timeout: 330000` 只是把时限抬到 `sleep` 之上（290000 > 默认 120000）。

4. **重定向那条 note 拦不住，而且不必拦。** `redirect-note`（`cap/tools.clj:732-745`）落在**事后**，
   措辞还是「read that file instead」——在模型读来是**确认了这条路**。而真正该被修的不是重定向，
   是**它为什么需要一个文件**。

5. **作业那套记录机器已经全在了。** 一份文件、一个写入者、每行 flush、末行自答（`[exit N]` /
   `[stopped]`，缺席即「还在跑」）、~~进程退出时收掉~~（**2026-09-20**：`.scratch/bash-record-persistence/
   spec.md` 翻掉这句——记录留下来）、住在配置家所以围栏自由（`cap/jobs.clj:16-45`，
   `cap/project.clj:636` 把 `home/root` 列在 `:free`，`test/harness/cap/project_test.clj:149-150` 钉着）。
   缺的只是**它的位置和它的名字**：`record-path`（`:96-104`，docstring 就写着「ONE PLACE BUILDS THIS
   STRING」）今天只服务「后台」这一档，目录就叫 `jobs/`。

## 非目标

- **不动 `job` 的行为**：不限时、不阻塞、不加通知、`job_kill` 不删记录。
- **不动 `redirect-note` 与 `output-redirect`**：命令自己把输出送去别处时，作业的记录照样是空的，
  那条 note 照样只报告、不拒绝。
- **不给 `bash` 加过滤参数**（`grep` / `tail` 挂在命令后面就够了——本仓有 `grep` 工具，不要再发明一个）。
- **不改 `read` / `grep` / `infra.shell`**，不做日志轮转、不做记录列表或面板、不跨重启。
- **不改 `timeout` 的语义**（毫秒、默认 120000、不封顶）。

## 验收主线

一条真会话，四件事看得见：

1. `bash {command: "seq 1 5000"}` → 头一行是「5000 行 + 路径 `<p>`」、后面是尾巴；
   `bash {command: "grep -c '^4999$' <p>"}` 答 `1`；`read <p>` 与 `grep` 读同一个路径**不挂审批**。
2. `bash {command: "echo hi"}` → 与今天**逐字相同**（`hi`），答案里没有路径、没有行数。
3. 记录里是**全部** 5000 行，一条不少；末行是 `[exit 0]`。
4. `bash {command: "seq 1 5000; sleep 300", timeout: 1000}` → 记录里是到点前打出来的那些行，
   末行是 `[timed out after 1000ms …]`；那条 `sleep` 的进程不在。

## 跨特征对照

- **`.scratch/job-output/spec.md`**：它把**作业**的输出落成一份文件；本特征把同一份形状推广到**前台**，
  于是「记录住哪」从「作业的记录」升格为「命令的记录」。它的决策 7（重定向只报告、不拒绝）不动，
  它的决策 5（记录随进程消失、`job_kill` 不删）原样适用于前台。
- **`.scratch/bash-lifetime/spec.md`**：本特征**翻**它的决策 1（「答案是字符串」不再当然后——它现在
  可能是一个头一行加一条路径）与「非目标：不改 `bash` 的任何行为」（只翻「输出去哪」这一半：毫秒、
  默认值、不封顶、到点收整棵树一个字不改）。它的决策 7 与 10（作业没有时限、没有人通知）**不动**，
  本特征一个字不碰——这正是本特征**不**加 `wait` 的理由。
- **`.scratch/omp-parity/spec.md`**：`write` 剥掉抄来的回声是「答案的形状可以为了别的目的改」的先例。
- **`.scratch/session-after-refresh/spec.md`**：它把「读记录再轮询」当形状；本特征让前台也有一份可读的
  记录，与之同向，但记录**仍然不进 jsonl**。
