# 03 — 停掉一条后台作业

**What to build:** 跑飞了的作业，模型能自己收掉。`bash_kill {job}` 把那条命令**连它起的子孙**一起停掉，
把还没被读走的输出一并带回（不让它凭空消失），然后把这个句柄从注册表里**忘掉**——
所以这是「停止」也是「不再关心」，一条后台进程不会因为没有停止手段而留在机器上没人管。

**Blocked by:** 02（后台执行：起一条命令拿句柄，读它打出来的新行）

**Status:** ready-for-agent

## 为什么「停」与「忘」是同一件事

作业的三种结局——被停掉、自己退出了、起来就失败了——都必须能**离开注册表**，否则注册表随进程无限长，
而模型手里那串 `j1`、`j2`… 也永远说不清哪个还在跑。本票定的规则是：**`bash_kill` 是唯一的收摊动作**，
对活着的作业它是「停」，对已经退出的作业它是「报出退出码，然后忘掉」。两次叫同一个句柄，
第二次得到的就是「没有这个句柄」那条指名拒绝——「忘掉」是幂等的，第二个调用者只是发现它已经不在。

**读那边不产生 `[stopped]`**：`[stopped]` 只可能出现在 `bash_kill` 的答案里，
`bash_output` 的状态行只有 `[running]` 与 `[exit N]`（票 02 定的）。一个状态词只在一种答案里出现，
读的人不必问「这条命令是被我停的，还是它自己死的」。

## 要做的事

- **`bash_kill {job}`**（required: `job`）。三种答案，一种形状——「还没读的输出（若有）+ 一行状态」：
  - 还活着：停掉整棵树 → `[stopped]`
  - 已经退出了：`[exit N]`（把它还没被读走的输出一并带回，免得模型先读后停的次序变成一次静默的数据丢失）
  - 句柄不认识：**抛**（缝把它变成给模型的错误），话里点明**本会话还活着的句柄有哪些**——
    与 `skill` 对不存在的技能、`read` 对不存在的文件同一条纪律：拒绝要指名，且要给下一步
- **收的是整棵树**：与票 01 用的是**同一个**收尾函数（先收子孙、再请壳停、最后 `destroyForcibly`）。
  本票不写第二份杀进程的代码。
- **从注册表里删除**：三种答案都在返回前把 `{thread-id job-id}` 这一项去掉；会话的计数器不回退
  （`j1` 用掉就不再出现，免得两个不同时刻的作业拿到同一个名字）。
- **句柄是字符串**（`"j1"`），不是数字：它是模型手里的一句话，不是序号。

## 不要做的事

- 不做「停掉本会话的全部作业」这种批量动词（要收摊就一条条收；批量停是又一个语义）。
- 不做自动清理（「退出后过一会儿自己消失」这类），不做作业列表端点，不挂 park。
- 不动 `cap.mcp` 的服务器生命周期——那是另一件事（一个服务器是会话级资源，一个作业是一次性的）。

## 验收

- [ ] 停一条在跑的：起一条会写自己子进程 pid 到临时文件、然后 `sleep 300` 的命令，
      `bash_kill` 的答案以 `[stopped]` 收尾，且**那个 pid 不在了**（对 pid 发信号 0，失败即通过）
- [ ] 停之前没读的输出不会丢：起一条先打几行再睡的作业，**一次都不读**就 `bash_kill`，
      答案里**有那几行**
- [ ] 已经退出的作业报出退出码并忘掉：起一条以非零码结束的命令，等它结束，`bash_kill` 答 `[exit 3]` 这种形状；
      紧接着 `bash_output` 得到的是「没有这个句柄」那条**指名拒绝**
- [ ] 不存在的句柄：指名拒绝，话里列出本会话还活着的句柄；再叫一次同一个句柄得到**同一条**拒绝
      （「忘掉」是幂等的）
- [ ] 状态词不串场：全量套件里 `[stopped]` 只出现在 `bash_kill` 的用例断言里；
      `bash_output` 的用例断言里没有它
- [ ] 工具表跟着改好：`bash_kill` 进了两条编辑模式的清单、三处硬编码清单、「十八个」这类措辞
      （15 + 3，票 02 之后再 +1）
- [ ] `timeout 1500 clojure -M:test -m harness.test-runner` 通过，失败**用例名**与基线一致；
      跑完 `pgrep -fl "harness.test-runner"` 只剩正在跑的那一条（**一条作业都不留**）
