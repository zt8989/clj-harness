# 02 — 后台执行：起一条命令拿句柄，读它打出来的新行

**What to build:** 模型能起一条**没人等**的命令，拿到一个句柄（`j1`），然后在自己想看的时刻去读它
打出来的**新行**、它还在不在跑、退出码是多少。命令的 cwd 与 `bash` 一样是本会话的项目目录。
作业活在**这个进程**里，按会话分家，JVM 退出时全部收掉。

**Blocked by:** 01（前台的时限）——不是因为它缺 01 的能力，而是两张票动同一处（`infra.shell` 的收尾与
`cap.tools` 的工具表）与同一套词（毫秒、`timeout`、「要停的时候收整棵树」只写一遍）。

**Status:** ready-for-agent

## 为什么起与读是一张票

「起来了」本身不是一个能验收的行为：注册表的形状（游标、有界尾巴、丢了多少行）是被**读**的需求决定的，
先做「起」等于猜。`infra.shell/start` 已经给了这台机器的一半——长活进程、stdout 排队、`:next-line`
带等待上限、`:stderr`、`:alive?`、`:close!`（收整棵树）。今天它只有一个调用者：MCP 的 stdio 服务器。

## 要做的事

### 一个新 ns 装作业，两个新工具只是它的脸

`cap.tools` 是「十五个工具的**脸**，别的什么都不是」，所以注册表落在**新的 `harness.cap.jobs`**：
起、读、收函数与注册表；`cap.tools` 里只放两个名字、两段描述、两个参数表，body 一行转发。
（先例：`cap.glob` / `cap.todos` / `cap.web` 都是这样被 `cap.tools` 引的。）

### 注册表（spec 决策 8）

- 形状 `{thread-id {:counter n :jobs {job-id job}}}`，进程内、`atom`、按**会话**分家。
  job id 是**每会话的计数器**：`j1`、`j2`…（短、可读；它只在会话里有意义，不需要全局唯一）。
- 一个作业记着：句柄、**游标**（读到第几行）、**一圈有界尾巴**（最近 500 行，一个 `def`）、
  **被挤掉的行数**、以及「退出了没有、退出码多少」。
- **run 结束不杀它、会话被删也不动它**（杀了就等于后台执行没用）。JVM 退出时全部收掉。
- 收尾要是一个**有名字、能被直接调用**的函数（`jobs/shutdown!` 的形状），退出钩子只负责装它一次
  （`cap.mcp/ensure-exit-hook!` 的先例）。**不为了它写 forked-JVM 的测试**——两个 JVM 对一个配置家
  会挂十三分钟，这是本仓已经踩过的坑，`cap.mcp` 那边对这条尾巴的处理是「写进测试文件的注释里 +
  手工核一遍」，照办。

### 输出：一圈尾巴，丢了就说丢了（spec 决策 9）

- 输出**不落文件**（不选家、不留清理策略），进内存里的一圈尾巴。
- 泵不要写第二遍：`start` 的句柄已经在两条线程上排干 stdout/stderr（一个进程灌满管道就永远卡住，
  这是 `start` 注释里写着的原因），本票只是在它上面挂一个「把 `:next-line` 倒进那圈尾巴」的排空线程，
  进程退出（队列给出 eof）或 `close!` 时它自己结束。**同一个流不许有两处读它。**
- 游标只对「这个会话读到了哪里」有意义，所以它是作业状态的一部分，不是工具的参数。

### 两个工具（英文作答，与 `bash` 的 `(no output)` / `[exit N]` 同一套写法）

**`bash_background {command}`**（required: `command`）

    起：答案 `job j1 started; read its output with bash_output`
    起不来（shell 没有、进程数到顶）：**抛**，让缝把原话给模型，且不留下一个空作业记录。

**`bash_output {job}`**（required: `job`）

    读：新行 + 一行状态；没有新东西就是 `(no new output)` 那行 + 状态行
    状态行只有三种：`[running]` / `[exit N]` / ——（`[stopped]` 是票 03 的 `bash_kill` 才有的）
    有丢行的那一次读多一行 `[N earlier lines were dropped]`
    句柄不认识：**指名拒绝**，并把本会话活着的句柄列出来（`skill` 工具对不存在的技能就是这么答的）

描述里必须写明的三件事：**作业没有时限**（它跑到自己结束，或跑到被 `bash_kill` 收掉）、
**起完之后没有任何东西会告诉你它结束了，你得自己来问**（spec 决策 10）、以及**它的 cwd 与本会话的
项目目录一致**。

### 命令走的是 `bash` 那个 shell，不是「启动一个程序」那条路（spec 决策 12）

`shell/start` 今天服务的对象是**一个要启动的程序**（Windows 上走 `cmd /c`，为的是保住反斜杠路径），
而这里起的是一条 **shell 命令**，它的承诺就是 bash——Windows 上必须是 Git Bash。
所以 argv 的构造要能区分两种形状，且**是一个纯函数**：Windows 那一支在 mac 上也要断言得了
（`infra.shell` 的 `select` / `locator` 就是照这个要求写的：链上每一档都能在被测机器上断言）。

### 别忘了跟着改的东西（不改就是当天就撒谎）

- `specs-expose-every-base-tool` 与 `editing_mode_tools_test` 的三条硬编码名字清单。
- `cap.tools` / `kernel.tools` / `test_support.clj` 里「十五个工具」那几处措辞（数字与名字清单）。
- `CONTEXT.md` 的「工具名的写法」是**闭的**一张清单，多两个名字就要多两个。
- `UI` **一个字不动**（spec 决策 13）：`subjectOf` 兜底取第一个字符串参数，对这两个工具恰好就读得对。

## 不要做的事

- 不给作业喂 stdin（`:write-line!` 在那儿，需要时另立票）。
- 不做半阻塞的读（「等 N 毫秒看有没有新输出」），不做通知，不做作业列表端点/面板。
- 不落文件、不进 sqlite、不加审计行、不挂 park、不动 AG-UI 与轨迹。

## 验收

- [ ] 起一条分三次打印的命令：`bash_background` 给出 `j1`；第一次 `bash_output` 拿到已经打出来的行；
      再读一次**只**说没有新东西 + `[running]`；命令跑完之后读到最后一行 + `[exit 0]`
- [ ] 尾巴有界：一条打了**多于 500 行**的命令，读回来的行数**不超过 500**，答案里有
      `[N earlier lines were dropped]` 且 N 与少掉的行数对得上，而且给的是**最后**那些行（第一行不在里面）
- [ ] cwd 与 `bash` 一致：在项目目录里放一个只有那里才有的文件，`bash_background {command: "cat marker.txt"}`
      然后读它——**不解析 `pwd`**，用那个相对路径找得到来证明（现状的 bash cwd 用例就是这套做法）
- [ ] 句柄按会话分家：A 会话起的 `j1`，B 会话读它得到**指名拒绝**；A 自己读得到
- [ ] 起不来的时候不留下空作业：让 `start` 抛一次（例如 `with-redefs` 一个会抛的 `shell/start`），
      断言缝把原话给了模型、且注册表里没有多出一个作业
- [ ] 进程退出时全部收掉：直接调那个有名字的收尾函数（`jobs/shutdown!`），断言树上的进程都不在了；
      退出钩子**只装一次**（连调两次 `ensure-exit-hook!` 只多一个钩子或不多）。
      真 JVM 退出那一条**手工核一遍并写进证据**（一个起作业、然后退出的子进程；第二次跑 `pgrep` 找不到）
      ——**不写 forked-JVM 的自动化用例**，理由抄 `cap.mcp` 测试文件里那段注释（两个 JVM 一个家会挂）
- [ ] **命令进的是 bash**：那条 argv 构造是纯函数，判据里**有一条 Windows 的**——在上面断言
      「一条 shell 命令」拿到的是解析出来的 shell（Git Bash 的那一档）而不是 `cmd /c`，
      而「启动一个程序」（MCP 那条路）拿到的仍是 `cmd /c`。这条在这台 mac 上就要跑得过
- [ ] 新 ns 进了 `harness.test-runner` 的清单，且**只进一次**（`grep -c` + `sort | uniq -d` 空）
- [ ] 工具表跟着改好：`bash_background` / `bash_output` 出现在两条编辑模式的清单里（它们不属于任何家族），
      三处硬编码清单与「十五个」的措辞都跟上了
- [ ] `timeout 1500 clojure -M:test -m harness.test-runner` 通过，失败**用例名**与基线一致；
      跑完 `pgrep -fl "harness.test-runner"` 只剩正在跑的那一条（**不留作业进程**）
