# 02 — 挂死、崩掉、改声明：一个坏掉的服务器自己站起来

**What to build:** 01 让一个**听话的**服务器能用。这一票让一个**不听话的**服务器不拖死任何人：调用挂死会在
超时后变成这次调用的错误结果（run 继续）；服务器进程中途死了，下一次用它会**重连**（重新 spawn、重新握手、
重新列工具）并照常把事办完；`mcp.edn` 里那条声明改了，下一次用它走的就是新的命令；服务器吐出来的
不是 JSON-RPC 的一行，会被**指名**当成协议错误，而不是被当成日志静默跳过。

**Blocked by:** 01

**Status:** ready-for-agent

## 决策

- **每个请求一个超时**，默认 60000ms，可按服务器用 `:timeout` 覆盖。超时的结果是一条**指名**的错误结果
  （server 名 + tool 名 + 毫秒数），不是异常、不是空结果——模型要能读懂「这次没成，因为超时」。
  超时后**这条连接要丢掉**（重连走回下一票/本票的重连逻辑）：一个还没回话的请求留在原地，后面每条消息
  都会跟它错位。
- **连接是缓存，不是事实。** 一个连接的身份是（会话的项目身份 × server 名 × **这条声明的形状**）：
  - 进程死了（stdout 到 EOF / 写入失败）→ 下一次用它时重连，**工具清单重新列一遍**（服务器重启后可能多一个
    少一个工具，表要跟着变）；
  - 声明改了（命令、参数、环境、超时任一不同）→ 下一次用它时重连，不看名字相同就复用；
  - 声明不见了（文件里删了这一条）→ 它的工具离开工具表，进程被收掉。
  这三条就是「配置每次现读」在长活连接上的对应物：文件是现读的，连接不能装作文件没改过。
- **协议错误要指名，不要宽容。** MCP 规定 stdout 只走协议消息、日志走 stderr，所以 stdout 上一行不是
  JSON 就是**这个服务器的错**：连接标记为坏、原因里带上那一行（截断到可读长度）。**不静默跳过**——
  「服务器在往 stdout 打 banner」如果被吞掉，下一个出现在协议位置上的怪东西就没人知道它是从哪来的。
  子进程的 stderr 永远**只当诊断读**（可入状态面），绝不参与协议。
- **不许留僵尸**：进程自己退出、我们主动收掉、超时清理，三条路径都要把进程回收干净（`waitFor` + 必要时
  `destroyForcibly`），并且不许有线程继续读一个已经死掉的 stdout。
- **一个坏服务器不影响别人**：这一票所有失败都止步于「这个服务器的工具用不了」，run、其余服务器、
  其余会话一律照常。失败一律落一行 `mcp/server` 审计行（边是唯一写入者，见 01），且**重连成功也落一行**
  ——「它自己站起来了」是有人需要知道的事实。

## 验收

- [ ] `:timeout` 生效：服务器挂住不回话 → 这次调用的结果是**指名**超时的错误结果，run 照常收尾并继续
      下一轮；那条连接被丢弃
- [ ] 测试从外部杀掉子进程（`.destroy`）→ **下一次调用重连成功**并把结果交回来；审计行里能看到
      断开与重连这两件事
- [ ] 重连后**工具清单重列**：假服务器换一套工具再重启，表跟着变（新增的进表、消失的离表）——两条断言
- [ ] 改 `mcp.edn` 里那条声明（换命令/加参数）→ 下一次用它连的是新命令；只改超时也算改（同一个断言家族）
- [ ] 从 `mcp.edn` 里删掉这条声明 → 它的工具不在表里了，子进程被收掉（断言进程已不在）
- [ ] 服务器往 stdout 打一行非 JSON → 连接标记为坏、原因指名那一行；**不是**静默跳过
- [ ] 子进程写 stderr 一行 → 握手与调用完全不受影响
- [ ] 一个服务器坏掉时，另一个服务器的工具在这一轮里照常调用成功（隔离断言）
- [ ] 三条收尾路径（自杀 / 主动收 / 超时）都不留僵尸进程，也不留读死掉的 stdout 的线程
- [ ] 离线全量 `harness.test-runner` 全绿
