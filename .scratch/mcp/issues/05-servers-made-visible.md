# 05 — 看得见：每个服务器现在什么状态、有哪些工具、能关掉

**What to build:** 一个只读端点交出这个会话的 MCP 账本——有哪些服务器、各自什么状态（连着 / 失败了并说明
原因 / 本会话关掉了）、每个服务器眼下有哪些工具在表里；以及一个开关，把这个会话的某个服务器关掉再打开。
界面上一块面板把这些摆出来，**`:env` 的值一个都不出现**（与 api-key 同一条纪律：只有「有/没有」，
没有值、没有长度、没有前缀）。

**这一票同时是 general-harness spec 里 MCP 两条用户故事的收口**：连不上的服务器要**被指名**（而不是
让整个工具面神秘地少几个），以及服务器能被启停。

**Blocked by:** 01, 02, 03

**Status:** ready-for-agent

## 决策

- **状态词只有三个，每个都对得上一个观察：**
  - `connected` —— 握手完成、工具在表里；
  - `failed` —— 最近一次连接或请求没成，**带原因**（服务器名 + 那一句话）。失败的服务器仍在账本里，
    这正是「被指名」的意思：工具没了，但账本告诉你为什么；
  - `disabled` —— 本会话把它关掉了（见下）。
- **关闭沿用本仓已经用了两次的那套词汇**（工具表的 availability 轴、hook 表的 disable/enable）：
  **关闭不是隐藏**——进程被收掉、这一次真的不再 spawn，但它的**工具仍在这张表里**（模型仍看得见，
  `specs` 照旧发给它），调用被既有执行缝以 `:disabled` 拒掉。理由是既有那句：藏起来会让「没有这个工具」
  和「这个工具关着」变成同一个观察，而前者是谎话。
  这是**本会话/本进程**的开关，重启即失——与工具 overlay、hook overlay 一致；**不改 `mcp.edn`**
  （那才是持久的，且是文件的事）。
- **`GET /api/mcp?threadId=..` 的形状**：`{:servers [{:server :transport :status :error :tools [{:name
  :description}…]}…]}`。`:transport` 是 `"stdio"` / `"http"`（人排查问题时要的第一件事）。
  未绑定/未知 thread 照旧是**答案而非错误**：声明是从**用户级 + 该 thread 的项目级**装配出来的，
  未绑定会话看到用户级那份。
- **只读端点不落审计行**——与 `GET /api/project`、`GET /api/model` 同一条规矩；**开关是能改东西的路由**,
  因此它要落一行（`mcp/server` 行，带 `enabled true/false`；这个 kind 在 01/02 已经建立）。
- **面板是自建组件，抄来的文件一个字不改**（与审批门、侧边栏同一纪律）。挂点：侧边栏底部「设置」旁边。
  project-sidebar 08 那版设置页落地后，这块面板**嵌进去**、独立的入口撤掉——本票不做设置页，
  只保证面板本体是能嵌的一块，并且这条去向写在票面里，免得两票各画一份。
- 失败与关掉**是两件事**，面板上不许合并：`failed` 的服务器下一次用它会自己重连（02），
  `disabled` 的服务器**不会**，直到人打开它。

## 验收

- [ ] `GET /api/mcp?threadId=..` 交出上面那个形状；三个状态各有用例（连着 / 失败带原因 / 关掉）
- [ ] **哨兵测试沿用既有形态**：把 `:env` 的一个值设成可辨认的哨兵，对**整个响应体**做字符串搜索，
      断言哨兵不出现（不是断言某个字段为空）；日志文件同样搜一遍
- [ ] 关掉一个服务器 → 它的工具**仍在** `specs` 里、调用得到 `:disabled` 的工具结果、进程被收掉；
      打开 → 重新连上、调用成功（两条断言）
- [ ] 关掉的是一个**失败的**服务器也成立（关掉不该需要先连上）
- [ ] 开关只影响这个 thread：另一个 thread 的同一个服务器照常
- [ ] 未绑定 thread 问这个端点 → 看到用户级声明，不是 400
- [ ] 面板显示：服务器名、transport、状态、失败原因、工具清单（名字），以及每个服务器一个开关；
      真 Chromium 走一遍三个状态并截图留档（截图里要有失败原因那行字）
- [ ] `cd ui && npm run build` 全绿；`cd ui && npm test` 全绿（新组件有自己的用例）
- [ ] 离线全量 `harness.test-runner` 全绿
