# 06 — 前端：四条新工具的步骤行读得出来

**What to build:** 对话里 `glob` / `todo_write` / `web_fetch` / `web_search` 的步骤行不再是
"扳手图标 + 第一个字符串参数"，而是像它们邻居一样一眼看懂：一个对的图标，一句说得清这件事的摘要。

从用户视角：一次搜索在对话里是"放大镜 · `clj harness sqlite`"，一份清单是
"清单图标 · 完成 3 / 7"，一次取页是"地球 · `example.com/a`"。不用点开就知道这一步干了什么。

**Blocked by:** 02, 03, 04, 05（没有工具就没有行可读）

**Status:** ready-for-agent

## 形状

改的是 `ui/src/components/message-parts.tsx` 里**两张按工具名开的表**——别的什么都不用动：

- `TOOL_ICONS`：四个名字各配一个图标。**不许复用已有工具用过的那个**（`anchor_grep` 已经占了放大镜），
  因为那张表的意思就是"看一眼图标知道这是哪只手"。
- `subjectOf`：四个名字各一个分支。摘要**只读参数，不做解析**——不解析 URL 的成分、不看文件存不存在、
  不去问库。这一行的职责是"把模型自己的话转述一遍"，与它邻居逐字同一条纪律。
  - `glob` → 模式，给了根就把根也带上
  - `todo_write` → 进度（完成数 / 总数），空清单时说"清空"
  - `web_fetch` → URL
  - `web_search` → 查询串

**摘要的措辞与同一函数里既有的写法看齐**：`subjectOf` 里既有 `→ 删除` / `→ N 行` 这样的短语，
新加的两处短语（若有）按它写，别在同一张表里换一种口气。

## 决策

- **这张表的默认分支是有意留的口子**：没进表的工具今天也能渲染（扳手 + 第一个字符串参数），
  所以本票交付的是**可读性，不是可用性**——不修，四条新工具也是能用的，只是读起来笨。
- **工具名就是键**，`CONTEXT.md` 说不许有别名，而这张表是又一个理由：改了名，图标会**静默**丢回扳手。
  四个名字取自票 01 立下的那一条。
- **只动这一个文件。** 不做新卡片、不改助手的组件、不动 `assistant-ui` 那份 registry 源码
  （那是要与上游逐字节可比的东西，见 `copied-ai-elements-use-local-markers`）。
  工具调用的 result 区本来就渲染结果，所以 `todo_write` 写下的清单在对话里是看得见的，
  不需要为它做组件。
