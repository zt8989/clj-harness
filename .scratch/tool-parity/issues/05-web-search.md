# 05 — `web_search`：搜索并拿回结果

**What to build:** 模型给一句查询，拿回几条结果——每条有标题、URL 和摘要——它就能挑一条再
`web_fetch` 去读。没配 key 的时候它拿到的是一句**指名**的话（要设哪个环境变量、放在哪），
不是一个空结果，也不是一个"没找到"的谎。

从用户视角：配一次 `.env`，之后搜索就一直能用；答案里看得见"共几条"以及"还有更多、怎么才能看到"。

**Blocked by:** 04（客户端与拒绝词汇都在 `harness.web` 里，本票当既有物用）

**Status:** ready-for-agent

## 形状

- 工具名 `web_search`，参数 `query`（必填）与 `count`（可选，默认 5、上限 20）。
- 答案：每条 `标题` / `URL` / `摘要` 三行成一块，块之间空行；头部说清共几条；
  上游说还有更多时补一句"还有更多，收窄查询或调大 count"。
- **检索结果一条都没有是一句答案**（"没有结果"），不是错误。
- 不带 `:requires-approval`：它的目的地在一条人写的配置里，不是每次调用由模型挑（与 `web_fetch` 的对比见
  spec 决策 8 与 11）。不适用 `:fence-paths`，不属于任何编辑家族。

## 决策

- **键的解析抽一次，不复制一份。** `HARNESS_SEARCH_API_KEY` 的解析顺序与 provider 的
  `HARNESS_API_KEY` **完全相同**（配置家的 `.env` 优先，然后环境变量）——那段逻辑今天私有在
  `harness.providers`（`parse-dotenv` / `api-key`），本票把它抽到 `harness.home/env-value`
  （文件归 `home` 管），两个用户共用。**provider 的优先级断言要保持逐字不变地通过。**
- **只有一个厂商，一个常量，一处。** 端点与请求头写在 `harness.web.search` 里；
  `harness.web` 不知道任何厂商的存在。要接第二家是加一节，不是改客户端。
- **测试要能把它指到本机服务**：端点从一个**调用时读取**的可改写槽位取（本仓的测试缝纪律：
  `alter-var-root`，不是 `binding`——服务在别的线程上跑），测试把它指向自己起的那台服务，
  于是本票**不打真网络**。
- **key 永不出现**在任何工具结果、任何 jsonl 行、任何端点响应里。做法照 `providers_test` 那条哨兵断言
  （`:961` 的 sentinel + `with-dotenv`）：往配置家的 `.env` 里写一个哨兵值，然后搜结果与日志。
- **上游形状不认识时指名**，不猜：响应里没有那家厂商的结果数组，就说清楚"这不是这个工具认识的形状"
  并点出厂商，而不是回一个空列表——空列表对模型是一句"世上没有这件事"的假话。

## 验收

- [ ] `harness.home/env-value` 存在：名字进、值出，配置家 `.env` 优先于环境变量；
      `harness.providers` 改用它，**`harness.providers-test` 一条断言都不改**全绿
      （尤其是 `.env` 胜过环境变量那条——`:1051` 附近）。
- [ ] 新命名空间 `harness.web.search`：请求构造（查询、条数、认证头、`Accept: application/json`）
      与响应解析（标题 / URL / 摘要 / "还有更多"）分开成可单独测的两半。
- [ ] 新命名空间 `harness.web-search-test` 写进 `harness.test-runner/test-namespaces`，
      自带本机 http-kit 服务（`{:port 0}`），覆盖：
      - 正常响应 → 三条结果的标题 / URL / 摘要都在答案里，且**顺序与响应一致**；
      - 服务端**看到**的查询串与条数正确、认证头就是那个哨兵值；
      - 空结果 → "没有结果"，`error` 为假；
      - 形状不认识（缺结果数组、JSON 坏）→ **指名**拒绝（报出厂商），不是空列表；
      - 401 / 429 / 500 → 指名拒绝，报出状态码；
      - 超时 → 指名拒绝、带毫秒数，run 不炸；
      - `query` 空白 / `count` 不合法（0、负数、非整数、超过上限）→ 指名拒绝。
- [ ] **没配 key 时**：指名拒绝，消息里包含 `HARNESS_SEARCH_API_KEY` 这个名字与"配置家的 `.env`"，
      并且**没有发出任何网络请求**（本机服务那条测试的请求计数为 0）。
- [ ] **哨兵断言**：`.env` 里写了哨兵 key，跑完一次成功搜索之后——工具结果里没有它、
      本次 run 的 jsonl 里没有它、`GET /api/settings` 与 `GET /api/model` 的响应里没有它。
- [ ] 工具描述写明：结果来自哪一类服务、几条是默认、以及"读某一页用 `web_fetch`"。
- [ ] `tools_test/specs-expose-every-base-tool` 两份名单各加一个 `web_search`。
- [ ] `clojure -M:test -m harness.test-runner` 全绿（除基线的两条环境失败）。
