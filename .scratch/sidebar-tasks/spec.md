# spec: 侧边栏分两块——任务（未绑定的会话）与项目

2026-09-20 立。**要的是：侧边栏分成两块。上面一块是「任务」——未绑定的会话，平铺、不分组；下面一块是
「项目」——今天那样按目录分组。归档是一块，两种都装。**

> 我希望侧边栏分两块，一块是任务（就是 unbound，不分组），还有一块是项目（现状）。

## 背景与定位

**一、库里早就有「未绑定」这个状态，界面一个都不显示。** `sessions.project_id` 与 `path` 一起为
NULL（schema 的 `CHECK` 保的），而 `GET /api/projects` 按 `project_id` 分组、把 `nil` 那一组丢掉。
这个状态由两件事产生：**移除项目**（`BEFORE DELETE` 触发器在同一句里解绑，会话留着
`last_project_path` 这个记忆）与**显式解绑**（`bind! id nil`，两列连同记忆一起清掉）。两件事的差别
不是风味，是「这段对话还记不记得自己有家」——本特征的任务判据正是踩在这条差别上。

**二、界面今天不产生未绑定会话，而这是上一特征的决定。** `project-sidebar` 决策 1：「项目是一等实体，
界面不再产生未绑定会话。新建任务时必须先选项目；一个项目都没有时说的是『先添加一个项目』」。
于是「新建任务」是一颗**必须先有项目**的按钮。**本特征推翻这一条**，理由写在决策 2 与代价一节里。

**三、归档今天住在每个项目底部。** 任务没有项目，归档要有地方去——而既然任务与项目会话是同一类东西
（都是会话，只差有没有家），两块各有一个「已归档」是同一件家具的两份。

## 决策

1. **谁是任务：库里没有项目、也**不记得任何目录**的会话**（`project_id IS NULL AND
   `last_project_path IS NULL`）。**移除项目放走的会话不是任务**——它们记得那个目录，把目录加回来
   就回来（`project-sidebar` 07 的行为与确认框文案一字不动）。显式解绑来的会话是任务。
   这条判据比「unbound」窄一格，是有意的：一块装「从来没家的对话」，不装「家在别处的对话」。
2. **「新建任务」不再要求先有项目：它造的就是一个任务。** 铸 id → 登记一行未绑定无记忆的会话 →
   切过去。有项目没有项目都能点，且**不会**因为界面上选中了某个项目就落进那个项目——
   项目里的新会话是**项目行那颗**按钮的事（那颗按钮照旧，一个字不改）。
3. **一条会话什么时候成为这个家的一条会话**：点「新建任务」当场登记，或者**第一次跑起来的那一刻**
   登记（`POST /` 收下一个库里没有的 thread id 时）。别的路径不产生任务行；页面挂载时铸的那枚 id
   **不登记**——一行登记配一段真的对话，否则每刷新一次就多一条空任务。
4. **任务的磁盘事实按 stem 问整棵树**（与点开它时 rebuild 问的是同一个问题），不是只看 `.unbound/`：
   显式解绑来的任务，它的日志还留在旧 workspace 里，行上写「还没有日志」就是撒谎。一个文件都没有
   ⇒ 两个字段为 `null`（既有含义：还没有日志）；同一个 stem 命中不止一份（换绑被拒留下的两份）⇒
   也为 `null`，点开会拿到服务端那句按名字的拒绝。
5. **归档是一块，装任务也装项目**：每个项目底部那个折叠组收掉，改成整个列表最下面**一块**默认折叠的
   「已归档」，里面既有归档的任务、也有归档的项目会话（行上带它从哪个项目来——分组没了，
   行上得能说出它从哪儿来）。空组照旧不画。
6. **本特征不给任务加「归到项目」的入口**。（落地时核过一处：`composer-chrome` 那条**目录选择器**
   本来就是「这个会话的目录」，对任务照旧有效——它是一条既有的路，不是本特征加的，也不因此改变本条
   的边界。）一个任务就是一段不属于任何目录的对话，这一版就让它一直是。
7. **词叫 Task / 任务。** `CONTEXT.md` 里「任务」已经被**任务清单**（`todos`）占着，所以本特征在词表里
   给「任务」立一个词条、写明两者的分界（任务 = 未绑定的会话；任务清单 = 本会话的待办），
   各自带「别叫成」。

## 代价（说清楚，不藏）

- **界面重新产生没有围栏的会话。** 未绑定 = 恒等：相对路径以进程工作目录为根、围栏关着、
  不读项目的 `harness.edn`。这是既有语义（`harness.cap.project` 的核心回归承诺），本特征只是让它
  重新从界面可达——决策 1 当年正是为了不走到这里才立的那条。
- **项目的「已归档」分组没了。** 归档的行从项目里挪出来，行上要能说出原属哪个项目；
  与归档有关的既有验收（分组、折叠、行落点）都要跟着改。
- **页面挂载期的那一场仍然短暂地不在清单里**（它没跑过、没登记）。这是决策 3 的字面后果，
  不是遗漏：它一跑起来就在了。

## 非目标

- 不做把任务绑进项目，也不做在项目之间搬会话。
- 不改 schema：未绑定这个状态早就有，不加表、不加列（`db_test` 的元断言原样绿）。
- 不动项目块的其余部分：分组、顺序、项目行上那颗「新建会话」、移除项目、添加项目。
- 不移除项目放走的会话（照旧不列，等目录回来）。
- 不做任务的重命名 / 标题生成 / 搜索。
- 不改 AG-UI 帧、不改既有管理边的形状（`GET /api/projects` 那份 payload 由数组换成对象是本特征
  自己的改动，见票 01）。

## 验收主线

1. 三关全绿：`clojure -M:test -m harness.test-runner`、`cd ui && npm run build`（`tsc --noEmit`
   0 error + Vite 通过）、`cd ui && npm test`。
2. **一个项目都没有的家**：点「新建任务」→ 任务块出现、新行标 `CURRENT`、页面在它上面、能立刻发一条。
3. **任务跨重启**：跑完一轮、重启进程，它仍在任务块里，体积与时间来自它自己的日志。
4. **移除项目放走的不进任务块**：移除一个有会话的项目 → 那些会话既不在项目块也不在任务块；
   把目录加回来，它们连归档标记一起回来（07 原样）。
5. **显式解绑的进任务块**，且行上的体积与时间来自它留在原 workspace 的那份日志。
6. **归档是一块**：归档的任务与归档的项目会话都在同一块「已归档」里，默认折叠，只要有一个就画、
   一个都没有就不画；归档前后 jsonl 的字节数与 mtime 逐字不变。
7. **刷新落回任务**：记住的是一场任务时，刷新之后仍在那一场（与
   `session-after-refresh` 票 03 的那次走查同一次）。
8. 真 Chromium 把上面走一遍，截图留档在 `.scratch/sidebar-tasks/evidence/`。

### 01 落地记录

`harness.cap.project` 多了 `tasks`（一个 WHERE 子句）与 `register-session!`；`sessions` 的 0/1 →
布尔那一步抽成私有的 `as-session`，两个读者共用一份转换；`harness.edge.http` 的 `projects-get`
答 `{projects, tasks}`，多了一个 `task-row` 与一条 `POST /api/sessions`，`handle-run` 在解析**之后**
登记陌生 thread id。

- **`tasks` 踩的是两个列，不是一列。** `project_id IS NULL` **且** `last_project_path IS NULL`：
  移除项目放走的会话留着记忆，等的就是目录回来，把它倒进任务里是这一票最容易做错的地方
  （用例里两条都钉了：显式解绑的**在**、移除放走的**不在**）。
- **任务的磁盘事实按 stem 问整棵树**（`replay/threads` 一次走树、按 stem 分组），不是只看
  `.unbound/`：显式解绑放走的会话日志留在旧 workspace 里，只看 `.unbound` 的行会说「还没有日志」，
  而**同一行点开会走 rebuild**——两者必须问同一个问题。一份都没有 ⇒ 两个 null；**不止一份**也
  ⇒ 两个 null（`replay/locate` 按名字拒绝，行不替它猜哪一份才是这段对话）。
- **`register-session!` 是 `ON CONFLICT DO NOTHING`，不是 DO UPDATE**：一句「这条会话存在」
  绝不能把一条已绑定的会话解绑、也不能把某条会话的「记得哪儿」抹掉。**`bind!` 的 nil 方向照旧不建行**
  ——放掉一段对话与开始保管它是两句不同的话，这条一字未改。
- **run 边也登记，登记发生在解析之后。** 页面挂载时铸的那枚 id 谁也不认识，它跑起来的那一刻就是一段
  真的对话——**界面自己开的那一场不能是侧边栏唯一看不见的一场**。放在解析之后是既有那条
  「被拒的请求一个字节都不留」：一个不是协议的 body 过去之后库里不多一行（用例里有）。
- **既有那条「跑过的未绑定会话不属于任何项目」的用例改了对象、也改了说法**（它现在属于**任务**），
  这是本票唯一一处改动的既有断言；别的断言只随 `GET /api/projects` 的数组→对象迁移动了取值方式
  （新的 `sidebar-listing` / `listed-projects` / `listed-tasks` 三个测试助手，五处 call site 共用）。
- 验收：**915 tests / 11693 assertions 全绿**（改动前 913 / 11647；本特征共 +2 个用例：
  两半清单与「谁是任务」那条，以及任务那一行也答同一个注册表问题的窗口态那条）。

### 02 落地记录

`lib/projects.ts` 的 `listProjects` → `listSidebar`（答 `{projects, tasks}`）+ 新的 `startTask`；
侧边栏上面多一块平铺的任务、`newTask` 改成「铸 id → 登记 → 切过去」，两句拒绝
（`refusal.noProject` / `refusal.noProjectSelected`）与它们的中文/英文词条一起删掉，
空态那句话改口；`session-memory.listedSession` 改成吃整份 payload、**两块都找**；
`composer-chrome` 的那条目录选择器跟着改吃 `.projects`。

- **项目行的点亮不再决定任何事。** 它原来唯一的作用是回答「新任务落哪个项目」；现在它只是那行长什么样，
  而且顺手诚实了一格：**当前会话是一个任务时，没有任何项目行被点亮**（原来会退回到列表第一个项目）。
  这条写进了票面与这里，因为一块只是家具的高亮将来要么给它一个意思、要么收掉它。
- **页面永不落在清单列不出的会话上。** 移除最后一个项目那条落地路径改成与「新建任务」同一条三步
  （登记 + 切过去）；**挂载时铸的那枚 id 照旧不登记**——一行登记配一段真的对话，它第一次跑起来时由
  run 边登记（票 01）。
- 验收：**47 条 UI 用例全绿**（46 → 47：新增那条渲染用例，见票 03）、`tsc --noEmit` 0 error、
  `vite build` 通过；真 Chromium 走查（见票 04）里「零项目点新建任务 → 任务块出现、CURRENT、能立刻发」
  与「跑完一轮刷新 → 仍在任务里」两条都过了。

### 03 落地记录

`ThreadListItem` 多了一个可选的 `label`（行自己说的一句关于自己的话），项目底部那个折叠组收掉，
侧边栏底部多了一块全局的「已归档」（两类行混在一起、默认折叠、空则不画），归档当前会话的落点
按**会话的种类**分（项目会话 → 同一个项目；任务 → 另一条任务）。

- **label 是行自己说的，不是它知道项目是什么。** 归档块是平的，行上不说出「它原来属于哪个目录」
  就没有地方说得出——而这个答案要紧：那段对话的日志还在那个目录的 workspace 下。组件只收一个字符串。
- **两个集合不通用。** 归档一条任务时页面切到另一条**任务**，绝不切进某个项目的会话里——
  不然「归档」就成了获得一个家的路。
- **`session.allArchived`（「这里的会话都归档了」）留着**：项目里没有未归档的会话时，那句话现在指向
  下面那块「已归档」，仍然是真的，而且比「这个项目里还没有会话」有用。
- 验收：走查里「归档一条任务 → 块出现且默认折叠、页面不挪窝」「归档一条项目会话 → 同一块里多一行、
  带着项目名」「取消归档 → 回它自己的项目」三条都过了；磁盘对照沿用既有那条（归档不写日志）。

### 顺手修掉的一处：隔离判据分两半（同分支，2026-09-20）

本特征验证过程中踩到并修掉了一件事，记在这里而不是另开一票：`harness.test-runner` 的隔离复查
**只**看真家 `harness.db` 的 `[bytes mtime]`，于是把「**别人**（开发者自己那个活着的 harness 会话）
写了它」也判成本进程越界，报出来的却是一句指向代码路径的话。

- 观察：两次 ISOLATION FAILURE 都出现在我用**带锚点的编辑工具**改文件的那几分钟里；对照是同一套用例在
  我只 sleep、不碰任何文件的 7 分钟里跑完，真库的 `[bytes mtime]` 前后逐字相同（`44744704 1789869896`
  -> 同一个），那次没有报错。
- 修法（两半，各自说得出自己知道的事）：`harness.infra.db/store-paths-opened` 记下**本进程**解析并打开
  过的库路径，`isolate!` 之后清空——**开过真家就是失败，按名字报出路径**（只读没动字节也算：读到别人的
  行就已经不干净）；文件动过而本进程没开过它 ⇒ 一行 `ISOLATION NOTE`，**不算失败**。用例：
  `test/harness/test_runner_test.clj`（纯输入，不碰任何库）；`AGENTS.md` 与 `docs/rules/testing.md`
  跟着改口。
