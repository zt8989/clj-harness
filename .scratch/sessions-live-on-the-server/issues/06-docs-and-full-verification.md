**What to build:** 仓库里关于「会话归谁」「历史从哪来」「记录是什么」的每一处说法与代码一致；
全量测试、UI 套件、构建全绿，基线写进本 spec；落地记录。这一票是扇入点：01–05 落地之后，
现状描述才真的过时到可以一次改对。

**Blocked by:** 02, 03, 04, 05

**Status:** ready-for-agent

## 要落地的判断

1. **`overview.md` 的铁律 1**：新措辞照 ADR 决策 10——**「run 中不读自己的日志（内存里就有）。日志只
   append、异步写、允许落后，且永远是会话的有序前缀。日志是恢复源；运行时的真相在内存。」**
   「写不进去就发不出去」那句推论**要删掉**（它不再成立），并把「写失败去哪儿了」指给降级态。
2. **`overview.md` 的铁律 3**：「客户端持有会话。服务端不建会话状态权威」**反过来**。新的说法要同时
   保住它真正想保的那件事：**服务端不做订阅**（副本自播 + 对账，不是推送）——这是它剩下的价值，
   别连同它一起丢。
3. **同一份文件的状态表**：「会话消息 | **客户端**（+ jsonl 记录）| 铁律 3」那一行改写；
   「system 消息里 hook 追加的那部分 | 不存」那一行要跟着核（注入物现在是**会话的一部分**，
   它不再每轮现算——这一点直接来自验收 6）。
4. **`kernel.md` / `edge.md`**：请求怎么拼出来（`inbound` 那一节）、`:context/injected` 与尾随消息的位置；
   `client.md`（副本、对账、刷新走内存）；`skills-and-instructions.md`（「对话归客户端所有，
   服务端每轮现收现算」那一节的推导要重写；「技能正文是派生的」**不改**）。
5. **`CONTEXT.md` 的「会话」词条**：今天写「一段有日志、可重建、可续跑的对话」。新模型下它是
   **服务端持有的**一段对话——词条要跟上，别让术语表描述一个已经不成立的世界。
6. **`.scratch/job-output` 决策 3（「帧就是客户端的会话」）**：它被推翻，按仓库约定**不改旧 spec**，
   但要**指出来**（本 spec 的跨特征对照已经写了）。
7. **README 一个字不加**。
8. 两套全量的报数与真浏览器走查证据，基线写进本 spec 的「已验证到什么程度」。
