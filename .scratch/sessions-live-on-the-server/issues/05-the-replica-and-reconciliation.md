# 05 — 副本与对账：刷新走内存

**What to build:** 浏览器是**只读副本**：它自播，只在**动作发生**与**刷新**时与服务端对账，配一个**单调序号**。
**刷新走内存，不走记录**。`rebuild` / `sofar` 的 live 语义跟着改；`stats` / `trajectory` 这些 live 视图
读内存。

**Blocked by:** 03

**Status:** ready-for-agent

## 要落地的判断

1. **为什么刷新必须走内存**（ADR 决策 8）：记录允许落后。走记录 ⇒ 刷新看到的是**更早的那一版**，
   而屏幕上刚才还显示着更新的内容 ⇒ 用户看见「会话丢了尾巴」，而它其实没丢。这一点是本票存在的全部理由。
2. **单调序号**：谁铸、什么时候加一、副本拿它做什么。它是「对账」唯一的凭据——没有它，副本只能整段重读。
   要定的是**粒度的选择**：一条消息一个序号，还是一帧一个？**我倾向一条消息一个**：副本画的是消息。
3. **对账的两种情形**：副本**落后**（服务端有它不知道的）与副本**超前**（它有服务端不知道的——今天会
   发生，因为客户端是作者；本特征之后应当**不可能**）。超前的处置是这一票的诚实测试：**不许静默丢弃**，
   要么说出来、要么当作一次显式的动作。
4. **`rebuild` / `sofar` 的归位**（ADR 决策 D6）：`rebuild`（`http.clj:1887`）今天读记录、并**先
   `close-off-open-run!`**（`:1827`）。内存成权威之后：
   - **live 会话** ⇒ 读内存（`close-off-open-run!` 不参与——它是对**死掉的**会话做的事）；
   - **冷启动 / 归档 / 作者工具（`evals`）** ⇒ 仍读记录。
   这一票要把这条分岔写在路由的 docstring 里，并**有用例钉住**「刷新不会回到更早那一版」。
5. **`sofar` 的 `:state`**：它今天答「记录里到哪了 + 本进程还在不在答它」（`running?`）。
   内存成权威之后前半句要改成读内存——两者的差别正是本票要处理的东西。
6. **用户正在打字 / 正在滚动**：对账发生时**不许**动它们。这一条要有交代（选中位置、滚动位置、输入框里
   未发出的字），至少要写清「今天会怎样」。
7. **`stats` / `trajectory` 的 live 视图读内存**：它们今天读记录（`stats/log-stats`、`trajectory`），
   在落后窗口里会显示一份更短的会话。要定的是**它们怎么读到内存那份**（同一个 seq？还是一份内存快照）。

## 验收

- [ ] 刷新回到的是**内存那一版**：构造一个「内存比记录新」的状态，刷新后看到的是新的那份（有用例）
- [ ] 副本落后时按序号补上，用户正在打字的位置**不动**（有用例 / 走查证据）
- [ ] 副本超前（构造一个）→ 说出来，不静默丢（有用例）
- [ ] `rebuild` 对 live 会话不调 `close-off-open-run!`；对死掉的会话照旧调（有用例）
- [ ] `node scripts/dev.mjs --scripted` 走查：刷新前后屏幕内容一致
