# 01 — 会话表：出生、寿命、上界

**What to build:** 服务端内存里一张 `thread-id → 会话` 的表。一个 thread 的第一次：读它那份 jsonl、
**重建一次**；其后每次 run 都在内存那份上做。出生在**点进界面**（或对它发起一次动作）时；此后
**空闲 30 秒**放掉。两个钉子把它按住：**正在跑**（run 没结束不放）、**还有没落盘的东西**（run 跑完也要等
记录写完才放）。内存的上界另靠一条：**限制同时运行的会话数量**。

**Blocked by:** —（可以立刻开始）

**Status:** ready-for-agent

## 要落地的判断

1. **表的形状**：一个 `atom`（或等价物），键是 thread-id 的字符串形，值与 `running?`（`http.clj:517`）和
   `session-started`（`http.clj:469`）**同族**——那两张今天的表是这张表的前身，要定的是**并进去还是留着**。
   留着的代价是「同一个会话的状态散在三处」，并进去的代价是一次搬家混进本票。
   **我倾向：本票只立这张表，另外两张不动**——搬家是收口票的事，不是骨架票的事。
2. **出生是「读一次」，不是「每轮读」**：重建走现成的 `edge/replay`（`rebuild`（`http.clj:1887`）用的就是它），
   但**不落任何服务端状态**。它必须在 hook sink 之外跑（重建不是一次 run，
   `replay.clj:425` 的 `assemble` 那段注释说明了为什么那里的 hook 不触发）。
3. **放掉的判据要说得出数字**：空闲 30 秒；「空闲」= 没有 run 在跑**且**没有未落盘的帧**且**没人认领着它
   （票 04 落地后认领也要算）。
4. **两个钉子各自对应一件已经存在的事实**：`running?`（进程内的注册表）与票 02 的「已落盘」水位。
   本票只解前者；后者的接口先留出来，票 02 填。
5. **同时运行的会话数是一个显式的上界**，不是「不会有这么多」：超了要**说出来**（拒绝还是排队，二选一，
   写在 docstring 里），不许静默。
6. **放掉不等于丢东西**：重建出来的那份必须与放掉之前**逐字节相同**——这是本票最重要的那条断言，
   因为它是「日志仍是记录」与「内存才是权威」两句话的接头处。

## 验收

- [x] 放掉再重建：重建出来的历史与放掉之前**逐字节相同**（有用例）
- [x] 跑着不放（run 没结束，空闲计时不生效）（有用例）
- [x] 没落盘不放（票 02 的接口先留，用例先用桩——已落：`watch-unflushed!`）
- [x] 空闲 30 秒后确实放掉（用例拿一个未来的时刻喂 `sweep!`，不真等 30 秒）
- [x] 超了同时运行的上界：**拒绝并说出理由**，且**不留下一个没跑起来的会话**（有用例）
- [x] 表里没有任何东西写进 sqlite / jsonl / 进程日志（有用例：读过的日志长度与 mtime 不变，
      日志树里一个文件都没多）
- [ ] **（移到票 03）**「同一场连跑两轮：第二轮用的是内存那份」——那是**接线**，本票只立表；
      表立好了而 run 还没读它，这在本票上是正常的，不是没做完。

## 落地（2026-09-20）

`src/harness/edge/sessions.clj` + `test/harness/edge/sessions_test.clj`（11 个用例 36 条断言，绿）。
三处实现时才发现、写票时没写到的判断：

1. **会话持有的是「对话」，不是 `message` 行的 submitted 侧。** 那份里有 **system 消息**（每轮现组装）与
   **注入物**（每轮现读现拼），冻结它们就是「改了没生效」。所以持有的是 `replay/sofar` 折出来的那份，
   **并且把只给屏幕看的卡消息（`data` part）丢掉**——它们进不了 provider（`provider-part` 会按名字拒绝）。
   这条推翻了本票原来那句「与 submitted 侧逐字节相同」，也把 spec 的验收 6 作废了（见那里）。
2. **从记录读的是 `sofar` 不是 `rebuild`**：一个会话正是在「有人看它」的那一刻出生，而那在进程重启之后
   就是一份**停在 run 中间**的日志——`rebuild` 会拒绝它，`sofar` 才是为这个场面存在的那个门。
3. **幂等**：`run-started!` 对「表里已经持有的那一枚 run」不当作第二条（否则收口时重放同一次注册会被拒）。

## 修正（2026-09-20，按 ADR 0003：读是窗口，不是全量）

本票立的是表的骨架，已经落地；下面四件事是 ADR 0003 采纳之后才看清的，**补在票 05 / 06**，
不改已经成立的实现：

1. **`(messages thread-id)` 这个全量读不是接口。** 读法要变成窗口：`beforeSeq` + `maxMessages` →
   `{messages, baseSeq, hasMore}`（票 05）。全量那个留着只会诱人写第二个全量调用点。
2. **每条消息要带序号**（票 05 判断 1），而且那个序号必须**能从记录重放出来**。本票的实现没有序号：
   `build` 折出来的是 `{:messages [...]}`。
3. **`:runs` 与 `http.clj` 的 `running?` 是同一件事实的两份。** 判断 1 当时说「另外两张不动」，但
   `registry` 里的 `runs` 与 `live-runs` 现在各答一次「这一场在不在跑」。**接 feed 之前必须合并成一处**
   ——否则窗口的 generation、票 06 的重开判据都要面对两个不一致的答案。
4. `watch-unflushed!` 的桩由票 02 填（原样不动）。
