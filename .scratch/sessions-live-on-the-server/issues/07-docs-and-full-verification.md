# 07 — 收口：两条铁律、状态表、文档、报数

**What to build:** 仓库里关于「会话归谁」「历史从哪来」「记录是什么」的每一处说法与代码一致；
全量测试、UI 套件、构建全绿，基线写进本 spec；落地记录。这一票是扇入点：01–06 落地之后，
现状描述才真的过时到可以一次改对。

**Blocked by:** 02, 03, 04, 05, 06

**Status:** ready-for-agent

## 要落地的判断

1. **`overview.md` 的铁律 1**：新措辞照 ADR 0002 决策 10——**「run 中不读自己的日志（内存里就有）。日志只
   append、异步写、允许落后，且永远是会话的有序前缀。日志是恢复源；运行时的真相在内存。」**
   「写不进去就发不出去」那句推论**要删掉**（它不再成立），并把「写失败去哪儿了」指给降级态。

2. **`overview.md` 的铁律 3**：「客户端持有会话。服务端不建会话状态权威」**反过来**。新的说法要同时
   保住它真正想保的那件事——**服务端不记谁在订阅**（ADR 0003 决策 7）：游标随连接走（`since=N`），
   服务端从会话里取 N 之后发，除了活着的连接，进程不持有任何「谁订了什么」。
   注意**不要**写成「服务端不做推送」——那是错的，feed 就是推的；要保的是「不做按客户端的推送状态」。
   票 05 落地时那句原话（「副本自播 + 对账，不是推送」）按这一条改。

3. **同一份文件的状态表**：「会话消息 | **客户端**（+ jsonl 记录）| 铁律 3」那一行改写；
   「system 消息里 hook 追加的那部分 | 不存」那一行要跟着核——**注入物不是会话的一部分**
   （验收 6 作废时已经查清：指令文件必须每轮现读，注入每轮重算；会话持有的是**对话**，见票 01 的
   落地记录）。还要**新加一行**：窗口 / `baseSeq` / `hasMore` / generation 住在**连接与副本**里，
   不是服务端的状态。

4. **`edge.md`**：feed 的三个动词（`tail` / `append` / `prepend`）、`since` 与 generation 的拒绝、
   `rebuild` / `sofar` 的 live 分岔（读内存 vs 读记录），以及「一条 feed 一条连接」的寿命。
   **`client.md`**：窗口（`baseSeq` / `hasMore` / `revision`）、「显示更早」那颗按钮、补页与重开的
   两种处置、刷新走内存、打字 / 滚动的锚定。**`kernel.md`**：请求怎么拼出来（`inbound` 那一节）、
   `:context/injected` 与尾随消息的位置。**`skills-and-instructions.md`**：「对话归客户端所有，
   服务端每轮现收现算」那一节的推导要重写；「技能正文是派生的」**不改**。

5. **`CONTEXT.md` 的「会话」词条**：今天写「一段有日志、可重建、可续跑的对话」。新模型下它是
   **服务端持有的**一段对话——词条要跟上。同时**新增术语**：窗口 / 尾页 / 补页 / feed / generation——
   它们在这套设计里是承重的名词，不收进术语表就会各自长出同义词。别让术语表描述一个已经不成立的世界。

6. **`.scratch/job-output` 决策 3（「帧就是客户端的会话」）**：它被推翻，按仓库约定**不改旧 spec**，
   但要**指出来**（本 spec 的跨特征对照已经写了）。

7. **README 一个字不加**。

8. 两套全量的报数与真浏览器走查证据，基线写进本 spec 的「已验证到什么程度」。
