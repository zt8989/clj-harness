# 02 — 异步写：每帧、失败进降级态

**What to build:** 记录（jsonl）的写从「流式响应里同步 `spit`」变成**一帧入队、单个消费者逐行 append**。
落后是允许的：记录永远是会话的**有序前缀**。「已经落盘」这件事要变成**问得出口的水位**——票 01 的两个钉子
之一靠它。写失败（盘满、权限）**不许静默**：那个会话进**降级态**，并在界面上说出来。

**Blocked by:** 01

**Status:** ready-for-agent

## 要落地的判断

1. **队列替代锁**：今天 `log!`（`http.clj:388`）在 `log-lock`（`:199`）里 `spit … :append true`——那把锁是
   为「hook 在别的线程上也会写」（`log-lock` 的 docstring）而设的。**单消费者队列天然保序**，锁可以退役；
   `carry-back!`（`:397`）那一步是「写这一行之前先把该带的段带过来」，它要么留在消费者线程里、要么在入队时
   做掉——**选一个并写清为什么**。
2. **每帧**（ADR 决策 6）：一帧入队就写。说清楚它的**收益**是什么——异步换的是「IO 不在响应路径上」，
   **不是「少写」**：落后窗口 = 队列积压。docstring 里不许出现「攒批更省」这类没有依据的话。
3. **「已落盘」水位**：给票 01 一个接口（`(flushed? session)` 或一个单调的水位号）。**没有这个事实，
   票 01 就安全地放不掉任何东西**——两票在这一点上是同一件事的两半。
4. **失败的去处**：会话进降级态 + 界面上说出来。要定的是**界面怎么知道**（它今天读帧；降级态是服务端状态）
   与**降级的语义**（还能不能继续跑？记录还能不能补上？）。ADR 只定了「要说出来」，这一票要把它做成具体形状。
5. **退出时收干净**：JVM 退出前把队列刷完（`harness.cap.jobs` 的退出收尾钩子是可抄的先例），
   否则「进程正常退出也会丢尾巴」，那比崩溃更难看。
6. **铁律 1 的措辞在票 07 改**，但这一票的 docstring 就是那条新措辞的第一次落地：**日志是恢复源，
   运行时的真相在内存。**
7. **写者与会话的序号契约**（票 05 判断 1，ADR 0003 决策 9）：会话按 `next-seq` 铸的序号，写者必须把
   它们**逐条**写成对应条数的记录——一条会话条目落一条记录，不多不少、不乱序。因此「已落盘水位」
   不只答「落没落」，还要答**「落到了哪一条序号」**：落后 = 记录短了多少条，而条数与序号必须对得上，
   否则票 05 的序号就重放不出来（刷新之后对账失效）。

## 验收

- [x] 帧按发生顺序落盘（用例：并发写多帧，文件里是一个有序前缀）
- [x] 落后是可观察的：进程在「已入队、未落盘」时被观察，`已落盘水位 < 当前帧数`（用例）
- [x] **水位是一条序号，不只是一个布尔**：会话铸到 N、落盘到 M 时，`M < N` 可读，且 M 落盘之后
      记录里的条数与序号对得上（用例，与票 05 的那条契约同一条）
- [x] 记录目录不可写 → 那个会话进降级态，**并且界面上说出来**（有用例；不是只记进程日志）
- [x] 进程正常退出：队列刷干净（用例）
- [x] `log-lock` 若退役，`log-lock` 的 docstring 里那条「半行 = 坏文件」的保证**仍然成立**（有用例钉它）

## 落地（2026-09-21）

`src/harness/edge/record.clj`（写者）+ `test/harness/edge/record_test.clj`（**9 个用例 51 条断言**）；
`src/harness/edge/http.clj` 的接线（`log!` 解析路径后 `append!`、`log-lock` 退役、`carry-back!` 进消费者、
`rebuild-post` 落盘后 `flush!`、`sofar` / `rebuild` 两条读路由带 `:record`）；
`test/harness/edge/http_test.clj` +1 用例；UI：`ui/src/lib/record-health.ts`、
`ui/src/components/record-notice.tsx`、`ui/test/suites/record.tsx`（2 个用例，渲染成字符串来读）。

**判断 1（队列替代锁）**：写者是**一个消费者线程**，`log-lock` 删掉，原位换成一段说明为什么不再需要它。
`carry-back!` 留在**消费者线程里**（每一行写之前跑），理由是它要写文件、而且它会改变「这一行是第几行」——
放在入队时做就有两个写者，锁省不掉。它还**必须回答「文件变了吗」**（真值 = 变了），变了就把水位重新基准化。

**判断 3 与 7（水位是一条序号）**：`flushed-seq` = 记录里最后一条的序号、`pending-count` = 还没写的条数，
`(+ flushed pending)` 就是下一条要铸的序号；落盘之后**文件行数 = `flushed-seq`**。票 01 的
`watch-unflushed!` 现在接到 `record/pending?`，用例钉住「有未落盘的行 ⇒ `sweep!` 不放」。

**判断 4（失败进降级态）**：`degraded` 答出**原因 / 还有几条 / 哪个文件**；`retry!` 是回来的路。
界面这一半走 `:record` 字段——**没有问题时不出现**（缺席 = 没事；一个每答都带的 `:state "ok"` 是没人会读的
字段），只在降级时出现在 `sofar` 与 `rebuild` 两条读路由上。前端 `recordNotice` 把它变成一句话，
`RecordNotice` 是一根**常驻的条**（不是 toast：状态还在，通知不能先消失）。

**走查（`node scripts/dev.mjs --scripted …/evidence/go.json` + `…/evidence/walkthrough.mjs`）抓到一个真洞，
它决定了这一票的最终形状**：第一版只在**挂载那次读**与**盯着别人跑的轮询**里上报记录状态，而
**自己驱动这一轮**的页面两者都不走（轮询的条件是读回来的 state 是 `running`）——于是跑中写失败
**谁都收不到**，页面安静地继续、记录安静地落后。修法是在**这一轮结束**时再读一次记录：同一个门、
同一个 fallback，一次 run 一次读，**不刷新**就出条（走查的 GREEN 就是两次 turn 之间没有 reload）。
证据：`evidence/02-record-notice.png` 与 `evidence/README.md`。

**这一票已知的边界（写给票 05/06）**：
- 一轮**跑到一半**盘坏掉时，条要等这一轮结束才出现（不是 1.2 秒内）。盯着别人跑的页面反而是实时的
  ——那条轮询本来就在跑。要「跑中就实时」，得让 feed（票 05）把记录状态随增量一起送。
- **记录目录从会话一出生就不可写**这个子情形，页面拿不到任何东西：文件从没建起来，`sofar` / `rebuild`
  都定位不到它（404），`:record` 也就没有可搭的 200。会话照跑、会话照丢记录，而页面上没有话说——
  这一条留给票 05 的连接通道去说。

实现时才发现、写票时没写到的三件事：

1. **写者不跳行。** 一行写失败就停在它上面（`serve!` 返回 blocked），所以记录永远是**有序前缀**，
   降级 ≠ 丢行；降级也不等于会话失败——内存仍是权威，会话照跑。
2. **`prepare`（carry-back 的口子）每一行都要问一次。** 第一版按「一天问一次」写（`prepared?` 标记），
   被 `records-that-landed-unbound-are-carried-back-into-the-project-file` 抓出来：期望 `[1 2 3 4 5]`
   得到 `[1 2 5]`——carry-back 只在**找到段落**时才自标完成，问了不等于带过来了。
3. **水位会重新基准化**（换文件，或 prepare 改了文件）。它记的是「相对这个文件的条数」，不是进程内的
   计数器——票 05 重放靠的就是这个。

**发现的两处既有漏，顺手补上（本票报数因此和票 01 报的不是同一个分母）**：

1. **`test/harness/test_runner.clj` 的 `test-namespaces` 是字面清单。** 票 01 的
   `harness.edge.sessions-test` 与本票的 `record-test` **都不在里面**——所以票 01 记的那句
   「后端全量 982 / 12083」**从来没有跑过 sessions-test**，而本票新写的 record-test 也一样对全量不可见。
   两个都加进去了，并在那里写了「新命名空间要和文件同一个提交进这张清单」。
2. 本票的验收 3 里「会话铸到 N」那半句**今天还读不到**：会话还没有序号（票 05 才铸）。已经能读的是
   「落盘到 M，且 M 之后文件行数 = M」——也就是票 05 要接到的那半条契约，另外半条跟着票 05 来。
