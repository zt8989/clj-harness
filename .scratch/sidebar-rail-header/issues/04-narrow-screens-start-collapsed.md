# 04: 窄屏默认就是 rail，宽屏默认展开

**What to build:** 从没设过偏好的时候，窗口窄（`<md`，768px）就**默认收成 rail**，宽就默认展开——
在 375px 的窗口上，15rem 的侧栏会把聊天区挤得没法读，这是宽度自己该给的答案，不需要人去点一下。
**人一旦点过 toggle，偏好说话，宽度不再插嘴**（03 的持久化优先于本票的默认）。

窗口从宽拖到窄、又拖回宽：没有偏好时形态跟着宽度走；有偏好时就待在人选的形态上，不跳。

聊天区不许被挤：列定义是 `minmax(0,1fr)`，窄屏下侧栏那一列只占 3rem，composer 与消息列表照常可用。

**Blocked by:** 03: 折叠状态刷新后还在（谁说话优先——偏好还是宽度——由 03 的读写规则定下）。

**Status:** ready-for-agent

- [ ] 无偏好时的默认：`<768px` → rail；`>=768px` → 展开。
- [ ] 有偏好时宽度不覆盖：窄屏上人手动展开过，刷新后（窄屏）仍是展开。
- [ ] 拖窗口：无偏好时跨过 768px 会跟着切；有偏好时不跳变。
- [ ] 375px 手验：侧栏 3rem，聊天区可用，消息列表与 composer 都在，横向不出现整页滚动条。
