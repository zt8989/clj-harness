# 04 — 一处推导，两处使用：活的写入与重建共用同一个投影函数

**What to build:** 今天活着的写入既写库又写记录（`bind!`、`remember-send!`、`todo_write`），那是**两个作者**——正是这一页要拿掉的东西。把「一条记录行 → 库里的一行」收进**一个纯函数**，让活的那条路（照旧低延迟）与票 03 的消费者（照旧离线）**都**调它。结果：两边不可能推导出不同的行，重建也不必另写一套逻辑。界面上一切行为不变——绑定、发送、待办照旧立刻看得见；这是**预重构**（「让改动变容易，再做容易的改动」），不是行为改动。

**Blocked by:** 03 — 消费者立起来，才有一处现成的推导可以抽出来共用。

**Status:** ready-for-agent

- [ ] 活的写入与消费者调用**同一个**推导函数（能一处断言它的调用点）
- [ ] 绑定 / 发送 / 待办三条路各有端到端用例，行为与今天逐字一致
- [ ] 一条用例证明「先直接写、后投影」对同一行是恒等（不会写歪、不会双写）
- [ ] 没有把活路径变成「等投影落库才回显」（延迟语义不变）
