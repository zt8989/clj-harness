# spec: 事实的真相在记录，库是它的投影

**立（2026-09-22，主人选了「B」并交代：不要 fsync、别做重、我们不是数据库）。**

## 一句话

**记录的字节是事实的真相；内存是运行时的*工作副本*，不是第二个真相；库装的是*能从记录推导出来的状态*，因此可以从记录重建。**

今天这三件事的排序是反的：内存是权威（ADR 0002 决定 1/10），库里那几张表由**活的写入直接落**（`bind!`、`remember-send!`、`todo_write`），记录只是「恢复源、允许落后」。这一页把它翻过来——不是重写整个存储层，是**换掉「谁是真相」**。

## 做

- **库成为投影**：库里可投影的那些列（会话身份与归属、标题、上次发送时间、任务清单…）改为**由记录推导**，而不是由活的写入独立落笔。
- **一处推导，两处使用**：把「一条记录行 → 库里的一行」收进一个纯函数，活的写入（照旧低延迟）与重建消费（照旧离线）都走它，两边不可能不一致。
- **从记录重建库**：库缺失或损坏时，能遍历记录把可投影的状态重建出来；启动时 offset 落后就增量追赶。
- **投影是幂等的**：同一行消费两次不产生重复、不漂移（`INSERT OR REPLACE` / `ON CONFLICT DO UPDATE` 配稳定主键）。

## 不做（从原 spec 砍掉的「重活」，逐条点名）

- **fsync**。字节到页缓存即可；本特征要的是「一个真相」，不是掉电不失。
- **攒批调参（Little 定律、组提交批大小/字节上限/延迟）**。写手的节奏是 ADR 0002 决定 6 的事，本特征不碰。
- **有界队列与 L0–L3 背压阶梯**、**应急文件 dump**。
- **流式 token 合并成 `stream_snapshot`**。帧必须逐帧能从记录重建（`.scratch/jsonl-two-kinds` 票 03），合并会破掉这条判据。
- **JSONL 首行 header / version**。格式冻结（ADR 0002/0003 边界）。
- **把对话搬进库**。对话正文仍由记录承载（`replay` / `stats` / `trajectory` / 窗口都是它的读者）；库里**一个对话字节都不进**。

## 投影的不变量

1. **库不装对话内容。** 可投影的是「状态」——能被记录里某一行确定地推出来、且不随记录增长而改写的那几个数；正文、帧、日志行永远不进库。
2. **记录只 append，一个写者，按发生顺序**（ADR 0002 决定 3）。投影的 offset 就是**记录行号**。
3. **不可投影的状态要点名。** 锚点归属与快照（铸造出来的状态）、本进程的 claim 行（进程事实）不从记录推导——它们**随库一起丢**，文档里写清楚，不假装能重建。
4. **重建幂等**：同样的记录跑两遍，库相同。

## 判据（做完这一页，应该能说这几句）

- 删掉 `harness.infra.db`、只留 `projects/` 那棵树，重启后侧边栏能列出会话、带上**标题**与**上次发送时间**，**任务清单**也在。
- 绑定 / 发送 / 待办的**活的写入**，与从记录重建，走的是**同一个推导函数**；先写后投影不会把同一行写歪。
- 库里仍然只有可从记录推导的状态——一条 `message` 行投影不成任何一列，守卫用例仍绿。
- 不可投影的那几样（锚点、claim）在文档里被点名「随库丢失」。
