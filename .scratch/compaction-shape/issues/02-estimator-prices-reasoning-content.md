# 02 — 估价器按厂商计价的东西计价（`reasoning_content` 也要算钱）

**What to build:** 压力表的两个量量的是**两种形状**，而估价器只认得其中一种，于是那笔账算错了。

- `current` 量的是 edge 装配好、**真要发出去的那个数组**：思考已被 `absorbed` 折进
  assistant 的 `reasoning_content`；
- `anchor-est` 量的是从记录折回来的**AG-UI 形状**快照：思考是独立的一条 `role "reasoning"` 消息；
- `harness.edge.pressure/estimate-message` **只读 `:content`，完全不看 `:reasoning_content`**。

真实记录实测（`f59c09dd-…jsonl`，2026-09-25）：

```
同一段 4000 字思考：
  {:role "reasoning" :content …}            → 1008 个估 token（算进去了）
  {:role "assistant" :reasoning_content …}  → 9 个估 token（不可见）

那个前缀上：provider 形状的估计 330,648 / AG-UI 形状的估计 689,229
            head 里 role=reasoning 的消息 588 条 = 1,414,626 字符 ≈ 354k 估 token
```

于是 meter 报的是 `1,019,523 + 330,648 − 685,403 = 664,768`（日志里那一行是 651,432），
而**同一次前缀拿记录自己折一遍**是 `1,023,349`（98%）——下一发请求厂商实收 `1,020,335`。
meter 少算约 36 万，永远够不着 70% 的阈值（734,003），`compact-if-pressured!` 每次直接返回。
四个检查点全都对得上：

| run | 日志里的 meter | 记录自己折出来 | 实际首个请求 `prompt_tokens` |
|---|---|---|---|
| `5edb3cb3` 19:42 | 515,496 (49%) | 808,321 (77%) | 800,819 |
| `6746c3b0` 21:09 | 589,972 (56%) | 912,272 (87%) | 890,868 |
| `ae7945f6` 22:37 | 651,970 (62%) | 1,021,300 (97%) | 1,013,961 |
| `0dc5857f` 22:40 | 651,432 (62%) | 1,023,349 (98%) | 1,020,335 |

**修法是让估价器把厂商计过价的东西都计上**（`reasoning_content` 是 Provider 形状里那段文字唯一
的落点）——两种形状于是估出同一个数，混用不再有代价。**不许**改 `default-ratios`、调低阈值、
或者拿「反正锚点会纠偏」把账赖掉：锚点只在**形状一致**时纠偏，这次正是它没纠。
