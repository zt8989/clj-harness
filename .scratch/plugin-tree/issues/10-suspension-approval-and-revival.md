# 10 — 悬置、审批与恢复

**What to build:** 悬置（`suspend!`）、审批 park/resume、断线恢复、以及 `agent/request` 这条瀑布——今天它们
横跨循环、工具缝、边三处，谁也说不全「拦住一次调用」这件事。这一票把它们收进 agent 词汇：
**谁可以拦、拦了以后状态记在哪、恢复走哪条路**。

**Blocked by:** 09 — `ctx.agentLoop`

**Status:** ready-for-agent

## 验收

- [ ] `agent/request` 是瀑布：listener 不调 `next` 就短路；短路的**结果进记录**，且说得清是人拒的、
      策略拒的、还是工具自己悬置的
- [ ] 悬置的三种应答案（放行 / 拒绝 / 换参数）行为与 wire 形状照旧（AG-UI 侧一字不改）
- [ ] 恢复之后**是新的一步、同一轮**——这条判据有断言
- [ ] 进程重启后未完成的会话照旧说得清（`unfinished`），能续
- [ ] 审批的等待**不做超时**：人一直不响应就一直待决（这是有意的无限等待，与 `bash` 的时限是两回事）
- [ ] 两个会话的待决审批互不串（按会话分家，有断言）
- [ ] 悬置中的工具调用在轨迹那一栏仍画得出来（还没被回答的调用也在其中）
