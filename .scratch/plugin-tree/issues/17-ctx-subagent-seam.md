# 17 — `ctx.subagent` 接缝

**What to build:** 子代理与委派是一条缝。dsh 拿它同时换出「新开一个子 agent」与「另一个产品里的委派回合」
两种实现；本仓今天有 `cap.subagents` 与 `edge.delegation`，但没有一条说清三个角色的地方。

**Blocked by:** 09 — `ctx.agentLoop`

**Status:** ready-for-agent

## 验收

- [ ] 定义 / 实现 / 消费三角各有名字；`edge.delegation` 明确是**实现侧的一种**
- [ ] **换一种实现**（假的子代理：立刻答一句）调用方一行不改——接缝成立的反证
- [ ] 子代理的可见性照旧：任务视图列得出、状态说得清（在跑 / 已结束 / 停了）
- [ ] 失败与取消有断言：不留悬着的句柄，不留一个永远「在跑」的条目
- [ ] 委派那一行（会话下行上的一条事实）的形状与位置不变
- [ ] 子代理与 `ctx.scope` 的关系说清：它自己那个域里注册的东西不泄漏到父会话
