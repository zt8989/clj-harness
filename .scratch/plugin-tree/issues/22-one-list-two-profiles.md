# 22 — 一份组装清单，两份 profile

**What to build:** 今天的装配是 `edge.http/start!` 里的一串函数调用。这一票把它变成**数据**：一份有序的
组装清单（每一行是一个插件 + 它的 `:inject`），两份 profile 各是清单的一层——`headless`（一次性运行）与
`web`（浏览器 + 管理边）。**不要** bundle、不要 patch 层（这一轮明确不做）。

**Blocked by:** 11 — 事件三域与「新行为该挂哪」

**Status:** ready-for-agent

## 验收

- [ ] 两个入口各起得来，且各自跑得通一条真路径：`web` 浏览器打开并发一句话；`headless` 一次性跑完
      （本仓今天的脚本走查与 `-M:evals` 那条路）
- [ ] 装配**是数据**：清单读得出来，行里写的是插件与依赖，不是函数调用
- [ ] 两份 profile 的差集**只有清单那几十行**，不是两份代码（有断言或一条人眼可查的对照）
- [ ] 组合根仍是唯一装东西的地方，`stop` 带回 teardown（本仓现有那条测试立场不变）
- [ ] 不写死端口；测试隔离协议照旧（配置根与 OS home 指向每进程唯一的临时目录）
- [ ] **待定作答**：`profile:web` 用今天的 `edge.http` 这套，还是用 `.scratch/cordis-clj/` 票 10–13
      新建的那套 Web 插件——**只能留一套**，写下选哪套、另一套怎么办（删掉/降级为示例），
      并回头改那份 spec 的范围，不许两套并存
- [ ] AG-UI 的 wire 形状一字不改（前端 `ui/` 一行不动）
