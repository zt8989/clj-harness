# 14 — `ctx.subprocess` / `ctx.shell` 接缝

**What to build:** 「起一个进程」与「在哪只壳里跑一行」是两条缝。**定义**：一次性 `run` 与长活 `start`
两种 spawn 形状、以及选壳的候选链与「按名字拒绝、不回退」；**实现**：本机进程 + 收整棵树 + 退出时
`reap!`；**消费**：`bash`、`job` 那一族四个动词、`infra.rg`、`cap.git`、hook 命令、文件夹对话框。

**Blocked by:** 06 — `ctx.tools`

**Status:** ready-for-agent

## 验收

- [ ] 两种 spawn 形状（`:program` 保反斜杠路径 / `:shell` 走解析出来的那只壳）行为不变
- [ ] 选壳：本机没有的壳与不是壳名的词**按名字拒绝**，不回退；每 kind 各自缓存；`stdin` 写完即关
- [ ] 进程自己退出时 `reap!` 照旧收掉这个 JVM 起过的**每一个**进程（扫进程树、先 SIGTERM、
      共享 2 秒预算、再 SIGKILL），钩子在 spawn 之前装且只装一次
- [ ] **换一个后端**（假进程或远程执行世界）`bash` 与 `job` 照旧工作——这条反证同时是票 19 的地基
- [ ] `job` 的记录语义一条不改：末行是状态、**无末行即还在跑**、记录活过写它的进程、
      `job_list` 列的是记录（含前台溢出的 `c*` 与上次运行留下的）
- [ ] 答案上界不变：按字节、留尾、stdout 与 stderr 各算各的、超了落成一份记录并在答案里说清
- [ ] `workdir` 不挂审批、只判「它得是个目录」，这条不变
