# 05 — 会话持久化的实现：jsonl 与库各归哪里

**What to build:** 记录的**字**（jsonl、行号、半行、格式、世代）与库里的状态（会话表、项目、待办、锚点）
今天分别在 `edge.sessions` 与 `infra.db`。这一票把它们归到「会话持久化」这条缝的**实现侧**，
并把本仓那条**状态 vs 记录**的边界写成判据：新表进库，必须先写清它是状态还是记录。

**Blocked by:** 04 — `ctx.sessions`

**Status:** ready-for-agent

## 验收

- [ ] 存储面只剩一个入口（`create` / `open` / `stat` / `list` / `export` 那一式，名字用本仓语汇）；
      **脊柱不认识文件格式**——连「日志在哪」都不知道（ADR 0005 的立场照旧）
- [ ] 库里每张表在归属表里都标了「状态还是记录」，`harness.infra.db-test` 的元断言照旧是守卫
- [ ] **换一个实现**（内存或临时目录）跑同一套会话测试，脊柱与循环一行不改——这是接缝成立的反证
- [ ] 老的记录文件照旧读得出来：不迁移、不重写、不改名（本仓对已提交世代的规矩）
- [ ] 记录是「一条流」这件事不变（ADR 0012）：同步答号、写不进去攒住重投、不许留洞
- [ ] 锚点四张表与待办表的主人是接缝的实现侧，不是脊柱
- [ ] 会话中断的尾巴（半行）处理语义不变，有断言
