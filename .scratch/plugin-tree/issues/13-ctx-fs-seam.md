# 13 — `ctx.fs` 接缝

**What to build:** 文件是一条缝：**定义**（读 / 写 / 改 / 搜的词汇）、**实现**（本地文件系统 + 锚点账本 +
漂移判定）、**消费**（`read` / `write` / `edit` / `replace` / `insert` / `undo_last_replace` / `grep` /
`glob`）。**围栏是策略**，挂在 `fs/*` 事件上，不写在文件工具里——这是这条缝存在的理由：
本仓的围栏今天硬在工具里，换个执行世界就得改工具。

**Blocked by:** 06 — `ctx.tools`

**Status:** ready-for-agent

## 验收

- [ ] 锚点、已展示行、漂移判定、**拒绝即交付**、批、撤销记录——本仓这几条承重语义逐条不变
      （现成的测试就是判据；它们不许被改写来迁就新形状）
- [ ] 围栏作为策略挂在事件上：把策略摘掉，同一次调用从「park 等人批」变成直行；装上又变回来
- [ ] **换一个实现**（内存 / 只读）文件工具照旧工作——接缝成立的反证
- [ ] `grep` 与 `glob` 共用那一条「rg 不在 PATH 上」的点名失败（退出码 127 那条判据）不变
- [ ] `cap.glob` 的两次列举取交集、按路径排序不变
- [ ] 审批与 `fs/*` 事件的关系说清：哪个先、拒了谁来说；`bash` 那条无围栏的立场不变
- [ ] 保留 `read` 的答案不被 spill 这条（取回的路径就是 `read`）不变
