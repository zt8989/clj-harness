# 15 — `ctx.web` 接缝

**What to build:** 出网是一条缝。**定义**：发一次请求，以及一条**取回指引**（取货单那种东西交出去的
是「去哪拿」）；**实现**：超时、手工跟随并封顶的重定向链、301/302/303 变 GET 而 307/308 保留方法与 body、
字节上限、按声明的字符集解码、有损的 HTML→文本；**消费**：`web_fetch`、`web_search` 各家厂商、
spill 的取回指引。

**Blocked by:** 06 — `ctx.tools`

**Status:** ready-for-agent

## 验收

- [ ] 抽取器仍是**纯函数**，不靠 socket 也能测；有损这件事写在它的 docstring 里（它不是渲染器）
- [ ] 重定向与状态码那几条规矩不变，各有一条断言
- [ ] 厂商由**哪个键在**决定、顺序写在那一张表里，而 `ctx.web` 不知道任何厂商的存在（这条不变）
- [ ] spill 的定位符**不透明**：消费方只按取回指引渲染，不假定它是文件路径；`read` 的答案不被 spill
- [ ] **换一个出网后端**（桩）`web_fetch` 照旧工作——接缝成立的反证
- [ ] 一条真请求端到端跑通（不写死地址与端口），且它落在临时目录里，不碰真配置家
