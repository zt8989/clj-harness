# 票 03 的走查：刷新回到刚才那一场

**怎么起的**（`AGENTS.md` 的那条铁律：家自己造，不碰 `~/.clj-harness`）：

```
node scripts/dev.mjs --scripted /tmp/a4f2/walk/restore-script.json --ui-port 5319
```

脚本替身两轮：**第一轮调 `bash` 跑 `sleep 20`**（好让刷新撞上正在跑的那一轮），第二轮才是回答。
走查用的项目目录是 `/tmp/a4f2/walk/project`。浏览器是 agent 那台 Playwright 里的真 Chromium。

**四件事都看了**，下面按票面的四条验收排。

## 一、跑完一轮，刷新 → 同一条会话

- 刷新前：会话 `1c2416b5-…`（「你好，看一下这个项目」那一轮，记录 42 KB）。
- 刷新后：`localStorage["clj-harness.session"]` 还是它；侧边栏那一行仍是**当前**，项目仍是
  `project`，对话与刷新前逐字一样（「1 次工具调用 · 2 条消息」+ 那条回答）。

## 二、刷新时那条 run 还在跑 → 回到同一场，最后那一轮是**没完**，并且它继续长

`09461bf3-…` 那一场，发一条消息之后**立刻**刷新（那一轮正卡在 `sleep 20` 里）。刷新落地的瞬间：

```
刷新撞上正在跑的一轮（长）

bash · sleep 20
待审批
```

——用户消息在、**正在跑的那一步的工具行在**（`bash · sleep 20`），而且**没有折叠成摘要行**
（没有「N 次工具调用 · M 条消息」）：那一轮是**没完**，不是一轮完整的回答。侧边栏那一行是**当前**，
项目仍是 `project`。这是票 02 那条读法 + `toThreadMessages` 把最后一颗状态给成 `running` 一起做到的：
这一页自己的 runtime 什么都没在跑（`isRunning` 为假），是**服务端**那半说它还在写。

然后**没有再做任何刷新**，页面自己长出了答案：约 9.5 秒后文本变成

```
1 次工具调用 · 3 条消息

第一轮的回答：看过项目了。
```

——轮询（`GET .../sofar` + `runtime.thread.import`）到位。

## 三、关掉标签页再打开 → 仍然回到那一场

新开一个标签页（同一个浏览器、同一个 origin），落在 `09461bf3-…`，那一行**当前**，整段对话都在。
用的是 `localStorage`（不是 `sessionStorage`），所以关掉重开也算。

## 四、存下来的 id 指向一场已经不存在的会话 → 落到一个新会话，什么都不报

把 `clj-harness.session` 写成一个不存在的 uuid（`00000000-0000-…`）再刷新：

- 页面落在一枚**新的** id 上（`5232e746-…`），`localStorage` 里也是 New 的那一枚（旧的被忘掉）；
- 侧边栏照常列出真实的三条会话，**没有**任何一条是当前（新会话没有项目、还没绑定）；
- 界面上没有任何错误句子（`/错误|失败|Error|无法/` 不命中），控制台也没有新错误
  ——只有既有的两条 `GET /api/threads/<没有日志的 id>/stats` 的 404（composer 下面那条数字条对一条
  还没有日志的会话本来就会 404，与本票无关）。
