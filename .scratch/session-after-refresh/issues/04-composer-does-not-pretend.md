# 04 — 那一场没完的时候，输入框不装作能发

**What to build:** 刷新落进一条**还在跑**的会话时，composer 不装作可以发：它说清楚那一场还在跑，
不提供 Send；那一场跑完之后，接着发就是同一份对话的正常下一轮。
悬置那一种（等人决定）也不许装作能发——那条由票 06 让卡片回得来，本票负责「不许发」。

**Blocked by:** 01（「在不在跑」的事实）、03（你得先回到那一场才能谈它的 composer）

**Status:** ready-for-agent

## 现场：本地的「在不在跑」是**这一个** runtime 的，刷新后它什么都不知道

```ts
// ui/src/lib/run-state.ts:22-23
export const runInProgress = (runtime) => runtime.threads.main.getState().isRunning;
```

```ts
// ui/src/app.tsx:186   能不能发，由它决定
const runtime = useAgUiRuntime({ agent, isSendDisabled: gateOpen, ... });
```

刷新之后这个 runtime 是新的，`isRunning` 是 `false`——**而服务端那条 run 还在跑**。
于是今天的输入框在你落地的那一瞬间就是「可以发」。发出去的后果归票 05（服务端没有门，
第二条 run 会往同一份记录里写第二条 `input`）；本票管的是**别让它发出去**。

## 要改成什么

**一、判据加上服务端那一个事实。** 票 01 的名：那一场在跑 ⇒ 不发。
两个来源都是真的，所以是**或**，不是替换——本地的 `isRunning` 管「我这一页刚发的」，
票 01 管「我回来之前就在跑的」。来自票 03 已经读过的那份 payload，不要为它新开一个请求。

**二、跑着的时候说什么。** 一句话，英文（仓里 UI 文案的规矩），说清是**那一场**还在跑；
不要画 spinner 就算说完——今天的界面上唯一会动的东西是流式文字，而**没有帧在进来**这一页
看起来就是静止的。这句话就是本票要交付的那个「看得见」。

**三、悬置也算没完。** `requires-action` 那一轮（人还没答）同样不让发；
`assertNoPendingInterrupts()` 会在 runtime 层拒掉并且**是静默的**（打进去的字被清空、哪儿都没到，
`app.tsx:59-73` 那段注释记着这件事），所以「关门」是唯一不吞别人输入的处理。
票 06 让卡片回得来之后，这一条才真的有意义——两票共用同一次走查。

**四、跑完之后要回到正常。** 这是本票最容易做坏的地方：一个只进不退的门
（「反正它在跑所以永久禁发」）在走查里看不出来，得靠那条「跑完之后接着发」的用例。

## 与 `.scratch/parallel-sessions/issues/05` 的关系

那张票要把 `isSendDisabled` 从 App 级的**一个**布尔改成**跟着会话走**（一场悬置不许关上别场的输入框）。
本票改的是**同一个门**的判据。**谁后落地谁适配**，但两票都要在各自票面里写清这一点，
别各改一半——今天这个门是 `app.tsx:186` 的一个 prop，绕开它另建一套「禁发」是两份真相。
