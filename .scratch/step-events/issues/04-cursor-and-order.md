# 04 — 游标与顺序：三族在一条 socket 上

**What to build:** 三族（`turn/*`、`step/*`、`model/*`）在同一条会话下行上的**相对顺序**站得住，
且 `step/*` 进得了事实族那条按记录行号的断线补齐。

从用户视角：断一次网，补回来的一段里三族的顺序与条数都对得上；重连不会漏一步，也不会把一步数成两步。

**Blocked by:** 03

**Status:** ready-for-agent

## 验收

- [ ] **顺序**：一轮里 `turn/start` 在任何 `step/start` 之前；同一步的 `model/*` 与 `tools/*`
      落在这一步两端之内；`turn/end` 在最后。断言的是**相对顺序**，不是时刻。
      一条用例把一整个 run 的事实帧收起来，逐对检查这个偏序。
- [ ] **`seq` 是记录行号**：三族帧的 `:seq` 都是那一行的行号（ADR 0006 决策 5）。
      `step/*` 进记录，所以它有真行号，不需要借任何别的行——**这是它比 `turn/*` 简单的地方**，
      用例要把这条说清楚（`turn/start` 借的是「将要拿到的那一行」，`step/start` 就是它自己那一行）。
- [ ] **断线补齐**：客户端 `factSince` 与 `harness.edge.mux/facts-after` 对 `step/*` 照旧工作——
      一条用例：发了几步之后断开、再声明一个旧游标，补回来的**不漏不重**（含 `step/*`）。
- [ ] **内存环的容量复核**：`harness.edge.mux` 的事实环按**帧数**有界。今天一步占四帧
      （`step/*` 两帧 + `model/*` 两帧），工具越多帧越多；把这个数与「一次短暂断线要补多久」
      一起量一下，答不上来就把上限调大或把「一步的帧」压成一条——
      **数字要落进 `evidence/`，不许拍脑袋**。
- [ ] **不分类就打死**这条规矩两边都有用例：服务端发出的每一个事实名，客户端 `familyOf` 都答 `"fact"`
      （01 立起来的那条在这里要能覆盖新加的两族）。
- [ ] `clojure -M:test -m harness.test-runner` 与 `cd ui && npm test` 全绿（报数带上分支与提交）。
