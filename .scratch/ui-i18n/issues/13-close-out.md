# 13 — 收尾：两种语言各走一遍主线

**What to build:** 从用户视角：两种语言下各走一遍 `spec.md` 那条主线，页面里**不该再有中文夹英文
（反之亦然）**——除了两处刻意留下的：后端自己的句子（工具结果、错误、审批话术、工具描述、
`prompt.md`）与模型的词汇（工具名、参数、结果正文）。

这一票同时是**对账**：目录里不留没人用的键，也不留只在一半语言里的键；`docs/architecture/client.md`
里那些被本特征推翻的旧话（「文案是英文」、「抄来的文件逐字节相同」）必须已经不在了。

**Blocked by:** 01–12 全部。这是整合与验证那一张。

**Status:** ready-for-agent

## 验收

- [ ] **目录对账进套件**（不是一次性人工检查）：每个键在 `ui/src` 与 `ui/test` 里都**字面**出现
      至少一次（没人用的键是死重量，而「键字面写」这条纪律就是为它立的）；两种语言的键集合相同、
      值都非空。缺一条就是失败。
- [ ] `docs/architecture/client.md` 通读一遍：语言判定链、目录位置、键的纪律、边界（后端句子原样
      穿过）、抄来的元素不再逐字节相同——五条都在，且**旧的相反说法一句不剩**。
      `grep` 一遍确认没有残留的「文案…英文」式断言。
- [ ] 真机两种语言各走一遍完整主线（项目 → 新任务 → 问一句 → 工具行与展开 → 审批 → 提问 →
      设置三页 → MCP → 轨迹两种排法 → composer 数字），**中英各一份整页截图**进 `evidence/`，
      并写「与票面的差异」——`flat-step-rows` 的「与票面的四处差异」是范例：差异照实记，不粉饰。
- [ ] **中文文案请牛总过一遍**（spec 决策 9）：这一票的走查就是那一次机会，改的文案记在
      「与票面的差异」里。
- [ ] 全量 Clojure 套件与基线**一模一样**：`clojure -M:test -m harness.test-runner`
      ——本特征不碰 `src/` 一行，所以数字应当是 852 tests / 11233 assertions（基线记在 `spec.md`
      的「状态」一节，取的是本支线 `b94a64f` 那一次）。**多一条少一条都要先问为什么**，
      不许直接改基线数字。
- [ ] `cd ui && npm run typecheck && cd ui && npm run build && cd ui && npm test` 全绿。
