# 08 — 客户端：轮与步都从事实来，折叠那一行按步计

**What to build:** 页面上的轮与步不再靠「相邻 assistant 消息」现推，改读推送来的 `turn/*` / `step/*`
事实（含断线后按 `factSince` 补齐的那一段）；轮末那一条摘要行改说**步数**：`3 步 · 25 条消息`。
从用户视角：折叠、composer 那条状态带显示的东西与今天一致（`calls` 那个数换成步数），但判据只有一份。

**Blocked by:** 06（一步的边界得先在记录里）、07（轮的事实得先在）。

**Status:** ready-for-agent

## 为什么

轮与步的判据今天在客户端与服务端各有一份（ADR 0006 的代价一节点名过）。服务端那两份在 06/07 里退休了，
客户端这两份不退休就还是两份——折叠与状态带会与轨迹说的不一样。

## 验收

- [ ] **服务端折得出来**：`harness.edge.turn` 的折叠多数一个 `steps`（数 `step/start` 行），
      `turn/end` 的载荷从 `{calls, messages}` 变成 `{steps, messages}`。
- [ ] `ui/src/lib/turns.ts` 的邻接判据改成读 `turn/*` / `step/*`；`turnCounts` 数出 `steps`。
      折叠时**只有一个主人**：运行中的轮以事件为准、落定的轮以读侧为准（ADR 0006 代价一节那条规矩）。
- [ ] **两个数相等**：同一轮上服务端 `turn/end` 的 `steps` 与客户端 `turnCounts` 的 `steps` 相等——
      一条共享用例表（照 ADR 0006「一份规则、一张用例表」的先例）。
- [ ] **那一行的规矩**（逐条钉住）：
      - 一轮三步两工具 ⇒ `3 步 · N 条消息`；
      - **一轮一步一条消息 ⇒ 那一行不出现**（今天 `calls === 0` 那条规矩在步上的对应：步恒 ≥ 1，
        「不画」的判据变成「1 步 1 条消息」——与今天逐字一样的行为）；
      - 中英两份文案加 `summary.steps`；**不再被任何地方画的 key（今天的 `summary.calls`）从两份语言
        文件里删掉**，不留孤儿。
- [ ] 断线重连（`factSince` 补齐）之后，轮与步与不重连时一致。
- [ ] **旧会话**（推来的事实里没有轮与步）仍走读侧现推——两种来源都认，只有一个主人。
- [ ] 展示的其余部分逐字不变：`statsCells` / `contextCells`、状态带、上下文圈、步骤行本身都不动。
- [ ] 前端用例覆盖上面各条；`npm run typecheck` / `npm test` / `npm run build` 全绿。
- [ ] `对话` 页签的行为不变：轮与步只是画法，不是协议（ADR 0006 的边界）。
