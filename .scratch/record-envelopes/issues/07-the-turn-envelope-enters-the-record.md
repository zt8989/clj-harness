# 07 — 轮进记录，服务端的现推删掉

**What to build:** `turn/start` 与 `turn/end` 各一行：轮边界成为记录里的一行。同时**服务端不再现推轮**
——`stats` 数的轮、轨迹分的轮，都从这两行读。
从用户视角：一份记录自己说得出「这是第几轮、这一轮走了几步、几条消息、思考了几次、占了哪段行号」。

**Blocked by:** 02（`turn/end` 的条数要数到返回侧，而返回侧得先能逐条落盘）。

**Status:** ready-for-agent

## 为什么

ADR 0006 决策 3 当初把轮挡在记录外，理由是「边界算得出来，再写一行就是同一件事的第二份」。
主人 2026-09-27 推翻了它：轮也要作为一个信封。**收了它，那份现推就必须删**——否则才是真正的第二份。

## 验收

- [ ] `turn/start` 写在边判定这一轮开了的那一刻（`speaks-for-a-person?`：一条没见过的、`source` 是
      client 的 user 消息；**不是**由 run 触发——悬置恢复写出的第二个 `input` 是同一轮的续）。
      **它的行号就是这一轮的名字**（`<thread>-t<offset>`），不再从 `:seq` 预测下一行。
- [ ] `turn/end` 写在返回侧**全部落地之后**，**它就是这一轮的最后一行**，带
      `{turnId, steps, messages, reasoning, seqFrom, seqTo}`。**`calls` 那个键要么有人读、要么删掉**
      （`steps` 接替它之后大概率没人读了——落地时一句话说清，不留没人读的键）。
- [ ] `:run/interrupt` **不写** `turn/end`（停在半路等人）；悬置恢复**不写**第二个 `turn/start`。
- [ ] `harness.edge.stats` 的轮数与 `harness.edge.trajectory` 的轮边界改从 `turn/*` 读；
      `stats/user-ids` 那条判据**退休**（一份事实一个主人）。
- [ ] **旧记录**（没有 `turn/*`）仍得到同样的轮：现推只作为旧形状的兜底，一条用例钉住。
- [ ] 真跑一轮后 jsonl 断言：`turn/start` 在提问行之前、`turn/end` 是最后一行。
- [ ] 推给客户端的两个事实（ADR 0006 已实现的那两个）改成从**行号**取名，与记录里的行对齐
      （断线补齐按 `seq` 的那条代数仍未变）。
