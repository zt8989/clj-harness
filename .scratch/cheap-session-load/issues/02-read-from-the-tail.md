# 02 — 从文件尾开始读：尾页与往前一页不再从头 `line-seq`

**做什么**

让**读一条会话的尾页**变成「从文件尾反向读，凑够一页就停」，而不是「从第一行 `line-seq` 到结尾」。
往前翻一页（`?beforeByte=`）同样只读它需要的那一段。

今天 `page-get` → `read-entries` → `record-entries` → `replay/read-records`/`lines->records`：
**每一次都从文件头开始**，`seq` 是行号（`replay/entries` 的 docstring），而 `beforeSeq` 只能靠从头数
才能定位。一场真会话 65 MB / 237,012 行，尾页只要最后 50 条条目——**读的量和要的量不成比例**。

**做法**

1. **反向读**：从 EOF 往前收行，直到**凑够 `page-size` 条条目**，并且**切在一轮的边界上**
   （`kernel.session` 的 `tail` 已经在切这个边界，规则照它）。一行一帧的记录本来就是只追加的，往回走没有
   歧义。
2. **页带字节游标**：页的答案除 `entries` / `baseSeq` / `cursor` 之外，再加上**最老那条条目的行首字节**。
   客户端「更早」用它问（`?beforeByte=`），服务端 `seek` 到那儿再往回读一页。**这就是索引**——
   文件自己的偏移，不需要新索引文件、不需要库表、不改 `seq` 的语义（规格的决策 4）。
3. **末尾半行照旧容忍**：`rows-tolerating-a-torn-last-line` 的判据是现成的，反向读必须用它，而且
   **不能把半行当一整轮**。
4. **`sofar` / `rebuild` 那条从头读的路留在票 03 里改**；这一票只管窗口那两条（尾页、往前一页）。

**Blocked by:** None

**Status:** ready-for-agent

- [ ] `page-get` 的尾页不再从文件头读；`test/harness/edge/http_test.clj` 里有一条**按字节**判的用例：
      对一场长会话（夹具造得比 `page-size` 大得多）拿尾页时，**读过的字节数远小于文件大小**。
      「答对了」不是这一条的判据——它本来就该答对。
- [ ] 往前一页：`?beforeByte=B` 只读 B 往前的那一段；同样的按字节判据。`?beforeSeq=N` 仍认（老客户端），
      但走的是原有的从头读那条路，两者答案逐字节一致。
- [ ] 尾页仍切在**一轮的边界**上，且与今天 `kernel.session/tail` 的结果一致（同一份记录、逐条比）。
- [ ] 文件末尾是一个没写完的行时，反向读的答案与正向读**一致**（不是「也能答」，是「答同一份」）。
- [ ] 现场数字进 `evidence/`：同一场 65 MB 会话，尾页前后各读了多少字节、服务端各花多久。
