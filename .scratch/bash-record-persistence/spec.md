# spec: 记录留下来 —— `bash` 的日志住在配置家，不再随进程消失

**一句话**：命令的记录（后台作业那份、前台超预算那份）**不再随进程退出被收掉**：`shutdown!` 只停进程、
清注册表，文件留在 `<配置家>/jobs/<会话>/` 里。因此记录的**文件名要带上「这是哪一个进程」的戳**——id 只在
进程内唯一（每次重启从 `j1` 重数），而落盘用的是**截断**打开，不带戳的第二次运行会把上一次的记录直接清掉。
整棵树一个字节封顶：**「持久」不能等于「无界」**，超了从最旧的一份开始删。

2026-09-20 立，当日落地。三张票：`01 → 02 → 03`。

## 问题

1. **想回头读一条命令说了什么，得趁进程还活着。** 现在记录是**这个进程的**：JVM 一退，`shutdown!` 连文件
   一起收掉（理由写在 `cap.jobs` 里：「答案里那条路径也随进程死了」）。可「回头再看」正是留日志的**全部**
   动机：昨天那次 `npm test` 的几万行，今天要 grep 的是**那一次**的现场，而现在它已经被删掉了。
2. **只把删除去掉，留下的不是日志。** 会话的 `j1` 只在进程内唯一（`counters` 按会话、进程内），
   而 `open-record!` 是**截断**打开——同一个会话的第二次运行会把上一次的 `j1.log` 清成这一次的内容。
   换句话说：少了戳，持久化会变成「保留一份，直到下一次运行把它吃掉」。
3. **「持久」与「无界」不能只做前一件。** 当初否掉落盘的理由（`.scratch/bash-lifetime/spec.md`）正是这一对：
   「落文件要选家并配一套清理策略」。家已经有了（配置家），缺的是清理策略。

## 决策

1. **记录不再随进程消失。** `shutdown!` 只做三件里该做的两件：停掉进程、关掉记录、清空注册表——**不删文件**。
   前台那张 `spilled` 表（`thread-id -> [path ..]`）**退场**：它的 docstring 写着它存在的唯一理由就是
   「`shutdown!` 得知道该收走什么」。`spill!` 因此也不再需要退出钩子（它不起进程）。
2. **记录路径带「哪一个进程」的戳。** `<配置家>/jobs/<会话>/<句柄>-<戳>.log`，戳 = 进程**第一次要路径那一刻**
   （毫秒）+ pid，一处算一次（`record-path` 仍是唯一拼这条字符串的地方，答案引用的就是它）。
   **这是把 id 的寿命写成事实**：`j1` 只在会话的一次运行里有意义，文件名的后半段说的就是「哪一次」。
   毫秒那一截不是装饰：**pid 会被回收**，而秒级的时间戳 + 回收来的 pid 正好能撞上一次运行的
   pid + 秒。（接缝是 `*tag-override*`，一个测试专用动态变量，与 `home/*root-override*` 同一条规矩——
   一个 JVM 没法真的是两次运行，而这件事只有测试会问。）
3. **封顶的是整棵树，不是一份文件。** 一个 `def`（`record-tree-budget-bytes`，见票 02）：
   这个进程**第一次**写记录之前扫一遍 `jobs/` 树——**一次/进程**——超了就从**最旧**（mtime）开始删到不超为止。
   不按年龄删：按 TTL 删会删掉「上周那次跑」而留下「今天的垃圾」，而留日志的动机恰恰是「回头再看」；
   按总字节删保证**新的必在、旧的先走**，且不误伤年龄。删不掉（权限）不是错误，记一行日志就走。
4. **跨进程只有「读」，没有「问」。** 注册表仍是进程内的，所以重启后 `job_output` / `job_kill` 照旧
   **指名拒绝**（`unknown-job` 的那句话跟着改：作业随进程死，**记录不随**，路径在盘上，`read` / `grep` /
   `bash` 读得到）。配置家是围栏的自由路径，所以读旧记录**不挂审批**——这是记录住在这里而不是项目目录里的
   第二个理由，现在成了主要的那个。
5. **落盘的门槛一个字不改。** 前台仍然只有**超过 `answer-budget-bytes`** 才落一份：不超预算时答案本身就是
   全文，再写一份是第二份副本，不是第二份事实。后台照旧从一开始就落。
6. **这不是会话历史。** 不进 jsonl、不进库、不加审计行；也不随 run 结束而死（一个字不改）。

## 非目标

- **不引入任何「列出/找旧记录」的动词**（`job_list` 之类）。旧记录是盘上的文件，读它的是 `bash` / `read` /
  `grep`——本特征只改寿命，不改工具面（**工具数 17 不动**）。
- **不改 `job_output` 的 `offset` / `limit` / `wait` / `timeout`**，不改通知（`<job-ended>` 三样事实），
  不改 `job_kill` 的幂等，不改记录末行的约定（`[exit N]` / `[stopped]` / 缺席即还在跑）。
- **不给记录加索引、不加 `jobs/` 之下的元数据文件**（要 `ls` 的答案就是 `ls`）。
- **不动 `ui/src`**。

## 验收主线

1. **记录活过 `shutdown!`**：起一条后台作业、等它结束、`shutdown!` → 文件还在，内容一字不差（末行仍是它
   自己写的那一行），路径仍是答案里给的那条。
2. **前台那份也一样**：`bash` 超预算落的那份记录，`shutdown!` 之后还在。
3. **两次运行不互相吃掉**：同一个会话、两个不同的进程戳 → 两个 `j1` 记录**都在**，后一份不覆盖前一份
   （戳这一个接缝可注入，用例绑着它跑）。
4. **封顶生效**：把预算绑小、往树里放几份「旧」文件 → 第一次写记录之后，最旧的先没了、最新的一定在，
   且**本进程正在写的这份**一根头发都不少。
5. **重启之后**：清空注册表 → `job_output {job: "j1"}` 指名拒绝，拒绝句里说到记录还在盘上、怎么读它。
6. **计数不动**：工具表仍是 17 个（两处清单用例 + `CONTEXT.md` 的闭清单是证据）。

### 01 — 记录不再随进程消失；文件名带上进程戳

- `shutdown!` 只剩两件事：**停进程**（`close!`）与**放开记录文件**（`close-record!`）——文件不删。理由是
  新的那一段 docstring：命令说过的话活得比命令长，而「昨天那次跑成了什么样」正是留一份文件的理由；
  `stop!` 本来就不删（那里的路径刚交到调用者手里），现在整条寿命规矩只剩这一条。
- **`spilled` 那张表退场**——它的 docstring 写着它存在的唯一理由就是「`shutdown!` 得知道该收走什么」；
  `spill!` 因此也不再装退出钩子（它不起进程，钩子只服务「别留下没人管的子进程」）。
- `process-tag`：**进程第一次要路径那一刻（毫秒）+ pid**，`(swap! this-process #(or % …))` 保证要一次、
  要完之后每次都是同一个答案（答案引用的路径不能指到没有人在写的文件上）。`record-path` 把戳拼进名字，
  仍然是**唯一**拼这条字符串的地方。pid 会被回收，毫秒那一截把「回收来的 pid 撞上一次运行的同名文件」
  这一格也堵上。
- 接缝是 `*tag-override*`（`^:dynamic`，生产不绑定，规矩同 `home/*root-override*`）——**与票面不一致的
  一处**：票面写的是 `reset-tag!`（「忘掉戳，下一次就当成新进程」），落地时改掉，因为同一个毫秒里重置
  出来的戳与原来**一样**，测试要的是确定地两个不同的运行：绑定一个名字比睡一觉等毫秒过去诚实。
- 话术跟上：`unknown-job`（作业随进程死、记录不随，文件还在盘上、`read`/`grep` 读得到）、`output`
  （「作业在本进程里还答得出来，记录活得更久，而重启之后这个动词答 unknown job」）、`open-record!`
  （截断打开今天为什么安全）、`close-record!`（关文件不是删文件）、模块 docstring 的寿命那一段。

### 02 — 整棵树封顶，最旧的先走

- `record-tree-budget-bytes` = 64 MiB（一个 `def`，测试能绑小）；`record-files`（`jobs/` 树下的文件、
  按 mtime 从旧到新）、`open-record-paths`（本进程还攥着的那些）、`prune-records!`（删到不超为止，
  答删掉的路径）、`sweep-once!`（进程内一次的 CAS 门）。`start!` 在**开记录之前**叫它，`spill!` 在落盘之前。
- 三条判据写进 docstring：**按字节不按年龄**（一份记录的价值不是它多老，而家真正付的是字节）；
  **本进程正在写的那份既不是候选、也不算它的字节**（一条从周二起就没再说话的老作业，不能因为它安静
  就把文件从底下抽走，也不能让它的字节逼着别人被删）；**删不掉只跳过**（这条路是「去跑一条命令」的
  必经之处，盘点失败不该让命令失败）。
- 用例抓到一个当场写错的 bug：预算循环里先 `.delete` 再 `.length` —— **删掉的文件长度是 0**，于是
  `over` 永远减不下去，一棵 3000 字节的树被删光。改成删之前先量，并把这句写进注释
  （`a-record-still-being-written-is-not-a-candidate` 与 `the-record-tree-is-capped-by-bytes-and-the-oldest-goes-first`）。
