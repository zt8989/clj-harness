# spec: 窗口自愈 —— 老会话的号、以及「再次被看到时」补一次存量

**一句话**：`.scratch/entry-numbering/` 留了两处「要人来治」的收尾：**旧进程里已经跑出来的会话**不会自己补号
（要么放掉一次、要么重启），**客户端点了不重读存量**（`show()` 对已存在的 host 是空操作）。这一票把两处都做成
**自愈**：服务端在一次**读**里从记录把号补回来；客户端在会话**再次被显示**时重新拉一次尾页，而一份**号倒着走**
的窗口就在那次读里被**重建**，不是在原样合并里被留住。

## 背景（前一票的读数，原样引用）

- 进程里那场会话：563 条 entry 只有 7 条带 `:seq`；同一份文件折出来 563/563 全带。
- 症状：`since` 把整个会话当差量 → 读者把更老的条目接在窗口末尾 → 「侧栏说等你回应，点进去底下是一轮老的」。
- 前一票修好了**将来**：一轮 run 的条目在 `settle!` 里、门铃之前拿到号（逐条，来自读者那份 fold）。
  **已经跑出来的那批 entry 仍然没号**——它们要等被放掉一次（从记录重生）或进程重启，**没有任何读会把它们要回来**。

## 决定

### 1（服务端）：一次读把号从记录里补回来

- **判据**：这次会话是**本进程手里的**、**没有 run 在跑**、**还没查过**、而且**真的有 entry 没号**。
  四条缺一不可：跑着的 run 它的新条目**本来**就没号（写的人在写），别人的会话不归这里管，查过的不用再查，
  而一条号都不缺的会话不该为这件事付任何代价。
- **读一次文件，流式折**（`replay/fold-entries`，与给窗口发号的是同一份 fold），把 `{entry-id line}` 交给
  会话（`session/number-entries!`，`group` 传 nil = 任何组）。**为什么只能读记录**：那些号是**行**决定的，
  而写那些行的 run 已经把内存里的东西带走了——文件是唯一还留着它们的地方。
- **查过的记号贴在会话自己的 fold 表上**（`set-fold-value!` 的 `:numbered-from-record`）：它是「这次会话被
  看过了」这一个事实，随会话一起死。**没有记录也照样打这个记号**——没有文件可依的会话再问一遍也只是多一次
  文件查找。
- **落在哪两扇门**：`read-entries`（`GET …/page`）与 `window-page`（下行那条），**在把对话交出去之前**——
  与 `revive-parks!` 同一处、同一个理由：交出去的对话要能被切页、能被问差量（不然读者拿到的是「看起来正常、
  其实没有坐标系」的一份）。
- **读仍然不写**：记录一个字节不动、不取 claim、不建会话。

### 2（客户端）：再次被显示 = 补一次存量；号倒着走的窗口重建

- **`inOrder`（`lib/window.ts`）**：一份窗口的号必须**不倒着走**。这是本侧**造出来的**每一份窗口都有的性质
  （`windowFrom` / `merged` / `prepended` 都按服务端给的顺序放），所以倒着走只可能来自「信了一帧不该信的」——
  2026-09-30 那一帧就是：没有号的服务端把整个会话当差量答回来，更老的条目被 `merged` 接在**末尾**。
  **`seq: null` 不算乱**（写的人还在写）：没有号就没有可比的东西。
- **`aligned` 的头一条**：拿到的这份**顺序不对**（而页里至少有东西，**空页不许把读者手里的抹掉**）⇒
  **从这一页重建**，报 `rebuilt` 与丢了多沙——与「页够不到我们手里的」那条同一个答案、同一句话。
- **再次被显示 ⇒ `align()`**（`app.tsx` 的 host）：`docs/rules/panel-data.md` 那两半——推送会丢，存量不会，
  而窗口的存量就是尾页（`align` 是把它**合并进来**、读者的位置不动）。**挂载那一次不算**：门已经为它读过
  一次（`sessionHistory`），之后每一次「再被看到」才算。上升沿用 effect 的 `visible` 变化判，不引任何定时器。

## 非目标

- **不做「重建门」的存量重读**：`read` 是 `rebuild` 的 host（一场已停下来的会话被侧栏点开）**本来就不跟窗口**，
  这是设计（「LOOK, DON'T HOLD」）；它那份快照要刷新，等于把这一扇门改成另一扇，是另一个判断。
- 不改 `since` / `before` 的算法；不动记录格式；不加定时器。
- 不把「号倒着走」当成服务端的问题去猜——服务端已经按 fold 给号，这一票只管**读**与**再次被看到**。

## 验收

- [x] 服务端：一场「跑过、号被抹掉」的会话（真跑一次 run，然后把内存里的号清掉，模拟旧进程），下一次
      `GET …/page` 答出的每条 entry 都带号，且**逐条等于文件 fold 给的号**；并且会话上留下「查过了」的记号
      （`http_test/a-conversation-whose-runs-predate-the-numbering-heals-on-the-next-read`）。
- [x] 客户端：号倒着走的窗口在 `aligned` 里被**重建**（不是被合并）、报出的丢数正确；顺序正常的窗口照旧合并；
      没有号（`seq: null`）的条目**不**触发重建（`ui/test/suites/window.tsx` 新用例）。
- [x] 真浏览器（`node scripts/dev.mjs --scripted` + 自写脚本真调 `ask`）：**切到另一个会话再切回来，网络里
      看得见一次 `GET /api/threads/<id>/page`**（改之前那次点击是空操作，一个请求都没有），并且转写底部就是
      那张卡。
- [x] 机器门：后端定向（`http` / `sessions` / `replay`）与全量；前端 `npm test`（188 例）/ `npm run typecheck`
      / `npm run build`；全量读数见提交信息。
