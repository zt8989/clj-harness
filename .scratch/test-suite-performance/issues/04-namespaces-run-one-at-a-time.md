# 04: 整轮只用了 22% 的 CPU —— 命名空间是**一个一个**跑的

**What to build:** 一次全量后端跑，JVM 的 CPU 时间约 **224s**，墙钟约 **1000s**——也就是说
这台 4 核机器**四分之三的时间在等**（等子进程、等 socket、等轮询）。而 runner 现在是
`(loop [todo (seq namespaces)] ...)`，**一个命名空间接一个**。

**而仓库自己已经把前提写下来了**：`AGENTS.md` 的测试铁律说 runner 把配置根和 OS home 指到
**每进程唯一的临时目录**，所以「并行跑多个 JVM 也互不干扰」；`docs/rules/testing.md` 也说了
没有哪个套件可以写死端口（一律 `{:port 0}`）。**这正是并行的前提条件，已经是设计的一部分。**

要造的是 runner 上的一个开关（`--parallel N`，或默认按核数），它把命名空间分给 N 个**子进程**，
每个子进程走**完全相同的协议**（指纹 → 隔离 → 跑 → 判据 → 收尾 → 退出码）。

**不许妥协的几件事**（`run-suite!` 今天保证的，一个都不能丢）：

- 退出码 0 / 1 / 2 的三分语义（撞限制是 2，而且**优先于**失败）；
- 每个命名空间自己的 300s 预算，以及整轮的 1800s 预算；
- 隔离判据（本进程开过真家的库没有）——每个子进程各查一次；
- 那行 `[16.3s] 名字` 要照样打得出来（卡住时「缺的那一行」就是它）；
- 收尾：`cleanup!` 与 `wipe-temp-dirs!` 各子进程各自做。

**分配方式按实测挑，别拍脑袋**：命名空间的耗时差了两个数量级（210s vs 0.0s），静态轮流切会
严重失衡。要么实测花费做贪心，要么用一个共享队列让子进程自己认领。
