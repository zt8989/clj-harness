# 07 — 键集合在三处不漂移

**What to build:** 命令的 frontmatter 键集合只有一份答案，而它同时被三处消费。这一票是把那份
一致性钉成一条会失败的测试——并且把「frontmatter 可选」与「两样东西合读」这两件事一起钉住。

**Blocked by:** 01、05、06

**Status:** ready-for-agent

- [ ] 一条测试断言三处是同一份：`harness.cap.commands/scan` 读的 frontmatter 键 =
      `GET /api/picks` 报出的命令行字段 = composer 菜单画的命令行。
- [ ] 加一个键（例如将来的 `allowed-tools`）必须三处都动，漏一处即失败。
- [ ] 同一条断言覆盖技能那三处（今天已有），所以「命令与技能各只有一份答案」是同一句话的两次
      断言，不是两套规矩。
- [ ] **可选性也要断言**：命令的键集合里没有任何一个是必需的。一条**没有 frontmatter** 的命令
      在 scan、`/api/picks`、菜单三处都必须与「有 frontmatter 且各键俱全」的命令走同一条路，不得分叉。
- [ ] 一条**裸文件**（正文以 `# 标题` 起始）与一条**空文件**都在测试里，且都不产生 `:reason`。
- [ ] **合并的骨架也要断言**：`/api/picks` 的每组同携 `:skills` 与 `:commands` 两个数组，
      且「两样都空的组不出现」；一个只有技能、没有命令的会话与一个两者都有的会话，
      在**同一条**读法下成立——不是两条分支。
- [ ] 测试**读**那份共用清单，不抄一份副本——抄一份就是第四处会漂移的地方。
