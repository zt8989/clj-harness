# 02 — `/name` 加载命令正文

**What to build:** 一条消息以 `/名字 ` 开头（`/` 在消息开头、名字后有分隔——与技能的触发形状
**同一形状、同一处实现**），harness 把那份命令的正文作为一条 `<command name="…">…</command>` 的
user 消息追加在那条消息之后。人打的字一个字不改，触发词留在原地。

**正文的边界**：文件没有 frontmatter 时，正文就是**整个文件**；有 frontmatter 时，正文是
`---` 块之后的部分。

标签用 `<command>` 而不是复用 `<skill>`：它们是两种东西，模型该看得见这个区别。

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] `/hello` 之后模型读到的下一条 user 消息是 `<command name="hello">…</command>`，正文逐字节等于
      该文件的正文（定义见上）。
- [ ] **裸文件不被误判**：一个以 `# 标题` 开头的 `.md`，第一行**不是** `---`，所以整份文件都是正文——
      `# 标题` 必须原样出现在注入里。frontmatter 只在文件**以 `---` 行起始**时才成立。
- [ ] **空正文是合法的**：一个空文件加载后注入 `<command name="…"></command>`（或等价的空正文），
      run 不失败——它是一条什么都没说的命令，不是一次错误。
- [ ] **派生而非累积**：注入由每轮现收现算得出（在 `harness.kernel.loop/drive!` 里对 history 施加），
      幂等、同名只注一次；刷新与重放都不丢。不新增服务端记录。
- [ ] 名字不在任何命令根里 → **点名说明**（说出收到的名字、以及本会话能加载哪些），run 照常继续。
- [ ] 命令文件坏了（按 01 的判据）→ 与「名字不存在」**不同**的一句话（说清坏在哪里），同样不中断 run。
- [ ] 正文每轮从根现读；命令在会话中途从根里消失时，注入位换成一句点名说明，**绝不静默少一段指令**。
- [ ] 技能与命令两条派生共享同一个施加点；`loaded-prefix` 那种「工具写、它读」的共用常量，
      在这里同样只有一份。
- [ ] 命令**不给模型调用**：没有对应的工具。它只有人这一条路——命令是「人此刻决定做什么」，
      与 `disable-model-invocation` 的技能站在同一边。
