# 01 — 一个接口答两样：`.agents/commands/*.md` 与技能同进一张菜单

**What to build:** 一个人打 `/`，看到的不只是技能，还有本会话生效的**命令**。一条命令是一个扁平的
markdown 文件，放在两个约定位置之一：`<OS 家目录>/.agents/commands/`（机器级）与
`<项目>/.agents/commands/`（项目级）。**文件名（去掉 `.md`）就是命令名**；前面的根赢同名。

**两样东西由同一个接口回答**：`GET /api/picks?threadId=…`，答
`{:groups [{:layer .. :root .. :skills [..] :commands [..]}]}`。按**根**分组这条既有骨架不动，
每一组多一个 `:commands` 数组。

理由就是 `skills-get` 的 docstring 已经写过的那条，只是现在它管两样：**哪些根、同名谁赢、一个东西为什么坏
——这些答案只有 `harness.cap.*` 有一份**。再开一个 `/api/commands` 就是第二份会漂移的答案，而且两条路由
各自的「谁赢」还会互相不知道——同名冲突（见 06）恰恰只在两样东西**同时**被读出来时才看得见。

**frontmatter 是可选的。** 一个命令可以完全没有 frontmatter——整份文件就是正文，菜单那一行只显示名字。
写 frontmatter 时它可以带 `description` 与 `argument-hint`（都可选）。这是刻意的：命令常常只是一段
你懒得取名的提示，强制 frontmatter 会把「一个裸 `.md`」变成一种坏文件。

这一票只做「文件在 → 列表出」这一条完整路径：扫描、合并、`GET /api/picks`、菜单里多出那几行。
参数与加载留给后面的票——本票结束时，选中一行写进输入框的仍是 `/名字 `，打出去什么都不会发生。

**Blocked by:** None — 可以立即开始

**Status:** ready-for-agent

- [ ] `CONTEXT.md` 多出两个词条，照既有格式带「*别叫成*」：**命令**（一个 `<名字>.md`，身份是文件名，
      不是 frontmatter 里的 `name`；frontmatter 可有可无）与**命令列表**（输入框里 `/` 弹出的那份菜单）。
      词条要写明**命令与技能是两种东西**，各有自己的根，却在**同一张菜单、同一个接口**里出场。
- [ ] 扫描是 `harness.cap.commands/scan`，与 `harness.cap.skills/scan` **同形**（坏文件仍在结果里、
      带 `:reason`、`:available? false`，不进列表、也选不动），但**坏文件的判据按命令的性质重定**：
      - 读不动（权限、非 UTF-8）→ 坏。
      - 有 frontmatter 但**写坏**（块没闭合、不是 `key: value` 的扁平形状）→ 坏。**这是硬失败**，
        与 `config.edn` / `harness.edn` 同族：存在却读不出来，与什么都没说，从外部看必须不同。
      - frontmatter 里写了 `name` 且与文件名不符 → 坏（`:name-mismatch`）；**没写 `name` 不是坏**。
      - **没有 frontmatter、没有 `description`、只有空白 → 都不是坏。** 一个空文件是一条正文为空的
        命令，它能加载、注入的正文是空串——与「跳过」不是一回事。
- [ ] 文件名**精确匹配** `.md`，不做大小写猜测；子目录里的文件不是命令（命令是扁平的，没有
      「一个目录一个命令」这回事）。以 `.` 开头的文件名不是命令。
- [ ] 两个种类**各自的**根按顺序排列、**前面的根赢同名**；与技能同一条纪律：被盖住的那份不出现在
      列表里。跨种类的同名**不在这里裁决**——那是 06 的事。
- [ ] `harness.edn` 的 `:commands {:roots […]}` 整表替换默认值，与 `:skills {:roots …}` 同一形状；
      配置里写的根**没有层**，只报出路径。
- [ ] **两个种类的根都进围栏**——`harness.cap.project/fence` 是它唯一的来源（门禁拿它判 park，
      `<project>` 块拿它对模型说规则，两处不能各写一份）。
- [ ] `GET /api/picks?threadId=…` 只读、**不留痕**，与 `/api/model`、`/api/choices` 同一条纪律。
      每组是一个根、按先后顺序（系统级在前），**两样都空的组不出现**；每行
      `:name` / `:description` / `:argument-hint` / `:available?` / `:reason`。
      **`:description` 与 `:argument-hint` 缺失时为 nil/省略**，不是空串占位。
- [ ] **一个会话没有命令也不是错**：`{:groups [...]}` 里命令数组为空（或该组只有技能），
      不是 404——「没得选」是日常状态，与 `GET /api/git` 答 `{:dir nil}` 同一条理由。
- [ ] composer 菜单把命令与技能**平铺成一张表**（不分节），每行标明它属于哪一层、以及它是哪一样；
      名字与描述可过滤。**没有 description 的命令那一行只有名字**，不显示占位文本。
- [ ] 端到端可见：往项目级命令根放一个**裸** `hello.md`（只有正文，没有 `---` 块），打开菜单
      就看到 `hello`，且与技能同处一张表；删掉它，菜单里就没有。
- [ ] 测试家目录隔离（`isolate!` 的两个**平级**临时目录）、端口由 OS 分配——照 `AGENTS.md` 的
      既有纪律，不新增写法。

**本票的界线**：不加载、不替换、不碰 `$ARGUMENTS`。菜单里能看见 ≠ 打出去有用。

**一处留给人的命名**：路由叫 `/api/picks` 是这一票替你定的（它答的不再只是技能）。若你更想保留
`/api/skills` 这个名字、把命令塞进去，改的只是这一票的一个字符串与它的 docstring——
但那条 docstring 会开始说一件不成立的事。
