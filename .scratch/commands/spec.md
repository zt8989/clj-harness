# Commands

**状态**：已拆票，未实现。票面在 `issues/`。

## 要解决什么

`harness.cap.skills` 今天有一条人的加载路径（输入框打 `/name`）和一份菜单（`/` 弹出的技能列表）。
它只回答一个问题：**加载哪份正文**。人无法把参数交给它——`slash-request` 的契约就是「回答要哪个名字」，
名字之后的一切都是模型自己的事。

命令补的是这一截：**一个由人命名、由人传参、不做任何决策的可复用提示**。它不是技能的一种——
技能是模型可以自己决定去用的能力，命令是人此刻决定要做的事。

## 决定

### 1. 命令是 `.agents/commands/*.md`，不是技能的超集

两个约定位置：`<OS 家目录>/.agents/commands/`（机器级）与 `<项目>/.agents/commands/`（项目级）。
与技能根**平级、分开**。

**文件名（去掉 `.md`）就是命令名。** frontmatter 里若写了 `name`，只用来核对是否一致，不一致即坏文件——
与技能同一条安全来源：`scan` 只产出它从目录列举里读到的名字，所以「按名字取一份命令」是查表，
不是路径拼接。

**命令是扁平的**：`commands/foo.md`。没有「一个目录一个命令」这回事（技能是目录，因为技能带资源；
命令只是一段文本，没有资源可带）。

### 2. frontmatter 是可选的

**一条命令可以完全没有 frontmatter**——整份文件就是正文，菜单那一行只显示名字。
写 frontmatter 时，它可带 `description` 与 `argument-hint`，两者都可选；`name` 也只是可选的核对项。

**没有任何键是必需的。** 这与技能刻意不同：技能的 `description` 缺失即坏，因为技能清单要靠那句
描述让模型选择；命令不做选择——人自己打的名字，所以没有描述也成立。

「空文件」因此不是坏文件，而是一条正文为空的命令。它加载后注入空正文，run 照常。
只有**存在却读不出来**（权限、非 UTF-8、`---` 块写坏）才是坏——与 `config.edn` 同族：
存在却坏掉，与什么都没说，从外部看必须不同。

frontmatter 只在文件**以 `---` 行起始**时才成立。一个以 `# 标题` 开头的 markdown 整份都是正文，
不会被误切。

### 3. 两样东西，一个接口

**`GET /api/picks?threadId=…` 一次答完命令与技能**：

```
{:groups [{:layer .. :root .. :skills [..] :commands [..]}]}
```

按**根**分组这条既有骨架不动（`/api/skills` 的形状），每组多一个 `:commands` 数组。
原来的 `GET /api/skills` 退役——它答的不再只是技能，那条路由名与它的 docstring 会开始说一件不成立的事。

**为什么合并，而不是各开一条只读路由。** 这是 `skills-get` 的 docstring 早已写过的理由，只是现在它管两样：
「哪些根、同名谁赢、一个东西为什么坏」这些答案只有 `harness.cap.*` 有一份，前端复刻一遍就是第二份会漂移的答案。
更要紧的是——**跨种类的同名冲突只在两样东西同时被读出来时才看得见**（决定 6）：两条各自独立的只读路由
永远发现不了对方占了同一个名字，所以合并不是省一次请求，是**唯一能让那个诊断存在**的形状。

**每一行因此带一个「它是哪一样」的字段**（技能 / 命令）。菜单仍是**一张平铺的表**，不分节。

「没得选」仍是日常状态：一个没有命令的会话答 `{:commands []}`（或该组只有技能），不是 404——
与 `GET /api/git` 对没有目录的会话答 `{:dir nil}` 同一条理由。

### 4. 命令只给人用，不给模型

没有对应的工具。模型不能调用命令——这与 `disable-model-invocation: true` 的技能站在同一边：
命令是「人此刻决定做什么」，让模型自己决定去用一条命令，就把它变成了技能。

### 5. 参数是文本置换，不是求值

`$ARGUMENTS` 是整串，`$1`…`$9` 是按空白切分的第 n 个。**不做任何展开**：`$(whoami)` 原样出现，
不执行。越界的位置参数替换成空串。替换是**一次性**的（替换进来的文本不再被扫一遍）。

这是刻意的窄：一旦允许求值，一条命令文件就获得了执行能力，那是另一个安全故事——
与「`allowed-tools` 刻意不信」同一条理由。

### 6. 同名不猜

命令与技能抢同一个名字时，**不静默取一个**：报成一条诊断、那一行选不动、打 `/名字` 得到点名说明。
理由是既有的那条——一个静默挑了一个的解释，与一个从没装过的解释，从外部看没有区别。

注意这条**只管「两种东西抢一个名字」**：技能之间、命令之间的同名，仍旧是「前面的根赢」那一条既有纪律。

### 7. 键集合只有一份答案

`scan` 读的键、`/api/picks` 报的字段、composer 菜单画的行，是同一份清单。
这一条是既有纪律的延续（技能那三处已经这样钉着），由一个会失败的测试守着——**「全都可选」与「合并骨架」也在这条测试里**。

## 代价（写清楚，不藏）

- 多一套根、多一份扫描，与技能那套结构重复。选它是因为两者**语义不同**（模型能否自己用、能否传参），
  合在一张表里就要在每个消费点判一次「这是哪一种」——但**答案本身仍然合在一个接口里**。
- **`/api/skills` 退役是一次破坏性改动**：前端 `lib/skills.ts` 与 composer 菜单都要改（本 feature 的一部分）。
  若仓库外还有消费者，它们在这次改动里会 404。
- frontmatter 可选意味着**没有任何字段可供校验**：一条名字打错的裸命令不会有任何抱怨，它就是一条
  没有正文的命令。这是「文件多写了字段不是错误」的另一面，收下来。
- `argument-hint` 是给人看的提示，**不是契约**：它不校验参数个数。
- 命令正文不冻结在会话里（每轮从根现读，与 `config.edn` 同一纪律）：命令在会话中途消失时，
  注入位换成点名说明。代价是重放要看当时的根，换来的是改一条命令下一轮就生效。
