# spec: 顶部品牌行 + 会话标题（浏览器 tab 与对话列顶栏）

2026-09-21 立。**要的是：照 assistant-ui.com 首页那份 demo 的样子，给页面补上「顶部」——
侧边栏顶行放 logo + 产品名、收起那颗搬到同一行里；对话列顶栏显示这一场会话的标题，
点会话就换标题，浏览器 tab 跟着换。** 原话是

> 参考 https://www.assistant-ui.com/ demo界面 增加顶部logo + title ，折叠按钮和logo放在一起，
> 点击会话更新浏览器标题和顶部title，先生成spec和ticket再实现

## 参考的那份 demo 是什么形状

assistant-ui.com 首页下半嵌入的那一屏（不是站点自己的导航栏）。它的根是一个两行两列的网格：

```
grid h-full grid-rows-[3rem_minmax(0,1fr)] md:grid-cols-[15rem_minmax(0,1fr)]
├─ 行一 左格(3rem)  [记号] [assistant-ui] …………………………………… [收起那颗 ms-auto]
├─ 行一 右格(3rem)  [展开那颗(折起来时才画)] [New chat] …… [动作]
├─ 行二 左格        + New thread / 会话列表
└─ 行二 右格        对话
```

**两条线是这么画的**（对着线上 HTML 读的：左格 `h-12 border-r border-b px-4`，
右格 `h-12 border-b px-4`）：两格**都是 `h-12`**，所以两条 `border-b` 落在**同一个 y** 上，
横线**通到侧边栏里**、看上去是整页一条；左格另外带 `border-r`，竖线从头贯到底。
这两件事是「高度一致」和「有明显分界线」的全部内容，不是巧合。

三条读出来的事实，本特征照抄的是这三条：

1. **品牌归左格，标题归右格**，不是一条通栏。`New chat` 那行是**对话列自己的顶栏**，不是页面的。
2. **收起那颗在品牌行的末位**（`ms-auto -me-1.5`），和它收起的那个面板叫什么在同一行。
3. **折起来时品牌行是 `hidden`（还在 DOM 里）**，网格换成单列；展开那颗改画在对话列顶栏的行首。

## 定下来的六件事

**一、两处标题，两个地方，不是同一句。** 侧边栏顶行是**品牌**：记号 + 产品名 `clj-harness`，
末位是收起那颗；这一格 `h-12` 且自己带 `border-b`（demo 的做法），所以横线通到侧边栏里、
与对话列那条落在同一个 y 上。对话列顶栏是**这一场会话的标题**：
**同一个 48px 块里的两行——上行标题，下行 视图页签（对话 / 轨迹）**。
为什么不做成一条通栏：demo 的两格各自属于自己那一列（列表的东西归列表，对话的东西归对话），
而这个页面窄窗下侧边栏是**抽屉**（`sidebar-fold` 决策四）——一条通栏要么盖在抽屉上、
要么跟着抽屉一起动，两种都不对。

**二、收起那颗搬走，展开那颗不动。** 收起从「`New task` 那一行的末位」搬到品牌行末位，
理由和 demo 一样：面板的出口和这个面板叫什么在一起，读一次就够。展开那颗**待在原地**
（页面级浮标、`absolute start-2 top-2 z-40`，`components/sidebar-toggle.tsx`）。

demo 把展开那颗画进了对话列顶栏的行首，这里**故意不跟**：那两颗今天是一对契约
（一个 `aria-controls`、各自报被指那块的状态），而对话列顶栏是**每个 host 各画一份**的
（`SessionColumn` 是 `SessionHost` 的 children）——把页面级的状态发到每一份顶栏里去，
要多一层传参，还多出一堆「哪一份在画浮标」的判据，换来的只是浮标挪个几像素。
代价写清楚：折起来时顶栏整条给浮标让位（`folded && "ps-12"`，**二版把这行数从 `ps-11` 调到 48**，
理由见那节：两行之后要按页签那组的盒子算，不能再按文字算），两行都接在整条的最前面，
于是自动落在浮标右边、压不到。

**三、会话标题是客户端从会话自己派生的：第一条有文字的用户消息。**

库房里没有标题这回事：`GET /api/projects` 的形状（`SessionSummary`）只有 id、归档位、
mtime、bytes 四个字段；`assistant-ui/elements/thread-list.aui.tsx` 头上那句注释今天还写着
「A session has no title in this product」。所以只有两条路：

* 新加一列 + 一条回填规则——对磁盘上每一场已经有日志的会话，都要读出第一条用户消息、
  决定谁写、什么时候写、写失败怎么办。这是在给一个**派生量**盖一间库房。
* **从已经加载进浏览器的这段会话里读。** 选这条：会话被点开时它的消息已经在核心里了
  （`SessionHost` 的 `useAgUiRuntime`），派生不花一次请求、不落盘、不引入第二个标题主人。

代价与好处都要说清：

* **不落盘 ⇒ 标题一致。** 它就是会话的第一句话，刷新一遍、换台机器、换个浏览器都是同一句。
  它也不是重命名——本产品仍然没有这个动词（`thread-list.aui.tsx` 的非目标原样有效）。
* **只有被打开过的会话有标题。** 侧边栏那些还没点开的行仍然是 id，这是**非目标**而不是遗漏：
  列表要显示标题，就得替磁盘上每一场会话都读一遍 jsonl。

**四、只有看得见的那一场在写 `document.title`。** `SessionColumn` 只被 `visible` 的那一个 host
渲染（`SessionHost` 里 `{visible ? children : null}`），所以「哪一场可见」这件事**根本不用问页面**：
顶栏里那个组件自己就是答案，也不需要一张 id → 标题的注册表。

* 选择器返回**字符串**，不是消息数组：`useAuiState` 按值比较选择器的返回
  （`message-parts.tsx` 的 `PREVIEW_LIMIT` 段把这条写下来了），一个字符串让顶栏在助手
  流式吐 token 时一次都不重渲。
* 切换会话时旧列卸载、新列挂载在**同一次提交**里：cleanup 把标题还原成产品名、新 effect
  紧接着写上新的，浏览器在提交之后才画——不会闪出一个产品名。
* 语言切换会重渲（`useTranslation`），所以回退词跟着语言走；**有第一句话的会话标题不跟着走**，
  那是用户自己说的话，不翻译。

**五、标题的边界，四条。**

* **取什么**：第一条 `role === "user"` 的消息里第一个非空白的 `text` part。用户消息可以只带图
  （composer 支持贴图），那就继续往下一条用户消息找；注入上下文是 `data` part，天然不参与。
* **怎么收拾空白**：内部连续空白折成一个空格、去首尾。一句话前面带两个换行不该让标题变成空。
* **截断在函数里**：**60 个码点**，用 `Array.from` 而不是 `slice`——一个 emoji 或一个汉字在
  UTF-16 里占两个码元，`slice` 会把它劈成半个；截断后接一个 `…`。为什么不是靠 CSS 省略号：
  浏览器 tab 没有省略号机制，字符串本身必须有界；顶栏的 `truncate` 是给窄窗的第二道。
* **一条都没有时**给回退词 `session.untitled`（en `New session` / zh `新会话`），**不是 id**：
  id 是 36 个字符的地址，不是名字，而且它已经在侧边栏行上写着，写第二遍不添任何信息。

三种时机都当场变：**发出第一条消息那一刻**（用户消息乐观进核心）、点开另一场会话（重建回来）、
切换语言（只影响回退词）。

**六、产品名不进词表。** `clj-harness` 是专有名词，两语同名。放进 `shell.json` 会得到一条
「两个语言必须同值」的条目，还要靠 i18n 套件放行；它是常量，住在 `lib/session-title.ts`，
和 `index.html` 里那份静态 `<title>` 一起——`lib/i18n.ts` 的 `<html lang>` 是同一个形状：
静态那份管首次绘制之前，模块那份管之后。`document.title` 的形状是 **`<会话标题> · clj-harness`**：
tab 是多个页面并排的地方，尾巴上得写着这是谁家的。

## 非目标

* **侧边栏行不改成显示标题。** 那要求列表替磁盘上每一场会话都读出第一条用户消息（决策三的代价段）。
* **不做重命名。** 本产品没有这个动词，标题是派生的、不是存的。
* **后端一行不动。** `/api/projects` 的形状、`SessionSummary`、库里的列都不变；这一条能在纯前端做完。
* **展开那颗浮标不动**（决策二）。
* **标题不进历史、收藏、搜索**，也不进会话列表的排序。

## 走查（`node scripts/dev.mjs --scripted .scratch/brand-header/evidence/script.json --ui-port 5211`，隔离家、OS 分配端口）——计划

脚本给一条普通回答即可；**第一句话是走查自己在 composer 里打的**——标题的源头就是它。

1280×800（宽窗 = 侧边栏并排）：

- 侧边栏顶行：`[data-slot="brand-mark"]`（`aria-hidden`）与文字 `clj-harness` 在**同一行**，
  收起那颗的 `y` 与文字相同、`x` 在文字右边；`New task` 那一行**没有**收起那颗，
  且它的 `y` 比品牌行大。
- 打一句「你好，先看看这个仓库的测试怎么跑」并回车：顶栏 `[data-slot="session-title"]` 的文本
  变成这句话，`document.title` 变成 `你好，先看看这个仓库的测试怎么跑 · clj-harness`。
- 头部点「新建任务」→ 新会话：标题回到回退词（`新会话` 或 `New session`，看当前语言），
  tab 跟着换成回退词——**不是**上一场的标题，也不是 id。
- 侧边栏点回第一场 → 标题与 tab 换回那句话；`location.href` 一个字没变。
- 收起侧边栏：品牌行连同 logo 一起不见（`display: none`），对话列顶栏的标题**不压在**浮标上
  （标题的 `x ≥ 40`），浮标仍在 (8,8)、32×32。
- 切到中文（设置里换语言）：回退词那场的标题与 tab 变成 `新会话 · clj-harness`；
  有第一句话那场**不变**。

390×844（窄窗 = 抽屉）：抽屉里品牌行在顶、收起那颗落在抽屉自己那一行的末位；点一条会话行，
抽屉收起、标题照样换。

## 套件钉住了什么、钉不住什么

`ui/test/suites/session-title.ts`（新）两例，钉 `lib/session-title.ts` 的算术：
第一条有文字的用户消息胜出（跳过助手消息、跳过没有文字的带图消息、跳过 `data` part）、
空白收拾、60 码点截断（含 emoji 与汉字各一个边界）、回退词、`<标题> · clj-harness` 的形状、
以及产品名常量本身。

`ui/test/suites/sidebar.tsx` 加一例，钉品牌行**说了什么**：`AppBrand` 渲染出产品名与那颗
`aria-hidden` 的记号；至于收起那颗**在哪一行**，`sidebar.tsx` 在这个 run 里渲染不了
（它经 `settings-panel.tsx` 走到 `lib/i18n.ts`，那份模块加载时就碰 `document`），
所以按源码文本读——和旁边那条 `SIDEBAR_ID` 的读法是同一个，理由也一样。

**钉不住的**：布局与交互本身——品牌行和 `New task` 那一行谁上谁下、浮标压不压标题、
点会话标题换不换、`document.title` 真的写没写、品牌行会不会连 logo 一起被 `hidden` 收走。
`useAuiState` 与 `document` 都要 DOM，而这些正是上面那一节走查的回答。

## 落地时与计划的出入（两处，都不改结论）

1. **`AppBrand` 的记号画成 `( • )`**（两条相向的弧夹一个圆点），计划里写的就是这个意思，
   落地时把路径定死了：`M6 3.5A5 5 0 0 0 6 12.5` 与它的镜像，中间一个 `r=1.6` 的实心圆。
2. **回退词的键叫 `session.untitled`、值是 `New session` / `新会话`**，与项目行那个按钮
   （`project.newSession`）同值不同键：一个是名词（标题），一个是动词（按钮），
   合成一个键会让其中一处将来改词时被另一处绑住。i18n 套件只查键齐不齐、值空不空，同值是允许的。

## 二版（2026-09-21，看过一版之后）

**改的是决策一那一格：顶栏从「一行、标题居左、页签靠右」改成「同一个 48px 块里两行」。**
要求是主人看了截图之后提的，三条：**侧边栏和 title 栏高度一致**、**有明显分界线**、
**title 栏上面是 title、底部是 会话/轨迹**。改完量的数（真 Chromium，1280×800）：

| 量什么 | 一版 | 二版 |
|---|---|---|
| `sidebar-brand` 高 | 48 | 48（不变） |
| `view-switch` 高 | 33（`py-1.5` + 一行 20） | **48**（`h-12`，与品牌行同高） |
| 两条 `border-b` 落在哪 | 品牌行没有下边线；顶栏那条在 y=33 | 品牌行 **y=48**、顶栏 **y=48**，同色，**通到侧边栏里成为一条** |
| 顶栏里有什么 | 标题 x=300、页签 x=1184（同一行） | 标题 y=4..24、页签行 y=23..43；页签首字 x=300 **与标题首字对齐** |
| 折起来时 | `ps-11`：标题 x=44 | `ps-12`：标题首字 **x=48**、页签首字 **x=48**、页签那组的盒子 x=40（= 浮标右缘，**不重叠**） |

- **高度用 `h-12` 而不是 `py-*`**：demo 两格也都是 `h-12`，写死高度才是「同高」这件事本身；
  靠内边距凑出来的 48 一旦哪边换了字号就散了。
- **品牌行自己带 `border-b`**（demo 也是），配合 `<aside>` 早就有的 `border-e`，
  左上角那个十字和 demo 一模一样。
- **页签那组 `-ms-2`**：按钮自带 `px-2`，不回这 8px 的话下一行看上去比上一行缩进。
  demo 对自己的行首控件（展开那颗）用的也是这一手（`-ms-1.5`），这里是页签。
- **让位从 `ps-11` 改成 `ps-12`，而且是从「盒子」算的不是从「文字」算的。** 浮标 `start-2`
  宽 32 ⇒ 右缘在 40；页签那组被 `-ms-2` 往左拉了 8，所以「页签的盒子」要清开浮标就得让
  `padding-inline-start` ≥ 40 + 8 = **48**。一版的 44 在只有一行文字时够用，两行之后就不够了：
  页签那组的盒子有 **4px 压在浮标底下**，那 4px 里点下去会去开侧边栏，而不是切视图。
  改成 48 之后 `overlap = 0`，而两行的首字仍然齐在 48（页签按钮自己那 8px 内边距正好把
  `-ms-2` 还回来）。这条只有在折起来时才看得见，所以是走查量出来的，不是读代码读出来的。
- `view-switch` 这个 slot 名没动（`.scratch/sidebar-fold` 的现场记录按它引 `ps-11`，
  那条记录是那次的历史，不改），新的页签行叫 `view-switch-tabs`。
