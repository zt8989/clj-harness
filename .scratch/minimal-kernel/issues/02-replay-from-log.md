# 02: 从日志 replay 续上

**What to build:** 每个 run 的入参与帧已经落在日志里，但那份日志**只写不读**。做出一条重建路径：从一个 thread 的日志还原出 provider 形状的消息序列，喂回去继续对话——不需要服务端持有任何状态。

这不是一个便利功能。契约里明确写了"改坏内核没有撤销，只能重启"，而**这句话能成立的全部依据就是这里**。没有它，03 就是一场没有安全网的走钢丝。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 从日志重放出的消息序列能直接喂回 `loop/run!`
- [ ] 重放之后继续对话，新产生的帧与原始运行的可观察行为一致
- [ ] 重放发生在内核之外——内核不认识日志格式，也不读自己的日志
- [ ] 断言日志里的内容能完整还原非 ASCII 文本（中文 reasoning 与工具结果都要覆盖）
- [ ] 日志被截断/写到一半时，重放给出可理解的失败而不是静默产出半截对话
