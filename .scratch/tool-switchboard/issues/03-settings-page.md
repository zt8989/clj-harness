# 03 — 设置面板的「Tools」页：两个组，基础能力逐格、hashline 一个总开关

**What to build:** 设置面板多一页，两**组**：

- **基础能力**：一行一个（`bash` / `read` / `edit` / `write` / `glob` / `grep` / `web_fetch` /
  `web_search` / `todo_write` / `eval` …），**每格都能单独启用 / 禁用**。勾 = 装、去勾 = 卸，
  下一次 run 的名册跟着变，不重启。`eval` 在新装的家是空的。
  **一行是一个 id**（`base/write`），标签写它的名字（`write`）——名字是模型说的话，开关管的是那一份定义。
- **锚点编辑（hashline）**：**只有一格总开关**。它的四个工具（`replace` / `insert` / `anchor_grep` /
  `undo_last_replace`）在**这一组底下列出来，但不各自可点**；开关关着时四行**显示成禁用**——让人看得见
  "关掉的是什么"，又不会以为能一个一个开。开关一勾，那四个进表，而 `edit` 那一行随之变成**派生的禁用**
  （写着"被 hashline 撤掉"）；把勾去掉，`edit` 自己回来。

从用户视角：打开设置 → Tools，上面一排基础能力各自可勾、`eval` 是空的；下面一组只有一格"锚点编辑"，
底下灰着四个工具名——想换回精确字符串编辑就关掉它，`edit` 就回来了。

**Blocked by:** 01, 02

**Status:** ready-for-agent

## 现场

- 面板今天三页（General / Models / MCP）。前两页各写 config.edn 的一节，并且**如实说出那个文件的名字**
  （General 页明写 `config.edn` 的 `:default`）。`GET /api/settings` 只读；写走 `/api/defaults` 与
  `/api/providers`，两者都经 `write-config!`（备份 + 原子落）。MCP 页有自己的 `/api/mcp`（GET + POST）。
- 编辑那套今天已经是**数据**：`cap.editing/families` 是 `:hashline → 四个名字` / `:str-replace → {edit}`，
  加上拒绝话术的三个短语。02 之后它是 hashline 那一层的内容，仍是这一页要显示的名字与话术的**唯一来源**。
- **`read` / `write` 两行有个新情况**（01/02 之后）：它们由**哪一层提供**是算出来的——hashline 开着时由
  hashline 提供（锚点那张脸），关着时由基座提供（plain）。所以这一页要答的不只是"装了没有"，还有
  **"这一刻提供它的是哪一层"**。
- `:anchor-grep`（harness.edn 的 `:editing {:anchor-grep false}`）是 `anchor_grep` 自己的会话旋钮，
  与"这一层装没装"不是一件事：**留它在 harness.edn，页面只读地提一句**，不给格。
- i18n 两种语言（`locales/{zh,en}/settings.json` 等），后端的话不翻译。
- 「渲染看不到布局」：`ui/test/suites/` 的套件把一行渲成字符串再读它说什么，而布局（类名、截断、行盒）
  只有真浏览器说得清——AGENTS.md 那条铁律。

## 决策

- **页面 ↔ 端点**：`GET /api/tools` 答"目录里的能力（两组）+ 装了没有 + 这一行为什么不在 / 谁决定的 +
  值来自哪一档（默认档 / config.edn）"，`POST /api/tools` 写。与 MCP 页同一个形状（自己的端点，
  不挤进 `/api/settings`）。
- **只写一个文件**：config.edn 的 `:tools`。**harness.edn 的写通道不开**——这一条**推翻上一稿**
  （上一稿让编辑家族那一组去写用户级 `harness.edn` 的 `:editing {:mode}`）。理由：`:editing {:mode}`
  是**会话偏好**（项目级也能说），与"这个进程装不装这一层"是两件事；页面写它就有两个真相。页面把会话偏好
  显示成只读的一行 + 一句"要改去 harness.edn"，于是"一页写两个文件"的形状和它的写盘通道都不必存在。
- **两组的形状就是能力的两档**（02 定的；身份是 01 的）：基础能力一格一个**能力名 = 工具名**，
  一格的**配置键**就是那个能力名（`write`），行上显示的标签是它的名字、底下一行小字是它的 **id**
  （`base/write`）；`hashline` 一格一个
  **能力名 ≠ 工具名**，它的四个成员名**只作显示、不是可写项**。因此"两套编辑不能同时上"不需要界面约定——
  只有一个勾，勾着就是锚点，不勾就是 `edit`。
- **一行三种状态，界面必须分得出来**：
  1. **可点**——由这一页决定（基础能力的每一格）；
  2. **灰的**——不由这一页决定，并写明是谁决定的（hashline 关着时它那四个成员；hashline 开着时的 `edit`）；
  3. **在**
  灰色那一档是**算出来的**（同一份折叠给出"谁让它不在"），两组共用一条规则，不许页面各写一份判断。
- **派生行禁止可点。** 把 `edit` 那一格做成可写的，就等于把结果写进配置——02 明令不许。要动它就动
  hashline 那个勾。
- **"提供它的是哪一层"也要显示出来。** hashline 开着时，基础组里的 `read` / `write` 两行由 hashline 提供
  （锚点那张脸），格是**灰的**并写明"由 hashline 提供；要基座那张脸就关掉 hashline"；hashline 关着时，
  那两行由基座提供、格可点。想彻底不要 `read` 这个能力 = 先关掉 hashline、再关掉那一格——两件事都由人
  来说，页面只把算出来的结果如实摆出来。
  - **这一栏与"灰行"共用 01 / 02 那份数据，不另算**：归属问 `tools/owner-for`（01：答的是 **id**，
    静态那一份 + 每会话那一层），接管名单（`:replaces`）是 02 的层声明（也是 id），页面只显示结果。**页面上没有"接管"的第二种写法**——
    接管是层的作者在 setup 里说的事（声明了才不响警告），界面不提供"改接管"的格。
  - 灰行**仍可被 POST 写**（字段本来就存在），但答案里要明说"已写入，当前由 hashline 提供、这一刻不起作用"：
    不许假装写成功，也不许后端替人拒掉一个合法的配置字段。
- **默认档与 02 同源**（除 `eval` 外全装）：界面不自己编一份默认，新装的家看见的就是那个答案。
- **这一页不列 MCP 的工具**：它们已有自己的启停路，且来源是外部服务器。页面写一句让人知道去哪儿找
  （MCP 页），而不是让它们"不见了"。
- **文案两种语言都到位**："谁让它不在"那句从后端来（后端的话不翻译），组名、开关名、灰行的说明走 i18n。

## 验收

- [ ] `GET /api/tools` 答**两组**：基础能力逐项（装了没有 + 值来自哪一档），hashline 一组带**总开关状态**
      与**成员名单**；两个名单与 02 的目录交叉断言，一个不差
- [ ] `POST /api/tools` 关掉一个基础能力 ⇒ 下一次 run 的 `specs` 里没有它（真 HTTP 断言），**不重启**；
      勾回来也一样
- [ ] hashline 那一格：勾 ⇒ `specs` 里四把都在、`edit` 不在，页面上 `edit` 那行是**灰的**且写明是
      hashline 撤的；去勾 ⇒ `edit` 回来、四把不在，那四行变灰、写明是这一层没装
- [ ] `:tools` 里**只有能力名、没有 id**：写盘前后读文件断言，里面不出现 `edit` / `replace` / `insert` /
      `anchor_grep` / `undo_last_replace` 各自的格（`edit` 是基础能力，允许有它自己的格；四个锚点工具名
      **一个都不许**出现）
- [ ] `GET /api/tools` 每项带**提供它的那一份**（**id**，数据来自 01 的 `owner-for`，端点不自己算一份）；
      hashline 那个勾翻面时，`read` / `write` 两行的提供者与灰态跟着翻（一条用例各跑一次）
- [ ] 灰行被 POST 时：字段确实进了 config.edn，而答案里明说"当前由 hashline 提供、这一刻不起作用"
- [ ] 写盘前后：config.edn 的 `:default` / `:providers` **逐字不变**
- [ ] config.edn 坏掉或顶层多键时**先拒绝**并说出是哪个文件，**不覆盖**、不重建
- [ ] 界面：两组分得清；基础能力每格可点；hashline 的四个成员**看得见但点不动**；灰行写明是谁决定的；
      `eval` 在新装的家是空的；两种语言的文案都在
- [ ] UI 套件有渲染断言（把一行渲成字符串再读它说什么），至少钉住"灰行 + 说明"这一格
- [ ] 动过 `ui/src/` ⇒ 跑一次 `node scripts/dev.mjs --scripted` 走查（AGENTS.md 的铁律）
- [ ] `node scripts/test.mjs` 全绿
