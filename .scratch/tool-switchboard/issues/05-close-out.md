# 05 — 收口：词汇、文档、全量

**What to build:** 把这一轮新增的东西写进本仓的词汇表与文档，跑一趟全量，并把**界面行为**那一层用真浏览器
走一遍。只有 markdown 与验收，不改代码。

**Blocked by:** 01, 02, 03, 04

**Status:** ready-for-agent

## 现场

- `CONTEXT.md` 是全仓的**术语表**：issue、spec、代码注释、测试名一律照用；工具名的写法也钉在那里
  （小写、多词下划线、不给别名）。今天那里没有"能力层/装与卸"这件事的词，也没有"问人"这件事的词。
- **一个名字不在本会话里**今天有四条路，而术语表只有前两条的词（park / 审批，与 `:disable` 那一路）：
  1. 某一份定义被**收走**（进程级或会话级，**按 id 说话**，01）：那一份不服务，**名字回落到更早的一份**；
     没得回落才轮到"这个名字不在服务"那句；
  2. 会话级 `session-disable!`——同一件事，只在这个会话里，可逆；
  3. **没装上**（02 新造的）：不进 `specs`、调用按名拒、拒绝说清哪个开关把它关的、怎么写回来；
  4. **不服务**（这一层被另一层撤掉，02 把编辑家族归到这里）：表现同 3，**出处**不同——撤它的不是开关，
     是另一层的 setup。
  3 与 4 必须有两个名字，否则下一份 spec 会把它们读成一条；1 与 2 的区别是**范围**（进程 / 会话），
  不是「名字在不在」。
- **"同名"与"身份"是同一件事的两面，也要有词**：`name` 是**模型那一侧的门**（`specs` 里那一项、调用带的
  那串），`id` 是 **harness 自己的身份**（`base/write` / `hashline/write`，01）。一个名字下可以站着多份
  定义，**后装的那一份算**（静态在折叠里、每会话在 `effective-tools` 里，同一条规则）；**收走与接管按 id
  说**，报归属答的也是 id。层要接管别人的一份得**声明**（`:replaces`）；装配时没声明就响一声
  `harness.infra.log/warn!`（kind `:tools/taken-over`），**行为不变**。"接管"（`:replaces`）、"撤掉一份"
  （`:disable`）、"这个会话不服务一个名字"（`:narrow`）是三件不同的事，今天术语表里一个词都没有。
- `config.edn` 从「两节」变「三节」（02），而 `docs/` 里多处写着「两节」。
- `README.md` 有工具清单与设置页清单；设置页从三页变四页（03）。

## 要写什么

- **CONTEXT.md**
  - 工具名表加 `ask`（写法规矩照旧，不给别名）；同一张表补上 **id 的写法**
    （`<能力>/<名字>`、小写、`/` 分隔，`base/write` 与 `hashline/write` 是同一张表里的两行）。
  - 新增术语 **能力层**：一次 `install!` 装上的东西；装上就是它的 **setup**（层作者只声明：
    定义 push 进 ctx、单槽口各一注、带副作用的活走 `use-effect`），返回的 **dispose** 就是卸下——
    **ctx 按登记的逆序自动撤**，层作者不手写反操作。工具表由层栈折叠**算出来**，从不写下来。
    正文点明"派生结果不进配置"（`edit` 在不在、`read` 用哪张脸都不许写）。
  - 新增术语 **没装上** 与 **不服务**（上一条现场里的 3 与 4），并说明它们与 `:disable` / `session-disable!`
    的区别：**见不见得着**与**谁让它不在**。
  - 新增术语 **基础能力 / 增强能力**：设置页上就是那**两个组**。基础能力一格一个、各自可启用禁用；
    增强能力（`hashline`）只有一个总开关，它的工具名只作显示。正文点明：**能力名不等于工具名**、
    **"这个名字这一刻由哪一层提供"**（`read` / `write` 随 hashline 翻面）、以及"一格被另一层决定时变灰、
    且是算出来的"这条显示规则。
  - 新增术语 **工具 id**（与 **工具名** 成对）：名字是模型说的话（`specs` 里那一项、调用带的那串，
    **一个名字在名册里只出一份**），id 是 harness 的身份（`base/write` / `hashline/write`）——**关掉、
    接管、报归属、拒绝话术、审计都用它**。正文点明：**同一个名字下可以站着多份定义**，后装的那一份算；
    按 id 收走一份之后**名字会回落**到更早那份，而按名字收窄**不回落**（这两句分开写，它们不是一条）。
  - 新增术语 **接管**（同名接管）：层要接管别人的一份必须**声明**（`:replaces`，写的也是 id）；装配时
    没声明就响一声警告（`harness.infra.log/warn!`，kind `:tools/taken-over`），**行为一个字不改**。
    正文把 **接管 / 撤掉一份（`:disable`）/ 这个会话不服务一个名字（`:narrow`）** 三句话分清，
    并写明"这一刻供它的是哪一份"是**算出来的**（`:owners` 与 `tools/owner-for`，答 id），设置页照它显示。
  - 新增术语 **提问**：模型向人提问走 elicitation 那条链（reason 仍是 `:elicitation`，同一张卡、同一个
    resume），答案作为该次调用的工具结果回到模型。
  - 核对「冻结的开头」与 04 改后的 `prompt.md` 是否仍逐字对得上。
- **`docs/architecture/`**
  - tools 那一节：名册**是算出来的**（层栈 → 折叠 → `specs`）、**名字与 id 的分工**（模型只带名字；
    关掉 / 接管 / 归属 / 审计用 id；解析 = 名字 → 在用的那一份，回落这条要写清）、目录的位置与优先级
    （基础在前、增强在后）、层的 setup 允许有什么副作用（举 hashline 撤 `edit` 这一例）、**接管**
    （`:replaces`、那声装配警告与它的边界「现算那一半查不了」）、"这一刻由哪一份提供"是算出来的、
    两条「不在服务」的路（没装上 / 不服务）的对照表（外加「接管不是不在，是换了人」）、派生结果不落盘。
  - 组件根那一节：装哪几层、各层的 dispose 收进 stop fn。
  - 写「config.edn 两节」的地方全改成三节。
- **`README.md`**：工具清单改成"目录"的说法（不写死一份名单）、设置页清单加 Tools 页、
  "哪个配置写哪个文件"那一段。
