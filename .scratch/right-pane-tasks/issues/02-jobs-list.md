# 02 — 后台任务那一段：列得出来，秒数在长

**What to build:** 服务端一条路由答出本会话的后台作业，界面在任务视图的「后台任务」段把它们画成行：
id、命令（一行）、状态、跑了多久；结束的那几行显示它自己的末行。栏开着时 1 秒一问，栏一关就停。

**Blocked by:** 01

**Status:** ready-for-agent

## 形状

- `GET /api/threads/<stem>/jobs` 答：

  `{:threadId .. :jobs [{:id "j1" :command .. :status "[running]" | "[exit 0]" | "[stopped]"
   :startedAt <ms> :path ..}]}`

  一个作业都没有 = `:jobs []`（**不是错误**：这是「有什么」的问法，与 `job_output` 的「点名」不同）。
  只读，所以不写审计行——照这个 edge 上每一条 GET 的规矩。
- **状态取自记录末行**：复用 `cap.jobs` 里已经在读这件事的那一处（`ending-of` / `terminal?`），
  没有那一行就是 `[running]`。**不新立枚举**（`CONTEXT.md` 的「后台作业」词条：状态就是这一行）。
- **`start!` 给作业条目补 `:started-at`**（毫秒，spawn 成功之后、登记之前那一处）。今天作业条目里有
  `:id :handle :path :command :writer :ended`，**没有起点**，而「跑了多久」需要一个起点。这是唯一要动
  `cap.jobs` 写侧的地方；`job` / `job_output` / `job_kill` 的答案与形状**一个字不改**。
- **注册表随进程死**：重启之后这条路由答 `[]`，不报错、不翻盘上的记录——「有什么」说的是这个进程
  手里有什么（记录在盘上，那是 `bash` / `read` / `grep` 的事）。
- 路由落进 `edge/http.clj` 那个闭合的 `thread-verbs` 集合（`[:get "jobs"]`），认不出的方法照旧 405。
- 界面那一行：id 等宽、命令**压成一行**（内部换行折成空格，过长截断）、第二行是状态与
  「跑了多久」（只有还在跑的那几行有秒数，**用一个具名常量控制刷新节奏**）、结束的那几行没有秒数、
  路径按 `job-receipt-no-path` 的规矩可以报（这一栏就是「读的那一个」）。

## 决策

- **轮询，不是订阅。** 作业的结局今天没有一条推送通道给客户端（通知走的是「下一通模型调用」那条路，
  不是帧总线），而这一栏要的是「现在怎么样」——1 秒一问、栏关了就停，比为一个面板新开一条 SSE 便宜。
  轮询只在**任务视图开着且页面可见**时跑；关掉之后不许有在飞的请求（与「关掉镜子就挂断跟随通道」
  同一条纪律）。
- **`c*` 前台溢出记录不进这一栏。** 它不是一个作业（`cap.jobs/spill!` 的原话：没有进程可停、没有 id
  有人会去寻址），这一栏是「后台任务」。模型那一侧的 `job_list`（`.scratch/readback-verbs`）列它是为
  了「回头找一条命令说过什么」，两个听众，两种范围——但**状态话只有一处出处**。

## 验收

- [ ] 用例：`GET /api/threads/<stem>/jobs` 三种行都对——没有作业 `[]`、一条跑完的（末行 `[exit 0]`）、
      一条挂着的（`[running]`、`:startedAt` 是一个数），且都是这个会话的（另一个会话的作业不出现）
- [ ] 用例：方法不对 → 405（照既有的那条）
- [ ] 用例：重启之后（注册表空）答 `[]` 而不是拒绝
- [ ] 界面用例：任务视图把行画出来——跑完的没有「跑了多久」、挂着的在长（无 DOM 的渲染用例，照
      `ui/test/suites/` 里既有的写法）
- [ ] 用例 / 走查证据：栏关掉之后轮询停了（没有在飞的请求，也没有定时器）
- [ ] 命令很长时那一行截断而不撑开栏（走查证据）
- [ ] 中英两套文案都在；`npm test` + `npm run typecheck` 绿
